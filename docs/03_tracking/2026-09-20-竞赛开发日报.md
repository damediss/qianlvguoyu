## 一、今日结论

今日竞赛开发从“实操组卷、试卷绑定和裁判资源管理”继续推进到“实操运行、裁判组调度和评分工作台”阶段。后端已补齐实操考评表、实操会话、选手题目提交、裁判启动门禁、裁判评分和实时控制台相关能力；管理端新增实操配置、实操控制台、裁判端/裁判组管理和蓝图维护页面；Android WebView Demo 增加竞赛实操裁判端变体。

当前代码可以 clean compile、前端构建和重点竞赛单测，但仍不具备可合并/可部署结论：理论试卷绑定回归仍有 1 个失败用例，数据库迁移和完整真实业务闭环尚未验收。

## 二、今日开发进展

### 1. 实操考评与运行链路

- 新增实操考评表、考评内容、考评要素和评分项相关模型、Mapper、Service、VO 及接口，支持从结构化考评表读取评分内容。
- 补齐实操会话初始化、选手任务、实操题提交状态、评分录入和成绩汇总的运行链路；新增实操比赛控制台，按选手展开任务和裁判评分卡。
- 增加裁判启动门禁：只有符合规则的裁判组组长可以启动对应实操任务，非组长启动会被拒绝并记录告警。
- 新增/调整 `V20260920_001`、`V20260920_003`、`V20260920_102`～`V20260920_104`，覆盖实操考评运行表、考评表编码修正、裁判启动门禁和选手题目提交状态。

### 2. 裁判组、裁判资格与实时评分

- 新增裁判组、裁判组成员和裁判资格范围模型，支持赛段外层级的裁判组维护、成员替换、资格等级范围及排期冲突检查。
- 补充裁判管理、裁判分配、裁判评分和实操实时控制器；评分服务覆盖任务查询、分数提交、组长门禁和范围校验。
- 管理端新增裁判组页面、裁判分配工作区、实操裁判端和实操控制台；Android 端新增 `competitionJudgeDebug` 与 `competitionJudgeLocalDebug` 变体及对应页面资源。
- 配套补充 `V20260918_004`、`V20260918_005`、`V20260920_002`、`V20260920_102`～`V20260920_104` 迁移，形成裁判全局化、资格范围、裁判组和运行门禁的数据基础。

### 3. 蓝图、组卷与实操试卷编排

- 增加理论/实操蓝图模板、解析器、模板下载和蓝图树查询；补充蓝图绑定、覆盖率和导入测试能力。

- 赛段编排、实操试卷绑定、选手理论/实操分卷和历史快照查看已形成管理端串联入口。

### 4. 需求与工程配套

## 四、遗留问题与风险

1. **P1：理论试卷绑定回归未全绿。** 先确认 `A 卷` 缺失是测试数据准备、页面筛选状态还是接口 mock 问题，再恢复全量竞赛前端回归绿灯。
2. **P1：数据库迁移尚未做环境验收。** 需分别查询测试库与生产库 Flyway 最大版本，在隔离库执行新增迁移，核对完整 BaseEntity 字段、唯一约束、索引、租户 10159 的菜单—权限码—角色授权链和重复执行。
3. **P1：实操运行链路缺少真实联调。** 当前证据主要来自编译和单测，裁判组排期、组长启动门禁、实时评分和成绩汇总仍需使用真实数据做最小闭环。
4. **P2：前端存在非阻断警告。** 组卷页出现重复 key，Ant Design 存在 `bordered`/`destroyOnClose` 弃用提示，正式考试控制台测试中有 Query mock 返回 `undefined` 的提示，建议后续单独清理。
5. **P2：工作区含本地生成物。** Playwright 报告、测试结果、运行时目录、上传文件、临时表格和 `.class` 文件不属于交付物，本次提交不纳入。
