### 1.2 共同列（双写必须对齐）

与 `PlatformSyncService.USER_COLUMNS` 一致：

```text
id, realname, idcard, phone, password, stat, addtime, logintime,
org_id, company_id, wxopenid, deleted, expert_id, task
```

detail 轻量壳沿用 ensure 现逻辑（gender/birthday from idcard 等）；PHP detail **无 `deleted`**，插入时不要带 SaaS 专有列。

### 1.3 密码（必须单测对齐）

| 端 | 算法 |
|----|------|
| PHP | `md5('123123'.$stat)`，`$stat = getRandChat(4)` |
| SaaS 现网 | `PlatformUserEnsureService.md5("123123", stat)` → `MessageDigest` 对 `password+stat` 做 MD5 hex |

**实现约束：** 双写时 **同一对 `stat`/`password` 写入两边**；REUSED 禁止改 `password`/`stat`。

### 1.4 id 边界

```text
id <  1_000_000_000  → PHP 来源（同步任务可对账/删除镜像）
id >= 1_000_000_000  → SaaS 本地高位（同步任务永不删除）
```

可登录学员的 `train_people_list.platform_user_id` **必须落在 PHP 区间**（新建走 PHP 自增；复用 PHP 已有 id）。

## 3. 模块设计

### 3.1 新建 `PhpPlatformUserWriter`

包建议：`com.guoyu.platform.integration.php`（与 `PhpExamQueryService` 同层）。

```java
public interface PhpPlatformUserWriter {
  /** 按身份证查未删除用户；无则 empty */
  Optional<PhpUserRow> findByIdCard(String idCard);

  Optional<PhpUserRow> findByPhone(String phone, Long excludeId);

  /** INSERT，返回自增 id；password/stat 由调用方算好传入 */
  long insert(PhpUserWrite cmd);

  /** 更新姓名/手机/org/company；禁止改 password/stat */
  void updateProfile(long id, PhpUserProfilePatch patch);
}
```

实现要点：

1. 注入 `@Qualifier("phpJdbcTemplate") JdbcTemplate`。  
2. `INSERT` 使用 `GeneratedKeyHolder` 取 id。  
3. SQL 显式列清单 = `USER_COLUMNS`（与同步一致）。  
4. `query-timeout` 沿用 `platform.sync.php.query-timeout-seconds`。  
5. 所有写操作打 info 日志（mask 证号/手机）。

### 3.2 改造 `PlatformUserEnsureService`

保持方法签名：

```text
ensureFromDivisionPerson(realname, idCard, phone, companyId, orgId) → EnsureResult
```

伪代码：

```text
normalize + 校验证号/手机（现有 SKIPPED 规则不变）

if (!phpWriteEnabled) {
  return legacySaasOnlyEnsure(...)   // 现有逻辑原样抽出
}

phpRow = phpWriter.findByIdCard(idCard)
if (phpRow.isEmpty) {
  if (phpWriter.findByPhone(phone).isPresent) → SKIPPED 手机占用
  stat, password = newStatAndHash("123123")
  phpId = phpWriter.insert(...)
  outcome = CREATED
} else {
  phpId = phpRow.id
  按现规则决定是否 updateProfile（手机冲突 warning 等）
  outcome = UPDATED | REUSED
  // 绝不改 password/stat
}

mirrorToSaas(phpId, fields...)  
  - selectById(phpId)：有则 updateById（可改姓名手机 org；新建镜像时写入 password/stat）
  - 无则 new Entity; setId(phpId); insert  ← 需支持指定 id
syncDetailFillEmpty(...)
return EnsureResult(outcome, phpId, warning)
```

**指定 id 插入 SaaS：**

- `PlatformUserEntity` 当前 `@TableId(type = IdType.AUTO)`。  
- 镜像插入时：`entity.setId(phpId)` 后 `mapper.insert`；MyBatis-Plus 在 id 非空时一般会写入该 id（需单测确认；若被忽略则改用 `JdbcTemplate` 主库 insert 或 `@TableId(type = INPUT)` 的专用方法）。  
- **禁止**先 AUTO 再改 id。

### 3.3 配置

`application.yml` 增加（默认生产倾向开启，本地可关）：

```yaml
platform:
  user-provisioning:
    php-write-enabled: ${PLATFORM_USER_PHP_WRITE_ENABLED:false}  # 生产显式 true
    fail-soft: ${PLATFORM_USER_PHP_FAIL_SOFT:true}               # PHP 单人失败 → SKIPPED+warning
```

新建 `UserProvisioningProperties`（`@ConfigurationProperties(prefix = "platform.user-provisioning")`）。

运维：**生产必须 `php-write-enabled=true`**，并给 PHP 账号：

```sql
GRANT SELECT, INSERT, UPDATE ON gjjddb.platform_user TO '<php_user>'@'<saas_ip>';
GRANT SELECT, INSERT, UPDATE ON gjjddb.platform_user_detail TO '<php_user>'@'<saas_ip>';
```

（具体账号沿用现有 `PHP_MYSQL_USERNAME`，由 DBA 扩权，勿在文档写死密码。）

### 3.4 事务边界（重要）

| 问题 | 做法 |
|------|------|
| PHP 与 SaaS 非同一 DB，无法单库事务 | **先写 PHP，成功后再写 SaaS** |
| SaaS 镜像失败 | `fail-soft=true`：记 warning，仍返回 `phpId`（花名册可绑）；依赖 `PlatformSyncService` 水位线/指纹在数秒～1 分钟内补齐镜像；另打补偿日志 |
| PHP 失败 | SKIPPED 或按 fail-soft；不写 SaaS 高位号 |
| 分班大事务 | 单人 ensure 异常不要拖垮整班（现 SyncStats 已支持 skip） |

可选 P1：表 `platform_user_php_mirror_fail`（php_user_id, payload_json, retry_count）+ 定时补偿；P0 可先靠同步任务。

## 5. 高位孤儿治理（补跑算法）

对花名册行 `platform_user_id = U`：

```text
if U == null → ensure 双写 → 写回新 id
if U < 1e9 → 校验 PHP 是否存在；存在则 loginReady；不存在则当 NULL 重跑
if U >= 1e9 →
    按身份证 ensure（PHP 优先）→ newId
    花名册 platform_user_id = newId
    SaaS 高位行：deleted=1（或保留不动，仅不再引用）
```

补跑入口复用/扩展：

1. `POST /training/division/pack-tasks/{id}/sync-platform-users`  
2. `POST /training/info-classes/{id}/people/sync-app-accounts`（新建）

## 7. 测试方案

### 7.1 单测

| 用例 | 期望 |
|------|------|
| 缺证号/手机 | SKIPPED，不调 PHP insert |
| PHP 无、手机干净 | PHP insert → SaaS 同 id → CREATED |
| PHP 已有同证 | 不改密；REUSED；SaaS upsert 同 id |
| 手机被其他证占用 | SKIPPED |
| `php-write-enabled=false` | 仅 SaaS（兼容旧行为） |
| 密码向量 | `stat=abcd`, pwd=`123123` → 与 PHP 样例 hex 一致 |

### 7.2 集成 / 手工

1. 准备测试身份证+手机（PHP/SaaS 均无）。  
2. 走分班确认或开班导入。  
3. 查 PHP：`SELECT id,phone,idcard FROM platform_user WHERE idcard=?`。  
4. 查 SaaS：同 id 行存在。  
5. 查花名册：`platform_user_id` = 该 id（&lt;10 亿）。  
6. App：`/appauth/login` 手机或证号 + `123123` → 成功。  
7. 再导入同一人：REUSED，密码仍可登录。

### 7.3 回归

- `PlatformSyncService` 周期仍成功；双写用户不被误删。  
- 提升/同步学旧账号登录不受影响。  
- 分班确认在 PHP 写权限缺失时：fail-soft 有 warning，建班仍成功。

## 10. 风险与实现对策

| 风险 | 对策 |
|------|------|
| MP insert 忽略手动 id | 单测卡住；改 JDBC `INSERT INTO platform_user (id,...)` |
| PHP/SaaS 字段默认值差异 | 只写共同列；NULL 与 0 对齐同步任务指纹 |
| 双写后同步指纹覆盖手机 | 两边同写；UPDATE 顺序 PHP→SaaS |
| 本地无 PHP 库 | `php-write-enabled=false`；CI 用 Testcontainers 或 mock Writer |
| 权限不足 | 启动可选健康检查：`INSERT` 探测失败则告警 |
