# 三年规划企业审核：筛选名单回传 + 排班表上传 实现方案

> 文档版本：v1.0  
> 编写日期：2026-07-15  
> 适用范围：`qianlvguoyu_saas` 方案规划 → 企业审核链路增强  
> 关联：`SolutionPlanningPage`、`EnterprisePlanReviewPanel`、`TrainThreeYearPlanApplicationService`  
> 下游预留：分班（`fen_ban`）、Scheduling 排班解析

## 一、需求澄清

### 1.1 业务目标

三年规划经机构审核并「提交企业审核」后，企业侧不是简单点「确认」，而是：

1. 下载机构提交的审核人员名单 / 已审核规划表  
2. **对企业培训名单进行筛选**（线下 Excel 调整或线上勾选，本期优先线下筛后回传）  
3. **将筛选后的名单上传回系统**  
4. **同时上传名单对应人员的排班表**  
5. **管理员（机构）可下载查看** 企业回传的名单与排班表  

确认后的回传材料作为开班/分班下游输入。

### 1.2 与现状差异

| 现状 | 目标 |
|------|------|
| 企业仅 `company-confirm` / `company-reject` | 确认前必须上传「筛选名单 + 排班表」 |
| 仅机构上传 `submit_personnel` / `submit_scheme` | 增加企业回传两类文件 |
| status `3→4` 无附件门槛 | `3→4` 绑定回传校验；或引入中间态 |

### 1.3 本期范围（建议）

**做：**

- 企业回传筛选名单（Excel）、排班表（Excel）  
- 文件落库、版本历史、机构下载/预览  
- 确认时强校验两份文件已齐  
- 简单校验：名单表头、不少于 1 行；排班表后缀与大小  

**暂不做（可二期）：**

- 在线勾选筛选（仍用 Excel 回传）  
- 自动解析排班表入分班算法  
- 名单与三年规划明细强一致校验（工号/身份证逐人 diff）——可作为开关增强

## 二、推荐流程（状态机）

### 2.1 方案推荐：**在 status=3 上完成回传，确认时强制校验**（改动最小）

```
机构提交企业审核 ──► status=3 待企业审核
                        │
         ┌──────────────┼──────────────┐
         ▼              ▼              ▼
      下载材料      上传筛选名单    上传排班表
         │              │              │
         └──────────────┼──────────────┘
                        ▼
              企业确认（两文件齐全）──► status=4
              企业驳回 ──────────────► status=5
```

- **优点**：少增状态码，兼容现有菜单筛选与权限  
- **代价**：status=3 期间可能「未上传 / 已上传未确认」，需 UI 展示回传齐套状态  

### 2.2 备选：增加中间态 `3.5 / 新码 7`

例如：`3 待企业审核` → `7 企业已回传待机构核对` → `4 确认`。  

仅当业务要求「机构再点一次验收」时采用；否则推荐 2.1。

### 2.3 驳回规则

- status=3 且**未最终确认**前：企业可多次覆盖上传回传文件  
- 驳回（5）：清空或保留回传文件均可；**建议保留历史**（history JSON），当前指针可清空，便于机构对照  
- 机构重新提交（5→3）：清空「当前回传文件指针」，历史归档

## 三、数据模型

### 3.1 表 `train_three_year_plan` 新增字段

```sql
-- Flyway 示例：V20260715_00x__add_enterprise_return_files.sql

ALTER TABLE train_three_year_plan
  ADD COLUMN enterprise_roster_file_id BIGINT NULL
    COMMENT '企业回传：筛选后培训名单文件ID' AFTER submit_scheme_file_id,
  ADD COLUMN enterprise_shift_file_id BIGINT NULL
    COMMENT '企业回传：排班表文件ID' AFTER enterprise_roster_file_id,
  ADD COLUMN enterprise_roster_file_name VARCHAR(255) NULL
    COMMENT '企业回传名单原始文件名' AFTER enterprise_shift_file_id,
  ADD COLUMN enterprise_shift_file_name VARCHAR(255) NULL
    COMMENT '企业回传排班表原始文件名' AFTER enterprise_roster_file_name,
  ADD COLUMN enterprise_return_time DATETIME NULL
    COMMENT '企业最近一次回传时间' AFTER enterprise_shift_file_name,
  ADD COLUMN enterprise_return_user_id BIGINT NULL
    COMMENT '企业最近一次回传人' AFTER enterprise_return_time,
  ADD COLUMN enterprise_return_username VARCHAR(64) NULL
    COMMENT '企业最近一次回传人姓名' AFTER enterprise_return_user_id,
  ADD COLUMN enterprise_return_history_json TEXT NULL
    COMMENT '企业回传历史 JSON' AFTER enterprise_return_username;
```

`enterprise_return_history_json` 示例：

```json
[
  {
    "rosterFileId": 101,
    "rosterFileName": "筛选名单.xlsx",
    "shiftFileId": 102,
```

文件本体复用现有 `file` / COS 存储（与 `submit_*_file_id` 同一套 `FileApplicationService`）。

### 3.2 不新增明细表（一期）

- 回传名单**默认当附件**存，不做入库逐行解析  
- 二期再：`train_three_year_plan_enterprise_roster` 解析行，供分班自动带入  

### 3.3 VO 扩展

`TrainThreeYearPlanVO` 增加：

- `enterpriseRosterFileId` / `Name`  
- `enterpriseShiftFileId` / `Name`  
- `enterpriseReturnTime` / `Username`  
- `enterpriseReturnReady`（computed：两文件均非空）  
- `enterpriseReturnHistory`

## 四、接口设计

Base：`/api/training/three-year-plans`

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/{id}/enterprise-return` | `enterprise_confirm` | multipart：`rosterFile` + `shiftFile`（可同传；也支持分次传其中一个并合并当前指针） |
| GET | `/{id}/download-enterprise-roster` | `view` | 机构/企业下载筛选名单 |
| GET | `/{id}/download-enterprise-shift` | `view` | 下载排班表 |
| POST | `/{id}/company-confirm` | `enterprise_confirm` | **改造**：确认前校验两文件齐全，否则 400 |
| POST | `/{id}/company-reject` | 同现有 | 不变（可选：驳回时写 history） |

### 4.1 `enterprise-return` 行为

1. 校验规划 `status == 3`，且当前用户为企业且 `targetOrgId` 匹配（复用 `assertEnterpriseCanConfirm`）  
2. 校验扩展名：名单 `.xlsx/.xls`；排班表 `.xlsx/.xls`（若现场另有 csv，二期放开）  
3. 大小限制沿用全局 multipart（如 20MB）  
4. 上传落库 → 更新当前指针字段 → append history  
5. 返回完整 VO（含 `enterpriseReturnReady`）  

**分次上传：** 允许只传 `rosterFile` 或只传 `shiftFile`，另一侧保留原值；`return_time` 每次刷新。

### 4.2 `company-confirm` 改造

```text
if (rosterFileId == null || shiftFileId == null)
  throw BAD_REQUEST("请先上传筛选后的培训名单与排班表后再确认");
// else 原确认逻辑 status=4 ...
```

### 4.3 下载

与现有 `download-submit-personnel` 同模式：按 fileId 取流 + `filename*=UTF-8''`。

## 五、前端改造

### 5.1 企业审核详情 `EnterprisePlanReviewPanel`

在 status=3 详情中增加区块 **「企业回传」**：

1. 提示：请先下载机构材料，筛选名单后上传，并上传对应人员排班表  
2. Upload：筛选名单、排班表（可拖拽；上传即调 `enterprise-return`）  
3. 已回传文件名 + 时间 + 下载/预览按钮  
4. 「确认」按钮：`enterpriseReturnReady !== true` 时 disabled，Tooltip 说明缺什么  
5. 「驳回」仍可用（可不依赖回传）  

### 5.2 方案规划详情 `SolutionPlanningPage`（机构）

当 status ∈ {3,4,5}：

- 展示企业回传齐套状态 Tag：`未回传` / `已回传待确认` / `已确认`  
- status≥3 且已有回传文件：提供 **下载筛选名单**、**下载排班表**（管理员查看）  
- status=4：回传文件只读下载  

### 5.3 列表列（可选）

企业审核列表增加「回传」列：未齐 / 已齐。

### 5.4 文案与模板（建议提供下载）

- 《企业筛选培训名单回传模板.xlsx》（字段建议见下）  
- 《排班表回传说明》（列约定可引用 Scheduling：姓名、工号、日期列班次）  

**筛选名单建议列（与机构提交名单尽量对齐）：**

`姓名、身份证号、工号、部门、工种、认定等级、认定时间、是否参加本期培训（是/否）`  

若继续用「删行=不参加」模式，则模板说明写清即可，系统一期不解析「是否」列。

## 八、验收用例

1. 机构提交后企业进入详情：可下载机构材料；确认按钮默认不可点  
2. 只上传名单：确认仍不可点；再上传排班表后可确认 → status=4  
3. 确认后机构可下载两份回传文件；企业不可再改传（或仅查看）  
4. 未上传点确认：接口 400，文案明确  
5. 驳回后机构重新提交：回传当前指针清空，历史仍可查（若做了 history）  
6. 无权限企业访问其他企业规划：403

## 九、风险与决策项（需产品拍板）

1. **确认是否必须两文件？** 建议必须。  
2. **驳回是否允许不传文件？** 建议允许。  
3. **确认后能否再次替换回传？** 建议否（冻结）；需改则机构驳回重走。  
4. **名单是否必须从表内人员子集来？** 一期不强制；二期做工号/身份证校验。  
5. **排班表格式是否强制 Scheduling 模板？** 一期只校验 xlsx；格式在说明中约束，二期解析。

## 十、结论

- **实现路径**：最小改动增强现有 status=3 企业审核——新增企业回传两个文件字段 + 上传/下载 API，确认时强校验齐套；机构侧增加下载查看。  
- **不阻塞**：在线勾选、解析入库、自动分班可放到二期，与 O3「分班 → 开班准备」衔接。  
- **优先落地**：Flyway → API → 企业 Upload UI → 确认校验 → 机构下载。  

确认本方案后可按第七节任务拆分直接开工。
