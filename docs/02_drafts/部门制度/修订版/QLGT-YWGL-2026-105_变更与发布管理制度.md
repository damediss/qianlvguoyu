# 千铝工投云平台与智能体开发部变更与发布管理制度

制度编号：QLGT-YWGL-2026-105　　版本：V1.1　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为统一管控生产环境的变更与应用发版，覆盖 Web、小程序、App、私有化部署包等多端发布通道，确保每次变更可回退、可追溯，特制定本制度。本制度遵循部门制度“简洁、可测试、可维护、持续迭代”的共同标准。

**第二条**　本制度适用于全部生产环境变更，包括应用发版、配置调整、中间件与数据库变更、生产数据订正。

## 第二章　变更分类与审批分级

**第三条**　常规变更：计划内发版与配置调整，至少提前 1 个工作日提交变更单，说明内容、影响范围、验证方式与回退方案，由运维负责人审批。

**第四条**　紧急变更：线上故障的应急修复，可先经运维负责人口头批准执行，24 小时内补录变更单。

**第五条**　生产数据订正：必须提供书面 SQL、影响行数预估、执行前备份方案，经运维负责人审批后由双人复核执行，执行结果与影响行数留痕。

**第六条**　无审批、无回退方案的变更一律禁止执行。

## 第三章　发布流程

**第七条**　Web 端（platform-api、admin-web）：代码合并主干 → 构建 → 测试环境验证 → 生产发布 → 发布人按冒烟清单验证 → 通报完成。数据库迁移脚本随版本执行，执行前先备份。

**第八条**　微信小程序：上传体验版 → 内部验证 → 提交审核 → 审核通过后先灰度发布 → 观察无异常后全量。

**第九条**　App：按渠道打包 → 内部测试包验证 → 渠道发布，记录各渠道版本号。

**第十条**　私有化部署包：输出安装包、升级脚本与升级手册，版本编号唯一，现场升级按 YW-10 执行。

## 第四章　变更窗口与灰度策略

**第十一条**　常规发布窗口为工作日 10:00–17:00，避开考试、集中培训等业务高峰时段；考试与集中培训期间冻结常规变更，冻结清单由值班人提前 3 个工作日发布。确需在高峰或节假日变更的，报部门负责人批准。

**第十二条**　影响面大的版本采用灰度策略：先单租户或小比例用户，观察至少 1 天无异常后全量；灰度期间安排专人盯监控。

## 第五章　回退机制与发布失败处置

**第十三条**　每次发布必须具备回退方案：代码可回退到上一版本标签，数据库变更配套回退脚本或恢复点；无法回退的变更须单独评审。

**第十四条**　发布后发现异常，发布人 30 分钟内决定修复或回退；预计修复超过 1 小时的一律先回退，禁止在线上长时间带病调试。

**第十五条**　回退执行后须验证业务恢复，并在变更单中记录失败原因与后续处理。

## 第六章　附则

**第十六条**　本制度由部门负责人负责解释。

**第十七条**　本制度自发布之日起施行。
