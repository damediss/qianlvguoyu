# 按工种与等级自动分班方案  
（确认名单 + 排班表 → 工种×等级切班 ≤50）

> 文档版本：v1.1  
> 编写日期：2026-07-20  
> 状态：已落地（决策确认并实现）  
> 关联：`名单排班自动分班方案.md`、现网 `POST /training/division/auto-pack` 与 `train_division_pack_task` 草稿审核流  

---

## 1. 目标

用系统中已具备的两类企业回传材料：

| 材料 | 来源 | 作用 |
|------|------|------|
| **筛选培训名单** | 三年规划企业确认后回传 | **谁要培训**；提供 **工种、等级** |
| **工人排班表** | 企业回传月排班 | **约束**：过滤当月几乎不能上课的人；可补全班组（**不作为本方案主分组维**） |

系统自动：

1. 解析名单入待分池  
2. 结合排班做可上课过滤（可选）  
3. 按 **工种 × 等级** 分组后，每组按班额上限切成培训班  
4. 默认每班 **≤ 50** 人（可配置）  
5. 先出 **草稿** → 机构编辑 → 提交企业审核 → **通过后再创建** `train_info_class` + `train_people_list`

**一句话：**  
稳定培训名册按「工种 + 等级」开班，不是按生产班组切班，也不是默认拆成很多「上午1班 / 下午2班」时段班。

---

## 2. 与现网策略对照

| 项 | 现网默认 `by_shift_team` | 现网可选 `by_job_level_slot` | **本方案 `by_job_level`** |
|----|--------------------------|------------------------------|---------------------------|
| 主分组 | 生产班组 / 倒班类型 | 工种×等级 × 上下午时段 | **工种 × 等级** |
| 排班作用 | 补全班组 + 可上课过滤 | 完整按日上下午算法拆班 | **过滤/补全为主，不拆时段班** |
| 班级形态 | `{前缀}{班组}-{n}班` | `{前缀}{工种}-{等级}-上午n班`（班多） | `{前缀}{工种}-{等级}-{n}班`（稳定） |
| 同人多班 | 否 | 是（多时段） | **否** |
| 班额 | ≤50 切块 | 算法班额 + 再切 | **≤50 切块** |

> **说明：** `by_job_level_slot`（工种等级 + 上下午时段）作为「高级/时段开班」保留，与本方案默认路径分离，避免班数量爆炸、与「稳定开班名册」目标混淆。

## 3. 总体流程

```
三年规划 status=4
  + 企业筛选名单 + 排班表齐套
      ↓
  确保 / 复用 train_info_list
      ↓
  按当前名单文件重解析 → train_plan_roster（待分池）
      ↓
  排班轻量画像（可选：过滤无可上课日）
      ↓
  【新】策略 by_job_level：按 (工种, 等级) 分组 → 每组 classMax 切块
      ↓
  写入 train_division_pack_task（status=draft）
      ↓
  机构编辑班级/学员 → submit → pending
      ↓
  企业审核通过 → 物化 train_info_class + train_people_list
```

复用现网能力：

| 能力 | 处置 |
|------|------|
| `POST /training/division/auto-pack` | **扩展**策略值 `by_job_level` |
| `train_division_pack_task` 草稿 / 提交 / 企业确认物化 | **复用** |
| `TrainShiftProfileService` | **复用**过滤与班组补全；**不**调用完整 L2 `ScheduleAlgorithmService` 拆时段班 |
| `by_shift_team` / `by_roster_order` / `by_job_level_slot` | 保留为备选 |

## 4. 分组与切班规则

### 4.1 分组键

| 字段 | 名单来源 | 空值默认策略（推荐） |
|------|----------|----------------------|
| 工种 | `job_name` | **不入自动班**，进「未分入」，原因：`缺工种` |
| 等级 | `level_name` | **不入自动班**，进「未分入」，原因：`缺等级` |

配置项建议：

| 配置 | 默认 | 说明 |
|------|------|------|
| `requireJobAndLevel` | `true` | 为 `false` 时，空值归入 `未填工种` / `未填等级` 再切班 |

**硬约束：** 不同工种之间不混班；不同等级之间不混班。

### 4.2 切班

1. 同一 `(工种, 等级)` 内人员按姓名排序（稳定可复现）。  
2. 按 `classMax`（默认 **50**）顺序切块：`1班、2班…`。  
3. 尾班允许少于 50；不强制 `classMin`（可选后续：尾班 &lt;20 提示合并，首期不做）。  

### 4.3 班级命名

```
{classNamePrefix}{工种}-{等级}-{序号}班
```

示例：`来铝-电工-高级/技师-1班`  

- 工种/等级原文做文件名安全替换（`\/:*?"<>|` → `-`）。  
- `classNamePrefix` 缺省：`{企业名}-{yyyyMM}-`（与现网一致，年月来自「排班年月」配置，仅用于命名前缀，见 §5）。

### 4.4 人员过滤与去重（入池后）

| 规则 | 结果 |
|------|------|
| 名单内身份证重复 | 后者进未分入 |
| 已在该培训信息学员中 | 未分入 |
| `useShiftFilter=true` 且当月无可上课日 | 未分入 |
| `excludeNoIdCard=true` 且无身份证 | 未分入（默认 false，无证仍可入班） |
| `requireJobAndLevel=true` 且缺工种或等级 | 未分入 |

人员主键：优先身份证。

## 5. 排班年 / 月与名单年份

| 配置项 | 含义 | 本方案约定 |
|--------|------|------------|
| 排班年、排班月 | 解析哪一月的倒班表 | **只服务排班画像与班级名前缀中的 yyyyMM** |
| 名单 `plan_year` | 人员所属培训规划年（若有） | **分班应按「培训年」过滤，与排班年对齐校验** |

### 5.1 推荐门禁

1. 解析名单时：若工作表名可识别年份（如 `明细_2026`），写入 `train_plan_roster.plan_year`。  
2. 一键分班时：取请求中的 `year`（界面「排班年」，产品文案可改为「培训/排班年」以免误解）。  
3. 若池中存在带 `plan_year` 的行：  
   - **仅保留** `plan_year == year` 的人参与分组；  
   - 其他年份进未分入，或直接报错「所选年份与名单无交集」（推荐：**无交集则报错**，避免 silent 空跑）。  
4. 若全部行 `plan_year` 为空（纯筛选名单无年份列）：不按年过滤，但界面提示「名单未带年份，将使用全部待分人员」。

> 这样可避免「选 2025 年仍把无 2025 规划人员整池分班」的产品问题。

## 6. 接口设计

### 6.1 扩展现有请求

`POST /training/division/auto-pack`

在现有 `TrainDivisionAutoPackReq` 上：

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "strategy": "by_job_level",
  "classMax": 50,
  "classNamePrefix": "来铝-",
  "year": 2026,
  "month": 4,
  "useShiftFilter": true,
  "requireJobAndLevel": true,
  "autoParseRoster": true
}
```

| 字段 | 说明 |
|------|------|
| `strategy` | 新增合法值 **`by_job_level`** |
| `requireJobAndLevel` | 可选，默认 `true` |
| 其余 | 与现网一致 |

### 6.2 响应

仍返回 `train_division_pack_task` 视图：`taskId、status=draft、classes[]、unassigned[]、warnings[]`。  
`classes[].group` 建议为 `{工种}-{等级}`；成员含 `jobName、levelName、workshop` 等已有字段。

### 6.3 后续链路（不改语义）

- `POST .../pack-tasks/{id}/patch`：机构改班名、调人（同人不可跨班重复，本策略下）  
- `POST .../pack-tasks/{id}/submit` → `pending`  
- `POST .../pack-tasks/{id}/company-confirm` → 物化建班  
- `POST .../pack-tasks/{id}/company-reject` → `rejected`，可再改再提

## 7. 前端

### 7.1 策略选项（建议文案）

| 值 | 展示 | 说明 |
|----|------|------|
| `by_job_level` | **按工种/等级切班（推荐）** | 本方案；建议改为默认 |
| `by_shift_team` | 按班组/倒班切班 | 现网默认，改为备选 |
| `by_job_level_slot` | 工种/等级 + 上下午时段（高级） | 班会很多，单独说明 |
| `by_roster_order` | 按名单顺序切班 | 最简 |

页面提示示例：

> 按名单中的工种与等级分班；排班表用于过滤当月难以上课的人员。不同工种或等级不会分入同一班。

### 7.2 「年 / 月」文案

建议改为：

- **培训年份**（或「培训/排班年」）：用于名单年份过滤 + 排班解析年  
- **排班月份**：仅用于当月排班解析  

结果页展示每班：工种、等级、人数、班名。

## 8. 数据落库（物化后）

与现网开班域一致：

```
train_three_year_plan
  → train_info_list
      → train_division_pack_task（draft → pending → materialized）

              → train_people_list
```

物化后班级 `company_confirm_status=1`（方案级审核已通过，与现网 pack 物化一致）。

## 9. 验收用例

| ID | 场景 | 期望 |
|----|------|------|
| J01 | 同工种同等级 80 人 | 2 班（如 50+30），班名含该工种与等级 |
| J02 | 电工-高级 40 + 电工-中级 40 | 2 班，**不混等级** |
| J03 | 电工-高级 40 + 钳工-高级 40 | 2 班，**不混工种** |
| J04 | 缺工种或缺等级（require=true） | 进未分入，不进自动班 |
| J05 | 排班显示当月无可上课日且过滤开启 | 进未分入 |
| J06 | 名单带 plan_year，所选 year 无匹配人 | 明确报错，不分班 |
| J07 | 企业驳回后机构调整再提交 | 状态 rejected→draft→pending，可再通过物化 |
| J08 | 同身份证已在该培训信息中 | 未分入，不重复建学员 |

## 11. 决策项（已确认）

| # | 问题 | 确认结论 |
|---|------|----------|
| 1 | 是否将 **`by_job_level` 设为产品默认策略**？ | **是**（确认名单 + 排班表，按工种和等级分班） |
| 2 | 缺工种/等级：未分入，还是进「未填」班？ | **进「未分入」**（`requireJobAndLevel=true`） |
| 3 | 排班是否仅做过滤、不参与分组？ | **是**（过滤无可上课日；不参与分组） |
| 4 | 本阶段是否默认启用「工种×等级×上下午时段」？ | **否**（`by_job_level_slot` 仅保留为高级选项） |
| 5 | 名单有年份时，所选年无人是否直接报错？ | **是** |

确认人：产品沟通 2026-07-20。按本文开发；落地后将状态改为「已落地」。
