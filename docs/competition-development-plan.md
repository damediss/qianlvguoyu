# 竞赛模块开发实施计划

> 范围：本文件是后续 Codex 开发任务的拆分依据。本阶段没有创建应用、页面、接口、菜单或 Flyway 迁移。

## 1. 第一阶段 MVP 范围

MVP 目标是跑通“选手获得赛事资格并完成基础赛事任务”的可靠最小闭环，而不是一次实现原型全部 102 个视图。

基础链路的可行性、唯一状态机、数据补充与验收路径见 [competition-foundation-chain-analysis.md](competition-foundation-chain-analysis.md)。MVP 开发前必须先冻结其中的赛事—企业参与关系、资格状态机与任务验收状态。

完整原型五端链路与基础链路的范围图、衔接顺序见 [competition-chain-comparison.md](competition-chain-comparison.md)。

基础链路进入实施时，以 [competition-foundation-design.md](competition-foundation-design.md) 和 [competition-foundation-development-plan.md](competition-foundation-development-plan.md) 为准；本文件保留完整竞赛模块的总体路线。

| 纳入 MVP | 说明 | 延后原因 |
| --- | --- | --- |
| 竞赛选手登录 | 企业导入名单后以身份证匹配、手机号验证码完成身份注册/登录、会话与资格校验 | 短信成本通过匹配后发送、频控、配额、供应商适配控制 |
| 基础赛事信息 | 首页、我的赛事、赛事详情、赛段与已发布通知 | 是后续任务入口的前置能力 |
| 企业名单与资格 | 企业批量导入名单、选手资料确认/资格激活、隐私授权、审核状态和补正/驳回展示 | 不提供个人报名；复杂名额规则延后 |
| 任务中心 | 本人任务、详情、截止时间、通用签到或成果提交 | 先验证任务模型，不引入课程/考试强耦合 |
| 个人中心 | 选手资料、隐私授权、退出登录 | 满足独立应用的账号闭环 |
| 运营/企业后台最小能力 | 平台赛事与企业内部赛、赛段、企业名单导入/审核、任务生成/查看、通知发布 | 以 `admin-web` 的角色数据范围、权限和审计接入 |
| 不纳入 | 在线考试、学习课程、成绩/排名/晋级、企业中心、专家工作台、公开大屏、AI | 分别涉及防作弊、成绩发布、跨角色数据权限、公开脱敏与 AI 审计，不能用模拟交付替代 |

详见 [competition-mvp-plan.md](competition-mvp-plan.md)。

## 2. 推荐开发阶段

| 阶段 | 交付目标 | 依赖/验收门槛 |
| --- | --- | --- |
| 0. 产品与合同冻结 | 固化已确认决策；输出 OpenAPI 草案、状态机、字段字典、权限矩阵 | 明确短信供应商/预算、身份证保护、赛段、任务完成和常规评分规则 |
| 1. 后端领域底座 | 竞赛包、Flyway 新迁移、赛事/赛段/报名/任务数据模型、管理端 API、权限和审计 | 空库迁移成功；多租户与权限拒绝用例通过 |
| 2. 管理端 MVP | 后台菜单和赛事、报名审核、任务、通知页面 | `npm run build` 通过；动态菜单、按钮权限和数据权限验证 |
| 3. competition-h5 MVP | 独立工程、选手认证、赛事、报名、任务、个人中心 | 移动端冒烟；401/403、资格不足、截止任务、隐私同意等路径通过 |
| 4. 集成与验收 | 管理员配置赛事→选手登录报名→审核→任务完成→运营端可见 | MockMvc/前端测试/Playwright 主链路；审计、日志、文件失败路径验证 |
| 5. 竞赛执行能力 | 线上考试、学习、成绩、排名、晋级、企业/专家/大屏按风险拆分 | 先完成专项安全和性能设计，不能跳过阶段 4 |

## 3. 后续 Codex 任务建议

任务按可独立编译、验收的纵向切片拆分；同一 Controller、同一 H5 页面、Flyway 主干迁移同一时间只分配一个任务。

1. **COMP-001：竞赛领域 API 合同与状态机**：冻结 DTO/VO、权限码、状态迁移、OpenAPI 和测试矩阵；不写业务页面。
2. **COMP-002：竞赛数据模型与 Flyway**：新迁移创建平台/企业内部赛事、赛事—企业参与关系、赛段、任务模板、企业导入名单、资格、任务、通知等 MVP 表及索引；空库迁移测试。
3. **COMP-003：赛事与赛段后台 API**：实体/Mapper/Application/Controller、`competition:*` 权限、操作审计、MockMvc。
4. **COMP-004：企业名单导入与选手资格后台 API**：名单导入、身份证匹配、短信验证码适配/限流、资格激活、审核、补正、幂等及数据权限测试。
5. **COMP-005：任务与通知后台 API**：任务模板/生成、本人范围过滤、签到/成果提交、提交与验收状态分离、通知发布与读取状态。
6. **COMP-006：admin-web 竞赛运营与企业视图**：只在 API 稳定后接入动态菜单、平台赛事与企业内部赛、名单导入、ProTable/ProForm 页面和权限门控。
7. **COMP-007：competition-h5 工程骨架与独立认证**：新工程、路由守卫、player API client、登录/退出/会话恢复及移动端测试。
8. **COMP-008：competition-h5 MVP 页面**：身份注册/登录、首页、赛事详情、资格激活、通知、任务、个人中心，接真实 API。
9. **COMP-009：端到端与安全验收**：从运营配置到选手提交的全链路，覆盖租户越权、选手越权、重复提交、文件失败、审计和 401/403。
10. **COMP-010：统一题库赛事选题专项**：复用课程题库的受控能力，完成赛事题集版本快照、锁定和权限测试；不复制题库页面或直连 Mapper。
11. **COMP-011+：考试/成绩/排名专项**：按在线考试安全、常规评分/复核/晋级、成绩发布和公开大屏分别立项，不与 MVP 混合。

## 4. 风险与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 选手账号与现有培训账号混用 | 越权、密码/令牌安全债务、用户生命周期混乱 | 新 player 认证域；仅经明确映射关联旧用户，不能复用 `/appauth` 的旧令牌实现 |
| 短信 API 成本或滥用 | 运营成本失控、验证码攻击 | 企业名单匹配后再发送；图形校验、频控、冷却、日配额、费用告警和可替换供应商适配 |
| 客户端决定考试时间或成绩 | 篡改、申诉不可追溯 | 服务端会话、计时、评分、发布快照和幂等提交 |
| 多租户与企业数据泄露 | P0 安全事故 | 后端 tenant interceptor + 主体/赛事/企业三重范围校验；公开端仅读发布投影 |
| 原型直接转代码 | 静态模拟被误当真实状态 | 原型只做页面与交互依据；先冻结 API/状态机/权限矩阵 |
| 过早建设五端和 AI | MVP延迟且核心链路不稳定 | 先落地运营后台与选手 H5；其余端独立排期 |
| Flyway 历史复杂 | 空库失败或环境漂移 | 仅新增新版本脚本；空库执行全部迁移；不修改已应用脚本 |
| 文件与 PII | 身份、报名材料泄露 | fileId + 访问策略、脱敏字段、下载授权、操作日志与保留期限 |

## 5. 验收基线

- 管理员仅可管理授权租户/赛事，并可审计每次发布、审核和任务操作。
- 选手仅能读取和提交本人已授权、未过期的赛事事项；无资格、跨赛事、跨租户均返回拒绝。
- 企业管理员导入名单→选手身份证匹配并手机号验证→资格激活/审核→选手完成签到/成果→运营端可追踪，主链路可跑通。
- 所有 API 返回统一结构；列表分页统一；文件成功和失败路径均可验证。
- 后端编译和迁移、管理端构建、H5 构建、关键 MockMvc/前端/端到端测试均通过后才进入考试或排行阶段。
