# 历年真题按「工种 + 等级」共享 · 改造方案（方案 B）

> 状态：**待审核**（2026-10-20）
> 决策：用户在 A（维持按考试计划隔离）/ B（全量切到工种+等级维度）/ C（保留归属+可选共享开关）中选定 **B**
> 前置文档：`docs/04_requirements/历年真题-实施计划与测试验收.md`（已按方案 R3 上线：真题绑定 `exam_id`）
> 审核要点：§3 目标口径、§5 数据治理、§12 待确认问题（Q1–Q6）

---

## 1. 一句话结论

把真题的归属维度从「考试计划（`train_exam_list.id`）」换成「**工种（`exam_work_type` 叶子节点）+ 等级（5 级标准码）**」，
同一租户下凡是工种与等级相同的考试计划，共用同一批真题。
**前置依赖：必须先给 261 条考试计划补齐结构化的工种与等级字段**——这是本方案的主要工作量与最大风险。

## 2. 现状：为什么会看不到

| 事实 | 证据 |
|---|---|
| 真题只认 `exam_id` | `ZhentiAppService.list()` 第 42 行 `.eq(ExamZhentiEntity::getExamId, examId)`；`ZhentiAdminService.page()` 第 72 行同 |
| 两个计划是两条独立记录 | 来宾新材料铝电解工(铝及铝合金熔铸工)-四级 = `id 442`；2026年南南铝加工铝及铝合金熔铸工中级工 = `id 484` |
| 「四级」与「中级工」是同一等级，但库里没这个知识 | `train_exam_list.level` 全表 261 行**都是同一个占位串** `初/中/高/技师/高级技师`，不承载真实等级 |
| 工种/等级只存在于标题文本 | `train_exam_list` 无 `work_type_id`、无等级码列（生产库 `SHOW COLUMNS` 已核实） |
| 生产库现有真题 1 条 | `exam_zhenti` 仅 1 行：`铝电解工（铝及铝合金熔铸工）五级理论科目`，挂 `exam_id=441` |

结论：按现行口径，442 上传的真题在 484 里查不到；每个考试计划要各传一遍，同一份 PDF 会存 N 个副本。

## 3. 目标口径

### 3.1 共享组定义

```
共享组 scope = (tenant_id, work_type_id, level_code)
```

- `work_type_id`：`exam_work_type.id`，**取工种树的叶子节点**（如「铝及铝合金熔铸工」= 35），不取父级职业（「铝电解工」= 18）
- `level_code`：统一 5 级标准码（见 §3.2）
- 真题查询、MD5 去重、下架/删除语义**全部以共享组为单位**

### 3.2 等级归一化规则

职业技能等级五级制，同一等级存在多种俗称，必须归一到同一个码：

| level_code | 标准名 | 需归一的写法 |
|---|---|---|
| 1 | 一级 / 高级技师 | `一级`、`高级技师` |
| 2 | 二级 / 技师 | `二级`、`技师` |
| 3 | 三级 / 高级工 | `三级`、`高级`、`高级工` |
| 4 | 四级 / 中级工 | `四级`、`中级`、`中级工` |
| 5 | 五级 / 初级工 | `五级`、`初级`、`初级工` |

**匹配必须长词优先**：`高级技师` 要先于 `技师` 判定，`高级工` 要先于 `高级` 判定，否则会被短词抢先命中。
该规则用 Java 常量类 `ZhentiLevel` 承载，服务端解析与前端下拉共用同一套定义（避免两边各写一份）。

### 3.3 降级规则（关键，保证改造不倒退）

考试计划的 `work_type_id` 或 `level_code` **为空**时，该计划**不参与共享**，退回到现行 `exam_id` 私有口径：

```
scope 有值 → 按 (tenant_id, work_type_id, level_code) 查
scope 为空 → 按 (tenant_id, exam_id) 查   ← 与今天的行为完全一致
```

这样即使数据治理没做完，已完成治理的计划先享受共享，没治理的**不会变成"看不到真题"**。

## 4. 数据模型改造

### 4.1 `train_exam_list` 新增两列

```sql
ALTER TABLE train_exam_list
  ADD COLUMN work_type_id BIGINT NULL COMMENT '工种 id（exam_work_type 叶子节点）' AFTER level,
  ADD COLUMN level_code   TINYINT NULL COMMENT '等级码：1高级技师 2技师 3高级工 4中级工 5初级工' AFTER work_type_id,
  ADD KEY idx_exam_list_scope (tenant_id, work_type_id, level_code);
```

> 不动既有的 `level` 列（虽是占位串，但前端有展示依赖，贸然改会扩散影响面）。
> `level_code` 用 `TINYINT` 且允许 NULL——NULL 即"未归类"，是降级规则的判定依据。

### 4.2 `exam_zhenti` 新增两列 + 索引调整

```sql
ALTER TABLE exam_zhenti
  ADD COLUMN work_type_id BIGINT NULL COMMENT '共享组：工种（上传时由考试计划带出）' AFTER exam_id,
  ADD COLUMN level_code   TINYINT NULL COMMENT '共享组：等级码' AFTER work_type_id,
  ADD KEY idx_zhenti_scope (tenant_id, work_type_id, level_code, status, deleted);

-- 去重键从 (exam_id, file_md5) 换到共享组
DROP KEY idx_zhenti_md5;
ADD KEY idx_zhenti_md5 (tenant_id, work_type_id, level_code, file_md5);
```

`exam_id` **保留**，语义变更为「首次上传来源考试计划」，仅用于溯源与审计，不再参与查询过滤。
存储对象键 `zhenti/{examId}/{md5}.pdf` 保持现状（改造后同一份文件仍只存一份，路径不影响共享）。

## 5. 数据治理：261 条考试计划补齐工种/等级

### 5.1 自动解析覆盖率实测（已在生产库数据上跑过）

规则：工种用 `exam_work_type` 叶子节点做**最长匹配**，等级按 §3.2 长词优先归一。

| 结果 | 条数 | 占比 |
|---|---|---|
| 工种 + 等级均可自动解析 | **154** | 59.0% |
| 缺等级（工种已命中） | 17 | 6.5% |
| 缺工种（等级已命中） | 58 | 22.2% |
| 工种等级都缺 | 32 | 12.3% |

**需要人工介入 107 条（41%）**，其中约 15 条是脏数据（`cs1`/`test`/`250527测试`/`笔答测试` 等）。

### 5.2 三类难点的处理

**(1) 工种库覆盖不全**——考试计划里出现的工有相当一部分不在 `exam_work_type`（当前 71 个）中：

```text
化学检验工、机修钳工、地勘钻探工、仓储管理员、井下作业设备操作维修工、
挖掘铲运和桩工机械司机、天车工、火法、浸出、净化 …
```

处理：先由运营在工种库补录（复用既有 `/exam/work-types` 与 `exam:work-type:create` 权限，前端已有接口封装），再跑解析。
补录不全的部分，走人工校对时手工指定或留空（留空 = 不参与共享，安全降级）。

**(2) 一条计划含多个等级**——如 `南南铝业（铝及铝合金熔铸工-二级、技师）复习`。

处理：自动解析**取最高等级**并在校对清单里标红为「需人工确认」，不静默采纳。

**(3) 简称与父级名混用**——`铝电解工`（父级职业）与 `铝及铝合金熔铸工`（叶子工种）在不同标题里混用；
`来宾新材料铝电解工(铝及铝合金熔铸工)-四级` 更是同时出现两者。

处理：匹配顺序 **叶子工种优先 → 再退回父级职业**；命中父级名的记录同样标「需人工确认」（因为父级是职业不是工种，共享粒度会偏粗）。

### 5.3 人工校对入口

**新增管理端页面「真题归类」**（`/exam/past-paper-scope`），不用逐条进考试计划编辑页改（261 条太慢）：

- 表格列出全部考试计划：标题 / 工种（下拉，来自 `/exam/work-types/tree`）/ 等级（下拉 5 档）/ 状态标签
- 顶部筛选：「只看未归类」「只看需人工确认」「按工种筛」
- 表格内直接编辑 + 批量保存（`PUT /training/exam-lists/scope/batch`）
- 顶部横幅显示进度：`已归类 154 / 261，待处理 107`

同时给 `TrainExamListUpdateReq` 加 `workTypeId` / `levelCode` 两个字段，让考试计划编辑页也能改（次要入口）。

### 5.4 回填方式

- 一次性脚本 `scripts/zhenti/backfill_exam_scope.py`：连库读标题 → 解析 → 输出 `UPDATE` 语句 + 未命中/需确认清单 CSV
- **脚本不直接写库**，产出 SQL 与 CSV 人工过一遍再执行（避免脏数据被静默写坏）
- 清单 CSV 交业务对照「真题归类」页面补录
