### 1.3 业务规则(PHP 实现)

1. **自动完成审核**:每次列表查询,检查 `status=2` 的任务,如果 `audit_role=1` 的审核记录数 == `nums`,则将 status 置为 3(完成),并把对应专家 `endtime` 填上
2. **指派专家互斥**:`role=1(终审)` 不能与 `expert_start` 相同;`role=0(初审)` 不能与 `expert_end` 相同
3. **不能重复指派**:同 (expert_id, task_id, task_role, tag) 已存在则报错
4. **指派后状态变更**:指派成功时把 task.status 置为 1(初审核中)
5. **task 列表**:`order by id desc`,默认 pageSize=30
6. **PHP 端登录态**:`yunLoginInfo()` 解析 JWT,本项目不涉及,Java 走 Sa-Token
7. **角色过滤(已弃用)**:`if(in_array($role, ['tikucka','tikuckb','tikuckc']))` → 题目要求的"expert_id IN (95,96,97) 硬编码"类似的 Tikuck 角色过滤,**直接忽略,不复刻**

### 1.4 不复刻/简化的部分

- **专家端流程**:`/yunexpert/task-*` 6 个接口不在本任务范围
- **Tikuck 角色硬编码**:`expert_id IN (95,96,97)` / `tikucka/b/c` 角色过滤逻辑跳过
- **PHP 老数据迁移**:不迁数据,空表即可
- **操作日志写库**:PHP 的 `buildLogs()` 写 `sys_logs`,Java 走 `@AuditLog` 注解统一处理
- **CDN 文件 URL**:PHP 是 `CDN_URL/...`,Java 用现有 `/api/exam/files/**` 路由

### 2.4 专家端录入 + 审核提交(新增范围)

PHP 端 `/yunexpert/task-{exam|examshicao|examsub}-submit` 的 3 个接口完整复刻:

**录入/审核表单(3 套字段不同)**:

| 题型 | 录入字段 |
|---|---|
| 理论 | exam_content(题干), exam_a~h(8 个选项), exam_answer(答案), isblod(重点审核 0/1) |
| 实操 | content(题干), pingfen(json 评分标准), kaochang(考场准备), kaosheng(考生准备) |
| 主观 | content(题干), answer(参考答案), isJisuan(是否计算题), pic(图片,可空) |

**业务规则**:
1. **任务筛选**:专家只能看到 `expert_id = currentUserId` 且 `task_role = 0(初审)` 或 `1(终审)` 的任务
2. **查重**:`exam_expert_audit_records` 中 (task_id, audit_role, exam_id) 已有记录则禁止重复提交
3. **状态推进**:
   - 提交初审 → task.status = 1(初审核中)→ 当所有题都提交了初审 → status = 2(终审核中)
   - 提交终审 → task.status = 3(完成)
4. **每日完成数**:`exam_expert_audit_records.ymd` 字段记录 YYYY-MM-DD,用于日统计
5. **关联 task_expert 表**:写入时同步往 `exam_task_expert` 写一条记录(复用通用表,不再用 ximu_expert)

> **冲突规避**:与现有 `ExpertAuditController`(V20260528)并存,**新代码不接管**。专家端的 3 个 controller 是独立的,职责清晰。

| 文件上传 | PHP 有 file_path 字段 | 一期 task.file_path 字段保留但允许 null,前端不上传,等下期 |
