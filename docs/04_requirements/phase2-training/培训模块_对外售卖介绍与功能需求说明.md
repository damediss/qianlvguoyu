# 千铝国昱 SaaS 云平台 · 培训模块对外介绍与功能需求说明

> **用途**：面向有意向采购云平台的客户、合作方与商务洽谈的**文字材料**  
> **模块**：SaaS 云平台中由培训业务负责的「培训模块」  
> **形态**：管理端（Web）+ 业务后端 + 学员/师资 App 协同  
> **日期**：2026-08-07  

---

## 写给客户的开场（可直接口述）

各位好。我负责的是云平台里的**培训模块**。

简单说，它帮培训机构或企业培训部门，把「找企业、定方案、分好班、开起班、跟住过程、接到考试与补贴准备」放到一套系统里，而不是继续靠 Excel、微信群和纸质台账拼起来。

管理端管流程与监管，手机 App 管学员填资料、学习和练习。两边数据是通的，班级开出来以后，考勤、学情可以按班查看，材料可以按模板生成，减少重复劳动，也方便以后审计留痕。

下面按「我们解决什么问题、系统怎么走、各阶段能做什么」做详细说明。

## 一、模块是什么

### 1.1 一句话定位

**培训模块是千铝国昱 SaaS 云平台上，面向企业技能培训、岗位技能提升、新型学徒制等业务的数字化运营中枢，以「企业—项目—班级—学员」为主线，贯通开班前准备与开班后过程管理。**

### 1.2 适合谁买、谁用

| 采购/使用方 | 典型诉求 |
|-------------|----------|
| 培训机构 / 培训部 | 多企业、多班级并行，流程标准化、材料可复用 |
| 大型企业培训管理部门 | 人才规划可确认、分班可审核、过程可监管 |
| 合作院校 / 认定协同方 | 名单与获证口径可衔接（按开通范围） |
| 一线角色 | 教务、企业班主任、授课老师、班长、学员各有入口 |

### 1.3 能解决的核心痛点

1. **名单乱**：企业人员底数、确认名单、分班花名册多次拷贝易错。  
2. **确认慢**：方案、分班方案缺少企业在线确认与状态留痕。  
3. **开班累**：人社/机构开班材料重复制作，格式多、改一处动全身。  
4. **过程散**：考勤、刷题学情散落在表格和聊天记录，班级维度看不清。  
5. **责任不清**：班主任、教务、主讲、班长职责未在系统固化，出事难回溯。  
6. **前后台割裂**：学员在 App 操作，后台看不到同一套数据。

### 1.4 产品设计原则（对客户可承诺的方向）

- **以班级为中心**：开班后考勤、学情、过程管理按班汇聚。  
- **开班前先跑通**：调研到开班、收集的主链路优先保证可用。  
- **管理端与 App 同一数据源**：避免两套台账。  
- **学习通道清晰**：考前复习、班级刷题、课堂作业分通道建设，互不混淆。  
- **过程可追溯**：关键操作与材料版本可查，服务合规与审计。

## 二、整体业务蓝图

培训模块覆盖从「谈项目」到「项目收尾」的完整业务愿景，四个阶段如下：

```text
【启动与规划】企业调研 → 方案规划（含企业确认）→ 分班
【开班准备】  开班准备（花名册/师资/课表/角色）→ 开班申报（材料生成）→ 信息收集
【培训实施】  跟班（考勤/学情/过程管理）→ 考试与考前辅导 → 结课与认定衔接
【项目收尾】  补贴材料与进度 → 归档 → 结算与总结
```

对客户可理解为一条运营流水线：

**摸清企业要训什么 → 方案谈妥并确认人 → 人分进班 → 材料备齐开班 → 跟班管过程 → 考试取证 → 补贴与收尾。**

管理端提供流程导航，业务人员按阶段推进；权限按角色开放，企业侧与机构侧可协同确认。

## 三、功能需求详细说明（按阶段）

以下用「业务目的 + 功能要求」叙述，便于写入标书、方案书或合同附件中的「功能需求」章节。

---

### 3.1 企业调研

**业务目的**  
摸清企业培训需求与人员底数，形成可进入规划的数据基础。

**功能要求**

1. 支持按企业建立调研任务，维护企业与联系人信息。  
2. 支持采集或导入在岗人员信息（姓名、证件、手机、岗位、意向工种与等级等），并做基本校验与查重。  
3. 支持与人才识别/查证能力衔接，对关键资格给出核对提示。  
4. 支持查看采集进度（已采集、缺项等），便于催办。  
5. 调研结果可衔接后续方案规划，减少二次录入。

**客户价值**  
市场与培训部不再从空白 Excel 起步，企业人员底数进系统、可追踪。

---

### 3.2 方案规划

**业务目的**  
输出可被企业确认的人才培养/培训规划，锁定可进入分班的人员范围。

**功能要求**

1. 支持编制与维护项目期或多年人才规划（工种、等级、规模、安排等）。  
2. 支持向企业推送确认；企业可确认、驳回或要求补交名单、排班等资料。  
3. 支持记录回传附件与确认状态（已确认、待补交等）。  
4. 对「未齐套却进入分班」给出业务提示，降低错班风险。  
5. 预留培训模式口径（如岗位技能提升、新型学徒、自费认定等），便于后续材料与补贴策略扩展。

**客户价值**  
方案确认有状态、有版本，分班依据清晰，减少口头确认扯皮。

---

### 3.3 分班

**业务目的**  
将确认名单拆分为可开班的班级，并在系统中生成真实班级与花名册。

**功能要求**

1. 支持按规则或排班约束生成分班草稿（班额、工种、等级等）。  
2. 支持人工调整草稿（调人、拆班、合班）。  
3. 支持企业审核分班方案，通过后方可正式生效。  
4. 生效后生成班级信息与学员花名册，关联企业、工种、等级等。  
5. 支持学员账号开通或补开，并对未开通账号给出清单处理能力。  

**客户价值**  
分班结果线上确认、一次物化，花名册与班级一致，学员可进入 App。

---

### 3.4 开班准备

**业务目的**  
班级落地后，配齐人员、师资、课表与资料入口，达到可申报、可开训状态。

**功能要求**

1. **花名册**：学员维护、班长设置、关键信息查询。  
2. **教务与负责人**：维护班级教务、企业负责人等。  
3. **班级角色**：支持指派企业班主任、跟班教务、主讲、助教等（双轨：企业管日常、培训部管合规），并作为后续跟班权限基础。  
4. **课表**：上传或解析课表，形成上课日期、时段、课程与教师等信息。  
5. **资料收集**：为班级发起或关联资料收集，督促学员补齐材料。  
6. **师资库**：维护讲师档案，按需导入班级。

**客户价值**  
开班前「人、师、课、材料入口」在一个班级视图内齐备，责任到人。

---

### 3.5 开班申报

**业务目的**  
按主管部门或合作机构要求，高效生成开班申报材料。

**功能要求**

1. 支持开班材料模板管理，并可按班级/项目挂载。  
2. 支持一键生成材料包（花名册、申请表、课表、承诺书等，以实际配置为准）。  
3. 生成内容自动带入班级真实数据（班名、人数、负责人、教师、课时、地点等）；缺项应可提示。  
4. 支持下载、重新生成与版本留存。  
5. 支持对线下盖章、提交等环节做状态备注。

**客户价值**  
大幅减少重复制表，开班申报从「手工拼材料」变为「核对后提交」。

---

### 3.6 信息收集

**业务目的**  
组织学员提交报名与开班所需信息及证照，审核通过后进入培训执行。

**功能要求**

1. 支持创建信息收集/报名计划，生成二维码或链接供填写。  
2. 支持学员填报身份、联系方式、学历、单位及影像材料等（字段可配置）。  
3. 支持后台审核（通过、驳回补正）与导出。  
4. 支持影像识别等辅助能力（在开通范围内）。  
5. 提供齐套情况摘要（应交、已交、待审），便于催办与开训门禁。  
6. 与开班准备中的班级资料收集协同，职责清晰、避免重复入口混乱。

**客户价值**  
材料收集线上化，审核进度可视，开训前缺件一目了然。

---

### 3.7 跟班（培训实施）

**业务目的**  
开班后以班级工作台为中心，管理日常考勤、排课、学情与过程指标。

**功能要求**

1. **进班工作台**：按班级进入；支持按业务日或课次查看。  
2. **概览**：学员数、当日出勤构成、累计出勤、近日出勤、预警与待办。  
3. **考勤**：按日登记出勤/缺勤/迟到/早退；支持导入外部考勤表（按身份证匹配本班）；支持学员考勤明细。  
4. **排课**：查看班级课表安排。  
5. **刷题学情**：为班级配置刷题范围，查看学员练习学情。  
6. **角色与指标**：展示班级角色摘要与出勤类指标。  
7. **规划扩展（可持续交付）**：课堂影像留痕、跟班作业/随堂练、班主任日志落库、督导检查、代签确认、满意度等，按客户分期纳入。

**客户价值**  
教务与班主任按班管过程，考勤与学情不再散落；具备向「证据链完整跟班」持续升级的空间。

---

### 3.8 考试与考前辅导

**业务目的**  
组织考试安排，并推动学员考前复习，提升通过率。

**功能要求**

1. 支持考试计划维护与查询。  
2. 支持通过 App 开展考前复习/题库练习（与跟班作业通道区分）。  
3. 支持将考试或认定结果用于通过率等指标展示（按数据来源开通情况）。

**客户价值**  
考务有计划，学员复习有入口，管理侧可关注班级准备度。

---

### 3.9 结课、认定衔接与项目收尾

**业务目的**  
结课通知、获证名单衔接，以及补贴材料、归档与结算准备。

**功能要求**

1. 支持结课/毕业相关状态与通知能力。  
2. 支持获证学员名单的接收、核对与归档衔接。  
3. 支持补贴申报相关材料管理、进度跟踪的产品化能力（可按客户分期交付）。  
4. 支持项目资料按「项目—班级—阶段—版本」归档检索。  
5. 支持结算、分成、项目总结等收尾流程（按财务与组织权限分期开通）。

**客户价值**  
从培训执行平滑过渡到获证与补贴准备，资料可查、责任可追。

## 四、跨模块基础能力（随培训模块一并说明）

### 4.1 组织与权限

- 按角色分配菜单与操作权限。  
- 班级内角色决定跟班侧可见与可操作范围。

### 4.2 双端协同

| 端 | 主要能力 |
|----|----------|

| 手机 App | 资料填报、学习刷题、练习任务、签到等（按开通范围） |

### 4.3 材料与模板

- 开班材料、协议、补贴等模板可配置。

### 4.4 关键业务指标（需求口径）

| 指标 | 含义 |
|------|------|
| 出勤率 | 有效出勤 ÷ 应到 |
| 作业/练习完成率 | 达标提交 ÷ 应交 |
| 通过率 | 合格 ÷ 参考 |
| 材料齐套率 | 已审通过 ÷ 应收集 |
| 满意度 | 问卷均分或 NPS（扩展项） |

## 六、可直接用于方案书的成稿文案

### 6.1 一句话

千铝国昱 SaaS 培训模块，以班级为中心，帮助培训机构与企业培训部门实现从调研规划、分班开班到跟班考勤与学情管理的数字化运营，并具备向考试认定与补贴收尾持续扩展的能力。

### 6.2 三段话（简介页）

**第一段**  
培训模块是云平台的核心业务模块之一，面向企业技能培训与学徒制等场景，服务培训部、企业、老师与学员多方协同。管理端负责流程与监管，App 端负责填报与学习，数据统一、责任到班。

**第二段**  
开班前，系统支持企业调研与人员采集、规划编制与企业确认、分班方案审核与班级物化，完成花名册与课表师资准备、开班材料生成及学员信息收集审核，缩短开班准备周期。

开班后，跟班工作台提供考勤管理、排课查看、刷题学情与班级概览，使过程数据可查可催；并支持按客户需要扩展影像留痕、课堂作业、督导预警以及补贴收尾等能力，满足合规审计与持续运营要求。

### 6.3 电梯稿（约 30 秒）

我们做的是培训数字化。客户用管理后台把企业调研、分班、开班材料和信息收集跑通，开班后按班级管考勤和学情；学员用 App 填资料、刷题学习。先解决「开班乱、过程散」，再按需要往作业留痕和补贴收尾加深。我负责的就是这一整条培训模块。

## 八、结语

培训模块的目标，不是再做一个「菜单很多的后台」，而是让客户在真实开班场景里：

- **开班前少返工**（名单、确认、材料、收集一次做对）；  
- **开班中看得见**（按班考勤与学情）；  
- **开班后留得下**（过程与材料可追溯，并向补贴与审计延伸）。  

如需演示、试点或按贵单位政策做模板与流程定制，可在标准能力之上分期交付扩展包，验收标准以双方确认的《功能清单》为准。
