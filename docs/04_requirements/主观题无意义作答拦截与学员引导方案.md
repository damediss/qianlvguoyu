# 主观题无意义作答拦截与学员引导方案

> 状态：**待审核**（v1.0，2026-10-21）
> 需求来源：生产日志（platform.log 2026-10-21 00:00~09:00）实证——学员论述题连续提交单字符答案
> （"2/3/4/5/6/Q/y/8/10"），每次都触发一次 deepseek-flash 判分调用并判 0 分。
> 拍板结论（2026-10-21）：Q1=A（拦截记 0 分落库+可重答）、Q2=A（开关默认开）、
> Q3=A（「查看解析」按钮本期做）、Q4=A（后端+App 端一起）。
> 代码取证均来自当前 dev 分支与 `docs/agent/schema-index.ai.json` 实测结构。

---

## 1. 根因判断（证据链）

**学员不是想刷 0 分，是想秒看参考答案。**

1. UI 规则：白名单主观题"先作答、提交判分后才展示参考答案"（`sortExam.vue:19/41`）；
2. 参考答案展示**不依赖判分质量**——提交任意非空内容即解锁；
3. 每次垃圾提交的真实代价（`AiGradeApplicationService.grade` 现无任何前置拦截）：
   - 一次 LLM 调用（日志实测 ≈250 token/次，最长 30s 线程占用）+ 一条无意义 `ai_generation_draft` 审计行；
   - **烧学员自己的限流额度**（`AiGradeRateLimitService`：每分钟 10 次/每日 200 次，计次在缓存 miss 后、LLM 调用前），乱点 10 题后真实判分被限流转自评兜底；
4. 不可逆性放大问题：判分后 textarea 因 `ai_result` 存在被禁用（`sortExam.vue:23`），**当前 UI 下任何主观题判分后都不能重答**（服务端幂等层其实支持"不同答案重判"——同答案或已答对才回放，见 `ReviewPlanApplicationService.answerSubjective`）。

**结论：只拦截不疏导，学员会换花样垃圾文本；必须拦截（P0）+ 正当出口（P1）一起做。**

## 2. 现状关键事实（实施前必读）

| 事实 | 位置/出处 |
|---|---|
| 判分链路 | `AiGradeApplicationService.grade()`：参考提取→缓存→模型配置→限流计次→LLM |
| 主链路调用 | `ReviewPlanApplicationService.answerSubjective()`（同步学 answer/mock 内部判分） |
| 老接口调用 | `AppReviewAiController /appreviewai/grade`（同一服务层，闸口自动生效） |
| 幂等回放 | 同答案或已答对 → `subjectiveReplayView`，不调 LLM |
| **`ai_review_answer` 无 `grade_source` 列** | schema-index 实测：回放视图 `gradeSource` 恒 null（代码注释"未落库"） |
| 作答表已有 `attempt_seq` | 多次尝试序列天然存在，重答不需要新机制 |
| 字典模式 | 判分类目已有 `ai_review_model_code` / `ai_review_grade_pass_rate` / 限流两个字典键 |
| 迁移取号铁律 | 新增迁移前**同时查两库** `SELECT MAX(version) FROM flyway_schema_history` 再加间隔（共用目录当前最新 20261020_004） |
| 字典种子租户 | `tenant_id=10159`，`INSERT IGNORE` 幂等（AGENTS.md 铁律 3） |

## 3. 方案设计

### 3.1 无意义作答闸口（P0 核心）

**新类 `SubjectiveAnswerGuard`**（`exam/reviewsync/support/`，与 `QuestionTypes`/`SubjectiveAnswerExtractor` 同级，纯函数、无依赖）：

```java
public final class SubjectiveAnswerGuard {
  public record Verdict(boolean meaningless, String reason) {}
  public static Verdict check(String userAnswer, String referenceAnswer, int minHanzi) { ... }
}
```

**判定规则（归一化 = trim + 连续空白折叠后，保守只抓极端垃圾）**：

| 规则 | 内容 | 样本 |
|---|---|---|
| R1 | 纯数字/纯字母/纯符号 | "2"、"Q"、"10"、"666"、"..."、"？" |
| R2 | 无汉字且总长 < 15 | "asdf"、"ok"、"idk" |
| R3 | 汉字数 < `minHanzi`（默认 4）且总长 < 8 | "不会"、"不知道"、"略"、"过" |
| R4 | 单字符重复 ≥4 或 2~4 字符片段重复 ≥3 | "哈哈哈哈"、"123123123" |
| 豁免 | **命中参考答案任一 ≥2 字关键词则不拦截** | "低碳、零排放"类言简意赅的真实短答 |

> 豁免实现：参考答案按标点/空白切分，取 ≥2 字的中文片段做包含匹配。宁漏勿错——
> 拿不准的一律放行给 LLM（误伤真实短答比浪费一次调用更糟）。

**闸口位置**：`AiGradeApplicationService.grade()` 参考答案提取之后、缓存/限流/LLM **之前**：

- 命中 → 返回 `SubjectiveGradeResult(true, 0, false, 引导话术, "rule")`；
- **不调 LLM、不计限流、不写 `ai_generation_draft`、不写判分缓存**（缓存只存真实 LLM 结果；
  同垃圾答案重提交由 answer 链路幂等层回放，老接口重走闸口成本≈0）；
- 打 INFO 日志：`[AI判分] 无意义作答拦截（不调 LLM）：tenantId userId questionId reason answerLen`——token 节省量可直接从日志量化；
- 老接口 `/appreviewai/grade` 共用同一服务层，闸口自动生效，无需单独改。

**话术（白话、不暴露规则细节）**：
> "系统未识别到有效作答，本题记 0 分。想看答案可以点下方「查看解析」；愿意动手可以重新作答。"

### 3.2 `grade_source` 列与重答持久化（Q1=A 的必要配套）

现状回放视图 `gradeSource` 恒 null（未落库），**拦截判 0 的可重答性在刷新页面后会丢失**（回放记录无法区分"AI 判 0"与"规则判 0"）。因此：

1. 新迁移：`ALTER TABLE ai_review_answer ADD COLUMN grade_source VARCHAR(16) NULL COMMENT '判分来源 ai/self/rule/skip'`（幂等守卫写法沿用既有 PREPARE + information_schema 模式；**取号前查两库 MAX(version)**）；
2. 实体 `AiReviewAnswerEntity` 加 `gradeSource` 字段；`persistSubjectiveAnswer` 写入；
3. `subjectiveReplayView` 从该列回显 `gradeSource`（存量行 NULL → 按 'ai' 默认，文档口径）；
4. 统计口径随之成立：`SELECT grade_source, COUNT(*) FROM ai_review_answer WHERE deleted=0 GROUP BY grade_source`。

### 3.3 「查看解析」主动放弃通道（Q3=A，根因疏导）

answer 接口新增可选参数 `giveUp=1`：

- 语义：学员主动放弃本题 → 记 0 分落库、`gradeSource="skip"`、响应立即返回参考答案+解析；
- **不调 LLM、不计限流、不写 draft**；幂等回放与普通作答一致；
- `gradeSource='skip'` 的作答同样允许重答（学员看完解析想动手，应该鼓励）。

### 3.4 字典开关（sys_dict，Q2=A 默认开）

| 键 | 默认值 | 说明 |
|---|---|---|
| `ai_review_grade_guard_enabled` | `1` | 闸口总开关；置 0 立即回旧行为（回滚手段） |
| `ai_review_grade_guard_min_hanzi` | `4` | R3 汉字数阈值，可调不重启 |

种子迁移随 3.2 迁移同文件或独立文件，`INSERT IGNORE`、`tenant_id=10159`。

### 3.5 App 端改动（gjjd_appnext，三个页面）

`pages/exam/sortExam.vue`、`syncExam.vue`、`randExam.vue` 三页均含白名单主观题作答区（grep 实证），改动一致：

1. **「不会，直接看解析」按钮**：作答区底部常驻；点击弹确认（"本题将记 0 分并直接展示答案，确定吗？"）→ 调 answer 接口 `giveUp=1` → 展示参考答案+解析；无判分 loading；
2. **提交前即时校验**：本地镜像 R1~R4 轻量规则，命中弹确认"作答内容过少将记 0 分，确定提交？"（确认可提交，不阻止——防误伤）；
3. **拦截后可重答**：textarea 禁用条件改为 `ai_result && !['rule','skip'].includes(ai_result.gradeSource)`；rule/skip 结果下方加"重新作答"按钮（清空 `ai_result` 回到作答态，服务端幂等已支持）；
4. 作答框 placeholder 改"请写出要点，敷衍作答记 0 分"；
5. 显示口径：`gradeSource` 只有 `'self'` 标"（自评）"，`'rule'`/`'skip'` 走默认分支——**显示逻辑零改动**（已取证）。

### 3.6 文案口径

全部面向学员的文案遵循白话化规则：不出现"拦截/规则引擎/LLM/AI 判分暂不可用"之外的新内部词；引导话术以"记 0 分 + 两个出口（看解析/重新作答）"为固定结构。

## 7. 回滚与风险

- **回滚**：`ai_review_grade_guard_enabled` 置 0 立即回旧行为；App 按钮为增量 UI，回滚前端即可；迁移只加列不回滚（铁律）；
- **误伤短答案**：豁免规则 + 阈值字典 + 总开关三重兜底；上线后看拦截日志抽样复核；
- **学员换花样垃圾文本**：观测日志迭代 R3 词库即可，不改结构；
- **`grade_source` 存量行 NULL**：回放按 'ai' 默认（本方案 §3.2-3 口径）；
- **与中断清洗开关无关**：日志中 `cleanEnabled=false` 属中断补救特性，勿混淆。
