> 关联：`默认模板导出_优化实现方案.md`（侧重异步任务/落盘/多实例；**本文聚焦导包内图片正确性**）

## 一、问题清单与现场证据

| # | 现象 | 典型场景 | 根因摘要 |
|---|---|---|---|
| A | 换图后导出仍是旧图 | 资料收集编辑页换证件照/正反面后默认模板导出 | 库字段取失败后**静默回退旧 CDN 约定路径**；或 CDN URL **本机还原命中旧盘同名文件** |
| B | 部分图片导不出 | 库有值、编辑页能看，ZIP 对应目录空 | `/api/files/{id}` / 公网拉取失败后无可用路径；旧路径命名与导出兜底不一致 |
| C | 身份证照片不会自动裁剪 | 管理端新上传未抠原图导出后仍大图/带背景 | 已提交代码仅 **4% 四周内收**；OCR 证件板裁剪仅在工作区 WIP，且依赖百度 Key |

### 1.1 李丹样例（回归用）

- 身份证：`452624199804140704`
- 本班计划：`sign_up_id=90055`（`26年国盛稀土新型学徒净化工技师1班-资料收集`）
- 库字段示例：

字段已写旧 URL 但导出解析失败时，同步显示成功/unchanged，导出仍空——属预期行为，**不能当修复手段**。

## 二、目标与非目标

### 2.1 目标

1. **正确性**：库字段指向的图（含换图后的新 `/api/files/{id}`、旧 `/api/file/contract/…`、CDN upload）导出与编辑页一致。  
2. **不静默用旧图**：库字段有记录但取失败时，该槽位空 + warn，**禁止**再命中旧约定路径冒充成功。  
3. **合同对齐展示层**：导出具备与 `SignUpPeopleSelfAssembler.resolveStoredOrCdnUrl` 同口径的 `contract/` 与历史 planId 兜底。  
4. **裁剪**：身份证正/反面导出时做 OCR 证件板裁剪；失败再 4% 内收；小二寸证件照**不做** OCR（保持现状，除非产品另定）。

### 2.2 非目标（本方案不做）

- 异步任务/zip/`result_file`/多实例（已在优化方案 P0，另跟）  
- 并行打包/模板缓存等性能项（优化方案 P1/P2）  
- 「同步历史」改为覆盖已有合同 URL 或从 PHP 跨库拉人（可另开需求）  
- 批量回填改写历史库字段 URL

---

## 三、设计原则

1. **展示与导出同口径**：能预览的图，导出必须按同一解析链取到（或明确失败打日志）。  
2. **有库记录则禁止「无记录式」旧路径碰运气**：`exportImageCandidates` 在 `hasRecord=true` 时，**不得**把旧约定路径当作成功兜底（见 §4.1）。  
3. **旧 URL 先映射本机，再 HTTP**：`/api/file/contract/{leaf}` → `contract/{leaf}`；CDN upload → 相对路径；失败再公网拉。  
4. **失败可观测**：`logMissingAsset` 已有；合同/正反面补「解析阶段」日志（命中候选序号、映射后相对路径）。  
5. **裁剪可降级**：OCR 未配置/失败 → 内收；不得因裁剪异常中断整人打包。

## 四、修复项（按优先级）

### P0-1 库字段有记录时禁止回退旧约定路径（修 A）

**文件**：`SignUpPeopleDefaultTemplatePackService.exportImageCandidates` / 调用方

**现状**：`preferredStored` 失败后仍追加 `idCard/headerOrigin/...` 等 legacy，导致换图失败时导出旧图。

**改为**：

```text
hasRecord=true  → 候选 = 仅 preferredStored（及由 URL 派生的本机相对路径，见 P0-2）
hasRecord=false → 候选 = 本机存在的 legacy 约定路径（保持 withRecordCandidates 行为）
```

可选增强：`hasRecord=true` 且全部失败时，**仅当** legacy 文件的 mtime/内容与库字段无法关联时仍不回退；一律不回退更简单、可测。

**验收**：换 `/api/files/新ID` 后，人为让新 ID 读失败 → ZIP 该槽空 + warn，**不得**出现旧 headerOrigin 图。

---

### P0-2 旧合同 URL / `contract/` 本机映射（修 B、D）

**文件**：`SignUpExportAssetService`；`SignUpPeopleDefaultTemplatePackService.copyPersonAssets`（合同三段）

#### 2.1 URL 映射

在 `relativePathFromHttpUrl` / `copyTo` 中增加：

| 输入 | 映射本机相对路径 |
|---|---|
| `https://api.gjjd168.com/api/file/contract/{leaf}` | `contract/{leaf}` |
| 任意 host 的 `/api/file/contract/{leaf}` | `contract/{leaf}` |
| `https://cdn.app.gjjd168.com/upload/...` | `upload/...`（已有逻辑保留） |

注意：不要把路径落成 `api/file/contract/...`（当前错误还原）。

#### 2.2 合同约定路径与 Assembler 对齐

导出合同候选在库字段之后（**仅当 hasRecord=false**，或作为「从 URL 解析出的 leaf 本机路径」——见下）增加：

```text
contract/{idCard}_{signUpId}_first_self.png
contract/{idCard}_{signUpId}_expire_self.png
contract/{idCard}_{signUpId}_sign_self.png
idCard/headerOrigin/{idCard}_{signUpId}_contact_first_page.jpg   # 保留旧命名
```

并从库字段 URL 用正则解析历史 planId：

```text
/_(\d+)_(first_self|expire_self|sign_self)\.(png|jpg)/
→ 额外尝试 contract/{idCard}_{parsedPlanId}_*.png
```

李丹：URL 含 `_80_` → 即使当前 `signUpId=90055`，也能命中 `contract/…_80_first_self.png`。

#### 2.3 顺序（hasRecord=true）

```text
1) 原库字段字符串（/api/files/id、https://…）
2) 由该 URL 映射出的本机相对路径（contract/{leaf}、upload/…）
3) （可选）从 URL 解析出的其它 planId 的 contract/ 同名变体
4) 禁止：当前班 signUpId 的空白约定路径碰运气（避免指错班）
```

HTTP `copyRemote` 仍作为映射与文件 ID 都失败后的最后一搏（非 loopback）。

**验收**：李丹三人页合同均进入 `合同/`；三页齐全则有 `合同(合并)`；编辑页能开的链接导出也能落盘。

---

### P0-3 CDN 本机还原防旧盘（修 A 残留）

**文件**：`SignUpExportAssetService.copyTo`（`938eabca` 引入的本机优先）

**现状**：同相对路径磁盘仍是旧文件时，本机命中会盖住 CDN 新图。

**改为（二选一，推荐 A）**：

- **A（稳）**：若库字段是 `/api/files/{id}`，**只走文件 ID**，不做「同名相对路径」回退。  
- **B**：本机命中后若存在「库字段 fileId 可读」，以 fileId 字节为准覆盖。

换照场景以 fileId 为主；纯 CDN 相对路径无 fileId 时保持本机优先（出网差环境需要）。

**验收**：库字段为新 fileId、磁盘旧 `headerOrigin` 仍在 → 导出必须是新图。

### P1-1 身份证正/反面 OCR 裁剪落地（修 C）

**文件**：

- 提交工作区已有：`IdCardExportOcrCropSupport.java` + Test  
- `SignUpPeopleDefaultTemplatePackService`：正/反面在 `copyFirstExisting` 成功后调用 `cropIdCardInPlace`  
- 配置：沿用 `BaiduOcrService` 的 apiKey/secretKey；未配置则跳过 OCR → `tightenInPlace`

**口径**：

| 槽位 | 是否 OCR |
|---|---|
| 身份证正面 / 反面 | 是（与 App 上传一致） |
| 小二寸 / 原证件照 | 否 |
| 合同 / 毕业证等 | 否 |

**验收**：

- Key 开启：未抠原图导出后明显裁到证件板（或日志「OCR 证件裁剪成功」）  
- Key 关闭：仍有 4% 内收，打包不中断  
- OCR 抛错：warn + 内收，整人继续

### P1-2 可观测性

- 合同/正反面：`copyFirstExisting` 失败时已有 `logMissingAsset`；成功时 debug 记录「候选下标 + 最终 src 类型（fileId/contractMapped/remote）」  
- 导出任务结束后可选：在任务 `error_msg` 旁不塞明细；依赖日志检索 `导出材料缺失`

## 七、实施顺序与风险

```text
1) P0-2 合同映射 + planId（最快止血李丹类）
2) P0-1 禁止旧路径回退（止血换图仍旧）
3) P0-3 fileId 优先
4) P1-1 提交 OCR 裁剪
5) 单测 + 李丹/换照手工验收
```

| 风险 | 缓解 |
|---|---|
| 禁止 legacy 回退后，仅磁盘有图、库字段空的人少图 | `hasRecord=false` 仍走 legacy；有字段失败变空是刻意正确 |
| 本机无 `contract/`、仅公网可拉 | 保留 `copyRemote`；生产确认 API 机出网或盘上有文件 |
| OCR 耗时/配额 | 仅正反面；失败降级；可后续加开关 `platform.baidu.export-idcard-crop=true` |
| WIP 与 HEAD 不一致 | 以本方案为准合入，避免只合半套 |

**回滚**：按提交粒度回滚 P0/P1；合同映射与禁止回退建议同批上线，避免只开一侧。
