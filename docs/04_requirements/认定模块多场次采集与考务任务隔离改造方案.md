# 认定模块多场次采集与考务任务隔离改造方案

## 一、问题结论

当前模型已经允许一个认定任务配置多个考试场次，并通过 `certification_candidate_exam_session` 为不同场次分配人员；但采集工作台及其状态、队列、导出入口仍有相当一部分只按 `task_id` 或 `task_id + candidate_id` 定位数据。

这会造成以下业务缺陷：

1. 同一认定任务内，不同场次的人员在工作台中被合并展示；
2. 同一人员参加理论、实操等多个场次时，只能共用一条采集状态和队列状态；
3. 从场次列表进入管理页后，页面丢失 `exam_session_id`，后续初始化、扫码、排队和导出均可能串场；
4. 导出时通过已有状态反推场次，无法保证标题、人员名单与证件照都来自用户选择的场次；
5. 实操评分和答辩目前仍以认定任务为主要边界，后续也会遇到相同问题。

因此，认定模块的稳定业务边界应为：

```text
认定任务 certification_task
  └─ 认定场次 certification_exam_session
       ├─ 场次人员 certification_candidate_exam_session
       ├─ 信息/实操采集状态、队列、指纹、签名、异常
       ├─ 实操评分任务与成绩
       └─ 答辩任务与成绩
```

## 二、设计原则

1. `task_id` 表示所属认定任务，`exam_session_id` 表示实际操作和数据隔离边界；二者必须同时校验，禁止只凭场次 ID 跨任务访问。
2. 新配置的场次必须显式传递 `exam_session_id`；工作台人员只能来自该场次中 `participation_status = 'ASSIGNED'` 的关系记录。
3. 状态、队列、指纹、签名、异常和导出统一按 `tenant_id + task_id + exam_session_id` 查询。
4. 同一人员在不同场次拥有独立状态。唯一约束由“任务 + 人员”调整为“任务 + 场次 + 人员”。
5. 历史无场次数据继续使用 `exam_session_id IS NULL` 的兼容作用域，不能与新场次记录混查。
6. 导出必须显式指定场次，并校验所选人员都属于该场次；证件照仍以资料清单中的 `DOC002` 有效文件为准。
7. 所有场次化写操作继续使用现有权限、租户过滤和审计日志，不通过数据库直写绕开业务校验。

## 三、分阶段范围

### 第一阶段：信息/实操采集闭环（本次实现）

- 场次列表进入管理页时保留 `examSessionId`；
- 管理端和平板端工作台按场次加载人员；
- 初始化、二维码、扫码匹配、搜索、排队、采集、异常处理、详情和导出全链路携带场次；
- 状态和队列唯一约束升级为场次级；
- 导出名单、场次标题、证件照、指纹和签名全部从同一场次作用域读取；
- 对旧任务保留空场次兼容路径。

### 第二阶段：实操评分任务场次化

- 实操评分配置、考评组、工位/考场、评分进度和成绩增加 `exam_session_id`；
- 开始评分前校验人员属于目标实操场次；
- 成绩唯一约束调整为“任务 + 场次 + 人员 + 评分维度”；
- 列表、看板、导入和导出全部以场次为筛选必选项。

### 第三阶段：答辩任务场次化

- 扩展考试场次类型，或建立答辩场次子类型，明确答辩日期、时段、考场和人员；
- 答辩配置、分组、签到、评分、复核和成绩增加 `exam_session_id`；
- 同一认定任务可创建多个答辩场次并分别授权、执行和归档。

## 四、兼容与迁移

1. 本次只新增 Flyway 迁移，不修改任何已应用迁移。
2. 现有 `exam_session_id IS NULL` 的采集数据视为历史任务作用域；不自动归并到任一新场次，避免误绑定。
3. 已经写入 `exam_session_id` 的状态记录原值保留，仅调整数据库唯一约束。
4. 接口中的 `examSessionId` 对历史路径保持可选；从新场次列表进入时必须传入。
5. 部署顺序为数据库迁移、后端、前端；由负责人执行生产部署和回归。

## 五、验收场景

以“来宾新材铝及铝合金熔铸工新型学徒一到五级”为例：

1. 理论场次进入采集工作台时显示 18 人；
2. 实操场次进入采集工作台时只显示“梁力勃、莫绍文、黄国系”3 人；
3. 3 人可在理论场次和实操场次分别拥有独立的二维码、排队和完成状态；
4. 实操场次导出只能选择这 3 人，导出的场次信息正确；
5. 每人的证件照取自其有效 `DOC002` 文件，且与该人员记录一致；
6. 在实操场次 URL 中替换为其他任务的场次 ID 时，后端拒绝访问；
7. 历史无场次任务仍可正常初始化、采集和导出。
