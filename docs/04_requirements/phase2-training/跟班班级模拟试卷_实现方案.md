```text
管理端 FollowClassWorkbench「模拟考」Tab

        ▼
platform-api
  /training/follow-tasks/**          （按 taskType=mock 过滤；可复用）
```

## 3. M0 — 后端

### 3.1 数据

**P0 可不加列**：现表已有 `pass_score`、`deadline_at`、`show_analysis_after_submit`。  
`task_type` 注释从 `homework/practice` 扩到含 `mock`（Flyway 仅改 COMMENT 可选）。

**挂载校验**：现 `validateMount` 强制课次或业务日。模拟考建议：

| 规则 | 说明 |
|------|------|
| P0 | `mock` 允许 `biz_date` 必填、`schedule_id` 可选；或仅 `class_id`（改 `validateMount`：`mock` 时挂载可选） |
| 推荐 | **`mock`：挂载可选**；有则展示，无则仅按班级 |

Flyway 示例（若选加字段，归 M3/P1）：

```sql
-- 可选 P1
ALTER TABLE train_follow_task
  ADD COLUMN time_limit_min INT NULL COMMENT '模拟考时长分钟' AFTER pass_score,
  ADD COLUMN allow_retake TINYINT NOT NULL DEFAULT 0 COMMENT '是否允许重考' AFTER time_limit_min;
```

P0 **不强制**跑上述 ALTER。

### 3.2 常量与校验

文件：`TrainFollowTaskApplicationService.java`

| 改动 | 内容 |
|------|------|
| `TYPE_MOCK = "mock"` | 加入 `TASK_TYPES` |
| `TASK_TYPE_NAMES` | `mock → "模拟考"` |
| `normalizeTaskType` | 错误文案改为含 mock |
| `listClassTasks` / admin 列表 | 支持 query `taskType`；作业 Tab 默认排除 mock；模拟考 Tab 只查 mock |
| `listStudentTasks` | 增加可选 `taskType`；默认行为：作业入口只返 homework/practice，模拟考入口只返 mock（**避免串入口**） |

### 3.3 未抽题 API（核心）

**新增**（App/管理端共用思路）：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/training/follow/classes/{classId}/mock-used-question-ids` | 返回本班 mock 已占用题 ID |
| 或 | 在 draw 请求增加 `excludeOtherMock=true` | 服务端内部拼 excludeIds |

推荐 **双支持**：

```text
GET  .../mock-used-question-ids
  ?excludeTaskId={当前草稿 id}   // 编辑本卷时不排除自己已选题
  &statuses=draft,published      // 默认；不含 closed 可参数化

响应：{ usedIds: number[], count: number }
```

`drawBankQuestions`：当 `excludeOtherMock=true` 时：

```text
excludeIds = union(客户端传入 excludeIds, mockUsedIds(classId, excludeTaskId))
余量不足 → BusinessException 明确文案（含剩余可抽数）
```

占用题来源：

```text
SELECT DISTINCT q.source_exam_detail_id
FROM train_follow_task_question q
JOIN train_follow_task t ON t.id = q.task_id
WHERE t.class_id = ? AND t.task_type = 'mock'
  AND t.deleted = 0 AND q.deleted = 0
  AND q.source_exam_detail_id IS NOT NULL
  AND t.status IN ('draft','published')  -- 默认
  AND t.id <> excludeTaskId              -- 可选
```

### 3.4 管理端 vs App 写接口

现状：任务 CRUD 多在 `TrainFollowAppController`（老师 App）。管理端已有 `TrainFollowTaskAdminController`（进度/同步名单等）。

P0 配卷仅管理端，二选一：

| 方案 | 做法 |
|------|------|
| **A（推荐）** | AdminController 补齐 create/update/publish/close/items/questions + bank-draw 代理，权限走管理端 PreAuthorize |
| B | 管理端临时调现有 `/training/follow/tasks*`（需管理端用户也能过 AppToken/或统一鉴权）——易踩鉴权坑 |

实现清单（方案 A）：

| 能力 | Admin API（建议前缀） |
|------|------------------------|
| 列表 | `GET /training/follow-tasks?classId&taskType=mock`（已有则加过滤） |
| 创建草稿 | `POST /training/follow-tasks` body.taskType=mock |
| 更新/换题 | `PUT /training/follow-tasks/{id}` |
| 发布/关闭/重开 | `POST .../publish` `.../close` `.../reopen` |
| 统计/名单 | 已有 stats / items |
| 答卷 | 已有 item answers |
| 未抽题 | `GET .../classes/{classId}/mock-used-question-ids` |
| 抽题 | `POST .../classes/{classId}/bank-draw` + `excludeOtherMock` |

复用 `TrainFollowTaskApplicationService`，禁止复制判分逻辑。

### 3.5 学员列表隔离

| 入口 | API | 过滤 |
|------|-----|------|
| 课堂作业 | `GET /student/tasks?classId` | `task_type IN (homework, practice)` |
| 模拟考 | `GET /student/tasks?classId&taskType=mock` | 仅 mock |

**兼容**：不传 `taskType` 时保持现状（只返作业类），避免旧 App 突然出现模拟考。或显式：`taskType` 缺省 = `homework,practice`。

### 3.6 重考（P0）

提交时若 `item` 已 `submitted`：直接拒绝（「不可重考」）。现逻辑若已支持覆盖，对 `mock` 分支禁止二次 submit。

### 3.7 后端文件清单

| 文件 | 动作 |
|------|------|
| `TrainFollowTaskApplicationService.java` | TYPE_MOCK、列表过滤、usedIds、draw 合并 exclude、mock 挂载、禁重考 |
| `TrainFollowAppController.java` | student/tasks 增加 taskType；可选 mock-used-question-ids |
| `TrainFollowTaskAdminController.java` | 配卷 CRUD + draw 代理（若走方案 A） |
| `FollowBankDrawReq.java` | `excludeOtherMock` Boolean |
| `FollowTaskSaveReq` / VO | 无需大改；taskType 文档注明 mock |
| Flyway（可选） | COMMENT 或 P1 时长字段 |
| 单测 / 集成测 | usedIds 并集；两套卷 draw 无交集 |

### 3.8 后端验收

- [ ] 创建 `taskType=mock` 草稿成功；`homework` 行为回归  
- [ ] `excludeOtherMock=true` 抽题与本班另一套 mock 题 ID 无交集  
- [ ] 编辑本卷时 `excludeTaskId` 不排除自身已选题导致抽不满的误伤（或文档约定：换题先清再抽）  
- [ ] 学员 `taskType=mock` 只看见已发布模拟考  
- [ ] 作业列表不出现 mock  
- [ ] 已交 mock 再次 submit 被拒

### 4.3 配卷交互（P0）

1. 新建 → 标题（如「一模」）→ 保存草稿  
2. 选题区：科目/知识点（默认 practice-scope）→ 题量 → 勾选 **「排除本班其他模拟卷已抽题」** → 智能抽题 / 手工检索添加  
3. 展示已选列表、可删题  
4. 发布 → 确认花名册人数  
5. 列表：状态、题量、已交/应交、均分；行操作：进度、答卷、关闭  

答卷详情：复用 `FollowHomeworkTab` 的学员表 + 逐题抽屉（抽成 `FollowTaskAnswerDrawer` 更佳，P0 可复制改过滤）。

### 4.4 API 封装

`apps/admin-web/src/api/training.ts`（或既有 follow-task API）增加：

- `listFollowTasks({ classId, taskType: 'mock' })`  
- `createFollowTask` / `update` / `publish` / `close`  
- `getMockUsedQuestionIds(classId, excludeTaskId?)`  
- `drawBankQuestions(classId, { ..., excludeOtherMock: true })`  
- stats / itemAnswers 复用  

### 4.5 管理端验收

- [ ] 一班可建两套 mock；作业 Tab 仍无这两套  
- [ ] 二套勾「未抽」后抽中题与一套无交集  
- [ ] 发布后学员侧可见；后台可打开某人答卷对错  
- [ ] 关闭后学员不可再交
