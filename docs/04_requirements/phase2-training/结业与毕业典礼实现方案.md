> **日期**：2026-08-14

## 一、结论（先看）

| 问题 | 答案 |
|------|------|
| 现网完成度 | **~30%**：四接口 + 页面壳有；学员打标 / 真通知 / 归档导出 / 证书关联未闭环 |
| 结业粒度 | **以班级为准**（`train_info_class`）；项目 `train_info_list.status=2` 仅在该培训下**全部班结业后**回写 |
| 通知通道（本期） | **站内信**；短信二期开关，不与验证码通道混用 |
| 证书 KR4 | **轻关联可查**：模板用 `train_file_temp`，发证记录用 `train_certificate`；不做复杂排版 |
| 建议工期波次 | KR1 → KR4（轻）→ KR2 → KR3 |

**一句话：** 先把「班/人结业状态」做成真相源，再通知、归档、挂证书；禁止继续「只改项目 status + 通知假成功」。

## 三、产品规则（评审冻结项）

### 3.1 状态机

**学员** `graduate_status`：

| 值 | 含义 |
|----|------|
| `0` / `pending` | 未结业 |
| `1` / `passed` | 已结业（合格） |
| `2` / `failed` | 不合格结业（是否允许由产品开关；默认**本期允许标记但不发证**） |
| `3` / `revoked` | 已撤销（可选，二期） |

**班级** `graduate_status`：

| 值 | 含义 |
|----|------|
| `pending` | 未结业 |
| `partial` | 部分学员已结业 |
| `done` | 全员已处理（合格+不合格均计「已处理」）或「已执行班级结业」 |

**项目** `train_info_list.status`：

- 保持文档约定：`1` 进行中 / `2` 已完成  
- **仅当**该 `train_info_id` 下全部未删班级均为 `done` 时，自动置 `2`  
- 禁止单班结业直接置项目完成（修复现网缺陷）

### 3.2 结业判定（本期最小）

| 规则 | 建议默认 |
|------|----------|
| 是否强制成绩达标 | **否**（教务可勾选结业）；UI 展示成绩并标黄「未达标」 |
| 达标参考 | `exam_score` / `real_score` / `normal_score`；阈值可配置，首期写死或读简单配置 |
| 与考试衔接（O2） | 成绩以花名册字段为准；O2 成绩回写完成前，允许手工改分或仅展示 |

### 3.3 通知

- 通道：**站内信**（培训域自建表，不复用竞赛 inbox）  
- 对象：结业操作涉及的学员（有绑定用户则投递；无用户记 `fail/no_user`）  
- 内容：班名 + 结业结果 + 时间；模板文案可配置常量即可  

### 3.4 归档内容（轻量）

归档 ZIP 至少包含：

1. 结业名单快照（xlsx）  
2. 可选：班级已生成的培训照片包引用说明（fileId 清单），**不强制**重打影像  

不做完整「项目档案中心」。

### 3.5 证书

- **模板**：`train_file_temp`（type 约定结业证，如 `graduation_cert`）  
- **班级挂模板**：`train_info_class.certificate_temp_id`（或复用 `file_temps` JSON 中约定 key）  
- **发证记录**：`train_certificate` 补齐 `class_id` / `people_id` / `template_id`  
- KR4 验收：**列表可查**即可；「一键批量颁发」可同波次做薄封装 `batchIssue`，非必须排版

## 五、接口设计（扩现有，少新造）

基路径：`/training` · 权限建议统一为 `train:graduation:view|update`（与菜单对齐，替换仅依赖 `train:info-class:*` 的散落）。

| 方法 | 路径 | KR | 说明 |
|------|------|-----|------|
| GET | `/info-classes/graduation-candidates` | KR1 | 增：`graduateStatus`、已结业/总人数；query：`keyword`、`graduateStatus` |
| GET | `/info-classes/{classId}/graduation-students` | KR1/KR4 | 增：学员结业态、成绩达标提示、`templateTitle`、`certificateNo`、`certStatus` |
| POST | `/info-classes/{classId}/graduate` | KR1 | body：`peopleIds[]?`、`mode=all|selected`、`allowUnqualified?`；幂等 |
| POST | `/info-classes/{classId}/graduation-revoke` | KR1 可选 | 撤销单人/班（二期可砍） |
| POST | `/info-classes/{classId}/graduation-notify` | KR2 | 真写通知表；返回 success/fail 计数 |
| GET | `/info-classes/{classId}/graduation-notices` | KR2 | 发送历史 |
| POST | `/info-classes/{classId}/graduation-archive` | KR3 | 生成 ZIP，写 archive 表 |
| GET | `/info-classes/{classId}/graduation-archives` | KR3 | 归档版本列表 |
| GET | `/graduation-ledger/export` | KR3 | Excel；query：`classId?` |
| PATCH | `/info-classes/{classId}/certificate-template` | KR4 | 绑定 `certificateTempId` |
| POST | `/certificates/batch-issue` | KR4 | 已有则接线：按班已结业学员批量建记录 |

## 七、分期交付与验收

### 波次 A — KR1（必须先做）

1. Flyway 学员+班级结业字段  
2. 改造 `graduate` / candidates / students  
3. 页面状态展示与勾选结业  

**验收**：待结业可筛；打标后刷新仍在；单班结业不把整项目 status 误置 2；幂等再点不重复污染。

### 波次 B — KR4 轻关联（可与 A 尾部并行）

1. 班级绑模板；名单返回模板/证号  
2. 修证书模板页模型  
3. （可选）已结业学员 batchIssue  

**验收**：指定班名单可见模板名与是否已建证记录。

### 波次 C — KR2

1. 通知表 + `graduation-notify` 真发送  
2. 发送历史 UI  
3. 无账号计入 fail  

**验收**：无「假成功」；库中有批次与明细；失败数可解释。

### 波次 D — KR3

1. 台账 Excel 导出（复用 XSSF 模式）  
2. 归档 ZIP + archive 表（复用补贴/开班 pack 模式）  

**验收**：导出与打标一致；归档可下载、可多版本。

### O3 总验收路径

```text
待结业班 → 看学员/成绩 → 打标结业 → 发通知有据
        → 导出台账 / 生成归档包 → 名单可见证书模板与证号
```
