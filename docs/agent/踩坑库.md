## 现行条目

### #1 MyBatis-Plus 默认 snake_case（2026-06-04）
Flyway 迁移的列名必须 snake_case，跟 Java 命名策略对齐。

### #2 `setDeleted(1) + updateById` 永远是假删（2026-06-09）
软删统一用 `mapper.deleteById(...)`，全项目禁止 `setDeleted(1)`。

### #3 PowerShell Set-Content 默认带 UTF-8 BOM（2026-06-09）
Java 编译会报非法字符；改源码用 Edit/Write 工具，不要走 shell 管道。
检查命令：`git diff --cached | grep -P '^\+\xEF\xBB\xBF'` 或对单文件 `head -c 3 file | xxd | grep efbbbf`。

### #4 Flyway 批量重命名迁移要按 description 还原真实 version（2026-06-05）
不要靠 description 猜 version，先 `SELECT description, version FROM flyway_schema_history` 反查。

### #5 前端 tsx 引用同目录 css 是约定（2026-06-05）
移植 Vue → React 时别漏 import 对应 css。

### #6 producer 阶段硬上限装不下全链路 E2E（2026-06-09）
拆 sub-task，或 owner 自己跑 E2E，或明确不让 verify-as-task 进 plan。
〔口径修订 2026-09-20：硬上限统一为 **15min**（系统硬限），原文"25min"作废，见 `多Agent协作协议.md`〕

### #7 新建 Flyway 迁移前先查最大 version（2026-07-14，2026-09-04 增补）
`SELECT MAX(version) FROM flyway_schema_history`，新迁移版本号 = 最大 version + 0.001；不要靠文件名猜，数据库里可能已有同 version 的迁移。**测试库（gjjddb2026）与生产库（gjjddbpro）历史已分叉，取号必须同时查两库取最大值并留间隔**（2026-09-04 事故：20260904.001/.002 在测试库已被 train_certificate 工作流占用，本地新建同名版本号迁移撞号）。

### #8 权限系统三步链：菜单→权限码→角色授权（2026-07-14，2026-09-04 增补）
只建菜单+权限码不够，还必须 INSERT `sys_role_permission` 把权限码授予目标角色（role_id=2000 是平台管理员），否则接口 403。**菜单/权限/角色授权种子的 tenant_id 必须写 10159（千铝工投，运行租户；admin/sys_user.tenant_id=10159，sys_menu 全表 340 行均为 10159），不要照抄部分历史迁移文件里的 tenant_id=1**——运行时菜单/权限查询走多租户拦截器按当前租户过滤，tenant_id=1 的种子对 10159 用户不可见。

### #9 Redis 缓存序列化：返回 mutable collection（2026-07-14）
`@Cacheable` 方法的返回值必须用 `ArrayList::new` 或 `new ArrayList<>(list)`，禁止用 `.toList()` / `List.of()` / `Map.of()` 等 immutable collection，否则 Redis 反序列化报 `Unexpected token (START_ARRAY), expected VALUE_STRING`。

### #10 前端 axios `responseType: 'blob'` 下载文件（2026-07-14）
`apiClient.get(url, { responseType: 'blob' })` 返回 `AxiosResponse`，blob 数据在 `.data` 里；API 函数签名应 `return (await apiClient.get(...)).data` 并声明 `Promise<Blob>`。

### #11 大数据量导入接口必须拆"快速返回 + 异步执行"两步（2026-07-15）
涉及文件上传/批量导入/批量处理等**数据量不确定**的场景，禁止在一个接口里同步完成"接收数据 + 后台处理"。需确认是否拆为：第一步只接收数据并入库/返回标识（秒回），第二步单独触发后台处理（秒回 batchId），第三步轮询进度。否则数据量大时前端会超时（axios 默认 20s），拿不到 batchId 就无法轮询。

### #12 线程池拒绝策略禁止用 CallerRunsPolicy（2026-07-15）
队列满时 CallerRunsPolicy 会把任务退化为调用者线程（HTTP 线程）同步执行，前端表现为"卡死"。必须用 `AbortPolicy` + 全局异常处理返回 503"服务繁忙，请稍后重试"，让客户端感知到限流。

### #13 调用第三方 API 前必须核对目标文档，不能假设兼容（2026-07-15）
OpenAI 兼容 ≠ 完全兼容。LongCat 不支持 `response_format` 字段，强发会导致模型返回空 content。调用任何第三方接口（LLM/支付/短信等）前，先确认目标平台文档明确支持该字段/参数，不支持的字段一律不传。

### #14 多个同类型线程池 Bean 必须用具体类型 + @Qualifier 注入（2026-07-20）
`@Bean` 方法返回类型必须用 `ThreadPoolTaskExecutor`（不能用 `Executor` 接口），否则 Spring 按返回类型注册导致找不到 Bean。注入端配合 `@Qualifier("beanName")` 区分。Flowable 还需要名为 `applicationTaskExecutor` 的 `AsyncTaskExecutor` Bean，缺少会启动报错。

### #15 TenantContextHolder 不跨线程传播（2026-07-20）
并行/异步场景中，编排线程 `setTenantId()` 对 Worker 线程无效。每条 Worker 线程必须独立 `TenantContextHolder.setTenantId(tenantId)` + `finally clear()`。编排线程仅在加载期 set/clear，不传给子任务。

### #16 Flyway 迁移脚本必须编译后才生效（2026-07-20）
Flyway 读取 `target/classes/db/migration/`，不是源码目录。新加 `.sql` 后必须 `mvn compile` 再启动，否则 Flyway 看不到新脚本。

### #17 MyBatis-Plus 多租户拦截器依赖 TenantContextHolder（2026-07-20）
Worker 线程中 Mapper 查询自动拼 `tenant_id` 的前提是该线程已 `setTenantId()`。未设置时查询不带租户条件，可能跨租户漏数据。

### #18 异步批处理 pause 不中断已提交的 LLM 长调用（2026-07-20）
暂停只阻止新任务块继续提交，当前块内已启动的 Worker 线程会跑完。设计时缩小块粒度、在 resume 时重置 `processing` → `pending`，并把批次内不变数据（如知识点全表）一次性加载到内存复用，避免每条记录都查库导致连接池被长耗时压垮。

### #21 主库 Druid wall 过滤器不支持 MySQL 8.0.19+ `AS new` 行别名（2026-08-04，2026-09-20 收窄）
`INSERT ... VALUES (...) AS new ON DUPLICATE KEY UPDATE c = new.c` 会被 wall filter 按 SQL 注入拦截（sql injection violation）。upsert 统一用旧式 `ON DUPLICATE KEY UPDATE c = VALUES(c)`（8.4 仍支持，仅弃用警告）。
〔收窄说明：该约束现只对业务 SQL 生效；Flyway 已走独立直连，见 #25〕

### #24 雪花 ID 超 JS Number 安全整数（2^53）（2026-08-04）
App 端接口响应中的雪花 id（planId/dayId/mockPaperId）必须以字符串下发，前端 JSON.parse 会把 2e18 级整数四舍五入成别的值（2084569567062556674 → ...6700），回传即"记录不存在"。参照竞赛模块 `@JsonSerialize(using=ToStringSerializer.class)` 或视图层直接 String.valueOf。

### #25 Flyway 迁移连接必须与业务 Druid 池分离（2026-09-07 生产部署触发）
Druid wall 会拦截迁移脚本中的 `PREPARE/EXECUTE` 动态 SQL（双库分叉场景的条件化 DDL 必用此写法，见 #7），空库重建/新环境首次部署必撞。`application.yml` 已通过 `spring.flyway.url/user/password = ${spring.datasource.*}` 让 Flyway 用独立直连（引用数据源属性防环境间配置漂移），勿删；也不要为此给 wall 开 none-base-statement-allow（等于给业务池放行动态 SQL）。**属性名是 `user` 不是 `username`**——写 username 会被静默忽略，JDBC 驱动回退 OS 用户名，启动报 Access denied for 'xxx'。新迁移继续沿用条件化 PREPARE 约定，不改已应用的历史脚本。

### #26 诊断"外网 IP 拉取超时"先排自回环，修复优先复用既有 helper（2026-09-15）
后端只监听 `127.0.0.1:8080`，nginx 仅代理 80→`127.0.0.1:8080`，8080 不对公网开放。生产把 `platform.cdn.url` 配成 `http://{本机公网IP}:8080/api/exam/files` 后，任何"本地缺失候选回退拉 `cdnUrl`"的代码 = **自己请求自己的公网 IP:8080，必连不上，每个候选干等连接超时**（默认模板导出 364 次失败、单次 18~22 分钟，前端轮询先超时报"未找到压缩包"）。排查要点：
(a) 日志里的"外网 IP"先核是不是本机公网 IP + 该端口是否对本机可达，别默认当成远端 CDN；
(b) 本机文件解析直接读盘，不要回环 HTTP 求自己——复用 `CdnFileServeHelper`（已实现 `cdn.path` + `file.local-root` 双根 + 远端回退），别新写解析逻辑也别改 `FileApplicationService.openInputStream` 这类底层；
(c) 自链接（`/exam/files/`、`cdnUrl`/`publicUrl` 前缀）剥成相对路径查盘，远端回退若指向自己也跳过；
(d) 单次批量任务共用一个 resolver 缓存命中/未命中，同路径不重复探测；
(e) 无记录槽位跳过约定路径盲试；
(f) 远端拉图连接超时按秒级收敛（3s）。
**流程教训**：治标方案（改 `CDN_URL=localhost` 配置）依赖运维改对配置、且仍走 HTTP，不如直接删自回环、双根读盘（2026-09-15 `dbac831` 修复）。

## 历史归档（2026-08-27 PHP 第二数据源已拆除，以下条款不再约束当前代码）

> 背景：`application.yml` 注释——「单库化（2026-08-27）：platform.sync 三表镜像同步、platform.sync.php 第二数据源…已随 `integration/php`、`integration/sync` 包拆除」。全库 grep `PhpDataSourceHolder` 0 命中，`integration/` 包只剩 `bot/`。
> 保留在此仅供理解历史决策；若未来再引入第二数据源，这 4 条重新生效。

### #19 [已拆除] 多数据源：任何 DataSource Bean 都会让主数据源自动配置整体退让（2026-08-04）
注册第二 DataSource Bean 后，`DataSourceAutoConfiguration` 按 `@ConditionalOnMissingBean` 退让，主数据源（SaaS 库）消失，Flyway 会对第二数据源（如 PHP 库）执行全量迁移（2026-08-04 冒烟事故，差点打挂 PHP 生产库）。正确做法：第二数据源用"持有器模式"（内部自建 DruidDataSource、不以 DataSource 类型暴露），主数据源自动配置完全不受影响。

### #20 [已拆除] 注册第二 JdbcTemplate 后必须显式 `@Primary` 主模板（2026-08-04）
`JdbcTemplateAutoConfiguration` 同样按 MissingBean 退让，未标注 `@Qualifier` 的 JdbcTemplate 注入点会全部拿到第二数据源模板（主库 SQL 打到 PHP 库报 bad SQL grammar）。多数据源项目：`@Bean @Primary JdbcTemplate` 钉住默认注入语义 + 第二模板必须 `@Qualifier` 引用。

### #22 [已拆除] 镜像表唯一约束必须与源库一致（2026-08-04）
PHP `platform_user_token.token` 无唯一约束（现网 85 组重复），SaaS 镜像表加 UNIQUE 后，`ON DUPLICATE KEY UPDATE` 把同 token 多行折叠，镜像行数永远少于源库且每周期反复覆盖（thrashing，checkpoint 恒见 updated≠0 不收敛）。镜像表索引按源库实际约束建；鉴权查询按 id 升序取首行对齐 PHP findFirst 语义。

### #23 [已拆除] mysql-connector-j 默认把 TINYINT(1) 映射为 Boolean（tinyInt1isBit=true）（2026-08-04）
会丢失 level=2/3 这类真实数值（`value instanceof Number` 为 false → 解析得 null），PHP 老库大量 tinyint(1) 存枚举/层级值。凡接 PHP 库的 JDBC URL 必须加 `tinyInt1isBit=false`；解析层对 Boolean 做 0/1 兜底。2026-08-04 权重解析因此全空、计划生成权重兜底失效。
