## 1. 文档口径

`training-management.md` 来自旧 Vue 3 + PHP Phalcon 项目，旧接口主要是：

```text
/yundemand/*
/yuntrain/*
/upload/yun
```

当前项目不沿用旧接口形态，统一使用：

```text
baseURL: /api
业务前缀: /training
完整路径: /api/training/...
```

当前前端为 React + Vite + TypeScript + Ant Design，接口封装在：

```text
apps/admin-web/src/api/training.ts
apps/admin-web/src/types/training.ts
```

当前后端实现位于：

```text
services/platform-api/src/main/java/com/guoyu/platform/trainingdepartment/
```

## 2. 通用约定

### 2.1 请求头

前端请求拦截器会自动携带：

```http
Authorization: Bearer <token>
X-Tenant-Id: <tenantId>
X-Request-Id: <uuid>
```

后端不得依赖旧系统 `token` header 或 `istate` query 参数。

### 2.2 响应结构

统一响应：

```json
{
  "code": "0",
  "message": "成功",
  "data": {}
}
```

标准分页响应：

```json
{
  "code": "0",
  "message": "成功",
  "data": {
    "total": 100,
    "page": 1,
    "size": 20,
    "records": []
  }
}
```

兼容旧页面迁移的部分接口当前返回：

```json
{
  "code": "0",
  "message": "成功",
  "data": {
    "list": [],
    "total": 100,
    "limit": 20
  }
}
```

涉及 `info-lists`、`info-classes`、`class-student-list`、`class-other`、`class-task` 的前端页面已按这种兼容结构处理。后续如调整为标准 `PageResponse`，需要同步修改 `apps/admin-web/src/types/training.ts` 和页面取数逻辑。

### 2.3 字段命名

当前项目存在两类字段：

- 新增通用 CRUD 接口多使用 camelCase，如 `trainInfoId`、`companyId`。
- 兼容旧前端迁移的聚合接口部分返回 snake_case，如 `train_info_id`、`company_name`、`work_type_title`。

前端页面已在 `types/training.ts` 中区分类型：

- `TrainInfoList`：camelCase 详情/CRUD。
- `TrainInfoListItem`：snake_case 列表项。
- `TrainInfoClass`：camelCase 详情/CRUD。
- `TrainInfoClassListItem`：snake_case 列表项。

后端补接口时要明确返回结构，不要同一个字段在同一个接口中混用两种命名。

### 2.4 权限

所有接口需要后端权限控制。当前已使用的权限码包括：

```text
train:demand-train:view/create/update/delete
train:solution:view/create/update/delete
train:info-list:view/create/update/delete
train:info-class:view/create/update/delete
train:people-list:view/create/update/delete/audit
train:task-log:view/create/update/delete
train:declare:view/create/update/delete
train:file-temp:view/create/update/delete
```

前端只负责展示控制，后端是最终裁决点。

## 4. 需求管理接口

对应前端：

```text
apps/admin-web/src/pages/training/RequirementsManagementPage.tsx
```

### 4.1 企业需求分页

```http
GET /api/training/demand-trains
```

权限：

```text
train:demand-train:view
```

Query：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | number | 否 | 页码，默认 1 |
| `pageSize` | number | 否 | 每页数量 |
| `keyword` | string | 否 | 关键词 |
| `orgId` | number | 否 | 企业/组织 ID |

返回：`PageResponse<DemandTrain>`。

前端用途：企业需求“全部/回收站/检索”等列表。

### 4.2 企业需求详情

```http
GET /api/training/demand-trains/{id}
```

返回：`DemandTrain`。

### 4.3 创建企业需求

```http
POST /api/training/demand-trains
```

Body：

```json
{
  "orgId": 1,
  "content": "需要50名电工初级培训",
  "nums": 50
}
```

后端要求：

- `orgId` 不应由企业端随意伪造；企业角色场景应从当前用户组织推导。
- 新增后 `status` 默认为待处理。
- 写操作记录审计日志。

### 4.4 更新企业需求

```http
PUT /api/training/demand-trains/{id}
```

Body 同创建，可传部分字段。

### 4.5 删除企业需求

```http
DELETE /api/training/demand-trains/{id}
```

后端要求：使用逻辑删除，不做物理删除。

### 4.6 待处理需求列表

```http
GET /api/training/demand-trains/pendings
```

Query：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | number | 否 | 页码，默认 1 |
| `pageSize` | number | 否 | 每页数量，默认 30 |
| `keyword` | string | 否 | 关键词 |
| `del` | number | 否 | `0` 正常，`1` 回收站 |

返回：

```json
{
  "total": 10,
  "page": 1,
  "size": 30,
  "records": [
    {
      "id": 1,
      "orgId": 1001,
      "orgName": "XX公司",
      "content": "需要电工培训",
      "nums": 50,
      "status": 0,
      "addtimeCn": "2026-06-01 09:00:00"
    }
  ]
}
```

前端用途：需求管理页面“待办”。

### 4.7 公共下拉数据

```http
GET /api/training/demand-trains/public-data
```

Query：

```text
tags=company&tags=worktype&tags=traininfo&tags=kejian
```

返回：

```json
{
  "company_list": [
    { "id": 1, "title": "XX公司", "tag": "company" }
  ],
  "worktype_list": [
    {
      "id": 10,
      "title": "电工",
      "options": [
        { "id": 11, "title": "初级电工" }
      ]
    }
  ],
  "traininfo_list": [
    { "id": 1, "title": "2026年第一期电工培训" }
  ],
  "kejian_list": [
    { "id": 1, "title": "安全生产基础" }
  ]
}
```

前端用途：

- 需求转培训：`company`、`worktype`
- 方案管理：`company`、`traininfo`
- 班级管理：`company`、`traininfo`、`kejian`
- 培训信息：`company`、`worktype`

后端要求：

- `tags` 为空时可返回默认常用数据。
- 返回字段名保持 snake_case，当前前端按 `company_list`、`worktype_list` 读取。

### 4.8 需求转培训

```http
POST /api/training/demand-trains/convert
```

权限：

```text
train:demand-train:create
```

Body：

```json
{
  "title": "2026年第一期电工培训",
  "companyId": 2,
  "trainCompanyName": "千铝工投",
  "workTypeId": 3,
  "workTypeLevel": 5,
  "num": 50,
  "traindemandId": 1
}
```

返回：

```json
{
  "id": 101,
  "title": "2026年第一期电工培训"
}
```

后端事务要求：

- 创建或更新 `train_info_list`。
- 如果 `traindemandId` 存在，更新 `demand_train.status=1`。
- 校验企业、工种、等级、人数。
- 防止同一企业需求重复转培训，重复时应返回明确业务错误或幂等返回已有记录。

返回：删除的 ID 数组。


返回：

```json
{
  "id": 1,
  "title": "电工初级培训方案"
```

- 新增或更新 `train_solution`。
- 全量替换 `train_solution_badge`。
- 新增方案后将对应 `train_info_list.status` 更新为 `1`，表示待企业确认。
- 校验 `title`、`companyId`、`traininfoId`。
- 费用字段允许为 0，不允许为负数。

```json
{
  "courseNum": 80,

  "status": 0
```

状态约定：

```http
DELETE /api/training/info-lists/{id}
```

后端要求：

- 如果已有班级、方案或报名数据，建议返回业务错误或要求二次确认。

### 6.5 企业确认方案

```http
POST /api/training/info-lists/{id}/company-confirm
```

说明：

- `id` 是 `train_info_list.id`，不是 `demand_train.id`。
- 确认后设置 `companyHasConfirm=1`，记录确认时间和确认人。
- 同时清空对应方案驳回原因。

### 6.6 企业驳回方案

```http
POST /api/training/info-lists/{id}/company-reject?reason=经费预算不合理
```

说明：

- `id` 是 `train_info_list.id`。
- 后端应将 `reason` 写入对应 `train_solution.reject_reason`。
- 建议将 `companyHasConfirm` 置为 `0`，并保留驳回记录。

## 12. 联调验收清单

### 12.1 需求管理

- 企业需求创建后，待办接口能查到。
- 待办转培训后，`info-lists` 能查到新培训信息。
- 重复转培训有明确提示或幂等返回。
- 公共下拉 `company`、`worktype`、`traininfo`、`kejian` 数据结构稳定。

### 12.2 培训方案

- 方案保存时 `badgeList` 正确落库。
- 方案列表显示预算合计和实际支出合计。
- 方案详情返回 `badgeList`、`file/file_path`、`fileType`。
- 企业确认后培训信息状态更新。
- 企业驳回后方案详情能看到 `reject_reason`。

### 12.3 培训信息

- 企业和工种筛选有效。
- 编辑 `courseNum`、`position`、`status` 后列表刷新正确。
- 删除培训信息时已有下游数据能被后端拦截。

### 12.4 班级人员

- 班级创建必须绑定 `trainInfoId`。
- 自助报名导入、身份证导入均能返回成功数量。
- 重复学员不会被重复导入。
- 教务/负责人列表按 `teacher`、`fuzhe` 区分。
- 任务保存后能回显课件名称和日期。

### 12.5 开班申报

- 申报基础 CRUD 可用。
- 模板 CRUD 可用。
- 模板挂载班级、移除模板、材料生成接口补齐后，前端可完成旧 `classApplication.vue` 的完整能力。
