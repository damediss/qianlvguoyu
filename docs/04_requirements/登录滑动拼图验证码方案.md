# 登录滑动拼图验证码方案

## 1. 功能概述

在管理端登录页面增加滑动拼图验证：用户填写完账号密码后点击「登录」，弹出拼图弹窗，
将带有图案的滑块拖动到背景图缺口处完成验证，验证通过后自动提交登录请求。

### 1.1 验证流程

```
用户填写表单 → 点击"登录" → 前端弹出拼图弹窗
  → 前端调 GET /auth/captcha/generate 获取拼图数据
  → 用户拖动滑块到缺口位置
  → 前端调 POST /auth/captcha/verify 提交验证
  → 验证通过返回 captchaToken
  → 前端将 captchaToken 附加到 LoginReq 中提交登录
  → 后端登录时校验 captchaToken 有效性
```

### 1.2 关键决策

| 决策点       | 选定方案                          | 理由                                      |
|------------|-------------------------------|-----------------------------------------|
| 底图来源     | 前端 Canvas 绘制渐变色/几何图案         | 无需管理图片资源，每次生成唯一底图                      |
| 临时状态存储   | Redis（`captcha:` key prefix）  | 项目已配置 Redis，天然支持 TTL 过期                   |
| 验证模式     | 后端生成 + 后端校验                   | 拼图缺口位置由后端计算，前端不知道正确坐标，防重放和篡改           |
| 图片传输     | Base64 内嵌 JSON 响应             | 无需文件服务，一期简单够用                          |
| Token 传递 | LoginReq 增加 `captchaToken` 字段 | 后端登录时先校验 token 有效性，再走原有认证逻辑             |

### 2.2 API 合同

#### `GET /auth/captcha/generate`

> 无需认证（permitAll），生成一组拼图数据。

**Response 200:**

```json
{
  "code": "0",
  "data": {
    "captchaId": "uuid-xxx",
    "bgImage": "data:image/png;base64,...",
    "sliderImage": "data:image/png;base64,...",
    "sliderY": 85
  }
}
```

| 字段           | 类型     | 说明                                    |
|--------------|--------|---------------------------------------|
| `captchaId`  | string | 本次验证唯一标识，UUID                        |
| `bgImage`    | string | 背景图 Base64（含缺口），前端直接设为 `<img>` src     |
| `sliderImage`| string | 滑块图 Base64（缺口裁切块），前端直接设为 `<img>` src   |
| `sliderY`    | number | 滑块纵坐标（px），前端渲染滑块时以此定位垂直位置            |

#### `POST /auth/captcha/verify`

> 无需认证（permitAll），验证滑块位置。

**Request:**

```json
{
  "captchaId": "uuid-xxx",
  "x": 168
}
```

| 字段          | 类型     | 说明                      |
|-------------|--------|-------------------------|
| `captchaId` | string | 之前生成的 captchaId        |
| `x`         | number | 用户拖动停止时的 x 坐标（整数 px）  |

**Response 200（验证通过）:**

```json
{
  "code": "0",
  "data": {
    "captchaToken": "one-time-token-xxx"
  }
}
```

**Response 200（验证失败）:**

```json
{
  "code": "400",
  "message": "验证失败，请重试"
}
```

### 2.3 Redis 存储设计

使用 `StringRedisTemplate` 存储两个 key：

| Key 格式                                    | Value               | TTL   | 用途         |
|-------------------------------------------|---------------------|-------|------------|
| `captcha:pos:{captchaId}`                 | `"{\"x\":168}"`     | 2 min | 生成时存入正确 X 坐标 |
| `captcha:token:{captchaToken}`            | `"verified"`        | 5 min | 验证通过后存入，登录时消费 |

- 生成时写入 `captcha:pos:{id}`，TTL 2 分钟
- 验证时读取并删除 `captcha:pos:{id}`（一次性），比对 X 坐标
- 容差：`|submittedX - correctX| <= 5` 视为通过
- 通过后写入 `captcha:token:{token}`，TTL 5 分钟
- 登录时读取并删除 `captcha:token:{token}`（一次性）

### 2.4 图片生成算法

使用 Java `BufferedImage` + `Graphics2D` 绘制：

1. **背景图**（320 × 160 px）：
   - 随机生成渐变色背景（每次不同色系）
   - 叠加随机几何图案（圆形、三角形、线条等）增加复杂度
   - 在随机位置挖一个 44 × 44 px 的拼图形状缺口（带凸起/凹陷边缘）

2. **滑块图**（44 × 44 px）：
   - 从背景图对应位置裁切出拼图块形状
   - 加半透明描边，使滑块看起来更立体

3. **缺口**：
   - 在背景图缺口位置填充深色半透明遮罩（让用户能看到缺口在哪）

> 由于选择了纯色/渐变底图，不需要真实图片文件，每次调用都是动态生成。

### 2.5 登录接口改造

#### `LoginReq` 增加字段

```java
public record LoginReq(
    @NotBlank String tenantCode,
    @NotBlank String username,
    @NotBlank String password,
    @NotBlank String captchaToken  // 新增：滑动验证 token
) {}
```

#### `AuthApplicationService.login()` 增加校验

```java
public LoginVO login(LoginReq req) {
    // 1. 先校验 captchaToken
    captchaService.consumeToken(req.captchaToken());

    // 2. 原有租户/用户/密码验证逻辑不变
    ...
}
```

`consumeToken()` 逻辑：
- 从 Redis 读取 `captcha:token:{captchaToken}`
- 不存在则抛异常「验证码已过期，请重新验证」
- 存在则删除（一次性消费）
- 继续后续登录流程

### 2.6 Security 放行

`SecurityConfig` 中增加拼图接口白名单：

```java
.requestMatchers(HttpMethod.GET, "/auth/captcha/generate").permitAll()
.requestMatchers(HttpMethod.POST, "/auth/captcha/verify").permitAll()
```

### 3.2 API 层新增

```typescript
// types/api.ts
export interface CaptchaGenerateVO {
  captchaId: string;
  bgImage: string;       // Base64 data URL
  sliderImage: string;   // Base64 data URL
  sliderY: number;
}

export interface LoginReq {
  tenantCode: string;
  username: string;
  password: string;
  captchaToken: string;  // 新增
}

// api/auth.ts
export function generateCaptcha() {
  return unwrap<CaptchaGenerateVO>(apiClient.get('/auth/captcha/generate'));
}

export function verifyCaptcha(captchaId: string, x: number) {
  return unwrap<{ captchaToken: string }>(
    apiClient.post('/auth/captcha/verify', { captchaId, x })
  );
}
```

### 3.3 SliderCaptcha 组件

**Props：**

```typescript
interface SliderCaptchaProps {
  onSuccess: (captchaToken: string) => void;  // 验证通过回调
  onClose: () => void;                         // 关闭弹窗回调
}
```

**组件行为：**

1. 挂载时调用 `generateCaptcha()` 获取拼图数据
2. 渲染：
   - 背景图区域（320×160），缺口位置可见
   - 滑块图（44×44），绝对定位在 `sliderY` 处
   - 底部滑动条，含拖拽手柄
3. 用户拖拽滑动条：
   - 滑块跟随水平移动
   - 滑动条显示「向右拖动完成验证」提示
4. 松手时调用 `verifyCaptcha(captchaId, x)`
   - 成功：显示绿色 ✓ + 「验证成功」，延迟 300ms 后回调 `onSuccess(captchaToken)`
   - 失败：抖动动画 + 红色 ✗ + 「验证失败」，自动重新生成拼图
5. 支持点击刷新按钮手动换一张

**交互细节：**

| 状态     | 滑块轨道颜色 | 滑块图标    | 提示文字        |
|--------|--------|---------|-------------|
| 初始     | `#e8e8e8` | `→` 箭头  | 向右拖动完成验证    |
| 拖拽中   | `#1890ff` | `→` 箭头  | 松开鼠标进行验证    |
| 验证成功  | `#52c41a` | `✓`     | 验证成功        |
| 验证失败  | `#f5222d` | `✗`     | 验证失败，请重试    |

### 3.4 AuthGate 改造

```typescript
// 伪代码，展示改造要点

const [captchaVisible, setCaptchaVisible] = useState(false);
const [pendingLogin, setPendingLogin] = useState<LoginFormValues | null>(null);

// 点击登录时：不直接调 login()，而是打开拼图弹窗
const handleFormSubmit = (values: LoginFormValues) => {
  setPendingLogin(values);
  setCaptchaVisible(true);
};

// 拼图验证通过后：附加 captchaToken 发起登录
const handleCaptchaSuccess = (captchaToken: string) => {
  setCaptchaVisible(false);
  if (pendingLogin) {
    loginMutation.mutate({ ...pendingLogin, captchaToken });
    setPendingLogin(null);
  }
};

return (
  <>
    {/* 原有登录表单 */}
    <Form onFinish={handleFormSubmit}>...</Form>

    {/* 拼图验证弹窗 */}
    <Modal open={captchaVisible} onCancel={() => setCaptchaVisible(false)}
           footer={null} title="安全验证" width={380} destroyOnClose>
      <SliderCaptcha
        onSuccess={handleCaptchaSuccess}
        onClose={() => setCaptchaVisible(false)}
      />
    </Modal>
  </>
);
```

## 4. 安全措施

| 威胁        | 防御手段                                         |
|-----------|----------------------------------------------|
| 暴力猜测缺口位置 | 容差仅 ±5px，captchaId 一次性消费，6 次验证失败后自动失效        |
| 重放 captchaId | Redis key 读取后立即 DEL，不可复用                     |
| 跳过验证直接登录  | LoginReq.captchaToken 为 @NotBlank，后端登录时校验并消费 |
| Token 过期  | `captcha:token:*` TTL 5 分钟，超时自动失效            |
| 接口滥用      | 生成接口限制同一 IP 每分钟最多 6 次（一期暂不实现，后续用 Redis 滑动窗口加约 15 行代码即可） |

## 6. 注意事项

1. **Redis 依赖**：本方案依赖 Redis 存储验证码状态。如本地开发环境无 Redis，可降级为 `ConcurrentHashMap` + 定时清理（5 分钟扫描过期 key）
2. **Base64 大小**：320×160 PNG 约 15-30 KB，滑块 44×44 约 2-5 KB，传输开销可忽略
3. **不影响现有 API 合同**：仅 `LoginReq` 增加一个必填字段，其他接口不变
4. **考评端复用**：`AuthGate` 的 `mode='assessor'` 也会走同样的拼图流程，无需额外适配
5. **后续扩展**：如需增加「点选文字」等更复杂验证码，可在 `auth/captcha/` 包下扩展，不影响登录主逻辑
6. **IP 限流（后续实现）**：采用 Redis 滑动窗口方案，新增 key `captcha:rate:{ip}` + TTL 60s，每次生成 +1，超过 6 次拒绝。约 15 行代码，不引入新依赖
