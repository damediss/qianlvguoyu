# 千铝工投云平台与智能体开发部部门风险与负面行为管理细则

制度编号：QLGT-BMGL-2026-004　　版本：V1.0　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为划定部门核心负面行为清单，重点管控代码事故、系统漏洞、模型故障、业务数据泄露、技术资料泄密、工作推诿甩锅、仅传消息不闭环确认、脱岗离岗、违规操作服务器等行为，明确违规分级处置、重大事故一票否决情形及整改追责流程，特制定本制度。

**第二条**　本制度管"行为"，不管"事故结果"：事故本身按故障制度走复盘改进（聚焦流程与系统，不追责个人）；行为违规按本制度处置。同一事件两套评价并行，不互相替代——复盘报告不作为纪律处分依据，纪律处置也不替代复盘。

## 第二章　负面行为清单

**第三条**　负面行为分四类：

| 类别 | 行为 | 示例 |
|---|---|---|
| 安全数据类 | 数据泄露、资料泄密、违规操作服务器 | 生产数据外发、密钥提交仓库、绕过跳板机直连生产、未审批执行生产 DDL |
| 工程质量类 | 代码事故、系统漏洞、模型故障 | 未经评审改核心链路、带病上线、跳过自测提测、AI 输出未校验直接使用 |
| 协作纪律类 | 推诿甩锅、仅传消息不闭环确认、脱岗离岗 | 告警认领后失联、任务到期不反馈、值班期间脱离响应 |
| 诚信类 | 隐瞒事故、编造数据、编造记录 | 瞒报故障、补记台账、代签验收 |

## 第三章　违规分级与处置

**第四条**　违规分三级：

| 级别 | 界定 | 处置 |
|---|---|---|
| 一般违规 | 首次发生、未造成实际影响、及时纠正 | 部门内通报纠正，记入个人档案 |
| 严重违规 | 造成 P1 级影响，或一年内二次一般违规 | 书面检讨 + 当期绩效降档 + 限期整改 |
| 重大违规 | 造成数据泄露或 P0 级影响，或瞒报编造 | 一票否决当期绩效，上报公司按员工手册处置 |

**第五条**　一票否决情形（发生即否决当期全部绩效，并按第四条重大违规处置）：

1. 业务数据泄露或技术资料泄密；
2. 安全违规事件（红线指标，附录 A 丁档）；
3. 故意隐瞒事故或编造数据、编造记录；
4. 未经审批对生产环境执行破坏性操作且造成损失。

**第六条**　故障响应期间的应急处置行为不视为违规：为恢复服务采取的紧急操作（重启、回退、扩容），事后 24 小时内补变更单即可；先恢复、后定责的原则适用于本制度。

## 第四章　整改追责流程

**第七条**　流程：发现（自查、互查、周检表、告警）→ 定级（部门负责人确认，涉安全数据的同步定安全事件）→ 处置 → 整改（措施 + 期限）→ 复核 → 销号。全程记入个人工作档案。

**第八条**　整改期一般不超过 2 周；逾期未整改的升级处置一级。整改情况在月度复盘会通报。

**第九条**　处置决策由部门负责人作出；涉及部门负责人本人的，上报公司分管领导处置。

## 第五章　附则

**第十条**　本制度由部门负责人负责解释，自发布之日起施行。
