# 确认名单 + 排班表按工种/等级自动分班方案

> 文档版本：v1.0  
> 编写日期：2026-07-20  
> 关联：`名单排班自动分班方案.md`、`分班主路径改为排班表驱动改造方案.md`  
> 状态：待确认后实施（本文档阶段不动代码）  
> 目标：用企业确认回传的筛选名单与排班表，按**工种 × 等级**生成稳定培训班草稿，经机构编辑与企业审核后建班  

---

## 1. 背景与问题

现网分班主路径已具备：

- 材料：三年规划 `status=4` + 企业回传**筛选名单** + **排班表**
- 流程：`auto-pack` → `train_division_pack_task` 草稿 → 机构编辑 → 企业审核 → 通过后物化 `train_info_class` / `train_people_list`
- 默认策略：`by_shift_team`（按生产班组/倒班类型切班 ≤50）

业务诉求进一步明确为：

> 用（确认名单 + 排班表），**按工种和等级**分班。

与现网默认「按班组」不一致；与可选策略 `by_job_level_slot`（工种×等级×每天上下午时段班）也不同——后者会拆出大量「上午 N 班 / 下午 N 班」，班级语义是时段编组，不是稳定开班名册。

本方案定义新策略 **`by_job_level`**：主分组为工种×等级，排班仅作约束/补全，**不**按日拆时段班。

---

## 2. 产品定义

### 2.1 一句话

名单定「谁」以及「工种/等级」；排班表约束能不能上课；系统按 **工种 × 等级** 打包成每班不超过 50 人的稳定培训班草稿，审核通过后再建班。

### 2.2 输入材料

| 材料 | 来源 | 作用 |
|------|------|------|
| **筛选后培训名单** | 企业回传 `enterprise_roster_file` | 待分人员池；提供工种、等级、身份证等 |
| **排班表** | 企业回传 `enterprise_shift_file` | 可上课日过滤；可选补全班组（本策略不用于主分组） |

### 2.3 产出

| 阶段 | 产出 |
|------|------|
| 一键分班 | `train_division_pack_task`（`status=draft`），班级 JSON 含学员 |
| 机构编辑 / 提交 | `draft` → `pending` |
| 企业通过 | 物化 `train_info_class` + `train_people_list`（已确认） |
| 企业驳回 | `rejected`，机构可改后再提 |

### 2.4 非目标（本方案不做）

- 不按「每天上午/下午能不能上课」拆大量时段班（属 `by_job_level_slot` / L2）
- 不按生产班组作为主分组（属 `by_shift_team`，保留为备选）
- 不改变企业审核通过后才建班的闭环

---

## 3. 与现网策略对照

| 维度 | `by_shift_team`（现默认） | `by_job_level_slot`（现可选） | **`by_job_level`（本方案）** |
|------|---------------------------|------------------------------|------------------------------|
| 主分组 | 班组 / 倒班类型 | 工种×等级 × 上午/下午算法班 | **工种 × 等级** |
| 排班作用 | 补全班组 + 可上课过滤 | 完整按日上下午拆班算法 | **可上课过滤为主**；不拆时段班 |
| 班级示例 | `来铝-一班-1班` | `电工-高级-上午1班`（班很多） | `来铝-电工-高级-1班` |
| 同人多班 | 否 | 是 | **否** |
| 班额 | ≤50 切块 | 算法班额 + 再切 | ≤50 切块 |

---

## 4. 总体流程

```
规划 status=4 + 名单 + 排班齐套
  → 确保 / 复用 train_info_list
  → 按当前企业名单重解析 → train_plan_roster（待分池）
  → 排班轻量画像（可上课日等）
  →【新】by_job_level：按 (工种, 等级) 分组 → 每组按 classMax 切块
  → 写入 train_division_pack_task（draft）
  → 机构编辑 → 提交企业审核（pending）
  → 企业通过 → 物化培训班 + 学员
```

## 5. 分组与切班规则

### 5.1 分组键

| 字段 | 来源 | 说明 |
|------|------|------|
| 工种 | `train_plan_roster.job_name`（名单解析） | 表头识别：工种 / 职业 / 岗位 |
| 等级 | `train_plan_roster.level_name` | 表头识别：等级 / 级别 / 技能等级 |

分组键：`{jobName}|{levelName}`（展示为 `工种-等级`）。

### 5.2 缺字段策略（建议默认）

| 配置 | 建议默认 | 行为 |
|------|----------|------|
| `requireJobAndLevel` | **true** | 工种或等级缺失 → 进入「未分入」，原因标明 |
| `requireJobAndLevel=false` | 可选 | 缺失归入 `未填工种` / `未填等级`，仍可成班 |

推荐默认 **true**，避免「未填工种-未填等级」糊成超大混合班。

### 5.3 排班约束

| 项 | 行为 |
|----|------|
| `useShiftFilter=true`（默认） | 当月几乎无可上课日（全夜/全休等）→ 未分入 |
| 班组字段 | 可展示、可写回名单；**不参与**本策略主分组 |
| 排班解析失败 | 警告 + 关闭过滤；仍可按工种×等级分班（或按产品改为硬失败） |

### 5.4 班额与命名

| 项 | 建议 |
|----|------|
| `classMax` | 默认 **50**；尾班可少于 50 |
| 不同工种 | **不混班** |
| 不同等级 | **不混班** |
| 班级标题 | `{前缀}{工种}-{等级}-{序号}班`，如 `来铝-电工-高级技师-1班` |
| sanitize | 去掉路径非法字符；等级过长可截断展示 |

### 5.5 去重与排除

1. 名单内身份证重复 → 未分入（保留一条）  
2. 已在该 `train_info` 学员表中 → 未分入  
3. 可选：无身份证排除（`excludeNoIdCard`）  

### 5.6 培训年份（建议一并约束）

| 项 | 说明 |
|----|------|
| 排班年 / 月 | 继续用于解析**排班表**对应年月 |
| 名单年份 | 若解析出 `plan_year`（如明细表 `明细_2026`），分班应按所选培训年过滤 |
| 不一致 | 该年无人 → **报错**，禁止把其他年份人员误分进班 |

> 说明：此前「排班年选 2025 仍能分班、但名单无 2025 人」的问题，根因是年月只作用于排班解析、未过滤名单。本方案要求补齐年份门禁。

## 6. 后端设计

### 6.1 策略扩展

在现有 `POST /training/division/auto-pack` 增加：

```text
strategy = by_job_level
```

请求示例：

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "strategy": "by_job_level",
  "classMax": 50,
  "classNamePrefix": "来铝-",
  "useShiftFilter": true,
  "requireJobAndLevel": true,
  "year": 2026,
  "month": 4,
  "autoParseRoster": true
}
```

### 6.2 核心逻辑（伪代码）

```
parseRoster(最新企业名单)   // 禁止静默回退 plan_item
loadShiftProfiles(year, month)  // 可选失败降级
filter(assignable)             // 证号、已入班、可上课、requireJobLevel
group by (jobName, levelName)
for each group:
  sort by name
  chunk by classMax
  emit draft class { title, group, members }
save pack_task status=draft
```

### 6.3 复用与不改动

| 模块 | 处置 |
|------|------|
| `train_division_pack_task` 草稿 / 提交 / 企业确认物化 | **复用** |
| `TrainShiftProfileService` | **复用**过滤 |
| `ScheduleAlgorithmService`（L2 按时段拆班） | **本策略不调用** |
| `by_shift_team` / `by_roster_order` / `by_job_level_slot` | **保留**，文案区分 |

### 6.4 DTO 建议增量

`TrainDivisionAutoPackReq` 增加：

- `requireJobAndLevel`（Boolean，默认 true）

其余字段沿用现有 `classMax` / `year` / `month` / `useShiftFilter` 等。

## 7. 前端设计

### 7.1 策略选项（建议文案）

| 值 | 展示名 | 说明 |
|----|--------|------|
| `by_job_level` | **按工种/等级切班（推荐）** | 本方案；建议改默认 |
| `by_shift_team` | 按班组/倒班切班 | 现网默认，改为备选 |
| `by_job_level_slot` | 工种/等级 + 上下午时段（高级） | 班会很多，谨慎使用 |
| `by_roster_order` | 按名单顺序切班 | 最简兜底 |

辅助文案：

> 按名单中的工种与等级分班；排班表用于过滤当月不能上课人员，不按班组拆班。企业审核通过后才会创建培训班级。

### 7.2 结果页

- 班级列表展示：班名、工种、等级（可从 `group` 解析）、人数 / 班额进度  
- 未分入列表展示原因（缺工种、缺等级、无可上课日等）  
- 编辑/提交/企业审核交互不变  

### 7.3 配置项

- 「排班年 / 月」：标注为「用于解析排班表」；若启用名单年份过滤，另提供「培训年份」或与排班年对齐并校验

## 8. 数据与验收

### 8.1 落库路径

```
train_three_year_plan
  → train_info_list
      → train_division_pack_task（by_job_level / draft→pending→materialized）
          →（通过后）train_info_class（nums≤classMax）
              → train_people_list
```

### 8.2 验收用例

| ID | 场景 | 期望 |
|----|------|------|
| J01 | 电工·高级 80 人 | 2 班（如 50+30），班名含电工与高级，不混其他工种等级 |
| J02 | 电工·高级 40 + 电工·中级 40 | 2 班，不混等级 |
| J03 | 电工·高级 40 + 钳工·高级 40 | 2 班，不混工种 |
| J04 | 缺工种或缺等级（require=true） | 进未分入 |
| J05 | 排班显示全月不可上课 | 进未分入（过滤开启时） |
| J06 | 名单有 plan_year=2026，分班选 2025 | 报错或该年池为空，不分错年人 |
| J07 | 企业审核通过 | 仅此时创建培训班；班级已确认 |
| J08 | 同身份证 | 同一培训信息下不进两个班（本策略） |

## 10. 实施前决策项

请确认后实施：

1. **是否将默认策略改为 `by_job_level`？** → 建议 **是**。  
2. **缺工种/等级**：进未分入（推荐）还是进「未填」班？ → 建议 **未分入**。  
3. **排班**：仅过滤可上课，是否还要在结果中展示班组？ → 建议 **展示但不分组**。  
4. **`by_job_level_slot`（时段班）**：保持高级可选，还是本期隐藏？ → 建议 **保留可选、默认不选**。  
5. **培训年份与排班年**：是否强制一致并过滤名单？ → 建议 **是**（避免错年分班）。
