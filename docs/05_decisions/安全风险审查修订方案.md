## 2. 第一批（止损）

### 2.1 P0-1 租户一致性校验（零例外）

- **改动**：新增 `security/filter/TenantConsistencyFilter`，注册进主安全链 `addFilterAfter(SaTokenBridgeFilter.class)`。
  - 逻辑：存在认证主体（PlatformUserPrincipal / App 学生主体）且 `TenantContextHolder.getTenantId()` ≠ 主体租户 → 403（统一 `{code,message,data}`）；无主体的匿名白名单请求直接放行。
  - `TenantContextFilter` 保持兜底不改（它执行最早，拿不到主体）；AppTokenAuthFilter 在链内，App 链路自动覆盖。
- **配套**：集成测试 3 个——A 用户带 B header → 403；A 用户带 A header → 正常；匿名白名单路径 → 正常。
- **主体类型兼容**：链内主体不止 PlatformUserPrincipal——AppTokenAuthFilter（App 学生）、CompetitionExamTokenBridgeFilter / CompetitionPlayerTokenBridgeFilter（竞赛选手/考评）也会设主体，比对逻辑须按通用方式取 principal 的 tenantId，避免竞赛链路被误伤（用例见 §8.1）。
- **上线前数据核对**（App/小程序 SaaS 通道依赖，SQL 见 §8.0 T0）：两端恒发 `X-Tenant-Id: 10159`，活跃 token 用户的 `platform_user.tenant_id` 必须与其一致，否则校验一上线这些用户全部 403。
- **上线后**：用两个真实租户账号做一次跨租户读写实测再关闭本项。

### 2.2 P0-5 文件接口收紧

- `SecurityConfig`：`/files/**` 由不限方法 permitAll 改为需认证；`GET /exam/files/**` **保持匿名不动**（证件照 `<img>` 直链依赖，单独决策）。
- `FileController`：上传两端点加 `file:upload` 权限码、删除加 `file:delete`；权限种子走三步链（菜单 → 权限码 → `sys_role_permission`，tenant_id=10159），新迁移取号先查两库 `MAX(version)`。
- `FileApplicationService.getTenantIdSafe()` 删除 0 兜底，未认证 → 401。
- 下载 / download-url / 元数据三个读端点补 `@AuditLog`（P2-6 并入）。
- 存量 `tenant_id=0` 文件：先 SELECT 出清单再定归属或删除。
- **兼容性已核实（2026-09-22 逐文件核对两客户端仓库）**：gjjd_appnext 与 wxmini-gjjd **全工程 0 处调用 `/files`**（上传走 PHP `/upload` 与 `/training/sign-ups/upload`，图片走 CDN 直链或带 header 的业务端点），admin-web 全走 apiClient blob / `downloadUrlFile`——收紧后三者均不受影响。App 端 `download-url` 对接由"必要前置"降为"未来按需"（见 §7.1）。
- **测试**：匿名上传 401/403；认证上传/下载/删除正常；跨租户下载 404；无权限码用户上传 403。

### 2.3 P1-12（提级）OnlyOffice 回调面

- **现状**（用户问题 6 的答复）：OnlyOffice 用于培训补贴工作台的材料 DOCX 在线编辑（`DocxOfficeEditor`）。前端先调 `office-config`，后端 `buildEditorConfig` 检查 `platform.onlyoffice.enabled`，未启用即返回 disabled 提示——生产未部署 Document Server 且未配置，**在线编辑生产不生效**，代码是本地联调形态（`docker-compose.onlyoffice.yml` 本机起文档服务器）。**但 `handleCallback` 不检查 enabled**：permitAll 下回调生产仍可达，`jwtEnabled=false` 零验签，body `status=2/6` 即拿其中的 `url` 下载并保存新版本（SSRF + 未授权写入，仅靠雪花 ID 难猜挡着）。
- **修复**：
  1. `handleCallback` 与 `/office/files/{fileId}` 在 `enabled=false` 时直接拒绝（404）；
  2. 删除 `signDownloadToken/verifyDownloadToken` 的硬编码 dev secret 兜底，改为未配置即 fail-fast；
  3. （将来启用时）配 `ONLYOFFICE_JWT_ENABLED=true` + 随机 SECRET，Document Server 容器同步；回调 body 的 `url` 加 host 白名单（只允许 `document-server-url` 的 host）。
- **测试**：enabled=false 回调 404；jwtEnabled=true 缺 token 401；url 白名单外拒绝。

### 2.4 P1-1 CORS 收口（生产正在发生）

- **配置侧（立即，不需发版）**：生产外置配置显式设置 `platform.cors.allowed-origins`，值必须包含：`https://java.app.gjjd168.com`（admin-web）**+ gjjd_appnext 的 H5 部署源（收紧前必须确认，仓库内未硬编码，见 §7.2-C3）**。重启生效。
- **不受 CORS 影响的形态**：gjjd_appnext 原生壳（plus.runtime 本地资源发原生请求）与微信小程序原生请求不走 CORS；仅浏览器 H5 形态跨域调 SaaS 依赖放行。
- **代码侧**：`CorsConfig` 未配置时的 dev 兜底从 `*` 收窄为仅 localhost/127.0.0.1 + warn 日志。
- **服务器侧**：生产 nginx 删除 OPTIONS 预检块里的 `Access-Control-Allow-Origin: *`，交由后端统一控制。
- **测试**：配置后仅该域名可带凭证跨域；未配置时 localhost 可用、外域不可用。

## 3. 第二批（防线）

### 3.1 P1-3 登录失败锁定（只做 B，验证码保持关闭）

- Redis 计数 key `login:fail:{tenantCode}:{username}`，5 次失败锁 15 分钟；锁定中返回业务白话文案（"尝试次数过多，请稍后再试"）；成功登录清零；失败与锁定写审计日志。
- **测试**：5 次失败 → 锁定；锁定中正确密码也拒绝；TTL 到期解锁；成功清零。

### 3.2 P1-8 StudentDetailPage 消毒

- `HtmlBlock` 接入 `sanitize-html`（复用 `RichTextEditor` 的 `sanitizeRichTextHtml` 或 `sanitizeExamHtml`），覆盖题干/选项 2 个调用点。

### 3.3 P1-5 WebSocket origin 白名单

- 三处 WebSocketConfig 的 `setAllowedOriginPatterns("*")` 改读配置 `platform.websocket.allowed-origins`（默认 `https://java.app.gjjd168.com` + localhost）；ticket 经 URL query 传递的泄露面（日志/Referer）记 backlog。

### 3.4 P1-7 xlsx → exceljs

- **测试**：人员证书 Excel 导入/导出回归（真实文件对拍）。

### 3.5 P1-9 测试开关收紧

- `permit-test-apis` 仅在非 prod profile 可启用；prod profile 下即使 env 为 true 也强制忽略并 warn。

### 3.6 P1-10 大文件口径（保持 1GB）

### 4.3 密钥轮换收尾（用户轮换完成后执行，口径 #7）

- `application.yml` 敏感默认值全部占位化，prod profile 缺失即启动失败（fail-fast）；
- `outputs/config/backend.env` `git rm --cached` + 加入 `.gitignore`（其中 MYSQL_PASSWORD/JWT_SECRET 是独立值，轮换清单要包含）；
- `deploy/application-prod.yml`（本地未跟踪，含 Redis 明文密码默认值）占位化后才允许入库；

### 4.4 CI 卡口

- gitleaks 密钥扫描 + npm audit / OWASP dependency-check 进 CI。

### 4.5 COS 预签名直传上传

- 与已上线的下载预签名同一思路：`FileStorage` 加 `presignedUploadUrl`（PUT），浏览器/App 直传 COS，Java 只签发 + 落元数据；1GB 文件不过服务器，顺带消掉上传 120s 超时风险；旧中转端点保留兼容，分期切换。

### 4.6 Backlog（记录，不实施）

- token localStorage → HttpOnly Cookie 方案评估；

- P1-11 DB 传输加密（确认走内网/VPC 后关闭；公网则排期 TLS）；
- P2-7 CSRF 结论文档化：Bearer token API 链可接受关闭，AS 链为框架默认开启。

## 7. App（gjjd_appnext）与微信小程序（wxmini-gjjd）影响评估

> 2026-09-22 对两个客户端仓库逐文件静态核实（请求封装、上传链路、图片展示、WS、登录）后得出。
