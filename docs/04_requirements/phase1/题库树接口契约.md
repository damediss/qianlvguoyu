# 题库分类导航聚合树接口契约

> 一次返回工种 → 课程 → 知识点 L0~L3 完整树,每节点带 `questionCount` 递归题数 badge。
> 替代前端 `QuestionBankPage` 当前三次串行 lazy-load(工种 → 课程 → 知识点)。

## 基本信息

| 项 | 值 |
| --- | --- |
| Method + Path | `GET /api/exam/question-bank-tree` |
| 鉴权 | `exam:question:view`(`@PreAuthorize` 强校验) |
| 多租户 | 由 MyBatis-Plus `TenantLineInnerInterceptor` 自动注入 `tenant_id` 条件,无手写过滤 |
| 逻辑删除 | `exam_exam_detail` 由 `@TableLogic` 自动过滤 `deleted=1`;`exam_knowledge_structure.status=0` 显式过滤 |
| Content-Type | `application/json; charset=utf-8` |

## 请求

无 Query / Body。租户、用户从 Sa-Token SecurityContext 取。

### 节点字段

| 字段 | 类型 | 必有 | 说明 |
| --- | --- | --- | --- |
| `key` | string | ✔ | 前端 React key。`workType-{id}` / `course-{id}` / `ks-{id}` |
| `id` | int | ✔ | 节点主键(`exam_work_type.id` / `exam_course.id` / `exam_knowledge_structure.id`) |
| `nodeType` | string | ✔ | 枚举:`workType` / `course` / `knowledge` |
| `title` | string | ✔ | 展示名;course 节点会自动拼上 `(X级)` 后缀 |
| `sortNumber` | int | ✔ | 排序号,小到大 |
| `status` | int | ✘ | workType/course 不返回;knowledge 节点返回业务状态(0=停用,1=启用) |
| `level` | int | ✘ | 仅 knowledge 节点(0/1/2/3) |
| `workTypeId` | int | ✘ | 仅 course 节点 |
| `courseId` | int | ✘ | 仅 knowledge 节点 |
| `questionCount` | long | ✔ | **递归题数** = 自身 L3 节点挂载的题数 + 所有后代节点的题数 |
| `children` | array | ✔ | **永远数组**,空叶节点是 `[]`,**不会**是 `null` |

### `questionCount` 汇总规则

1. 题目挂载点:`exam_exam_detail.knowledge_id`,必须是非 null 的 L3 知识点。
2. L3 叶子节点:`questionCount` = 该 knowledge_id 下未逻辑删除(`deleted=0`)的 exam_exam_detail 数量。
3. 非叶子节点(knowledge L0~L2、course、workType):`questionCount` = `sum(children[].questionCount)`。
4. 停用知识点(`status=0`)**不进树**,其挂载的题目不计入任何祖先的题数。
5. 逻辑删除的题目(`exam_exam_detail.deleted=1`)**不入统计**。

## 边界场景

| 场景 | 行为 |
| --- | --- |
| 租户无任何工种 | `data: []`(空数组,不是 null) |
| 租户有工种但工种下没课程 | 工种节点 `children: []`,`questionCount: 0` |
| 课程下没知识点 | 课程节点 `children: []`,`questionCount: 0` |
| 知识点 L0~L3 全部有题但其中一段为空 | 中间层级 `questionCount` 自动从后代累加,不会出现 0 但有非空 children |
| 多租户隔离 | 不同 token 拿到的树完全独立,数据不串(由 MP 拦截器保证) |
| 题目 `knowledge_id` 指向不存在的 knowledge | 通过 L3 自查丢弃(L3 ID 不在 knowledgeMap → `l3Count` 不增加,该题不计入) |

## 实现路径

走 **路径 A:一次性全量返回 + Java 后序遍历累加**。

- 4 次 SQL(工种 / 课程 / 知识 / 题目投影),租户规模 < 10k 节点开销可忽略。
- 没有用 MySQL 8 递归 CTE 是为了不破坏现有 MyBatis-Plus `LambdaQueryWrapper` 风格。
- 不需要新加字段或闭包表,无 Flyway 迁移。

## 后续可优化(不阻塞本期)

- 工种/课程/知识点超 10k 节点时,改用闭包表(path 字段)或 MySQL 8 递归 CTE。
- 加 Redis 缓存(租户维度的树,5 分钟失效),减少冷查询。
