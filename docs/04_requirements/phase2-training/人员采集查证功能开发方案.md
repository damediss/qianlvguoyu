## 一、需求摘要

在「人员采集」抽屉页面新增「查证」功能：

1. **入口**：人员采集抽屉的搜索框旁，新增「查证」按钮（**前端已实现**）
2. **数据传递**：将选中人员的 **姓名 + 身份证号** 上传到后端 verify-cert 接口
3. **查询匹配**：后端复用 chazheng 查证引擎，按姓名+身份证调用第三方查证接口
4. **回填字段**：查证完成后，将证书信息回填到 `train_sign_up_people_self` 表对应人员：
   - 已有证书等级（`level`）
   - 证书编号（`paper_no`）
   - 发证日期（`cert_issue_dates`）
   - 多证书 JSON（`certificates_json`）
   - 查证状态（`cert_verified`）
5. **选择方式**：支持 **全选 / 多选 / 单选**（**前端已实现**）
6. **进度反馈**：查证完成后弹出进度结果 Modal（**前端已实现**）
7. **数据匹配**：查出的数据必须与人员精确匹配（按 peopleId 对齐）

## 二、为何不使用 `/api/chazheng/users/import`

> 本章节为 v1.1 新增，澄清与 chazheng 子系统接口的关系。

`/chazheng/users/import` 是 chazheng 子系统自有的「Excel 导入 + 异步批量查证」入口，与企业调研人员采集抽屉的需求**不在同一条业务数据流上**：

| 维度 | `/chazheng/users/import` | 企业调研抽屉查证（本方案） |
|------|--------------------------|------------------------------|
| 入参 | `MultipartFile`（Excel） | `{ peopleIds: number[] }` |
| 数据源 | 新建/更新 `chazheng_user` 表 | 已有 `train_sign_up_people_self` 表 |
| 结果存储 | `chazheng_cert` 表 + `chazheng_user.isCert/isChecked` | 回填 `train_sign_up_people_self` 的 level/paper_no 等 |
| 查询模式 | 异步 + 轮询 `batchId` 进度 | 同步完成弹结果 Modal |
| 关联键 | `chazheng_user.id`（自动生成） | `train_sign_up_people_self.id`（peopleId） |
| 前端是否对接 | ❌ 抽屉页不调用 | ✅ 已对接 verify-cert 路径 |

**结论**：`/chazheng/users/import` 是查证子系统的 Excel 批量入口；抽屉页查证应**复用 chazheng 的查证内核**（调第三方 + 解析响应），而不是直接调用 import 接口。两个接口共存：

- `/chazheng/users/import` → 独立查证管理页的 Excel 批量查证
- `/training/.../verify-cert` → 人员采集抽屉的上下文查证（内部调 chazheng 引擎）

```
未查证 (null)
   │ 点击查证
   ↓
查证中 (0) —— 临时状态（同步接口执行期间）
   │
   ├── 接口返回 found=true → 已查证 (1)
   ├── 接口返回 found=false → 查证无结果 (2)
```

```java
  @Override
  public void migrate(Context context) throws Exception {
    Connection connection = context.getConnection();
    try (Statement statement = connection.createStatement()) {
```

### 6.3 新增 `ChazhengCertQueryService`（抽取查证内核）

**路径**：`services/platform-api/src/main/java/com/guoyu/platform/chazheng/service/ChazhengCertQueryService.java`

> 将 `ChazhengApplicationService.certCheck()` 中「调第三方 + 解析响应」部分抽取为独立服务，按 `(name, idCard, tenantId)` 查询，**不写入 chazheng 表**，返回 `List<CollectedCert>`。

```java
@Service
@Slf4j
public class ChazhengCertQueryService {

  private final CertCheckConfigService certCheckConfigService;
  private final RestTemplate chazhengRestTemplate;
  private final ObjectMapper objectMapper;

  /**
   * 按姓名+身份证查询证书，不落库。
   * 复用 chazheng 的 sys_dict 配置与多模板轮询逻辑。
   */
  public CertQueryOutcome queryByNameIdCard(String name, String idCard, Long tenantId) {
    String apiUrl = certCheckConfigService.findApiUrl(tenantId);
    if (!StringUtils.hasText(apiUrl)) {
      throw new BusinessException(ErrorCode.INTERNAL_ERROR,
          "查证接口未配置(sys_dict: chazheng_url)");
    }
    List<Map<String, Object>> templates = certCheckConfigService.findRequestTemplates(tenantId);
    if (templates.isEmpty()) {
      throw new BusinessException(ErrorCode.INTERNAL_ERROR,
          "查证请求模板未配置(sys_dict: chazheng_datas)");
    }

    CertCheckResult result = new CertCheckResult();
    for (int i = 0; i < templates.size(); i++) {
      Map<String, Object> template = templates.get(i);
      if (template == null) continue;
      Map<String, Object> reqData = new LinkedHashMap<>(template);
      reqData.put("idcode", idCard);
      reqData.put("username", name);
      processOneTemplate(apiUrl, reqData, name, idCard, i, result);
    }
    return new CertQueryOutcome(result.anyNormal, result.anyCertFound, result.certs);
  }

  // processOneTemplate / isBizResponseOk / buildCertName 等
  // 从 ChazhengApplicationService 迁移而来，参数由 ChazhengUserEntity 改为 name+idCard
}

public record CertQueryOutcome(
    boolean anyNormal,       // 任一轮业务正常
    boolean anyCertFound,    // 任一轮查到证
    List<CollectedCert> certs
) {}
```

**抽取原则**：
- `processOneTemplate` / `isBizResponseOk` / `buildCertName` / `getStringOrEmpty` / `getMapOrEmpty` / `logRequestResponse` 从 `ChazhengApplicationService` 迁移到本类
- 参数从 `ChazhengUserEntity user` 改为 `String name, String idCard`（日志文件名按 name+idCard 生成）
- `CollectedCert` 复用既有类（`certNo`, `certName`, `certDate`）

### 6.4 新增 `ResearchCertBackfillService`（字段映射）

**路径**：`services/platform-api/src/main/java/com/guoyu/platform/trainingdepartment/service/ResearchCertBackfillService.java`

> 将 chazheng 的 `CollectedCert` 映射到采集表字段，并更新 `train_sign_up_people_self`。

```java
@Service
@Slf4j
public class ResearchCertBackfillService {

  private final TrainSignUpPeopleSelfMapper peopleMapper;
  private final ObjectMapper objectMapper;

  /**
   * 回填查证结果到 train_sign_up_people_self。
   * @return CertVerifyDetail 供 Controller 组装响应
   */
  @Transactional
  public CertVerifyDetail backfill(TrainSignUpPeopleSelfEntity person,
                                    CertQueryOutcome outcome) {
    CertVerifyDetail detail = new CertVerifyDetail();
    detail.setPeopleId(person.getId());
    detail.setName(person.getName());
    detail.setIdCardNumber(person.getIdCardNumber());

    if (!outcome.anyNormal()) {
      // 全部异常 → 失败
      person.setCertVerified(3);
      detail.setFound(false);
      detail.setErrorMessage("查证请求异常，请重试");
    } else if (!outcome.anyCertFound() || outcome.certs().isEmpty()) {
      // 业务正常但无证 → 无结果
      person.setCertVerified(2);
      detail.setFound(false);
      detail.setErrorMessage("未查到证书信息");
    } else {
      // 查到证 → 回填字段
      List<CollectedCert> certs = outcome.certs();
      CollectedCert primary = pickPrimaryCert(certs);  // 取最高等级或首张
      person.setPaperNo(primary.certNo());
      person.setCertIssueDates(primary.certDate());
      person.setLevel(extractLevel(primary.certName()));  // 文本→1-5
      person.setCertificatesJson(buildCertJson(certs));    // 多证 JSON 数组
      person.setCertVerified(1);
      detail.setFound(true);
      detail.setCertLevel(primary.certName());
      detail.setCertNo(primary.certNo());
      detail.setIssueDate(primary.certDate());
    }
    person.setUpdateTime(LocalDateTime.now());
    peopleMapper.updateById(person);
    return detail;
  }

  /** 从 certName（如"电工_钳工(三级)"）提取等级文本并转 1-5 */
  private Integer extractLevel(String certName) {
    if (!StringUtils.hasText(certName)) return null;

    // 映射: 一级/初级=1, 二级/中级=2, 三级/高级=3, 四级/技师=4, 五级/高级技师=5

  }

  /** 一人多证时取最高等级证书 */

  /** 组装多证书 JSON 数组 */
```

### 6.6 Service 方法

**位置**：`TrainResearchCollectionApplicationService.java`

```java
@Transactional
public CertVerifyBatchResultVO verifyPeopleCertificate(
    Long researchOrgId, List<Long> peopleIds) {

  // 1. 校验 researchOrgId + 批量拉取 people（按 id 过滤，确认属于当前采集批次）
  TrainResearchOrgEntity research = requireResearchOrg(researchOrgId);
  TrainSignUpSelfEntity signUp = requireSignUpById(research.getActiveSignUpId());

  List<TrainSignUpPeopleSelfEntity> people = peopleMapper.selectList(
      new LambdaQueryWrapper<TrainSignUpPeopleSelfEntity>()
          .in(TrainSignUpPeopleSelfEntity::getId, peopleIds)
          .eq(TrainSignUpPeopleSelfEntity::getSignUpId, signUp.getId())
          .eq(TrainSignUpPeopleSelfEntity::getDeleted, 0));

  if (people.isEmpty()) {
    throw new BusinessException(ErrorCode.BAD_REQUEST, "未找到选中的人员");
  }

  Long tenantId = SecurityContext.currentUser().getTenantId();

  // 2. 逐人调用 chazheng 查证引擎（同步，复用 FixedRateLimiter 限流）
  List<CertVerifyDetail> details = new ArrayList<>();
  int verified = 0, notFound = 0, failed = 0;

  for (TrainSignUpPeopleSelfEntity person : people) {
    if (!StringUtils.hasText(person.getName())
        || !StringUtils.hasText(person.getIdCardNumber())) {
      // 姓名或身份证缺失 → 无效
      details.add(buildInvalid(person, "姓名或身份证为空"));
      failed++;
      continue;
    }
    try {
      CertQueryOutcome outcome = chazhengCertQueryService.queryByNameIdCard(
          person.getName().trim(),
          person.getIdCardNumber().trim(),
          tenantId);
      CertVerifyDetail detail = researchCertBackfillService.backfill(person, outcome);
      details.add(detail);
      if (detail.getFound()) verified++;
      else if (outcome.anyNormal()) notFound++;
      else failed++;
    } catch (Exception e) {
      log.error("[verify-cert] 查证失败 peopleId={}, err={}",
          person.getId(), e.getMessage(), e);
      person.setCertVerified(3);
      peopleMapper.updateById(person);
      details.add(buildFailed(person, e.getMessage()));
      failed++;
    }
  }

  return new CertVerifyBatchResultVO(
      people.size(), verified, notFound, failed, "查证完成", details);
}
```

## 八、关键实现要点

### 8.1 人员匹配逻辑

按 `peopleId`（即 `train_sign_up_people_self.id`）对齐，避免同名同身份证的边缘情况：

```java
for (TrainSignUpPeopleSelfEntity person : people) {
    CertVerifyDetail detail = researchCertBackfillService.backfill(person, outcome);
    details.add(detail);
}
```

### 8.2 限流

复用 chazheng 的 `FixedRateLimiter`，配置 `chazheng.batch.rate-limit-per-second`（默认 10 QPS）：

```java
// ChazhengCertQueryService 内部
rateLimiter.acquire();  // 每次调用第三方前限流
```

### 8.3 失败处理

- 单条失败不影响其它人员（try-catch 逐人处理）
- 超时/网络错误 → `certVerified=3`，details 中带 errorMessage
- 姓名或身份证缺失 → 标失败，不调第三方

### 8.4 证书等级文本转数字

chazheng 返回的 `certName` 形如 `电工_钳工(三级)`（来自 `metadata.zymc + gzmc + zyjndj`），需从括号或 `zyjndj` 提取等级文本再转数字：

```java
private Integer extractLevel(String certName) {
    if (!StringUtils.hasText(certName)) return null;
    // 提取括号内文本（zyjndj）
    Matcher m = Pattern.compile("[（(]([^）)]+)[）)]").matcher(certName);
    String levelText = m.find() ? m.group(1) : certName;
    return switch (levelText.trim()) {
        case "一级", "初级"     -> 1;
        case "二级", "中级"     -> 2;
        case "三级", "高级"     -> 3;
        case "四级", "技师"     -> 4;
        case "五级", "高级技师" -> 5;
        default                -> null;
    };
}
```

> 映射规则需与业务方确认（一级=1 / 三级=3 等）。

由于查证为同步返回，"进度"采用 **完成后弹结果 Modal** 的方式：

| 阶段 | UI 表现 |
|------|---------|
| 执行中 | 查证按钮 loading，Table 上方提示 `正在查证 N 人，请稍候...` |
| 完成 | 弹出结果 Modal（总数 / 成功 / 无结果 / 失败 + 可展开查看每条明细） |
| 失败兜底 | 网络异常时单条标失败，仍弹结果 Modal |

> 若后期查证量大（>50 人）耗时较长，可升级为异步任务 + 轮询 chazheng 的 `batchId` 进度（chazheng 批次能力可复用）。现阶段同步足够，与前端 120s 超时一致。

## 十三、与 chazheng 子系统接口对照

| 接口 | 用途 | 是否复用 chazheng 引擎 |
|------|------|------------------------|
| `POST /chazheng/users/import` | 独立查证页 Excel 批量导入 + 异步查证 | ✅ chazheng 自有流程 |
| `POST /chazheng/users/{id}/cert` | 单个 chazheng_user 查证 | ✅ chazheng 自有流程 |
| `POST /training/.../collection/people/verify-cert` | 人员采集抽屉上下文查证 | ✅ 内部调 `ChazhengCertQueryService` |

三个接口共存，各司其职。抽屉页查证接口**不复用** `/chazheng/users/import`，但**复用** chazheng 的查证内核（`sys_dict` 配置 + 多模板轮询 + 响应解析）。
