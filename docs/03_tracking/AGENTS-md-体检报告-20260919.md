### 9.2 对 §7.1 的修正：局部规则用子目录 AGENTS.md 承载

原方案把下沉内容全部放 `docs/agent/*.md`。问题在于：**`docs/` 下的 md 不会被任何 Agent 工具自动加载**，Agent 只有读到导航链接并主动打开才生效——这与「每轮必读规则」的诉求不匹配，链接一断就成死文档。

修正为两类载体：

- **局部规则**（前端规则、后端分层约束、DB 规则、异步陷阱、LLM 接入规范）→ **子目录 `AGENTS.md`**：
  - `apps/admin-web/AGENTS.md` —— 前端规则全部（HTTP 错误处理 / 登录态 / 多租户 header / TanStack Query / ProTable 等）
  - `services/platform-api/AGENTS.md` —— 后端分层约束、数据库规则、异步与多租户陷阱、LLM 接入规范
  - 机制依据：Codex 会从仓库根目录一路读到当前工作目录，**越靠近代码的规则优先级越高**（根目录是"共同宪法"，子目录是"地方条例"）；Claude Code 对子目录 `CLAUDE.md` 有同等的按需加载。规则贴着代码放，被触达的概率远高于放 `docs/`。
  - 工具差异要在根文件导航段写明：Codex / Claude Code 自动加载子目录文件；Cursor 走 Rules、Qoder 走 `.qoder` 引用——对这两类，根 AGENTS.md 保留一行指针（如"前端任务先读 `apps/admin-web/AGENTS.md`"）。
- **参考资料**（踩坑库、项目现状快照、多 Agent 协作协议、本地环境）→ 仍按原方案放 `docs/agent/`。这类是"按需查阅"而非"每轮必读"，不自动加载可以接受。

### 9.3 新增：修订后的验证流程

修订落地不是改完文件就结束。采纳 Astra 文与 Codex 文的方法，定为四步：

1. **Candidate 先行**：新 AGENTS.md 先存为候选（分支或 `AGENTS.md.next`），不直接覆盖现役文件。
2. **复述验证**：开新会话让 Agent "列出你加载的指令来源并总结有效规则"，确认三点：① 加载了正确的文件；② 子目录规则覆盖生效；③ 关键边界（密钥 / 迁移版本号 / 异步 SecurityContext / 软删）无遗漏、无截断。
3. **行为 A/B**：挑 3 个高频真实任务（新增 Flyway 迁移、改一个前端页面、改一个导出功能），分别用原版与 Candidate 各跑一次，对比安全边界、多 Agent 协作、授权/确认逻辑无退化。
4. **正式采用单独提交**：验证通过后单独一个 commit 替换，message 注明行为对比结论；不在 A/B 过程中顺手切换。

### 9.4 不采纳项（Da1sypetals 风格）

- **处罚修辞**（"毁灭性打击""严重惩罚"）、**逐字禁用汉字表**、**"你只是一个工具"式身份贬抑**：不适合团队共享文件——这份文件同时是新人 5 分钟上手的项目规范浓缩版，威胁修辞对人不可读；也无证据表明处罚语气提升遵循率。
- 可借鉴且已覆盖的：**预防性条款**（针对模型常犯错误预设禁令）= 本项目踩坑库 26 条正是这个思路；"规则违反无例外"的表述强度 = 现有 Never / 禁止类条款已体现。

### 9.6 体量依据补强
