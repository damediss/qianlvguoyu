# 国家职业技能标准 → 理论知识考评要素细目表 生成功能实现方案

> 版本：v1.0　日期：2026-08-12
> 需求方拍板记录（2026-08-12）：① 叶节点（考评点）= **LLM 概括 + 人工审核**；② 功能形态 = **管理端页面全流程**（上传 docx → 解析预览 → 人工编辑 → 确认导出）；③ 重要程度 X/Y/Z = **LLM 建议 + 人工审核**；④ 多方向工种（焊工 4 方向）= **每方向独立课程树**
> 参考材料：`docs/osta-standards/`（DOCX转Markdown转换指南.md、矿山救护工.docx、焊工标准.docx、知识结构生成材料/ 三份样例 md + 细目表 xlsx）

## 1. 背景与目标

将国家职业技能标准 docx 中的**基本要求**（编号段落）与**工作要求**（4 列表格）解析为结构化知识树，经 LLM 概括叶节点（考评点）+ 人工审核后，产出两类交付物：

1. **知识树入库 SQL**：`exam_work_type` / `exam_course` / `exam_knowledge_structure` 的 INSERT 语句（父子层级、编码、重要程度），目标为 PHP 库（`gjjddb`，tenant_id=10159），由运维执行；
2. **理论知识考评要素细目表 Excel**：按等级×方向导出，版式对齐样例 `11_矿山救护工_初级工_细目表_主观_20260812171129.xlsx`（Sheet1）。

**为什么不直接写 PHP 库**：SaaS 对 PHP 库的既有架构约束是"只读 holder + exam_result 仅 INSERT 回写"（鉴权方案 §3.5/AI 同步学 §4.7），直写 PHP 业务表会破坏该边界。产物以 SQL 文件交付、运维执行，全程可审。SaaS 库内的 staging 草稿表仅作解析/编辑载体，不落 `exam_knowledge_structure`。

## 2. 输入/输出结构契约（已逐字段核实）

### 2.1 源 docx 结构（两本标准实测一致）

| 区块 | 形态 | 解析要点 |
|---|---|---|
| 封面/说明/职业概况（1.x） | 段落 | 仅取职业名称、职业编码（如 6-16-01-12）、版本年；其余跳过 |
| **2. 基本要求** | **编号段落**（不在表格内） | `2.1` 职业道德、`2.2` 基础知识 → L1；`2.1.1` → L2；`（1）（2）…` → 叶素材原文。**部分 L2 无列举项**（如矿山救护工 2.1.1）→ LLM 概括补叶 |
| **3. 工作要求**（3.1 五级/初级工 … 3.5 一级/高级技师） | **4 列表格**：职业功能/工作内容/技能要求/相关知识要求 | 表格归属于所在"3.x 等级"节；**含 vMerge 纵向合并单元格**（restart/continue 必须继承）；职业功能 → L1，工作内容 → L2，**相关知识要求**的 `（1）（2）…` → 叶素材原文；技能要求列**不入树**（理论细目表只用相关知识） |
| 4. 权重表（末尾 2 张） | 表格：项目 × 等级（%），焊工为 **方向×等级矩阵** | 取"理论知识权重表"的项目级权重（基本要求/工作要求/各职业功能）；方向列识别（电焊工/气焊工/钎焊工/焊接设备操作工） |
| 干扰项 | `续表` 段落、页脚注（①②）、`6-16-01-12` 职业编码 | 按《DOCX转Markdown转换指南》坑 3/4/5 规则排除 |

### 2.2 目标知识树结构（对齐 `exam_knowledge_structure_矿山救护工初级.md` 样例）

```
L0  基本要求A                     level=0
L0  工作要求B                     level=0
L1    职业道德A-A                 level=1（2.1 → A 段第 1 字母）
L2      职业道德基本知识A-A-A      level=2
L3        工匠精神培养A-A-A-001    level=3 + important=X/Y/Z   ← LLM 概括 + 人工审核
```

- **编码规则**：基本要求=A 段 / 工作要求=B 段；L1 按序取字母 A/B/C…；L2 在 L1 编码后再取字母；L3 在 L2 编码后接 3 位序号（001 起）。编码**内嵌在 title 文本尾部**（如 `遵章守法，安全第一A-A-B-001`），与样例一致。
- **固定列默认值**（按样例）：`use_type=0, type=0, cover/intro 空, series_no NULL, sort_number=100, status=1, deleted=0, amount=10.00, user_id/org_id/org_name 可配置, tenant_id=10159（PHP 口径）, create_time=执行时 NOW()`。
- **字段类型差异（已核实）**：PHP 库 `important` 为 **varchar（X/Y/Z）**；SaaS 同名表为 int（语义不同、未使用）——staging 草稿表按 **varchar X/Y/Z** 存储，对齐 PHP 口径。

### 2.3 细目表 Excel 结构（对齐样例 Sheet1，10 列）

```
第1行：标题「{工种}({等级})理论知识考评要素细目表」（合并整行）
第2-4行：复合表头——考评范围(一级|二级|三级) + 相关知识 + 考评点(代码|名称|重要程度)
数据行（纵向合并单元格）：
  一级: 名称+代码+(X:Y:Z 计数) + 权重      如「基本要求 A（42:8:0）」0.25
  二级: 同上                                如「职业道德 A（10:0:0）」0.05
  三级: 名称+代码+(计数)+考评权重            如「职业道德基本知识 A（4:0:0）」0.02
  相关知识: docx 原文列举项（1.…2.… 换行拼接）
  考评点: 代码 001… | 名称（概括短语）| 重要程度 X/Y/Z
```

## 3. 总体流程

```
上传 docx（存 file 模块，返 fileId）
   │
   ▼
[1] 规则解析（同步，秒级）          ── DocxStandardParser
   骨架树：L0/L1/L2 + 叶素材原文 + 权重表 + 工种方向 + 等级
   │  写入 staging（status=parsed），页面立即可见骨架
   ▼
[2] LLM 概括（异步批处理）         ── 复用 FaqLlmClient + DeepSeek JSON mode
   按 L2 小节逐块调用：概括叶节点标题 + 建议 important(X/Y/Z)
   │  全部落草稿（review_status=pending），ai_generation_draft 留痕
   ▼
[3] 人工审核编辑（页面）            ── 树形表格在线编辑/增删/调整
   │  可单小节「重新生成」；可微调 L1/L2 权重
   ▼
[4] 确认导出（页面按钮）
   ├─ 细目表 Excel（按 等级×方向 逐个 Sheet/文件）
   └─ 入库 SQL 文件（exam_work_type / exam_course / exam_knowledge_structure，PHP 口径）
```

## 4. 系统架构与模块划分

平台内聚在 `platform-api`，**不引新框架、不引新 jar**（docx 读取用既有 `poi-ooxml` 的 XWPF；Excel 写出用 POI SXSSF；LLM 复用 `FaqLlmClient`）：

```
exam/standard/
  controller/StandardParseController.java          // 管理端 /api/exam/standard/**
  service/StandardParseApplicationService.java     // 用例编排（任务状态机）
  service/StandardLlmSummarizeService.java         // LLM 概括（按 L2 小节分块）
  parser/DocxStandardParser.java                   // 纯解析：docx → 骨架树（可单测）
  parser/model/…                                   // ParsedStandard/SectionNode/WeightTable 等 POJO
  export/KnowledgeSqlExporter.java                 // 知识树 → INSERT SQL 文件
  export/MubiaoExcelExporter.java                  // 树 → 细目表 Excel（POI 合并单元格）
  entity/ExamStandardTaskEntity.java               // staging：解析任务
  entity/ExamStandardNodeEntity.java               // staging：树节点草稿
  mapper/…                                         // 两个 BaseMapper
```

**线程边界**：LLM 概括走既有 `reviewSyncExecutor` 风格的独立线程池（AbortPolicy，坑 #12）；`tenantId` 在 HTTP 线程捕获后参数传递，异步链不调 SecurityContext（AGENTS.md 异步陷阱）；知识树/权重表一次性加载内存复用（坑 #18）。

**LLM 复用约束**：模型配置取 `exam_faq_model_config`（sys_dict 指定 code）；DeepSeek JSON mode + 空 content 重试沿用 `FaqLlmClient` 既有能力；调用留痕 `ai_generation_draft`（draftType=`standard_knowledge`）；**不支持的字段一律不传**（坑 #13）。

## 5. DOCX 解析器设计（DocxStandardParser，纯规则、黄金样例可单测）

### 5.1 解析步骤

1. `XWPFDocument` 顺序遍历 body 元素（`IBodyElement`：段落 `XWPFParagraph` / 表格 `XWPFTable`），保持文档顺序；
2. **标题识别**：沿用《转换指南》编号正则（`\d+(\.\d+)*\.? + 中文`），排除 `续表`/脚注/职业编码（编号后必须跟中文字符）；识别 `2.` `3.` `3.1` 等节边界，记录当前所在"等级节"（3.1=五级/初级 … 3.5=一级/高级技师）；
3. **基本要求段落解析**：`2.x` → L1 素材；`2.x.y` → L2 素材；`（n）xxx。` → 追加到当前 L2 的叶素材列表；
4. **工作要求表格解析**：
   - 4 列固定语义（职业功能/工作内容/技能要求/相关知识要求）；
   - **vMerge 处理**：`tcPr/vMerge[@val='restart']` 记录值，`vMerge` 无 val（continue）继承上一行同列值；gridSpan 横向合并按列序展开；
   - 每行产出（职业功能， 工作内容， 相关知识要求原文）；职业功能去重成 L1、工作内容成 L2、相关知识要求内 `（1）（2）…` 拆叶素材；
   - 单元格内多段落按换行拼接；条目编号兼容 `1.` `（1）` `1)` 三种写法；
5. **权重表解析**：末两张表——按表头行识别"理论知识权重表"（含"基本要求/相关知识要求"行）；焊工类二级表头为方向列，产出 `Map<等级, Map<项目, 百分比>>`，含方向维度；
6. **职业元信息**：职业名称（封面大字段落）、职业编码（`职业编码：x-xx-xx-xx` 正则）、版本年。

### 5.2 已登记解析陷阱（对应《转换指南》坑 + 实测）

| 陷阱 | 对策 |
|---|---|
| vMerge 纵向合并 | restart/continue 继承，悬空 continue 记解析警告 |
| 表格内编号段落 | 表格内容不进标题检测（坑 5） |
| 职业编码 `6-16-01-12` 误判标题 | 编号后必须中文字符（坑 3） |
| `续表` 行 | 跳过（坑 4/指南 Q4） |
| 中文间多余空格 | 仅清 `[ \t]`，不动换行（坑 2） |
| 换页导致一行表格拆断 | 以 vMerge 与列数校验，断行并入上一行 |
| 基本要求某 L2 无列举项 | 叶素材为空 → 标记 `needLlm=true`，交 LLM 概括 |

### 5.3 输出 POJO

```
ParsedStandard
 ├─ workTypeTitle / seriesNo(职业编码) / version
 ├─ directions: List<String>          // 无方向=单元素 ["默认"]
 ├─ levels: List<LevelDoc>            // 五级/初级…一级/高级技师
 │    ├─ levelCode(0~4) / levelName
 │    ├─ skeleton: Node树             // L0 基本要求A/工作要求B → L1 → L2(含叶素材原文列表)
 │    └─ weights: Map<项目编码, BigDecimal>   // 该等级(×方向)权重
 └─ parseWarnings: List<String>       // 解析异常提示，页面展示
```

## 6. LLM 概括设计（StandardLlmSummarizeService）

### 6.1 调用粒度与 prompt

**按"L2 小节 × 等级"一次调用**（矿山救护工初级约 12 个小节 = 12 次调用，焊工全等级约 60 次），输入输出契约：

```
system：你是职业技能鉴定命题专家，正在为「{工种} {等级}」编写理论知识考评点。
user：
  小节路径：基本要求/职业道德/职业道德基本知识
  原文素材：
   （1）……（2）……        ← 可能为空（无列举项）
  要求：
   1. 概括 4~8 个考评点，每个为 ≤20 字的名词性短语，不得照抄长句；
   2. 每个考评点给重要程度：X=核心必考，Y=重要（法律法规、安全规程类），Z=一般了解；
   3. 以 JSON 输出（必须含 "points" 数组）。
输出 JSON：{"points":[{"title":"工匠精神的基本内涵","important":"X"}, …]}
```

### 6.2 确定性护栏（不过度信任模型）

- **JSON mode + 解析失败重试 ≤2 次**（第二次把错误原因回喂）；仍失败 → 该小节叶素材原文逐条兜底为叶节点（`source=extract`，标记待人工）；
- **important 枚举校验**：仅接受 X/Y/Z，非法值 → 默认 X 并记警告；
- **数量护栏**：单小节叶节点 >15 截断并记警告（对照样例单节 4~35 条）；
- **编码生成在 Java 侧**（不让模型写编码）：按 §2.2 规则由序号器统一分配，杜绝模型编错码；
- 全部产出 `review_status=pending` 草稿，**人工确认前不参与导出**（AGENTS.md AI 规则 #3/#4：写操作草稿 + 来源/模型/时间留痕）。

### 6.3 批处理与任务状态机

```
任务状态：uploaded → parsed → llm_running → reviewing → confirmed → exported
LLM 执行：任务级异步（线程池）；按小节顺序执行；支持失败小节单独重试（页面「重新生成」按钮）
并发保护：同任务重复触发 LLM 直接 409（数据库状态前置校验）
```

### 7.1 `exam_standard_task`（解析任务）

### 7.2 `exam_standard_node`（树节点草稿）

| 列 | 说明 |
|---|---|
| id / task_id / parent_id | staging 树（parent_id 为本表 id，0=L0 之上） |

## 8. 权重分配规则（LLM 不参与，纯规则 + 人工微调）

1. **项目级权重**（基本要求 A / 工作要求 B / 工作要求下各职业功能）：直接取 docx 理论知识权重表（按 等级×方向 取值）；焊工方向专属职业功能只在对应方向树出现；
2. **L1 细分权重** = 项目权重 ×（该 L1 叶节点数 ÷ 项目总叶节点数），保留 4 位小数；
3. **L2 考评权重** = L1 权重 ×（该 L2 叶节点数 ÷ L1 总叶数）；
4. **重要程度比例**（细目表 `(42:8:0)`）= 该节点子树内 X:Y:Z 叶节点计数，导出时实时统计；
5. 页面对 L1/L2 权重可手动微调（校验：同项目下 L1 之和 = 项目权重，超限红字提示）；

> 对照样例：基本要求 0.25（docx 权重表）→ 职业道德 0.05 / 基础知识 0.20（按叶数 10:40 ≈ 1:4 分配，样例 0.05/0.20 吻合）。

## 9. 导出设计

### 9.1 入库 SQL 导出（KnowledgeSqlExporter）

- 目标口径：PHP 库（tenant_id=10159，`important` varchar X/Y/Z）；
- **id/parent_id 处理**：PHP 表为 int auto_increment → 按层级分段生成，每个节点 `INSERT …; SET @k_A_A_A = LAST_INSERT_ID();`，子节点 `parent_id = @k_父编码`（编码任务内唯一，变量名用编码字母数字转义）；
- `exam_work_type` / `exam_course` 若已存在（按 title+series_no 匹配）则生成注释说明跳过，不重复插入；
- 生成顺序：work_type → course（每方向每等级一行）→ knowledge_structure（按层级序）；
- 文件头注释：来源 docx、生成时间、操作人、行数统计；文件落地 `outputs/` 并提供页面下载。

### 9.2 细目表 Excel 导出（MubiaoExcelExporter）

- POI SXSSF；按 §2.3 版式：标题合并行 + 4 行复合表头 + L0/L1/L2 纵向合并（`CellRangeAddress`）；
- 每个「等级×方向」一个文件（如 `焊工(五级)电焊工_理论知识考评要素细目表_yyyyMMddHHmmss.xlsx`）；
- 样式：表头加粗居中、权重列数字格式 `0.00`、边框细线；列宽自适应内容上限 60。

```
  小节操作：「重新生成」（仅 LLM 节点，重跑该 L2 的 LLM 调用）
  顶部按钮：全部标为已审 | 权重校验 | 导出细目表Excel | 导出入库SQL
  侧栏：解析警告列表（vMerge 异常、空小节、LLM 失败兜底等）
```

## 12. 边界与异常

- docx 非国家标准格式（无编号标题/无权重表）→ 解析阶段报错并给出警告清单，不进 LLM；
- LLM 全局不可用 → 任务停在 `parsed`，骨架仍可人工补叶后导出（**主链路降级不挂**）；
- 权重表缺失某等级 → 该等级权重列为空，页面提示手工填写；
- 同一 docx 重复上传 → 按 fileHash 提示已存在任务，选择覆盖重建或查看；
- 导出前置校验：存在 `review_status=pending` 叶节点 → 禁止导出并定位提示；
- 所有写操作（上传/编辑/重新生成/导出）记操作日志（@AuditLog）。
