# 千铝工投云平台与智能体开发部多端角色与权限管理制度

制度编号：QLGT-YFGL-2026-107　　版本：V1.1　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为定义管理端、学员端、小程序、App 等多端的角色模型与权限分配规则，保障多租户数据权限安全，特制定本制度。后端是权限的最终裁决点，前端只做展示控制。本制度遵循部门制度“简洁、可测试、可维护、持续迭代”的共同标准。

**第二条**　本制度适用于培鉴赛 SaaS 平台全部端的角色与权限管理，以及新接入端的角色模型扩展。

## 第二章　多端角色模型

**第三条**　角色模型分端定义：管理端设平台管理员、租户管理员、考务人员、命题专家等；学员端（小程序/App）设学员、教师、企业管理员等。角色清单及权限矩阵以平台权限配置为准，新增角色须经部门评审。

**第四条**　权限开通遵循三步链：菜单 → 权限码 → 角色授权，三步齐备方可生效；仅建菜单或仅配权限码而未授权角色的，接口必须拒绝访问。

## 第三章　权限分配与审批流程

**第五条**　租户内角色由租户管理员在平台内分配；平台级角色（平台管理员等）由部门负责人审批后配置。权限变更全部留痕，含操作人、时间、变更内容。

**第六条**　临时权限（如赛事期间的临时考务权限）须设定到期时间，到期自动失效或人工回收。

## 第四章　多租户数据权限要求

**第七条**　涉及租户数据的查询与写入必须经多租户机制自动过滤，禁止业务代码绕过；跨租户访问一律视为 P1 级缺陷，涉及数据泄漏的按安全事件处理。须特别注意：X-Tenant-Id 请求头可被客户端伪造，业务鉴权禁止以 TenantContextHolder 中取值为唯一依据，须结合登录态与数据源过滤等可信上下文二次校验。

**第八条**　异步与批处理场景（线程池、异步任务、定时任务）中，租户与用户标识必须在请求线程捕获后随参数传递，工作线程自行设置与清理上下文，禁止在异步链路中直接读取会话上下文。

**第九条**　对外接口下发的雪花 ID 一律以字符串形式返回，防止前端数值精度丢失导致越权误判或数据错挂。

## 第五章　权限审计与定期复核

**第十条**　敏感操作（权限变更、数据导出、批量删除）写入审计日志，可按人、租户、时间检索。

**第十一条**　每季度由部门负责人组织权限复核，3 人互核：核对平台级角色成员、抽查租户管理员授权合理性；离岗与兼职结束的账号及时停用。

## 第六章　附则

**第十二条**　本制度由千铝工投云平台与智能体开发部负责解释。

**第十三条**　本制度自发布之日起施行。
