# 一期 MVP 功能清单

版本：V0.1 草稿  
日期：2026-05-01

## 一、目标

第一阶段目标是跑通“平台底座 + 培训学习考试闭环”，不是一次性完成培训、竞赛、认定、补贴和复杂驾驶舱。

一期完成后，应能做到：

1. 平台管理员创建租户、组织、用户、角色和菜单权限。
2. 课程人员维护课程、章节、题库和试卷。
3. 培训负责人发布考试安排。
4. 学员登录后查看课程、学习章节、参加考试、查看成绩和错题。
5. 课程发布支持基础审批：提交、通过、驳回、记录留痕。
6. AI 样板可根据课程主题和资料生成课程大纲草稿，但不自动发布。

## 二、首批角色

| 角色 | 默认首页 | 一期权限范围 |
| --- | --- | --- |
| 平台管理员 | 系统管理首页 | 租户、组织、用户、角色、菜单、字典、文件、全部数据 |
| 老板/管理层 | 管理概览页 | 查看基础统计、课程/考试概览，不做复杂驾驶舱 |
| 培训负责人 | 培训管理首页 | 管理课程发布、考试安排、学员学习和成绩 |
| 课程人员 | 课程题库首页 | 维护课程、章节、题目、试卷，发起课程发布审批 |
| 认定专员 | 预留首页 | 一期只保留角色和菜单样板，不做认定全流程 |
| 竞赛运营 | 预留首页 | 一期只保留角色和菜单样板，不做竞赛全流程 |
| 企业管理员 | 企业首页 | 一期只保留角色和账号，不做完整企业端下单/确认 |
| 学员 | 学员学习首页 | 查看课程、学习、考试、成绩、错题 |

## 三、后台功能

| 模块 | 一期功能 | 说明 |
| --- | --- | --- |
| 登录认证 | 账号密码登录、刷新 token、退出、当前用户 | 短信、微信、企微后置 |
| 租户组织 | 租户维护、组织树、企业/部门节点 | `tenant` 代表平台客户/公司，企业和部门走组织模型 |
| 用户管理 | 用户 CRUD、启停、重置密码、绑定组织和角色 | 学员也是用户，通过角色和用户类型区分 |
| 角色权限 | 角色 CRUD、绑定菜单、绑定按钮权限 | 后端做最终权限裁决 |
| 菜单管理 | 菜单树、路由、图标、排序、显隐 | 前端动态加载 |
| 字典管理 | 字典类型、字典项、状态、排序 | 工种、等级、题型、课程分类等先用字典承载 |
| 文件管理 | 上传、元数据、下载/预签名 URL、删除 | 本地开发存磁盘，生产接 OSS/COS |
| 操作日志 | 记录写操作、登录、审批、AI 样板调用 | 一期先后台查询，不做复杂审计分析 |
| 课程管理 | 课程 CRUD、章节 CRUD、课程状态 | 状态：草稿、审批中、已发布、已驳回、停用 |
| 题库管理 | 题目 CRUD、选项、答案、解析、分类标签 | 支持单选、多选、判断，问答题后置 |
| 试卷管理 | 试卷 CRUD、选题、分值、及格线、时长 | 支持手动组卷，自动组卷后置 |
| 考试安排 | 选择试卷、课程、时间、参考学员范围 | 一期按租户内学员开放 |
| 流程样板 | 课程发布审批 | 提交、通过、驳回、审批记录 |
| AI 样板 | 课程大纲草稿生成 | 保存草稿，人工确认后再复制到课程 |
| 需求与职责管理 | 部门职责、岗位职责、业务流程、需求池、问题池、项目任务 | 一周内优先建设，帮助公司快速梳理各部门业务流转、系统需求和待解决问题 |
| 需求附件与资料上传 | 支持在需求、问题、流程、职责、任务中上传和关联附件 | 包括 Word、Excel、PDF、PPT、图片、截图、录屏、压缩包、历史资料和已填写内容文件 |
| 需求资料 AI 分析 | 对需求文字、附件、截图和历史资料进行摘要、归类、提取需求点和生成任务拆解建议 | AI 只生成草稿和建议，需求确认、任务分配和关键动作仍由负责人确认 |

### 3.1 需求与职责管理模块 P0 范围

该模块用于解决公司各部门业务流转不清、系统需求分散、问题反馈不集中、开发完成后用不起来的问题。一期应先做到“能收集、能说明、能归类、能分派、能跟踪、能让 AI 辅助分析”。

| 功能 | 一期要求 | 说明 |
| --- | --- | --- |
| 部门职责 | 维护部门职责、负责人、协作部门、主要输出物 | 复用现有组织、用户和角色能力 |
| 岗位职责 | 维护岗位职责、对应人员、参与流程和系统使用范围 | 用于快速了解每个人负责什么、在哪些流程中承担动作 |
| 业务流程 | 维护流程名称、适用部门、流程节点、责任人、输入资料、输出结果 | 先支持文本和表格化维护，复杂流程图后置 |
| 需求池 | 记录各部门对系统的需求、业务背景、期望效果、优先级、负责人和状态 | 支持小需求、大需求、模糊需求先进入需求池，再逐步拆解 |
| 问题池 | 记录现有系统、业务执行、数据、流程和交付中的待解决问题 | 支持标记紧急程度、影响范围、责任人和处理进度 |
| 项目任务 | 将确认后的需求和问题转为任务，跟踪负责人、计划时间、完成状态和验收结果 | 一期先做基础看板，不做复杂项目管理 |
| 附件上传 | 每条需求、问题、流程、职责和任务均可上传附件 | 附件用于补充说明需求背景、现有系统情况和已填写内容 |
| 截图说明 | 支持上传屏幕截图、系统页面截图、错误截图、流程截图、标注截图 | 用于降低口头描述误差，帮助负责人和 AI 理解真实场景 |
| 资料关联 | 可关联公司已有制度、表格、历史方案、客户资料、课程资料、考试资料和项目资料 | 重要资料可进一步纳入公司知识库 |
| AI 辅助分析 | AI 根据文字、附件、截图和历史资料生成需求摘要、问题归类、流程判断、字段提取和任务拆解建议 | AI 输出为草稿，不直接覆盖原始需求和任务 |

## 四、学员端功能

| 模块 | 一期功能 | 说明 |
| --- | --- | --- |
| 学员登录 | 账号密码登录 | 手机短信登录后置 |
| 课程列表 | 查看已发布课程 | 按课程分类、工种、等级筛选可后置 |

## 五、不进入一期的范围

1. 竞赛报名、签到、排名、团队赛、答题闯关。
2. 认定全流程、认定材料、实操检查、归档和证书归档。
3. 补贴申报、拨款进度、人社系统接口。
4. 复杂驾驶舱、经营分析、领导大屏。
5. 短信登录、微信登录、企微登录、SSO。
6. 多租户计费、套餐、客户自助开通。
7. 自动组卷、随机抽题策略、题目难度算法。
8. 完整 Agent 编排和自动执行。
9. n8n 客户侧配置能力。
10. Kubernetes、全量微服务、细业务服务拆分。

## 六、一期完成标准

1. 平台管理员能完成租户、组织、用户、角色、菜单配置。
2. 课程人员能创建课程、章节、题目、试卷。
3. 课程发布能走一次审批流并留痕。
4. 培训负责人能安排考试。
5. 学员能登录、学习、答题、提交、看到成绩和错题。
6. 数据隔离可验证：不同 `tenant_id` 不能互相访问业务数据。
7. MySQL 空库能执行全部 Flyway 迁移脚本。
8. 本地文件上传能真实保存文件并读取元数据。
9. AI 样板能生成课程大纲草稿，且无权限用户无法调用。
10. `platform-api`、`ai-gateway`、`mcp-server`、`file-service`、`workflow-service` 的职责边界清楚，AI 和 MCP 不能直连业务数据库。
11. 能维护部门职责、岗位职责和业务流程，管理层能快速查看各部门负责事项和主要业务流转。
12. 各部门能提交系统需求和待解决问题，并能上传附件、截图、历史资料和已填写内容文件作为说明依据。
13. AI 能基于需求文字、附件和截图生成需求摘要、问题归类、资料缺失提示和任务拆解建议，输出结果作为草稿由负责人确认。
