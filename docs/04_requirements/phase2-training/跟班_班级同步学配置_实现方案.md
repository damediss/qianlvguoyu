## 〇、一句话

在跟班工作台为班级配置 **「用哪套同步学考试计划 + 开不开 + 名单/灰度开通」**；同步学排题/答卷引擎不变，班级层只做 **绑定与开通编排**。

---

## 一、问题与目标

### 1.1 现状断层

```text
已有：AI 同步学按 examId 运行（/appreviewsync/**）
已有：灰度白名单 ai_review_gray_whitelist（exam|user）
已有：进练校验 train_exam_people_list
已有：跟班「刷题」Tab → 通道 A 试题配置（practice-scope）
缺失：班级 ↔ 同步学 exam 的显式绑定
缺失：教务在跟班一键把花名册写入考生名单 / 灰度
缺失：班级入口 / 助教稳定拿到本班 examId（现靠隐式猜或提升区自带 exam_id）
```

### 1.2 目标

| 角色 | 能力 |
|------|------|
| 跟班教务 / 管理员 | 在跟班工作台为本班选定同步学计划、启用/停用、看开通差额、一键同步名单与灰度 |
| 学员（App） | 从「我的班级」进入同步练习时自动带本班绑定的 `examId`；未配置或未开通则隐藏入口并说明原因 |
| 学员 AI 助教 | bootstrap「该刷哪 / 继续练」读同一 `resolveClassExam`，不再默认 `go_precise`（通道 A） |

### 1.3 非目标

| 不做 | 原因 |
|------|------|
| 改同步学排题/阶段/日题量算法 | 仍按 exam 维 + 全局 `sys_dict` |
| 班级级权重、模考参数 | 与计划快照冲突；继续考试/课程维配置 |
| 把同步学答卷并入作业/刷题学情 | A/B/C 隔离已锁 |
| 替换提升区原 `exam.vue` 同步练习入口 | 增量班级入口，不砍旧路径 |
| P0 一班多 exam 并行练 | 先 1 班 1 绑定；多计划为 P2 |
| 老师侧催交同步学 | 见助教方案，另立需求 |

## 二、结论（先看）

| 问题 | 答案 |
|------|------|
| 配置绑什么？ | **一个** `train_exam_list.id`（`examId`）+ `enabled` + 可选开放窗口 |
| 数据放哪？ | 新建 SaaS 表 `train_class_review_sync`（对标 `train_class_practice_scope`） |
| 学员就能练了吗？ | **还要**：灰度放行 + `train_exam_people_list` 在册；配置页提供开通动作 |
| 改引擎吗？ | **不改** `/appreviewsync` 核心；只增加班级解析器供入口/助教调用 |
| 和刷题配置关系？ | 并列；刷题=通道 A，本方案=通道 C，指标不混算 |
| 无配置时？ | 隐藏班级同步学入口与助教「该刷哪」；可选 P1 回退工种匹配（默认关） |

**一句话：**  
班级绑定 exam →（可选）同步名单/灰度 → App/助教 `resolveClassExam` → 仍走同步学引擎。

```text
                └─► /appreviewsync/*       作答与学情
```

## 四、已拍板默认决策

| # | 项 | 默认 | 说明 |
|---|----|------|------|
| D1 | 绑定粒度 | **1 班 1 exam** | UK(`class_id`)；多 exam 留 P2 |
| D2 | exam 候选 | 同 `train_info_id` 下 `train_exam_list` | 按班级 `workTypeId+level` 与 `train_exam_work_type_list` 匹配置顶 |
| D3 | 显式配置优先 | **有绑定用绑定** | 无绑定不自动猜（P0）；P1 可开关「无绑定时工种回退」 |
| D4 | 保存是否自动开通 | **否** | 保存只写绑定；名单/灰度用独立按钮，避免误开全量 |
| D5 | 灰度写入范围 | 优先写 `scope_type=exam` | 一班开通即整 exam 试点；可选再补 user 级（P2） |
| D6 | 名单写入库 | 与现网考试名单同源 | 能写则 upsert；无写权限则提示人工导入并展示差额 |
| D7 | 管理端入口 | 跟班工作台 | 「刷题」Tab 内分区，或独立「同步学」Tab（见 §7） |
| D8 | App 入口 | 学员班级工作台 | 深链现有 `pages/exam/syncHome?exam_id=` |
| D9 | 助教 | 读同一解析器 | `go_sync` / `sync_today` 替换 `go_precise`（与助教方案对齐） |

## 五、数据设计

### 5.1 新表 `train_class_review_sync`

> Flyway 版本号实施前查库 `flyway_schema_history` 最大成功版本后分配，本文用占位名。

```sql
CREATE TABLE train_class_review_sync (
  id              BIGINT       NOT NULL AUTO_INCREMENT,
  tenant_id       BIGINT       NOT NULL,
  class_id        BIGINT       NOT NULL COMMENT 'train_info_class.id',
  exam_id         BIGINT       NOT NULL COMMENT 'train_exam_list.id',
  enabled         TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0停用',
  sync_start_time DATETIME     NULL COMMENT '班级开练开始，空=不限',
  sync_end_time   DATETIME     NULL COMMENT '班级开练截止，空=不限',
  auto_enroll     TINYINT      NOT NULL DEFAULT 0 COMMENT '预留：保存时是否自动补名单（P0 不用）',
  remark          VARCHAR(255) NULL,
  create_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  update_time     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted         TINYINT      NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_class (tenant_id, class_id, deleted),
  KEY idx_exam (tenant_id, exam_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='班级同步学配置（通道C绑定层）';
```

### 5.2 不改的表

| 表 | 原因 |
|----|------|
| `ai_review_plan*` / answer / mock | 引擎域，仍按 exam |
| `ai_review_gray_whitelist` | 开通动作写入，结构不变 |
| `train_exam_people_list` | 开通动作写入，结构不变 |
| `train_class_practice_*` | 通道 A，互不引用 |

### 5.3 解析规则 `resolveClassExam(classId, now)`

```text
1. 查 train_class_review_sync（tenant + class + deleted=0）
2. 无行 / enabled=0 → null
3. 若 sync_start/end 有值且 now 不在窗口内 → null（原因码 WINDOW）
4. 校验 exam 仍存在且未删 → 否则 null（原因码 EXAM_GONE）
5. 返回 { examId, examTitle, enabled, window... }
```

App/助教在拿到 `examId` 后仍调 `availability`；未放行则隐藏入口（与现网 fail-closed 一致）。

## 六、接口设计

权限：与跟班/开班准备班级写权限对齐（建议复用 `train:info-class:edit` 或跟班既有 permission；实施时挂现网角色）。  
App 读解析：Bearer itoken + 本班学员角色。

### 6.1 管理端

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/training/info-classes/{classId}/review-sync-config` | 配置 + 开通摘要 |
| PUT | `/training/info-classes/{classId}/review-sync-config` | 保存绑定（body 见下） |
| GET | `/training/info-classes/{classId}/review-sync-config/exam-options` | 候选考试计划 |
| POST | `/training/info-classes/{classId}/review-sync-config/enroll-roster` | 花名册 → 考生名单 |
| POST | `/training/info-classes/{classId}/review-sync-config/ensure-gray` | 写入 exam 灰度白名单 |
| GET | `/training/info-classes/{classId}/review-sync-config/roster-gap` | 在册/未开通/无账号统计（可与 GET config 合并） |

**PUT body**

```json
{
  "examId": 454,
  "enabled": true,
  "syncStartTime": null,
  "syncEndTime": null,
  "remark": ""
}
```

**GET config 响应（建议）**

```json
{
  "examId": "454",
  "examTitle": "浸出工初级-同步复习",
  "enabled": true,
  "syncStartTime": null,
  "syncEndTime": null,
  "remark": "",
  "grayEnabled": true,
  "examInGray": false,
  "roster": {
    "total": 40,
    "withPlatformUser": 38,
    "inExamPeople": 12,
    "missingAccount": 2,
    "missingEnroll": 26
  },
  "statsPath": "/training/exam-lists/454/review-sync-stats"
}
```

> 雪花/大 id 一律字符串下发（AGENTS 坑 #24）。

**enroll-roster 行为**

1. 读花名册 `train_people_list`（本班、未删）  
2. 跳过无 `platform_user_id`（计入 `missingAccount`）  
3. 对已有账号：upsert `train_exam_people_list(exam_id, platform_user_id, …)`（字段对齐现网考试名单写入口径）  
4. 返回 `{ inserted, existed, skippedNoAccount }`  
5. **不**自动建 `ai_review_plan`（仍由学员首次 overview 懒生成）

**ensure-gray 行为**

1. 若 `ai_review_gray_enabled=false` → 返回「已全量开放，无需白名单」  
2. 否则 upsert `ai_review_gray_whitelist(scope_type=exam, scope_id=examId)`  
3. 幂等

### 6.2 App（跟班消费）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/training/follow/classes/{classId}/review-sync` | 学员侧：解析结果 + 是否建议展示入口 |

响应示例：

```json
{
  "configured": true,
  "examId": "454",
  "examTitle": "…",
  "entryVisible": true,
  "reasonCode": null,
  "deepLink": { "path": "/pages/exam/syncHome", "query": { "exam_id": "454" } }
}
```

`entryVisible` 建议服务端综合：配置有效 ∧ availability.allowed ∧（可选）在名单；不在名单时 `reasonCode=NOT_IN_ROSTER`，前端展示「请联系教务开通」。

助教：`bootstrap` 复用同一 ApplicationService 方法，避免两套解析。

## 十、分期与验收

| 阶段 | 交付 | 验收 |
|------|------|------|
| **P0** | 表 + CRUD + Modal + `resolve` + App 班级入口读配置 | 配 exam 并启用后，学员入口可见且 `exam_id` 正确；停用/无配置则隐藏；与刷题学情数据隔离 |
| **P1** | enroll-roster + ensure-gray + roster-gap 展示 | 一键后差额下降；灰度开时 ensure 后 availability=true；无账号学员明确列出 |
| **P2** | 多 exam / 工种回退开关 / 班内同步学进度嵌入 | 不阻塞 P0 |
| **联调** | 助教 bootstrap 改读绑定 | 「该刷哪」进同步学而非 preciseHome |

### 10.1 P0 验收场景

1. 未配置 → 学员班级无同步学入口；助教无「该刷哪」（若已上助教）。  
2. 配置 exam A 并启用 → 入口深链 `exam_id=A`。  
3. 停用 → 入口消失。  
4. 窗口外 → 入口消失，教务端可见原因。  
5. 仅配置未 enroll → 入口可显但进 overview 报不在名单（P0 可接受）；P1 后教务应先看到差额提示。  
6. 通道 A 刷题学情人数不因同步学作答增加。

### 10.2 P1 验收场景

1. 「同步本班名单」后，有账号学员均在 `train_exam_people_list`。  
2. 灰度开启时「加入灰度」后，种子学员 `availability.allowed=true`。  
3. 重复点击开通动作幂等、无重复脏数据。

## 十一、风险与红线

| 风险 | 应对 |
|------|------|
| 只绑不开通，教务以为配完就能练 | UI 强制展示差额；P1 开通按钮置顶 |
| exam 挂错工种 | options 标注匹配度；保存时 warn 不阻断 |
| 名单写库失败（权限/异库） | fail-soft 返回明确错误；提供人工导入指引 |
| 与助教「自动匹配」文档冲突 | **本方案：显式配置优先**；助教文档以本表为准 |
| 灰度 exam 级影响其他班 | 产品说明：exam 白名单是计划级；若需仅本班，P2 改 user 批量白名单 |
| 大 id 精度 | JSON 字符串 |

**红线**

- 不混 A/B/C 答卷与指标  
- 不在班级配置改同步学算法参数  
- 不静默全员开通灰度（须按钮确认）  
- 学员不可通过本配置查看他人进度

## 十五、结论

方案可落地，形状对齐已验证的 **练习范围配置**，同时尊重同步学 **exam 中心** 与 **灰度/名单** 双门槛。P0 交付「能配、能跳」；P1 交付「能开通」；不触碰排题引擎即可支撑跟班场景与后续学员 AI 助教。
