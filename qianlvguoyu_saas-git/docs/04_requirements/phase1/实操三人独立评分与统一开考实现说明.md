# 实操三人独立评分与统一开考实现说明

## 业务规则

- 同一认定任务、工种、等级和考试日期只能绑定一套已发布实操试卷及一个考评组。
- 考评组必须恰好包含 3 名已绑定有效平台账号的考评员。
- 评分任务按“考生 × 试题 × 3 名考评员”幂等生成。
- 单份试题得分由服务端按评分要素汇总，客户端合计不可信。
- 三人全部提交后，试题得分按三人平均值计算并使用 `HALF_UP` 取整数。
- 考生实操总分为所有试题最终整数分之和，兼容字段 `weight` 固定为 100 且不参与计算。

## 统一开考链路

1. 管理端完成当天唯一试卷、三人考评组配置并生成评分任务。
2. 现场工作人员在管理端核对身份后执行“考生确认”。
3. 三名考评员分别在平板端核对考生和试卷并执行“考评员确认”。
4. 服务端校验评分任务均匹配同一试卷且考评员集合恰好为 3 人。
5. 最后一次确认在数据库事务内将会话更新为 `started`。
6. 事务提交后，通过 `/api/ws/practical-scoring` 向该考生的三个平板广播统一开始事件。
7. 服务端在会话进入 `started` 前拒绝保存草稿和提交评分。

WebSocket 使用 60 秒一次性票据进行握手，不在 URL 中传递登录令牌。订阅时再次校验租户和本人评分任务归属。

## 平板端

- 独立入口：`/assessor-scoring`，不展示管理端侧栏。
- 大尺寸触控扣分按钮、固定考生信息、实时得分和固定提交区。
- IndexedDB 按用户、任务、修订号保存草稿。
- 短时断网可继续编辑，恢复网络后自动同步。
- 服务端版本冲突时停止覆盖并要求重新加载，不执行自动合并。
- 评分提交后二次确认并清除本地草稿。

## 主要接口

- `PUT /api/certification/practical-scoring/tasks/{taskId}/config`
- `POST /api/certification/practical-scoring/tasks/{taskId}/generate`
- `POST /api/certification/practical-scoring/tasks/{taskId}/candidates/{candidateId}/confirm`
- `GET /api/certification/practical-scoring/tasks/{taskId}/progress`
- `GET /api/certification/assessor-scoring/tasks`
- `POST /api/certification/assessor-scoring/tasks/{assessorTaskId}/confirm-start`
- `PUT /api/certification/assessor-scoring/tasks/{assessorTaskId}/draft`
- `POST /api/certification/assessor-scoring/tasks/{assessorTaskId}/submit`
- `POST /api/certification/assessor-scoring/websocket-ticket`
