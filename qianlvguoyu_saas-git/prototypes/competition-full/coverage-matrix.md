# 竞赛模块全量静态原型覆盖矩阵

> 文档性质：独立需求覆盖与后续验收基线，不代表当前原型已经通过验收。  
> 需求基线：`竞赛模块需求说明书 V0.1` 及用户提出的“所有模块、所有页面、点击跳转链路与弹窗都生成展现”。  
> 原型边界：静态模拟数据即可，不要求真实后端；但所有呈现为可操作的入口都必须有可观察反馈，不能存在无说明的空链接或死按钮。

## 1. 范围口径

“所有页面”按业务视图而非 HTML 文件数量验收。同一个 HTML 通过 hash、页签、抽屉或 JavaScript 切换出的完整业务视图，可以视为一个页面；但必须同时满足：

1. 有明确页面标题或面包屑，可判断当前所在业务视图；
2. 可从总览或上级页面点击到达，也能返回上级；
3. 主要操作可以打开对应弹窗、抽屉、下一步视图或明确的模拟结果；
4. 不能只放菜单文字、卡片标题或“后续建设”占位来声称已覆盖；
5. 涉及新增、编辑、查看详情、发布、删除、导入、分配、审核等不同意图时，应分别展示对应交互状态；
6. 敏感数据、未公开数据和跨企业数据必须通过角色视图差异体现，而不是所有端复用同一份无限制数据。

## 2. 全局交互与可用性验收

| ID | 范围 | 必须覆盖 | 验收点 |
|---|---|---|---|
| G-01 | 总入口 | 组织方、企业、选手、专家、公开大屏五类入口 | 五个入口均可点击进入真实页面；不能以灰色占位卡代替 |
| G-02 | 角色导航 | 各端独立菜单与当前项高亮 | 点击一级/二级菜单后标题、内容、面包屑同步变化 |
| G-03 | 返回链路 | 返回总览、返回列表、返回详情 | 不依赖浏览器后退也能完成主要返回链路 |
| G-04 | 列表交互 | 搜索、筛选、重置、分页/页码示意 | 操作后有列表变化或明确 toast；禁止无反馈按钮 |
| G-05 | 行操作 | 查看、编辑及模块特有操作 | 至少一条样例记录的每个可见操作都能打开正确视图/弹窗 |
| G-06 | 通用弹窗 | 标题、内容、确认、取消、关闭 | 确认后数据/状态/toast 至少一项可观察变化；取消不应误提交 |
| G-07 | 危险操作 | 删除、取消赛事、撤回发布、归档等二次确认 | 弹窗说明对象与影响范围；按钮有明显危险态 |
| G-08 | 抽屉/侧栏 | 详情、快速配置、任务详情 | 可关闭；层级和遮罩正确；内容不能与当前对象错配 |
| G-09 | 表单 | 必填、格式、步骤进度、上一步/下一步 | 至少展示一次校验失败和一次成功反馈；步骤可前后切换 |
| G-10 | 空/异常态 | 无数据、无权限、加载/操作失败 | 至少用可切换样例或明确设计状态呈现，不以白屏代替 |
| G-11 | 静态原型说明 | 模拟保存、模拟导出、外链/二维码等 | 不具备真实能力时必须 toast/说明“原型模拟”，不能伪造已下载文件 |
| G-12 | 链接完整性 | 页面引用的 HTML/CSS/JS/图片 | 本地直接打开时无 404；控制台无阻断主要功能的错误 |
| G-13 | 文案与编码 | 中文标题、按钮、表格数据 | UTF-8 无乱码；同一业务对象命名一致 |
| G-14 | 响应式 | PC 后台与 H5/移动端 | 组织方/企业/专家页面在常见桌面宽度可用；选手端在 390px 宽不横向溢出 |
| G-15 | 可达性 | 键盘焦点、遮罩层、可读对比度 | 主要按钮和弹窗可识别；弹窗打开后不被底层内容遮挡 |

## 3. 跨模块核心链路

| ID | 起点 | 点击链路 | 终点/反馈 | 验收点 |
|---|---|---|---|---|
| L-01 | 原型总览 | 组织方后台 | 组织方数据驾驶舱 | 入口不是占位卡 |
| L-02 | 竞赛计划列表 | 新建竞赛 → 填写基础信息 → 选择阶段 → 预览 → 保存草稿 | 新计划详情/列表新增记录 | 新建流程完整可走通，阶段选择只决定“有哪些阶段” |
| L-03 | 计划详情 | 发布竞赛 → 发布确认 | 状态变为已发布/报名中 | 发布后出现报名入口与流程节点已生成提示 |
| L-04 | 已发布计划详情 | 查看流程/去配置 | 流程设计器定位到该赛事 | 赛事名称与计划 ID 上下文一致 |
| L-05 | 流程设计器 | 选择节点 → 节点配置 → 资源配置 → 完成条件 | 节点详情更新 | 节点级人员、设备、物料、费用只在流程配置出现 |
| L-06 | 流程设计器 | 生成任务 → 预览任务 → 确认生成 | 任务中心出现按角色生成的任务 | 专家、企业、赛务、选手任务可区分 |
| L-07 | 发布赛事/报名管理 | 报名入口 → 企业导入/个人报名 → 审核 | 报名名单与统计更新 | 企业、自主报名两种入口在原型中需标明规则，避免无边界混用 |
| L-08 | 初赛管理 | 创建/绑定试卷 → 发布初赛 → 选手答题 → 交卷 | 成绩与排名 | 至少一条完整选手端联动演示链 |
| L-09 | 初赛成绩 | 设置晋级规则 → 预览晋级名单 → 人工确认 | 后续阶段参赛名单 | 支持前 N、企业前 N、分数线、组合规则的配置展示 |
| L-10 | 企业内部初赛 | 人员名单 → 发起内部初赛 → 查看排名 → 推荐 | 行业赛晋级/推荐名单 | 仅本企业人员可选 |
| L-11 | 决赛管理 | 排期/分组 → 裁判分配 → 成绩录入/汇总 → 排名确认 | 待发布结果 | 线上与线下两种决赛形态均有明确入口 |
| L-12 | 结果管理 | 成绩复核 → 发布确认 | 选手端成绩、公开大屏结果 | 发布前外部端不可见，发布后才联动展示 |
| L-13 | 技术研讨 | 上传初稿 → 分配专家 → 专家意见 → 汇总修订 → 确认终稿 | 技术文件正式版本 | 保留版本、修改人、时间、意见记录 |
| L-14 | 命题中心 | 分配命题 → 专家选题/新建 → 提交 → 审核 → 入库 → 组卷 | 赛事题库版本 | 未分配专家不能看到题目；角色冲突需提示 |
| L-15 | 流程资源配置 | 选人员/场地/设备/物料 → 套用费用标准 | 节点预算、整场预算 | 数量×单价×天数计算关系可见 |
| L-16 | 任务中心 | 打开任务 → 更新状态/上传成果 → 提交完成 | 流程进度与驾驶舱更新 | 逾期、异常、缺成果状态可识别 |
| L-17 | 赛事结束 | 结果确认 → 资料检查 → 归档确认 | 赛事档案详情/历史赛事 | 缺少必需资料时应有提醒或校验样例 |
| L-18 | 各角色端 | AI 助手 → 提问 → 查看答案来源 | 当前赛事/专业知识回答 | 赛事助手和专业助手知识范围、权限范围清晰分隔 |

## 4. 组织方后台覆盖矩阵

### 4.1 数据驾驶舱

| ID | 页面/视图 | 关键跳转 | 必需弹窗/抽屉 | 验收点 |
|---|---|---|---|---|
| A-D01 | 驾驶舱总览 | 指标卡→报名/任务/预算/成绩；赛事卡→赛事详情 | 指标口径说明 | 展示赛事数、企业数、报名/审核/初赛/晋级人数、任务完成率、超期数、专家、资源、预算、成绩 |
| A-D02 | 单场赛事驾驶舱 | 流程节点→节点监控；异常数→异常任务 | 节点进度详情、异常任务抽屉 | 明确当前阶段和各阶段完成进度 |
| A-D03 | 统计分析 | 图表维度切换、时间/赛事筛选 | 导出确认 | 能查看报名、成绩、企业、预算等趋势或分布；内部指标不外泄 |

### 4.2 计划管理

| ID | 页面/视图 | 关键跳转 | 必需弹窗/抽屉 | 验收点 |
|---|---|---|---|---|
| A-P01 | 竞赛计划列表 | 新建、详情、编辑、复制、发布 | 筛选；复制确认；发布确认 | 展示草稿至归档/取消等状态，行操作随状态变化 |
| A-P02 | 新建竞赛-基础信息 | 下一步→阶段选择 | 离开未保存确认 | 覆盖名称、年度、主承办方、对象、工种、内容、形式、报名/比赛时间、地点、条件、奖项、联系、说明、附件 |
| A-P03 | 新建竞赛-模式/阶段选择 | 上一步；下一步→预览 | 阶段模板说明 | 可组合通知、研讨、初赛、复赛、开/闭幕、决赛、公示、归档 |
| A-P04 | 新建竞赛-预览发布 | 保存草稿、发布 | 发布确认 | 只汇总计划和阶段，不出现节点级人员/设备/物料/费用编辑 |
| A-P05 | 竞赛计划详情 | 编辑、发布/撤回、去流程配置、报名管理 | 发布/撤回/取消确认 | 基本信息、附件、阶段模式、状态日志齐全 |
| A-P06 | 编辑竞赛计划 | 保存、取消 | 已发布计划变更风险确认 | 赛事进行中不得无提示改动关键时间/阶段 |
| A-P07 | 竞赛通知编辑/预览 | 从计划详情进入；发布通知 | 附件选择、发布确认 | 企业和选手端可见内容与内部计划字段分离 |
| A-P08 | 发布管理/变更记录 | 查看版本、撤回、重新发布 | 版本详情、撤回确认 | 展示发布人、时间、范围、版本与状态 |

**计划与流程职责硬边界：**计划管理只回答“办什么赛事、面向谁、何时何地、采用哪些阶段、何时发布”；负责人、参与人、前置/完成条件、输出成果、资源、任务、节点费用全部属于流程配置。若计划表单直接承载后者，判定职责冲突。

## 10. 待确认需求在原型中的处理

下列问题不能由原型自行拍板。允许用“候选方案/待业务确认”展示，但不得悄悄固化为唯一规则：

1. 企业能否自主创建完整竞赛，或只能参与组织方赛事；
2. 专家、命题专家、审题专家、裁判能否重叠及具体回避规则；
3. 复赛是否是标准节点；
4. 线上与线下决赛比例、线下实操评分规则；
5. 企业内部初赛是否统一使用平台题库；
6. 课程、认定、竞赛题库的共享权限边界；
7. 技术文件是否需要实时协同编辑（当前只要求意见与版本管理）；
8. 外部大屏指标、赛事资讯/图文直播的最终范围；
9. 费用仅做预算，还是扩展到报销和支付；
10. 供应商是否成为独立管理模块；
11. 流程节点的审批、条件分支、并行、回退深度；
12. 两类 AI 助手最终采用一个入口还是两个入口；
