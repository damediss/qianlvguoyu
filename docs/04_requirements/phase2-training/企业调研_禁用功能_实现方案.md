# 企业调研 · 禁用功能 — 实现方案

> 目标项目：`qianlvguoyu_saas`（`platform-api` + `admin-web`）  
> App/H5：`gjjd_appnext`（公开采集 `/training/public/research-collection/**`）  
> 关联页面：`EnterpriseResearchPage.tsx`、`ResearchCollectionDrawer.tsx`  
> 状态：方案稿（可开发）  
> 编写日期：2026-08-27  

---

## 〇、一句话

将 `train_research_org.status` 从「列表标记」升级为 **业务开关**：**禁用后禁止一切新增/变更采集**，保留 **只读查看与历史数据**；与删除区分，可随时重新启用。

---

## 一、问题与目标

### 1.1 现状

| 项 | 现状 |
|----|------|
| 字段 | `status`：`1` 启用 / `0` 禁用（实体已存在） |
| 列表 | 已支持状态列 + 筛选（全部/启用/禁用） |
| 采集 | `TrainResearchCollectionApplicationService` **不校验** `status` |
| 公开 H5 | 扫码 token 有效即可提交，**不校验**调研企业状态 |
| 用户感知 | 「禁用」看起来像无效开关 |

### 1.2 目标

| 角色 | 禁用后应获得的能力 |
|------|-------------------|
| 跟班教务 | 明确「已下线」；不能开新采集、不能增删改人员；**可查看**已采数据、导出、证照核验 |
| 扫码学员 | 打开链接见「已结束采集」；**不能提交/更新** |
| 产品 | 禁用 ≠ 删除；历史与三年规划引用保留 |

### 1.3 非目标

| 不做 | 原因 |
|------|------|
| 禁用后物理删数据 | 用逻辑删除；禁用只停写 |
| 禁用后自动作废已生成的三年规划 | 历史产物保留 |
| 禁用后拦截「方案规划」里已关联的旧记录打开 | 只拦 **新建** 时选禁用企业 |
| 本期做禁用审计字段（人/时间） | 可 P1 补 `disabled_at` |

---

## 二、结论（先看）

| 问题 | 答案 |
|------|------|
| 禁用起什么作用？ | **停止该调研企业的采集写入**（含后台与 H5） |
| 还能看数据吗？ | **能**——列表、采集抽屉只读、人员列表、导出模板 |
| 还能编辑企业资料吗？ | **能**——改名称、关联系统企业、字段配置、重新启用 |
| 和删除区别？ | 删除=逻辑删整条；禁用=停采但记录仍在列表 |
| 实现要点？ | 后端统一 `assertEnabled`；写接口拦截；读接口放行（H5 读接口返回 `collectable=false`） |

**一句话：**  
禁用 = **只读归档 + 停采**；启用 = 恢复正常采集。

## 三、语义定义

### 3.1 状态机

```text
        创建（默认 status=1）
              │
              ▼
         ┌─────────┐
    ┌───►│  启用   │◄───┐
    │    │ status=1│    │ 重新启用
    │    └────┬────┘    │
    │         │ 禁用     │
    │         ▼         │
    │    ┌─────────┐    │
    └────│  禁用   │────┘
         │ status=0│
         └────┬────┘
              │ 删除（逻辑删，任意状态可删）
              ▼
           [deleted]
```

### 3.2 与删除对比

| | 启用 | 禁用 | 删除 |
|--|------|------|------|
| 列表可见 | ✅ | ✅（可筛） | ❌ |
| 后台查看采集 | ✅ | ✅ 只读 | ❌ |
| 后台写入采集 | ✅ | ❌ | ❌ |
| H5 提交 | ✅ | ❌ | ❌ |
| 编辑调研企业主数据 | ✅ | ✅ | ❌ |
| 方案规划新建时可选 | ✅ | ❌（下拉过滤） | ❌ |

## 四、接口拦截矩阵

统一入口：`ResearchOrgStatusSupport.assertEnabled(TrainResearchOrgEntity)`  
未启用抛：`BusinessException("RESEARCH_ORG_DISABLED", "该调研企业已禁用，无法采集")`（HTTP 400/422，与现网 BusinessException 一致）。

### 4.1 调研企业 CRUD（`TrainResearchOrgApplicationService`）

| 接口 | 禁用后 |
|------|--------|
| GET 列表/详情 | ✅ 允许 |
| POST 创建 | ✅（新建默认启用） |
| PUT 更新（含改 status） | ✅ **允许改回启用** |
| DELETE | ✅（与现网一致） |

### 4.2 人员采集（`TrainResearchCollectionApplicationService`）

| 方法 | 类型 | 禁用后 |
|------|------|--------|
| `getCollection` | 读 | ✅ 允许；VO 增加 `readOnly: true`, `disabled: true` |
| `pagePeople` | 读 | ✅ |
| `exportCollectionTemplate` | 读/导出 | ✅（仅模板，不写库） |
| `startCollection` | 写 | ❌ |
| `createPerson` | 写 | ❌ |
| `updatePerson` | 写 | ❌ |
| `deletePerson` | 写 | ❌ |
| `verifyPeopleCertificate` | 写（回写证照） | ❌ **P0 建议拦**；若业务需补历史证照可 P1 放开 |
| `createThreeYearPlan` | 写 | ❌ |

> **P0 口径：** 禁用 = 采集域 **零写入**。证照核验若会回写人员字段，归入写操作一并拦截。

### 4.3 公开 H5（`PublicResearchCollectionController`）

| 接口 | 禁用后 |
|------|--------|
| `GET /{token}` | ✅ 返回详情，但 `collectable: false`，`disabledReason: "该调研采集已结束"` |
| `GET /{token}/mine` | ❌ 或返回空（推荐 **403**，避免禁用态下还查个人信息） |
| `POST /{token}/submit` | ❌ |

H5 页 `pages/research/collect.vue`：根据 `collectable===false` 展示结束页，隐藏表单与提交按钮。

### 4.4 下游引用（方案规划等）

| 场景 | 规则 |
|------|------|
| `SolutionPlanningPage` 新建方案选「关联企业调研」 | 下拉 **仅 status=1** |
| 已关联禁用企业的历史方案 | **只读打开**，不强制解绑 |
| `ensureSystemCompany` | 与 status 无关 |

## 五、技术设计

### 5.1 后端

**新建（建议）**

```text
com.guoyu.platform.trainingdepartment.support.ResearchOrgStatusSupport
  - boolean isEnabled(TrainResearchOrgEntity e)  // status != null && status == 1
  - void assertEnabled(TrainResearchOrgEntity e)
  - void assertEnabled(Long researchOrgId)       // 查库后 assert
```

**改造点**

1. `requireResearchOrg` / `requireResearchOrgById`：**不**在 require 里默认 assert（读接口还要用）。  
2. 各 **写** 方法开头：`assertEnabled(research)`。  
3. `getCollection` / `getPublicCollection`：不 assert；组装 VO 时带 `readOnly` / `collectable`。  
4. `TrainResearchCollectionVO`、`PublicResearchCollectionVO` 增加字段（向后兼容，默认 `readOnly=false`）。

**列表查询（已落地）**

- 不传 `status` → 查全部；传 `0`/`1` → 筛选。保持不变。

**方案规划 exam-options 类接口（若有 research 下拉）**

- 增加 `status=1` 条件（查 `TrainResearchOrgMapper` 或复用 page 接口参数）。

### 5.2 管理端 UI

| 位置 | 改动 |
|------|------|
| `EnterpriseResearchPage` 列表 | 状态列：禁用用 `Tag color="default"`；操作列「人员采集」**不禁用按钮**（进抽屉只读） |
| 编辑弹窗 Switch | 切到禁用时 `Modal.confirm`：「禁用后将停止后台与扫码采集，已采数据仍可查看。确定？」 |
| `ResearchCollectionDrawer` | 读 `collection.readOnly` 或 `researchOrg.status===0`：隐藏「开启采集」「新增人员」「保存」「生成三年规划」；展示 `Alert type="warning"` |
| 公开二维码区 | 禁用态灰显二维码，文案「采集已结束」 |

### 5.3 H5 / App

| 文件 | 改动 |
|------|------|
| `gjjd_appnext/pages/research/collect.vue` | `collectable===false` → 结束态 UI |
| `api/research-collect.js` | 无需改路径；处理 403 文案 |

### 5.4 无需 Flyway（P0）

`status` 字段已存在。  
**P1 可选：** `disabled_at`、`disabled_by` 审计列 + 启用时清空。

## 六、交互说明

### 6.1 禁用操作流程

```text
教务在「编辑调研企业」将状态切为禁用
  → 二次确认
  → PUT status=0
  → 列表显示「禁用」
  → 采集抽屉变只读；H5 新提交被拒
```

### 6.2 重新启用

```text
编辑 → 状态改启用 → 保存
  → 采集抽屉恢复写操作
  → H5 可再次提交（token 仍有效）
```

### 6.3 边界

| 场景 | 行为 |
|------|------|
| 禁用前已开启采集、有二维码 | token **不失效**；H5 打开见「已结束」，不能提交 |
| 禁用期间教务想改一条人员电话 | P0 **不允许**；需临时启用或走数据修复脚本 |
| 禁用企业被方案规划历史引用 | 方案仍可查看；新建方案下拉不出现该企业 |
| 并发：禁用同时 H5 提交 | 以提交时 `assertEnabled` 为准，后提交失败 |

## 七、分期与验收

| 阶段 | 交付 | 验收 |
|------|------|------|
| **P0** | `ResearchOrgStatusSupport` + 采集写接口全拦 + H5 submit 拦 + VO 标志位 + 抽屉只读 + 禁用确认框 | 禁用后后台不能新增/改/删人员、不能开采集、不能生成三年规划；H5 不能提交；可查看列表与人员 |
| **P1** | 方案规划下拉过滤禁用企业；H5 结束页样式；禁用审计字段（可选） | 新建方案选不到禁用企业 |
| **P2** | 禁用后允许「仅证照核验」等特例开关（`sys_dict`） | 按运营反馈 |

### 7.1 P0 验收场景

1. 启用企业：采集全流程与现网一致。  
2. 禁用后点「人员采集」：能看人数与列表，无「新增/开启采集」按钮。  
3. 禁用后调 `POST .../collection/.../people` → 明确错误文案。  
4. 禁用后 H5 扫码：见结束提示，`submit` 失败。  
5. 改回启用：采集恢复。  
6. 删除与禁用互不影响（禁用企业可删）。

## 八、风险与红线

| 风险 | 应对 |
|------|------|
| 运维误以为禁用=删数据 | 确认文案写清「已采数据保留」 |
| 禁用后无法改错数据 | 临时启用或 DBA/修复接口；产品接受 |
| 公开接口只拦 submit 不拦 GET | GET 必须带 `collectable=false`，避免用户填完才失败 |
| 前端只灰按钮不拦 API | **以后端 assert 为准** |

**红线**

- 禁用 **不得** 逻辑删除或清空 `activeSignUpId` / 人员表  
- 禁用 **不得** 自动删除三年规划  
- 错误码与文案统一，便于 H5/后台展示

## 十一、结论

禁用应定义为 **「调研企业采集下线」**：停一切采集写入（含 H5），保留查看与主数据编辑，并可一键恢复。P0 不改表，集中在一个 `assertEnabled` + 前端只读态即可落地，与删除、列表筛选形成清晰分工。
