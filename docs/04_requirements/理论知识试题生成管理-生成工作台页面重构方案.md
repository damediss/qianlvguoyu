# 理论知识试题生成管理 —— 生成工作台页面重构方案

> 状态：**T1~T3 已实施（2026-09-09）**，T4 联调验收待真实环境走查
> 关联：`理论知识试题生成管理方案.md`（功能主体方案）、`理论知识试题生成-并发与成本优化方案.md`、复盘文档 §7~§9
> 已确认的关键决策（2026-09-09 与使用者确认）：
> 1. **合并为生成工作台**："生成任务 / 试题草稿 / 入库与导出"三页签合并为单一工作台页，取消批次下拉，批次总览表行内直达操作；"细目表导入"页签保留。
> 2. **草稿审核锁定批次 + 全部开关**：从工作台行进入草稿默认锁定该批次，提供"全部批次"开关支持集中过审。
> 3. **总览表完整型信息密度**：批次/时间/工种/等级/模型/状态（动效）/进度/审核进度/入库状态/操作一屏看全。

---

## 1. 背景与目标

### 1.1 现状问题

页面现有 4 页签（细目表导入 / 生成任务 / 试题草稿 / 入库与导出），其中 3 个页签靠"批次下拉框"选择操作对象：

| 下拉 | 位置 | 问题 |
|---|---|---|
| 细目表批次下拉 | 生成任务 | 随导入批次线性增长；label 超长截断（`09-09 10:52 · 重冶备料工（4级/中级工）理…`），等级/点数不可见 |
| 生成批次下拉 | 试题草稿、入库与导出 | 同上；纯靠逐行扫读"时间+短号+中文状态"辨认目标批次 |

且"工作进展与成果"分散在四处：生成进度在生成任务页表、审核进度只能逐批进草稿页数、入库状态要到入库页试选才知道。操作者每次任务都要经历"切页签 → 展开长下拉 → 辨认 → 选择"的循环。

### 1.2 目标

1. **取消全部批次下拉**：批次总览表即选择器，行内按钮直达草稿审核 / 入库 / 导出。
2. **一屏看全进展与成果**：每个批次的生成进度、状态、草稿审核进度、入库状态在总览表同行呈现。
3. **保留并扩展动态工作反馈**：已有"等待中持续变色 / 生成中呼吸光晕 / 进行中 Loading / 完成后自动联动"全部保留，并扩展到总览表行级进度。

## 2. 方案总览

### 2.1 页面结构（2 页签）

```
理论知识试题生成管理
├── 页签一：细目表导入（保持现状，仅两处微调）
│     工种/等级选择 + 上传 + 批次列表（已含权重校验明细、细目表下载）
│     └── 行内"生成"按钮：携带该批次上下文跳转工作台发起区（现状已有此按钮，行为不变）
│
└── 页签二：生成工作台（新）
      ┌─ 发起区 ─────────────────────────────────────────────
      │  [工种▾可搜索] [等级▾] [细目表批次▾(按工种+等级过滤，数据量小)]
      │  [模型▾] [单选n 道/点] [多选n 道/点] [判断n 道/点]
      │  [主观5分制 n 点/道] [主观10分制 n 点/道](仅二/一级可编辑)  [提交生成]
      ├─ 批次总览表（核心，替代三个下拉）─────────────────────
      │  时间 | 工种 | 等级 | 模型 | 状态 | 生成进度 | 审核进度 | 入库 | 操作
      │  ── 进行中批次置顶区（轮询行）：状态变色动效 + 进度条 + 数字跳动
      │  ── 历史批次分页区
      ├─ 草稿审核面板（选中批次后展开，页签内联不跳页）─────────
      │  [全部批次 开关] [审核状态▾] [题型▾] [批量通过] [批量驳回]
      │  草稿表格（展开行显示选项，现状功能保留）
      └──────────────────────────────────────────────────────
```

### 2.2 关键交互流

1. **发起生成**：细目表批次选择框改为按"工种 + 等级"二级过滤后再选批次（候选通常 ≤3 条，不再有长列表）；或直接由"细目表导入"行内"生成"按钮带入。
2. **进行中批次**：总览表进行中行实时轮询（3s），状态徽标变色/呼吸、进度条动画、点数/题数跳动（复用现有动效类）。
3. **完成联动**：批次转"已完成"时——消息提示 + 该行短暂高亮闪烁 + 操作列"草稿"按钮转主按钮；若草稿面板空闲（未锁定其他批次）则自动载入该批次草稿，不强制打断正在审核的批次（取代现在"强制跳页签"行为）。
4. **草稿审核**：点行内"草稿"→ 面板锁定该批次加载；"全部批次"开关开启后按时间倒序跨批次浏览（审核状态/题型过滤仍可用）。
5. **入库/导出**：行内"入库"弹确认 Modal（新建/追加任务模式、低于配额二次确认沿用现逻辑）；"导出"行内直接下载 xlsx（按钮 loading 保留）。

## 3. 详细设计

### 3.1 批次总览表（完整型列定义）

| 列 | 内容 | 说明 |
|---|---|---|
| 批次 | `MM-DD HH:mm` + 短号（`批次…5800193`） | 时间取 `startedAt ?? createdAt`（等待中批次 startedAt 为空，见 §4.1） |
| 工种/等级 | 工种名 + 等级中文（如"矿井通风工 · 技师"） | workTypeId/level 后端透出，工种名前端由工种树映射 |
| 模型 | modelId + 思考开/关标签 | 现状保留 |
| 状态 | 等待中（变色循环）/ 生成中（呼吸光晕）/ 已暂停 / 已完成 / 失败 | **沿用 `xmb-status-waiting` / `xmb-status-running` 动效**；失败态徽标挂 Tooltip 展示 `failReason`（自动补跑耗尽原因不再丢失） |
| 生成进度 | `已完成点/总点数` + 进度条 + `已产题 N 题（主观 M）`；进行中行进度条 `status="active"` 动画 | subjectiveCount 并入本列展示（不单独占列） |
| 审核进度 | `通过 X · 待审 Y · 驳回 Z`（草稿 review_status 分组计数） | 后端聚合，见 §4；审核操作后即时刷新（见 §5） |
| 入库 | `已入库 N` / 未入库 | 草稿 publishStatus=1 计数；入库后即时刷新 |
| 操作 | [草稿] 主按钮 + [更多▾]（暂停/继续/重试失败/补跑缺口/入库/导出） | 按状态条件显示（沿用现有条件规则）；菜单项 useMemo，避免 3s 轮询整树重渲染 |

- **进行中/等待中批次置顶**：**两个独立查询**——进行中区 `status=pending,running` 不分页（后端支持状态过滤，见 §4.1），历史区服务端分页；3s 轮询只作用于进行中区，历史分页不随轮询重拉。
- **排序**：进行中区按提交时间正序；历史区按 id 倒序。
- **列宽与滚动**：表格设 `scroll={{ x: 1200 }}`，各列给 minWidth；窄屏横向滚动不挤压。

### 3.2 草稿审核面板

- 默认隐藏；点"草稿"展开并锁定批次（面板标题显示批次标签，可关闭/收起）。
- "全部批次"开关：开启后批次锁定解除，草稿按创建时间倒序；**默认审核状态过滤为"待审"**（避免上千条全量草稿首屏翻页），开关旁标明当前过滤条件；**该模式下表格增加"批次"列**（时间+工种等级），便于识别来源。
- 批量通过/驳回、行内编辑 Drawer、展开行选项高亮——现状功能原样保留；**过审/编辑/入库成功后同步刷新总览表计数**（见 §5）。

### 3.3 发起区

- 细目表批次选择：`工种（可搜索，既有 worktypes 树）→ 等级 → 批次`三级联动；**批次候选走服务端按 workTypeId+level 过滤查询**（`listBlueprints` 已支持该参数），不再依赖 `pageSize:200` 全量拉取——细目表超过 200 条时发起区不会缺批次（顺带修掉现存隐患）。
- 配额区：沿用现有 5 个输入（含主观题轮转配额，仅二级/一级可编辑），推荐值按等级自动填入（现逻辑不变，取值来源改为过滤后的候选集合）。
- 提交后新批次出现在总览表进行中区，`activeBatchId` 自动接管（现逻辑不变）。

### 3.4 动效规范（保留 + 扩展清单）

| 动效 | 位置 | 状态 |
|---|---|---|
| `xmb-status-waiting` 变色循环 | 总览表状态列 | 保留 |
| `xmb-status-running` 呼吸光晕 | 总览表状态列 | 保留 |
| `LoadingOutlined` 旋转 | 进行中区标题 | 保留（移入进行中区行首） |
| 进度条 `status="active"` | 生成进度列 | **新增**（antd Progress 条纹动画） |
| 完成行高亮闪烁（一次 2s 淡入淡出） | 完成联动 | **新增**（CSS keyframes，跃迁后打一次即停） |
| 导入进度条 + 闪烁提示 | 细目表导入页签 | 保留 |

### 3.5 完成联动（替代"强制跳页签"）

现状：批次完成 → `message.success` + 强制切"试题草稿"页签。
新行为：
1. `message.success('批次已完成，已载入草稿')`（条件见 3）；
2. 总览表该行状态翻转（终态，轮询停止）+ 一次高亮闪烁；
3. 若草稿面板**未锁定任何批次**或锁定的正是该批次 → 自动载入该批次草稿；若用户正在审别的批次 → 仅提示，不打断。

**挂载位置**：完成联动与进行中轮询放在工作台组件内，但工作台页签加 `forceRender`（antd Tabs 未激活的页签默认不挂载；页面初始页签是"细目表导入"，不加 forceRender 则用户停在导入页签时收不到完成提示）。

## 4. 接口改动清单（后端）

### 4.1 `GET /exam/theory/gen/page` —— VO 扩展 + 状态过滤

**查询参数**：新增可选 `status`（逗号分隔，如 `pending,running`）——进行中区置顶查询用，避免前端全量拉取后自行过滤。

`TheoryGenBatchVO` 增加字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| workTypeId | Integer | 批次表已有列（V20260908_010），补透出 |
| level | Integer | 同上 |
| createdAt | LocalDateTime | 批次提交时间；时间列取 `startedAt ?? createdAt`（等待中批次 startedAt 为空） |
| approvedCount / pendingReviewCount / rejectedCount | Integer | 草稿按 review_status 分组计数 |
| publishedCount | Integer | 草稿 publishStatus=1 计数 |
| subjectiveCount | Integer | 主观题数（question_type ∈ 主观集合），并入生成进度列展示 |

实现：批次分页查出后，按 batchId 集合一次聚合（`QueryWrapper.selectMaps` + groupBy，租户/逻辑删拦截器自动生效，无需手写）：
```sql
SELECT batch_id, review_status, publish_status, question_type, COUNT(*) FROM exam_theory_gen_draft
WHERE batch_id IN (?) GROUP BY batch_id, review_status, publish_status, question_type
```
每页 10~20 个批次，聚合开销可忽略（`idx_etgd_batch (tenant_id, batch_id)` 覆盖）；无草稿的批次各计数为 0。

### 4.2 `GET /exam/theory/draft/page` —— batchId 改可选

- `batchId` 由 `@RequestParam(required=true)` 改为 `required=false`；为空时按租户 + 可选 reviewStatus/questionType 过滤、按创建时间倒序（"全部批次"模式）。
- 响应行附带批次展示信息：草稿实体已有 batchId/blueprintId，前端有批次数据可本地映射；**不需要**后端 join。
- 既有按 batchId 精确过滤的行为不变（向后兼容）。

### 4.3 新增索引（迁移 V20260909_002）

"全部批次"模式按 `created_at` 倒序跨批次翻页，现有索引均以 `batch_id` 为前缀，会走 filesort。新增：

```sql
ALTER TABLE exam_theory_gen_draft ADD KEY idx_etgd_tenant_time (tenant_id, created_at);
```

条件化 ADD INDEX（information_schema.statistics 判重，沿用踩坑 #7/#25 的 PREPARE 惯例），两库幂等。

### 4.4 不需要改动的接口

入库 `POST /exam/theory/draft/publish`、导出 `GET /exam/theory/draft/export`、暂停/继续/重试/补跑、模型配置列表——全部沿用。

## 6. 兼容与迁移

- **路由不变**：菜单/权限码（`exam:theory:blueprint:*` / `exam:theory:gen:*` / `exam:theory:draft:*`）不动，菜单数据无需改。
- **一次性切换**：旧三页签直接替换为工作台，不留并存入口（决策已确认）；旧页签内的全部功能（配额、暂停/继续/重试/补跑、批量审核、编辑、入库二次确认、导出）逐项对照迁移，无功能阉割。
- **接口向后兼容**：`draft/page` 的 batchId 改可选不影响旧调用（传了照旧精确过滤）；`gen/page` 只增字段不改语义。
- **历史数据**：无迁移；总览表历史批次审核/入库计数由聚合查询现算。

## 7. 测试与验收

### 7.1 后端

- 批次聚合统计单测：多批次 × 各 review_status/publish_status/题型的组合计数并入 VO；无草稿批次计数为 0。
- `gen/page` status 过滤：传 `pending,running` 只返回进行中批次；不传行为不变。
- `draft/page` batchId 为空路径回归：不传时按租户过滤 + 时间倒序；传了时行为与现状一致。

### 7.2 前端

- 组件单测：状态徽标动效类挂载（pending/running 各带对应 className）、审核进度渲染（通过·待审·驳回）、进行中置顶区排序、"全部批次"开关切换数据源。
- 完成联动：跃迁后高亮类出现一次、草稿面板空闲时自动载入。

### 7.3 手工验收清单

1. 发起一个二级批次（带主观配额）→ 进行中区出现变色/呼吸动效、进度跳动；
2. 批次完成 → 提示 + 行闪烁 + 草稿自动载入（不打断正在审的批次）；
3. **停在"细目表导入"页签时批次完成 → 同样收到提示**（forceRender 验证）；
4. 总览表直接行内"入库/导出"，不再出现批次下拉；
5. **批量过审/编辑/入库后，总览表"审核进度/入库"列即时更新**（终态批次轮询已停，靠操作后刷新）；
6. "全部批次"开关跨批次审核（默认只显示待审）；
7. 五/四级批次主观配额输入置灰（沿用现状规则）。

## 9. 风险与注意

1. **轮询成本**：进行中区 3s 轮询（含聚合 SQL）。聚合按当前批次集合分组且走 `idx_etgd_batch`，量级可忽略；历史区与草稿面板不随轮询重拉。
2. **总览表分页**：历史区服务端分页（10/页）；进行中区由 `status` 过滤独立查询（不分页），避免进行中批次被翻到第 2 页看不到。
3. **跨批次草稿编辑**：全部批次模式下编辑/批量审核按行操作，行内显示批次来源列避免误审。
4. **完成联动行为变更**（强制跳页签 → 条件载入）需在验收清单里明确告知使用者。
