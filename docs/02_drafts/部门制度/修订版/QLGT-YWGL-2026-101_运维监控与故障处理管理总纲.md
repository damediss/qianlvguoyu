# 千铝工投云平台与智能体开发部运维监控与故障处理管理总纲

制度编号：QLGT-YWGL-2026-101　　版本：V1.1　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为规范部门云平台运维工作，保障各业务系统安全、稳定、高效运行，明确运维组织职责与制度衔接关系，特制定本制度。本制度是运维制度体系的顶层文件。

**第二条**　本制度体系借鉴“驾驭工程”（Harness Engineering）理念：AI 是跑得快的“野马”，制度是缰绳与马鞍。制度的目的不是束缚团队，而是为人与 AI 的协作建立共同语言与质量底线。全体制度条款按“像代码一样”的标准设计：简洁，每条只讲一件事；可测试，每条可检查、有证据；可维护，职责单一、版本化管理；持续迭代，定期评审修订。

**第三条**　本制度适用于部门负责运维的全部系统及其承载资源，包括：培鉴赛 SaaS 平台（platform-api 后端、admin-web 管理端、学员端小程序/App）、PHP 存量平台、仿真训练平台（含私有化部署项目）、扣子/n8n 自动化工作流，以及腾讯云账号下的云服务器、数据库、缓存、对象存储等资源。

**第四条**　运维总体目标：（一）核心系统月度可用性不低于 99.5%；（二）P0 级故障 2 小时内恢复、P1 级故障 4 小时内恢复；（三）变更成功率不低于 95%，所有变更可回退；（四）备份可恢复率 100%，恢复演练每季度不少于 1 次。上述目标值按《制度体系总览与对标映射》附录 A 分档口径对齐，其中核心系统月度可用性纳入附录 A 乙档基线考核（2026 年只建基线不计分）。

**第五条**　运维工作基本原则：（一）线上优先，故障处置先恢复、后定责；（二）变更必有回退方案，无回退方案不变更；（三）操作留痕，所有生产操作有记录、可追溯；（四）最小权限，按需授权、定期回收。

## 第二章　运维组织与职责分工

**第六条**　运维组织设三类角色：运维负责人、值班人、产品线运维接口人。运维负责人由部门负责人兼任，负责制度制定与修订、重大变更与故障升级的审批决策、月度运维指标评审。

**第七条**　值班人按 3 人轮值表轮值（周轮换），负责当值期间的告警首响、日常巡检、故障接报与升级。值班表于每周最后一个工作日前排定并在部门群公示；换班须经运维负责人同意并留痕。

**第八条**　产品线运维接口人按 3 组设置：SaaS 平台组（含培鉴赛 SaaS 平台、PHP 存量平台、小程序/App）、仿真与私有化组（含仿真训练平台及私有化交付项目）、工作流与第三方组（含扣子/n8n 自动化工作流）。每组设 1 名接口人，负责本组内各系统的日常巡检、发布执行、台账维护与文档更新。

**第九条**　值班人交接须当面或书面交接未闭环事项，包括进行中的故障单、待执行变更、告警待办，交接记录留存于运维群或工单系统。

## 第三章　制度体系地图与各制度衔接关系

**第十条**　运维制度体系由本总纲与 9 项专项制度组成，研发侧另有 9 项制度与运维制度配套衔接。各制度职责单一，执行中如与专项制度不一致，以专项制度为准；专项制度之间冲突时，由运维负责人裁定并推动修订。

| 编号 | 制度名称 | 主要衔接关系 |
|---|---|---|
| YW-01 | 运维监控与故障处理管理总纲 | 顶层文件，统领全部运维制度 |
| YW-02 | 云资源与环境管理制度 | 资源与环境是所有运维活动的载体 |
| YW-03 | 账号与访问权限管理制度 | 为 YW-05/06/08/09/10 提供权限约束 |
| YW-04 | 监控与告警管理制度 | 告警是 YW-06 故障流程的主要入口 |
| YW-05 | 变更与发布管理制度 | 变更执行依赖 YW-08 备份与 YW-04 监控 |
| YW-06 | 故障与应急管理制度 | 复盘改进项回流 YW-04/05/07/09 |
| YW-07 | 容量与性能管理制度 | 扩容执行走 YW-02 资源流程 |
| YW-08 | 数据备份与恢复管理制度 | 为 YW-05 回退、YW-06 应急提供数据保障 |
| YW-09 | 安全运维管理制度 | 安全事件按 YW-06 分级处置 |
| YW-10 | 平台交付与客户培训管理办法 | 现场运维遵循 YW-03/09 安全要求 |

**第十一条**　新系统上线或新资源启用前，运维负责人须确认其落入上述制度的管辖范围；无对应制度的，先补充制度再上线。

## 第四章　运维工作流程总览

**第十二条**　日常运维主链路为：值班巡检 → 监控告警 → 变更/发布 → 故障处置 → 复盘改进。各环节的执行细则分别由 YW-04、YW-05、YW-06 规定，本制度只规定衔接要求。

**第十三条**　每日巡检由值班人按巡检清单执行，覆盖：核心服务可用性、主机资源水位、数据库与缓存状态、备份任务执行结果、证书与域名有效期。巡检结果当日记录，异常项转告警或工单处理。

**第十四条**　所有生产环境变更（含应用发版、配置调整、数据订正）一律走 YW-05 变更流程；故障处置一律走 YW-06 故障流程；禁止绕开流程直接操作生产环境。

**第十五条**　复盘输出的改进项须明确责任人与完成期限，纳入周检表跟踪，直至闭环。

## 第五章　监督考核与制度修订机制

**第十六条**　运维负责人每月召开运维例会，评审：可用性、故障次数与恢复时长、变更成功率、备份演练结果、告警响应及时率等指标的达成情况，形成月度运维报告。

**第十七条**　制度执行情况纳入部门月度绩效考核，对应指标包括运维工单响应处置及时率、交付物一次验收通过率等，按部门 KPI 考核办法执行。

**第十八条**　制度每季度评审一次，评审人包括运维负责人与各 3 组接口人。修订采用版本号管理（如 V1.0 → V1.1），修订内容、原因、生效日期留痕归档；条款无法检查或长期无人执行的，一律改写为可检查条款或删除。

**第十九条**　任何团队成员均可对制度条款提出修订建议，提交运维负责人，在最近一次季度评审中处理并答复。

## 第六章　附则

**第二十条**　本制度由部门负责人负责解释。

**第二十一条**　本制度自发布之日起施行，此前与本制度不一致的运维相关规定同时废止。
