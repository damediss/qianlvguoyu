# 知识归属修正接入 bocha-jev-v1 分层改造方案

> 状态：v0.9 · **代码实施完成**（2026-09-28：后端+前端+迁移+67 单测全绿；本地可验证的测试/验收项已全部勾选，生产相关 4 项待 §13 步骤 8 部署后实测——见 §11.4/§12 标注）
> 关联功能：课程管理 / 资源管理 / 知识归属修正（`exam/knowledgefix`）
> 决策背景：owner 明确——**不做影子跑批；接受精度下降；接受分层处理；目标是砍掉成本大头；低置信的行才走现有 LLM（要理由）；执行中途必须可暂停；成本优先于精度**
>
> **术语约定（2026-09-28 统一语言）**：本文与代码 UI 中，**apply=改挂**（建议改挂到其他知识点，待写回落地）、**keep=保留**、**flag=存疑**（自动判定无把握，需人工定夺）、写回=把改挂建议写进题库。四个中文词为唯一表述，禁用"应用/采纳/待关注/可疑"等旧译名；数据库状态码（'apply'/'keep'/'flag'…）为内部标识符，不属同义词范畴，保持不变。

## 1. 背景与现状

### 1.1 现有流程（KnowledgeFixClassifyService）

每行试题当前走"两阶段 + 三采样自一致 + 旗舰升级"：

1. 阶段 1：L2 章节粗分，1 次调用（`theory-gen-glm`）
2. 阶段 2：L3 鉴定点细分，**3 次采样**多数投票（同模型）
3. 三票各不同 → 升级旗舰模型复判（`knowledge-fix-pro`，第 5 次调用）
4. 确定性卫兵（关键词零重合拦截）+ keep 判定 + 置信 0.7 分层

即每行 **4~5 次 LLM 调用**，且均为生成式调用（输出 JSON 文本）。

### 1.2 成本现状（批次 67612419 实测）

| 指标 | 值 |
|---|---|
| 总行数 | 8805 |
| 累计 LLM 调用 | 9,217 次 |
| 累计 tokens | 494.8 万（缓存命中 147.1 万） |
| 失败重试 | 384 次 |
| 质量门禁 | 未分类 75%（上限 5%）、自一致率 0.7178（下限 0.80）→ 未达标禁止写回 |

### 1.3 Jev 是什么（已核对官方文档 + 真实接口探针，见 §4）

bocha-jev-v1 是博查团队自训、上线在 TokenDance 的**决策型模型**（非生成式），协议与 TypeSafe Jev（上游原版 jev-1.13）同构：

- 输入一段文本 + 预定义选项，**一次请求直接返回各选项的概率分布 + 最优选项 + 置信度**，不生成任何文本
- 支持三种题型：`choice`（多选一）、`noul`（是/否判断）、`score`（分级评分）；一次请求可含多个问题共享同一 state
- TokenDance 模型页口径（2026-09-27）：端到端延迟平均 **142ms**，近 7 日可用性 **93.8%**，价格 **¥0/M tokens（限时免费）**；上游官方定价 $0.042/M 输入 token、输出免费
- **本机真实探针实测（2026-09-27，合成数据）**：端到端（含网络+网关）约 **1.0s（3 选项）~ 5.6s（255 选项）**，单次推理 `metadata.inference_ms=6.2ms`——e2e 延迟随选项数增长，批次耗时按 e2e 口径估算（§7）；`usage.input_tokens=70 / output_tokens=0`（输出真实为 0）
- 响应 metadata 实测：`checkpoint_status: trained`、`checkpoint_id: bocha-jev-v02`、`calibrated: true`（上游 jev 标 experimental，谨慎等级不降）；TokenDance 侧配置了**双服务商路由（博查 / TypeSafe Jev），请求自动路由、故障自动切换**——同一模型的实际应答方可能漂移（见 §9 风险 3/4）

## 2. 改造目标与边界

| 项 | 目标 |
|---|---|
| 成本 | **第一优先级**：砍掉成本大头（生成式调用量预计下降 60% 以上；限时免费期内 Jev 侧成本为 0，真实成本只剩 LLM 兜底行） |
| 精度 | **不追求高准确率**，接受概率直判的误差（边界见 §7.1） |
| 速度 | 批次耗时大幅下降（实测 e2e 1~5.6s/次 vs 生成式数秒 × 4~5 次串行；且单行调用数从 4~5 降到 1~2） |
| 理由 | Jev 不产生文本理由；仅未过双门的行走现有 LLM 补理由 |
| 可暂停 | 批次执行全程可人工暂停、断点续跑（见 §10） |
| 写回 | 不变——仍只有 apply 行可人工点"执行写回"，写操作人工确认（LLM 规范 #6/#10） |

明确不做：**不做影子跑批、不做双模型对比评估**（owner 决策）。

## 3. 目标流程（分层设计）

```
每行试题：
  │
  ├─ 通道开关：knowledge-fix-jev 配置行缺失或 status≠enabled → 本批次 0 次 Jev，
  │     全部行走 LLM（红线回退语义：安静降级不计失败——见 §5 首行，禁止抛错）
  │
  ├─ 前置拦截：该课程无存活 L2（criteria 为空）→ 不发请求，直接降级 LLM
  │     （实测 2026-09-28：空 criteria 422 `min_length=2`——选项至少 2 个；拦截条件 = <2 或 >255）
  │
  ├─ Jev 阶段1：L2 粗分（1 次 choice，criteria = 该课程 L2 章节列表）→ l2_id + conf₁
  │     ├─ conf₁ < θ₁ → 降级走现有 LLM 全流程（L2 都拿不准，阶段2 无意义）
  │     ├─ 所选 L2 下无存活 L3 → L2 直收尾（沿用现有业务裁定，basis=jev-l2-direct）
  │     └─ Jev 调用失败/超时/连续失败 ──→ 降级走现有 LLM 全流程（§5）
  │
  ├─ Jev 阶段2：L3 细分（1 次 choice，criteria = 该 L2 下鉴定点列表）→ node_id + conf₂
  │
  ├─ keep 判定：node == 当前挂载节点 → keep（防过度修正，沿用；阈值不拦截 keep）
  ├─ 确定性卫兵：关键词零重合且非素养节点 → flag（沿用）
  │
  └─ 置信分层（双门，阈值进配置：θ₁ / θ₂ 配置默认均为 0.5，与小批次起步一致——
        绿灯后按 §7.1 边界人工改配置逐级放开 θ₂ → 0.4 → 0.3，下限 0.3）：
        conf₁ ≥ θ₁ 且 conf₂ ≥ θ₂ → apply（basis=jev，无理由文本）
        否则 → 走现有 LLM 全流程（三采样 + 旗舰升级，产出 reason）
               该行的最终结论与置信以 LLM 结果为准（basis=llm / llm-pro）
```

> 【为什么保留双门（认同同事 v0.2 修订①）】最终答案正确 = 阶段1 对 × 阶段2 对（阶段2 只在阶段1 选定的 L2 内判别）。若只卡 conf₂，会放过"L2 选错、但在错误 L2 内高置信"的自信错误直接落 apply。该修订数学上成立，保留。
>
> 【为什么 θ₂ 可以比 θ₁ 低（owner 成本优先决策）】两类错误的代价不对称：**L2 错 = 整道题挂进错误章节**（高代价，且 L2 候选少、conf₁ 天然偏高，θ₁=0.5 拦得住也花不了多少兜底成本）；**L3 错但 L2 对 = 同章节内挂错相近鉴定点**（低代价，owner 已明确接受低精度，且有卫兵 + 导出人工抽查 + 写回人工确认 + 可回滚四层兜底）。L3 候选动辄几十个，概率分布天然更平，是被阈值卡进 LLM 兜底的**主力来源**——θ₂ 放开到 0.4/0.3 是单点最大的省钱杠杆。放开的节奏与限度按 §7.1 边界执行，不一步到位。
>
> 【被否的备选：乘积门 conf₁×conf₂ ≥ 单阈值】数学上更优雅（近似联合概率），但 θ 的含义对运营不直观、调参时要同时心算两个数，且与"阶段1 不过就不发阶段2"的短路逻辑冲突。复杂度不值，否决。
>
> 【阈值口径已实测闭环（§4-F2）】bocha 侧 confidence = 最大候选概率（maxP），θ 语义明确；路由漂移到 TypeSafe 侧时口径切换为分布形状推导（更严格，行更多落入兜底——方向安全，见 §9 风险 4）。θ 终值仍以 §13 步骤8 小批次实测置信分布校准。

与现状的差异点：

| 环节 | 现状 | 改造后 |
|---|---|---|
| L2 粗分 | 生成式 1 次 | Jev choice 1 次（e2e 实测 1~5.6s，输出免费） |
| L3 细分（过双门的行） | 生成式 3 次采样 | Jev choice 1 次 |
| L3 细分（未过双门的行） | 同上 | **不变**，现有 LLM 三采样 + 旗舰升级 |
| 自一致率 | 3 采样多数票 | 高置信行不再存在该概念；仅 LLM 兜底行保留 |
| 理由 | 每行都有 | 仅兜底行有；Jev 行 reason 为空 |
| 每行调用数 | 4~5 次生成式 | 1~2 次 Jev + 4~5 次 LLM（仅兜底行；占比为假设，待小批次实测校准，见 §7） |

## 4. 字段核对结果（v0.5：文档核对 + 真实接口实测，2026-09-27 合成数据探针）

请求形态（已按官方 API 参考确认，阶段 1 同理，criteria 换成 L2 列表；**base_url 实测锁定：`https://tokendance.space/gateway`，注意 `/gateway` 前缀**）：

```json
POST https://tokendance.space/gateway/typesafe/v1/systemone
Authorization: Bearer <key>
{
  "model": "bocha-jev-v1",
  "state": "【试题】<题干+选项答案+解析，stripTags 后>",
  "questions": {
    "l3": {
      "type": "choice",
      "instructions": "该试题真正归属的鉴定点",
      "criteria": { "<nodeId1>": "<标题1>", "<nodeId2>": "<标题2>", "...": "..." }
    }
  }
}
```

返回取 `answers.l3.choice`（= criteria 的 key，即 nodeId，**实测原样回传**）、`answers.l3.confidence` 与完整 `probabilities` 分布（实测含全部 criteria key）。

| # | 待核实项 | 结果 | 依据 |
|---|---|---|---|
| 1 | criteria 能否做 id→标题 映射 | ✅ **可以（实测）**。key 自定义（放 nodeId 字符串），value 放标题/描述或 null；`choice` 返回 key 原样回映射 | 官方 API 参考 + 实测 |
| 2 | 选项数量上限 | ✅ **每个 Choice 最多 255 个选项，实测确认：255 通过 / 256 被拒（422）**。我们 L2/L3 远低于此；>255 的行降级 LLM | 官方 API 参考 + 实测 |
| 3 | state 长度上限 | ✅ **每请求 64k tokens；state + 最长单个 question ≤ 32k**。纯文本（string/object/array），不支持图像。题干+解析远低于此；超限防御性截断 | 官方 Models 页 |
| 4 | 错误码 / 协议兼容 | ✅ **非 OpenAI 协议**（独立 client 确认必须）。**401/422 已实测**：401 返回 JSON `{"code":"unauthorized","message":"API 密钥不存在"}`；422 返回校验数组（`detail[].loc` 精确指向出错字段，256 选项实测命中 criteria；**空 criteria 实测 422 `min_length:2`（2026-09-28 补测）——选项至少 2 个，单选项同样拒绝**）；429/529 为文档口径，遵循 retry-after | 官方 API 参考 Errors 节 + 实测 |
| 5 | usage 字段 | ✅ **实测确认**：`usage.input_tokens=70`、`usage.output_tokens=0`（合成探针，输出真实为 0）。审计直接取真实 usage，无需估算；"估算兜底"仅为防御分支 | 实测 |
| 6 | 限流/并发上限 | ⚠️ 上游 jev-1.13：250k tokens/s + 1200 req/min，**官方声明动态调整**；**TokenDance 免费期配额未见公开文档** → 独立并发上限保守起步（默认 5），小批次实测摸顶 | 官方 Models 页 + TokenDance 无公开说明 |
| 7 | 免费期后价格 | ⚠️ TokenDance 当前 ¥0/M（限时免费）；上游 $0.042/M 输入。免费期结束时间/后续价未公布 → 成本测算按上游价做保守锚点 | TokenDance 模型页 |

### 文档核对的两项重要新发现

**F1 · 中文精度是本方案最大的未知数（比阈值更大）**：上游 jev 官方明说"主训练语言为英文，CJK 语言可用但精度更低"。bocha-jev-v1 是博查自训国产版，中文表现无公开基准。**2026-09-27 合成探针 1 例：极简单的中文选择题答错（问"描述的物品是什么"，正确"自行车"选成"汽车"，maxP 0.40）**——n=1 不作结论，但与上游声明方向一致。→ §13 步骤8 小批次**必须含中文准确率人工抽查**（不只置信分布；**抽 50 行**——n=30 的统计区分力不足以分开 10% 与 20% 错误率，见 §7.1），结果按 §7.1 三色边界处置。

**F2 · confidence 口径（bocha 侧已实测闭环）**：TypeSafe 官方 confidence 由概率分布形状推导（文档示例公式 `(n×maxP−1)/(n−1)`，n 为选项数）；**2026-09-27 实测 bocha 侧响应 `metadata.confidence_definition = "maximum candidate probability; not guaranteed correctness"`、`calibrated: true`——confidence 就是最大候选概率（maxP）**。两侧不是同一个数，且路由漂移到 TypeSafe 侧时口径会切换。→ 实现要求：审计落库必须记录 `metadata.confidence_definition` 与 top1/top2 概率；θ 终值按实测置信分布校准——bocha 侧 maxP 口径已确认，θ₂ 的下探空间比分布形状口径更大（分布平不平不影响 maxP 读数）。

**criteria 区分度可选增强（保留同事 v0.2⑧）**：criteria value 官方支持"标题 + 描述"结构；语义相近的鉴定点可放"标题 + 关键词"，提升区分度（输入 token 增加但当前免费/单价极低），两种形态小批次对比后定稿。

## 5. 降级与异常路径（规范 #4）

| 场景 | 行为 |
|---|---|
| **Jev 配置行缺失或 status≠enabled** | **通道关闭语义（红线回退 = 停用配置行）**：本批次 0 次 Jev，全部行直接走 LLM 全流程，不计失败（info 日志一条便于审计）。**禁止复用 requireConfig 的 NOT_FOUND 抛错语义**——现有代码对缺失配置抛错（KnowledgeFixClassifyService.requireConfig），照搬会把红线停用变成批次失败 |
| 候选为空（课程无存活 L2 / criteria 空） | **不发请求**，该行直接降级 LLM，不算失败（实测空/<2 均 422 min_length=2，client+service 双层前置拦截） |
| Jev 单行调用超时/5xx/解析失败 | 该行降级走现有 LLM 全流程，计 basis=llm-fallback |
| Jev 连续失败 ≥ 5 次（沿用熔断阈值） | 本轮停止派发 Jev，剩余行全部降级 LLM；批次不失败 |
| Jev 返回 401/422 | 401=配置错误：立即熔断整批转 LLM 并 warn 告警（密钥错不会因重试变好；**实测 401 为 JSON `{"code":"unauthorized"}`，客户端可稳定识别**）；422=请求构造 bug：该行记失败并跳过，连续 422 ≥5 次熔断（**实测 422 为校验数组，`detail[].loc` 指向出错字段**） |
| Jev 返回 429/529 | 按指数退避重试（遵循 retry-after）；连续限流计入"连续失败"熔断口径；Jev 并发上限独立配置（默认保守值 5），不与 LLM 并发池混用 |
| Jev 返回的 choice 不在 criteria 内 | 视为确定性卫兵拒绝（GuardRejectException 语义），行降级 LLM |
| criteria 数量 >255（官方上限，**实测确认：255 通过 / 256 拒绝**） | 该行直接降级 LLM，不算失败 |
| Jev 阶段2 失败而阶段1 已成功 | 仍降级 LLM **全流程**（含 LLM 自己的阶段1），不复用 Jev 的 L2 结论，避免"Jev L2 + LLM L3"混合归因 |
| 降级 LLM 也失败 | 沿用现有重试/未分类收尾逻辑 |

降级路径复用现有 `classifyRow` 的 LLM 分支，不新写流程。**近 7 日可用性 93.8%（TokenDance 口径，≠单请求成功率，重试可吸收部分瞬时故障）意味着最坏情况每批约 6% 的行走降级分支**，降级路径不是摆设。

## 6. 质量门禁调整

现有两项门禁在三采样消失后口径失效，按 owner"精度不用很高"的决策调整：

| 门禁 | 现状 | 改造后 |
|---|---|---|
| 未分类占比 ≤ 5% | 卡批次 failed | **保留不变** |
| 自一致率 ≥ 0.80 | 卡批次 failed | **不再卡门禁**。仅对 LLM 兜底行统计并展示（样本太少时无统计意义）；Jev 行改展示"平均置信度 / 未过双门占比"作为信息项 |
| 写回控制 | 仅 apply 行可写回 | 不变，且写回仍是人工点击（人工确认环节不省） |

批次统计字段新增：Jev 分类数、LLM 兜底数、Jev 平均置信度；审计表 `exam_knowledge_fix_llm_log` 的 `stage` 增加 `jev-stage1` / `jev-stage2` 取值，`model_id` 记响应实际返回的 model 字段（路由可能漂移，见 §9 风险 3/4），输出 token 记实际 usage（LLM 规范 #10 全程可审计）。

## 7. 成本测算（估算，实测为准）

以 8805 行为例。**核心假设：双门通过率（conf₁≥θ₁ 且 conf₂≥θ₂ 的行占比）为 70%——这是无实测依据的假设**，且与 criteria 规模、confidence 口径（§4-F2）强相关，小批次实测前只作量级参考：

| 部分 | 估算 |
|---|---|
| Jev 部分 | **限时免费期内为 ¥0**；免费期后按上游 $0.042/M 输入锚点：8805 行 × 1~2 次 × 约 800~1500 输入 token ≈ 700~2600 万输入 token ≈ **$0.3~1.1** |
| LLM 兜底部分 | 兜底行 × 4~5 次生成式 ≈ **现状成本 × 兜底占比**（兜底 30%/50%/70% → 综合降幅约 70%/50%/30%） |
| 对比现状 | 兜底行以外的生成式调用全部消失，Jev 侧当前免费；**综合成本 ≈ 现状 × 兜底占比**（免费期内再减 Jev 零头） |
| 批次耗时 | Jev 约 0.9~1.8 万次 × e2e 1~5.6s（**实测，随选项数增长**；默认 5 并发下纯 Jev 部分约 1~3 小时，选项少的课程偏下限，并发摸顶后可显著压缩）+ 兜底行 LLM 时间；整体显著快于现状（单行少 3~4 次生成式串行调用），准确值小批次回填 |

**阈值敏感性（θ₂ 是唯一大杠杆）**：综合降幅 ≈ 1 − 兜底占比，兜底占比几乎全部由 θ₂ 决定（L2 候选少，conf₁ 普遍高，θ₁ 卡掉的行少）。**θ₂ 的起步、放开与下限一律按 §7.1 边界执行**：配置默认 0.5 保守起步测精度，绿灯后才逐级放开 0.4 → 0.3——每次放开 = 直接换钱，精度损失由四层兜底承接（§9 风险 2）。

> **基线矛盾待核对（同事 v0.2②，保留）**：§1.2 实测 9217 次调用 ÷ 设计口径 4~5 次/行 ≈ 仅 2000 余行真正走完全流程，与 8805 行总数不符（大量行应是 keep/免调通行）。兜底行成本测算的基线必须以审计表按行核对为准，本节仅保留量级判断。

### 7.1 成本-精度边界（v0.6 新增，owner 已认可；小批次实测与后续每批次按此执行）

**起步参数（第一轮小批次）**：

| 参数 | 起步值 | 说明 |
|---|---|---|
| θ₁ | 0.5 | 不动：L2 错 = 整章错挂，高代价 |
| θ₂ | 0.5（**与配置默认值一致**——v0.7 修正：配置默认即 0.5，杜绝首轮误按 0.4 跑） | 中文精度未验证（§4-F1 探针答错 1 例），第一轮必须在"Jev 行最可信"的阈值下测精度，把精度测量与阈值选择分开；绿灯后按三色边界放开 |
| Jev 并发上限 | 5 | 按方案，小批次摸顶 |

**三色边界**（人工抽查对象 = apply 行，**抽 50 行**——n=30 时 10% 与 20% 错误率在统计上分不开（±11% 噪声），n=50 才有区分力，人工量约 1 小时；判卷口径从宽：归属说得通即算对，避免苛判偏差）：

| 读数 | 判定 | 动作 |
|---|---|---|
| 错误率 ≤10%（≤5/50）**且错 L2 = 0** | 🟢 绿灯 | θ₂ 按实测置信分布下调追成本（改配置对下一批次生效），下限 0.3；按方案推进 |
| 10~20%（6~9/50）**或错 L2 ≥1** | 🟡 黄灯 | 收紧不复议：θ₁ 0.5→0.6、θ₂ 保持 0.5、criteria 改"标题+关键词"重跑小批次；仍 >10% 再升级讨论 |
| >20%（≥10/50）**或错 L2 ≥3** | 🔴 红线 | 把 `knowledge-fix-jev` 配置行 `status` 置 disabled（即 §5 首行的通道关闭语义），整批回现有 LLM 全流程（降级路径即回退路径，不改代码）；方案复议，等中文更优 checkpoint 再试 |

**成本侧**（同一次小批次读数）：双门通过率 ≥60% 按方案推进；50~60% 降级为"可接受"，§12 验收线相应下调；**<50% 建议放弃接入**——新 client/审计/状态的复杂度换不到一半降幅不值，且通过率低通常与精度红线同源（模型吃不准中文）。

**硬底线（任何时候不为省钱突破）**：

1. θ₂ ≥ 0.3——maxP 口径（§4-F2 实测）下再低接近概率噪声档，人工兜底成本反噬
2. 未分类 ≤5% 门禁、写回人工点击、可整体回滚——三件套不动
3. **每个真实批次写回前抽查 50 行 apply 行，>20% 该批次不写回、复位走 LLM**——成本压力下最容易被顺手省掉的闸，预先钉死；连续两批绿灯后可降为 30 行/批

**边界依据**：错挂与漏挂不对称——这批行现状多为未分类，漏挂对组卷是无害中性态（蓝图采不到），错挂是**主动污染**（蓝图按错误知识点抽到不考它的题，伤考证培训的组卷效度），故精度底线不因"现状本就差"无限下移；20% 红线的含义 = 超过后人工抽查自身不可信、四层兜底实际失效，等于把污染批量写进题库；错 L2 单独计数（章节级错误），绿灯零容忍。

## 9. 风险与限制

1. **新模型 + 限时免费**（实测 `checkpoint_status: trained`、bocha-jev-v02，但模型仍新）：稳定性与免费政策可能变化；降级路径必须真实可用，不能形同虚设
2. **精度未知且不做验证**：按 owner 决策接受，但失败模式写明——Jev 是小参数决策模型，**对语义相近的长尾知识（相近鉴定点互混）判别最弱**，典型错误是"高置信选错相近节点"；零重合卫兵只拦"完全无关联"的错配，拦不住"相近但不零重合"。兜底 = 双阶段置信门 + 卫兵 + 人工抽查清单 + 写回前人工确认 + 可整体回滚
3. **中文精度 + 服务商路由双重不确定**：上游 jev 官方明说 CJK 精度更低；bocha 自训版中文表现无公开基准（合成探针 1 例答错，n=1 不作结论）；TokenDance 双服务商（博查/TypeSafe Jev）自动路由意味着**同一批数据可能部分被英文原版应答**，行间精度不一致。对策：审计记录响应 model 字段（§8.8）；小批次抽查中文准确率 50 行（§7.1/§11.4）；若漂移明显，向 TokenDance 询问是否可固定服务商
4. **confidence 口径随路由切换（v0.7 补充处置）**：bocha 侧实测 maxP（§4-F2），TypeSafe 侧为分布形状推导（同 maxP 下选项越多数值越低）。**被路由到 TypeSafe 口径的行天然更保守**（confidence 偏低 → 更多落入 LLM 兜底）——方向安全，无需特殊处理；但兜底占比会随 TypeSafe 流量占比上升，若小批次发现该占比显著（审计 model 字段可观察），向 TokenDance 申请固定服务商再谈 θ 校准
5. **可用性 93.8%**：最坏情况约 6% 的行会走降级，兜底 LLM 成本比静态测算略高；熔断与降级按 §5 执行
6. **Jev 行无理由**：导出清单中 Jev 行的理由列为空，审核人只能看置信度；若后续审核体验差，可把 θ₂ 上调——只改配置不改代码
7. **选项上限 255（已核实）/ 空候选**：超过 255 或候选为空的行降级 LLM（成本上升但流程不断）
8. **数据外发面**：试题题干/选项/解析将发送至 TokenDance（路由至博查或 TypeSafe），与现有生成式 LLM 调用同级，无新增敏感数据类别；Jev 客户端同样收敛在 `ai/` 包并全程审计（规范 #10）

## 10. 暂停与恢复（执行中途可暂停）

批次执行全程可人工暂停，机制沿用现有 FIX-10 通道并做一处加固：

| 能力 | 行为 |
|---|---|
| **暂停入口** | 页面"暂停"按钮 → `POST /exam/knowledgefix/classify/pause`（现有接口，权限沿用 `classify:submit`） |
| **暂停语义** | 编排线程在**每一行派发前**检查暂停标志：命中即停止派发新行；已派发（在飞行）的行跑完当前调用后收尾——Jev 行 ≤ 超时×重试次数的预算（read 30s × 重试次数，约 1~2 分钟级）、LLM 兜底行 ≤120s（踩坑 #18：pause 不中断已提交的长调用，靠行粒度天然够小） |
| **暂停收尾** | 批次置 `paused`，写明"已分类 done/total"；**剩余行保持 pending，不写"批次中断未分类"兜底**，不触发质量门禁 |
| **恢复** | 再点"提交分类批次"，新批次只覆盖剩余 pending 行；已完成行（apply/keep/flag）结论不受影响 |
| **费用失控场景** | 进度接口已含累计 token 用量，页面上看到费用/异常超预期 → 直接暂停 → 排查后复位重跑或继续 |

**加固点（本次新增）**：现有暂停标志是纯内存态（`pauseRequests` 集合），**进程重启即失效**——重启后编排线程已死倒也无碍，但若暂停与重启重叠，语义模糊。改造为"内存标志 + 批次表状态"双判：暂停时同时把批次行 `status` 置为 `pausing`，派发边界两处都查（每行一次主键查，开销可忽略）；进程重启后若有 `pausing/running` 遗留批次，启动时统一收尾为 `paused`，剩余行仍是 pending 可续跑。

**复位与互斥口径（v0.7 补齐）**：flag 行可"复位并重跑"；`paused` 视为无进行中批次，可复位可再次提交；**`running/pending/pausing` 三种状态下 reset 与重复 submit 均被拒**（`pausing` 是暂停过渡态，在飞行行未收尾，reset 会与之竞态）。
