# 三个月数字化与 AI 建设计划（草稿）

版本：讨论稿 v0.1  
日期：2026 年 4 月 29 日  
周期：三个月

## 一、总体思路

未来三个月数字化与 AI 建设，不先做大而全的平台，也不做脱离业务的 AI 展示，而是围绕当前最急的培训、竞赛、课程、知识库和项目交付，先形成可使用、可验收、可持续迭代的数字化基础。

当前资料显示，公司正在同时推进以下事项：

1. 企业培训中心 SaaS 云平台，一个月内需要可用。
2. 企业竞赛系统，两个月内需要支撑企业竞赛和政府全区竞赛活动。
3. 公司智能体雏形，两周左右需要上线并进入资料喂养阶段。
4. 课程初稿开发工作流，两周内需要跑通样板。
5. 培训 AI 精准学，一个月内需要在云平台内形成基础能力。
6. 服务器选型和本地模型部署方案，需要尽快明确。
7. 各部门 AI 智能体配置，两个月内需要完成首批建设。

因此，三个月工作的核心不是“全面重建”，而是先把重点项目排清楚，把主流程跑通，把外包和内部交付管起来，把 AI 落到具体业务资料和岗位场景里。

## 二、三个月建设目标

### 1. 建成一个基础数字化底座

建立公司统一的项目台账、资料归档、代码与外包成果交接、知识库目录、基础服务器和存储方案。

目标是让公司核心资料有目录、有负责人、有权限、有备份，避免资料分散在个人电脑、微信、Excel 或外包团队手里。

### 2. 推进两个核心业务系统

第一个是企业培训中心 SaaS 云平台，先满足培训报名、学员管理、课程学习、题库考试、成绩记录、证书或学习证明、后台统计等一期主流程。

第二个是企业竞赛系统，先满足报名、赛程、题库、考试或评分、排名、证书或结果公示、数据导出等核心流程，确保能够支撑企业竞赛和政府全区竞赛活动启动。

### 3. 落地三类 AI 能力

第一类是公司智能体，用于内部制度、流程、项目资料、客户和培训问答、知识检索。

第二类是课程 AI 开发工作流，用于课程大纲、课件初稿、讲义、题库、短视频脚本等初稿生成。

第三类是培训 AI 精准学，用于错题记录、薄弱知识点识别、推荐练习和学习报告。

### 4. 建立一套项目治理机制

所有系统和 AI 项目统一纳入项目看板，形成周报、里程碑、风险、外包交付和验收标准。

每周能向老板汇报：本周完成了什么、下周做什么、当前风险是什么、需要协调什么。

## 三、推进原则

### 1. 先保交付，再扩功能

培训 SaaS 和竞赛系统优先满足对外承诺和业务主流程。复杂报表、深度算法、精细化运营功能可以放到二期。

### 2. 先定验收，再谈开发

所有外包开发必须先形成 MVP 功能清单、角色权限、数据样例、验收标准和交付物清单。否则容易报价不准、反复返工、责任不清。

### 3. 先云端或混合验证，再决定本地重投入

本地模型部署和 AI 电脑服务器采购投入较大，建议先明确必要性、数据安全要求、成本测算和维护责任，再决定采购规模。

### 4. AI 必须绑定业务资料和人工审核

智能体和课程工作流必须依托资料库、流程、模板和人工审核，不做脱离业务的演示型功能。

### 5. 源码、数据、账号必须归公司

外包成果必须交付源码、数据库结构、接口文档、部署文档、账号权限和维护说明，不能只验收页面效果。

## 四、重点建设项目

### 1. 企业培训中心 SaaS 云平台

目标：一个月内形成一期可用版本。

一期建议范围：

1. 企业账号和学员账号管理。
2. 学员报名和培训人员管理。
3. 课程上传、课程分类、课程学习。
4. 题库管理和考试功能。
5. 成绩记录和学习证明或证书管理。
6. 管理后台基础统计。
7. AI 精准学基础入口。

关键风险：

1. Node.js 新开发和 Java 既有平台复用路线未定。
2. 当前需求只有大纲，详细需求文档不足。
3. 外包团队边界、源码归属、验收标准还需要明确。

第一步动作：

1. 明确一个月内必须上线的功能。
2. 明确哪些功能可以二期再做。
3. 完成 Node.js 新开发与 Java 平台复用对比。
4. 输出一期 MVP 功能清单和验收标准。

### 2. 企业竞赛系统

目标：两个月内支撑企业竞赛和三个政府全区竞赛活动启动。

一期建议范围：

1. 竞赛报名。
2. 参赛人员管理。
3. 赛程管理。
4. 题库管理。
5. 考试或评分。
6. 排名和结果公示。
7. 数据导出。
8. 阶段上线和应急处理。

关键风险：

1. 政府活动时间固定，系统上线不能拖。
2. 阶段上线边界如果不清，会影响测试和验收。
3. 系统稳定性、数据导出和现场应急要求较高。

第一步动作：

1. 明确竞赛活动排期。
2. 明确当前是否已有系统基础。
3. 拆分报名、题库、考试、排名、导出等阶段上线节点。
4. 制定测试和人工兜底方案。

### 3. 公司智能体与知识库

目标：两周内上线雏形，两个月内完成首批部门智能体配置。

首批建议场景：

1. 公司制度和流程问答。
2. 培训业务流程问答。
3. 课程资料检索。
4. 竞赛项目资料检索。
5. 项目周报和会议纪要辅助。
6. 常见客户问题和销售话术辅助。

第一步动作：

1. 明确首批试点部门。
2. 建立资料收集清单。
3. 统一资料命名和归档目录。
4. 先做一个能用的问答样板，再逐步扩展。

### 4. 课程 AI 开发工作流

目标：两周内用一门课程跑通样板，一个月内基本替代人工初稿。

建议流程：

资料输入 → 课程大纲 → 课件初稿 → 讲义 → 题库 → 短视频脚本 → 人工审核 → 定稿入库

第一步动作：

1. 选一门课程做样板。
2. 收集原始资料、课件、题库、标准和参考内容。
3. 设计提示词和输出模板。
4. 建立人工审核表，明确哪些内容必须由课程负责人确认。

### 5. 培训 AI 精准学

目标：一个月内在培训平台内形成基础入口。

一期建议范围：

1. 学员错题记录。
2. 知识点标签。
3. 薄弱知识点统计。
4. 推荐练习。
5. 学习报告。

第一步动作：

1. 定义题库知识点标签。
2. 定义错题和学习记录字段。
3. 先做基础推荐，不做复杂算法。
4. 与培训 SaaS 的题库和考试模块同步设计。

### 6. 服务器选型与本地模型部署

目标：先形成方案，不急于直接重投入采购。

需要对比三种方案：

1. 云端 AI 工具方案：启动快，成本低，但数据安全和访问稳定性需要评估。
2. 本地模型方案：数据可控，但硬件投入和维护压力高。
3. 云端 + 本地混合方案：先用云端跑通场景，敏感资料和后续核心能力逐步本地化。

第一步动作：

1. 明确哪些数据必须本地处理。
2. 明确模型用途：知识库、智能体、课程生成、代码辅助还是内部搜索。
3. 明确预算边界和维护责任。
4. 输出服务器配置、预算和部署建议。

## 五、三个月阶段安排

### 第一阶段：第 1-2 周，摸清现状与快速样板

重点任务：

1. 梳理三家公司业务、人员、系统、项目和资料情况。
2. 建立项目看板和周报机制。
3. 确定培训 SaaS 一期 MVP 范围。
4. 上线公司智能体雏形。
5. 选一门课程跑通 AI 初稿样板。
6. 完成服务器和本地模型部署方案初稿。

阶段成果：

1. 业务图、人员图、系统流程图。
2. 问题优先级表。
3. 项目看板和周报模板。
4. 智能体雏形。
5. 课程 AI 样板。
6. 服务器选型初稿。

### 第二阶段：第 3-4 周，培训 SaaS 一期上线

重点任务：

1. 确定 Node.js 新开发或 Java 平台复用路线。
2. 完成培训主流程需求、角色权限、原型和数据样例。
3. 推进培训 SaaS 一期开发或改造。
4. 接入 AI 精准学基础入口。
5. 联调题库、考试、成绩和证书或学习证明流程。

阶段成果：

1. 培训 SaaS 一期可测试版本。
2. AI 精准学 MVP 设计。
3. 测试问题清单。
4. 上线验收标准。

### 第三阶段：第 5-8 周，竞赛系统与部门智能体扩展

重点任务：

1. 锁定竞赛系统阶段上线范围。
2. 推进报名、题库、考试或评分、排名、导出等核心模块。
3. 建立竞赛系统测试和应急方案。
4. 扩展各部门知识库和智能体。
5. 标准化课程 AI 工作流模板。

阶段成果：

1. 竞赛系统阶段上线版本。
2. 竞赛活动支撑方案。
3. 首批部门智能体配置完成。
4. 课程 AI 开发模板库。

### 第四阶段：第 9-12 周，稳定运行与内化能力

重点任务：

1. 优化培训平台和竞赛系统稳定性。
2. 补齐报表、权限、日志、备份和审计。
3. 完成外包阶段交付验收。
4. 固化培训、竞赛、课程、智能体相关 SOP。
5. 形成二期建设路线图。

阶段成果：

1. 三个月复盘报告。
2. 外包交付验收清单。
3. 运维交接表。
4. 二期建设计划。

## 七、项目管理机制

### 1. 周报机制

每周固定输出一版项目周报，包含：

1. 本周完成。
2. 下周计划。
3. 当前风险。
4. 需要协调。
5. 是否影响最终交付。

### 2. 外包管理机制

外包项目必须明确：

1. 谁写需求。
2. 谁确认范围。
3. 谁验收。
4. 谁保管源码和账号。
5. 谁负责后续维护。

外包交付物必须包含：

1. 源码。
2. 数据库结构。
3. 接口文档。
4. 部署文档。
5. 账号权限。
6. 运维说明。

### 3. 项目优先级机制

P0：影响一个月或两个月内对外交付的事项，每天跟进。  
P1：影响 AI 落地和内部效率提升的事项，每周推进。  
P2：基础设施、服务器、长期优化类事项，按节点复核。

## 八、主要风险

### 1. 培训平台技术路线未定

影响：开发周期、报价、后续维护都会受影响。  
应对：一周内完成 Node.js 新开发和 Java 平台复用对比，老板拍板后锁定范围。

### 2. 需求文档不足

影响：外包容易报价不准、返工和扯皮。  
应对：先补 MVP 功能清单、角色权限、数据样例和验收标准。

### 3. 竞赛活动时间固定

影响：上线延期会影响政府活动。  
应对：拆分阶段上线，提前压测，准备人工兜底流程。

### 4. 资料分散且质量不一

影响：智能体和课程 AI 输出质量不稳定。  
应对：建立资料目录、命名规范、负责人和审核机制。

### 5. 本地模型投入较大

影响：采购后可能带来维护压力和成本风险。  
应对：先完成云端、本地、混合部署对比，明确必要性后再采购。

### 6. 外包成果不可控

影响：后续无法维护或二次开发。  
应对：合同和验收中写明源码、文档、部署、账号、数据库和维护交接要求。

## 九、需要老板尽快拍板的事项

1. 三个月内最优先的项目排序。
2. 培训 SaaS 是 Node.js 新开发、Java 平台复用，还是阶段性混合方案。
3. 外包主责团队和内部最终确认人。
4. 服务器和本地模型部署的预算边界。
5. 跨部门协调授权，明确哪些人员必须配合资料、需求、测试、验收和智能体喂养。
