# 基于 qianlvguoyu_saas SaaS 系统完成“认定归档”功能开发

请在现有 `qianlvguoyu_saas` 项目底座上，按照《认定归档模块开发文档.md》完成“认定归档”模块开发。该模块属于认定管理业务链路的一部分，承接认定任务执行完成后的档案归集工作，用于对状态为“已完成”的认定任务进行基础信息快照归档、认定材料归档、考生材料批量导入、文件归集、异常校验和归档详情查看。

开发时必须遵循项目根目录 `AGENTS.md` 中的技术规范：

- 后端：Java 21、Spring Boot 3.5、MyBatis-Plus、Sa-Token、Spring Security、Flyway、MySQL 8.4。
- 前端：React、Vite、TypeScript、Ant Design Pro、ProComponents、TanStack Query。
- 接口返回：统一使用 `{ code, message, data }`。
- 分页：统一使用 `PageQuery` / `PageResponse`。
- 权限：后端使用 `@PreAuthorize`，关键操作使用 `@AuditLog`。
- 租户隔离：所有业务表必须包含并校验 `tenant_id`。
- 数据库变更：新增 Flyway 迁移文件，不得修改既有历史迁移。
- 文件存储：前期使用本地目录存储，但必须通过统一 `FileStorageService` 抽象，后期可平滑切换到 MinIO 或对象存储。

## 一、菜单层级

在现有后台管理系统中复用一级目录【认定管理】，新增二级菜单【认定归档】。

菜单建议：

- 一级目录：认定管理
- 二级菜单：认定归档
- 路由：`/certification/archive`
- 前端组件：`certification/Archive`
- 菜单权限：`certification.archive.task.view`

注意：

- 不得删除或替换现有【项目管理】、【认定筹备期】等菜单。
- 【认定归档】应与【项目管理】、【认定筹备期】同属【认定管理】目录。
- 认定归档页面进入时应默认展示当前用户有权限查看的已完成认定任务或归档工作台。

## 二、模块定位

“认定归档”不是认定任务创建模块，也不是认定筹备模块，而是认定任务完成后的档案固化模块。它必须复用已有 `certification_task` 作为业务主任务，并且只允许对状态为“已完成”的认定任务进行归档。

业务主线：

1. 在上游模块中完成认定任务执行。
2. 认定任务状态变更为“已完成”。
3. 进入【认定归档】选择已完成任务。
4. 生成并保存认定任务基础信息归档快照。
5. 上传认定任务级材料。
6. 通过 ZIP 压缩包和考生清单 Excel 批量导入考生材料。
7. 系统解析文件、匹配考生、校验材料完整性。
8. 用户查看解析统计和异常列表。
9. 用户确认后将材料元数据和文件 Key 落库。
10. 在归档详情中查看基础信息、认定材料、考生档案和文件。

归档核心原则：

- 归档任务必须来源于已完成认定任务。
- 归档数据必须形成历史快照。
- 归档文件本体不进入数据库。
- 数据库只保存文件元数据和 `file_key`。
- 表名必须统一使用 `certification_` 前缀，区分认定管理模块。

用途：展示可归档的已完成认定任务、已有归档记录和归档进度，并作为各子功能入口。

- 认定任务名称
- 认定批次
- 工种/职业
- 认定等级
- 认定完成时间
- 认定人数
- 任务状态
- 基础信息归档状态
- 资料归档状态
- 归档总状态
- 最近归档时间
- 最近操作人

主要操作：

- 查询已完成任务
- 查看归档详情
- 基础信息归档
- 资料归档
- 上传认定材料
- 导入考生材料
- 查看导入批次
- 查看导入异常

校验规则：

- 只有状态为“已完成”的认定任务允许创建归档记录。
- 同一 `tenant_id` 下同一 `task_id` 原则上只允许存在一条有效归档记录。
- 已归档的基础信息默认只读，不得因上游任务修改而自动变化。

## 四、文件存储要求

前期开发确认使用本地目录存储文件，但必须预留对象存储迁移能力。

### 4.1 存储抽象

后端必须实现统一文件存储接口：

```text
FileStorageService
├── LocalFileStorageService
└── MinioFileStorageService，后期扩展
```

业务代码只能依赖 `FileStorageService`，不得直接在 Controller 或业务 Service 中硬编码本地磁盘路径。

### 4.2 配置建议

```yaml
certification:
  archive:
    storage-type: local
    storage-root: D:/qianlvguoyu/storage
```

### 4.3 文件 Key 规则

数据库中保存 `file_key`，不保存绝对路径。

认定任务材料：

```text
certification/archive/{taskNo}/{archiveId}/task-materials/{materialType}/{fileName}
```

考生材料：

```text
certification/archive/{taskNo}/{archiveId}/candidates/{idCard}/{materialType}/{fileName}
```

导入原始 ZIP：

```text
certification/archive/{taskNo}/{archiveId}/import-batches/{batchId}/{zipFileName}
```

### 4.4 安全要求

- 文件名必须做安全处理，防止路径穿越。
- 上传文件需要记录 `file_hash`。
- 文件读写失败需要记录明确错误。
- 文件下载必须做权限校验。
- 身份证号展示时需要脱敏。
- 生产环境不建议长期使用单机本地目录，后续应迁移到 MinIO 或统一文件服务。

## 十、归档完成检查

实现归档完成检查逻辑。只有满足以下条件时，归档状态才允许变更为 `ARCHIVED`：

- 当前任务状态为“已完成”。
- 基础信息已归档。
- 必要的认定任务材料已上传。
- 考生材料导入批次已确认入库。
- 导入异常已处理或明确允许带异常归档。
- 归档记录、考生材料、文件元数据均已落库。

检查结果应返回结构化数据：

```json
{
  "passed": false,
  "items": [
    {
      "code": "basic_archive_required",
      "name": "基础信息归档",
      "passed": true,
      "message": "基础信息已归档"
    },
    {
      "code": "candidate_material_missing",
      "name": "考生材料",
      "passed": false,
      "message": "有 2 名考生缺少学历证明"
    }
  ]
}
```
