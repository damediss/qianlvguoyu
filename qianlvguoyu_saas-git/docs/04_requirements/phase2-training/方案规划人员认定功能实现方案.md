## 一、现状与目标

### 1.1 现状

| 项 | 说明 |
|----|------|
| 入口 | 方案规划（`pxan_fang_gui_hua`）→ Tab「人员认定」 |
| 现有能力 | Excel 上传 → SheetJS 解析 → **前端 Mock 查证** → 写回单元格 → 下载 |
| 缺口 | 未调用真实查证引擎；结果不落业务库；与三年规划 / 人员采集表无联动 |
| 已删除 | 「规划人员认定」子 Tab（按三年规划批量认定/驳回，从未接后端）——**本期不恢复** |

### 1.2 目标（本期）

把「人员认定」做成**可生产使用的离线采集表查证回填工具**：

1. 上传「高命中率认定采集模板精简版」类 Excel（含姓名、身份证）
2. 后端按姓名+身份证调用真实查证引擎（复用 `ChazhengCertQueryService`）
3. 前端把证书等级 / 编号 / 发证日期写回原 Excel，并支持下载
4. **不强制落库**（与企业调研抽屉「回填 `train_sign_up_people_self`」分流）
5. UI 流程尽量沿用现有三步卡片，仅把 Mock 替换为真实 API

### 1.3 非目标（本期不做）

- 不恢复「规划人员认定」工作台（选规划 → 认定/驳回）
- 不把结果写入 `chazheng_user` / `chazheng_cert`（那是查证管理子系统职责）
- 不在本页创建三年规划或改写规划明细
- 不做 >200 人异步批次（预留二期；本期前端分片同步调用）

## 二、与既有三条链路的关系

```
┌─────────────────────────────────────────────────────────────────┐
│                         查证能力分层                              │
│  ChazhengCertQueryService（姓名+身份证 → CollectedCert）         │
│  配置：sys_dict.chazheng_url / chazheng_datas + FixedRateLimiter   │
└───────────────┬─────────────────────┬───────────────────────────┘
                │                     │
        ┌───────▼────────┐    ┌───────▼──────────────────────────┐
        │ 企业调研抽屉    │    │ 方案规划 · 人员认定（本方案）       │
        │ peopleIds 入参  │    │ {name,idCard}[] 入参               │
        │ 回填人员采集表  │    │ 不落库，返回明细给前端写 Excel     │
        │ verify-cert ✅  │    │ verify-lookup（新建）              │
        └────────────────┘    └────────────────────────────────────┘
                                      │
        ┌─────────────────────────────┼──────────────────────────┐
        │ 查证管理                      │                            │
        │ /chazheng/users/import       │  Excel → chazheng_user     │
        │ 异步 batch + 落 chazheng 表  │  与本页数据流不同，勿混用     │
        └──────────────────────────────┴────────────────────────────┘
```

| 维度 | 查证管理 import | 企业调研抽屉 verify-cert | **方案规划人员认定（本方案）** |
|------|-----------------|--------------------------|--------------------------------|
| 入参 | MultipartFile | `{ peopleIds }` | `{ people: [{name,idCard}] }` |
| 持久化 | `chazheng_*` | `train_sign_up_people_self` | **无**（仅 API 返回） |
| 模式 | 异步 + 轮询 | 同步 | 同步（前端分片） |
| 前端产物 | 列表刷新 | 抽屉列表刷新 | **下载回填 Excel** |

**结论：** 禁止本页直接调用 `/chazheng/users/import`；必须复用查证内核，接口形态对齐「查询型」而非「导入落库型」。

## 三、端到端流程

### 3.1 用户视角

```
1. 打开「方案规划」→「人员认定」
2. 上传 Excel（推荐精简版采集模板；Sheet「采集表」优先）
3. 系统解析表头，识别姓名 / 身份证 /（可选）证书列映射 → 展示人数
4. 点击「开始查证回填」
   ├─ 前端按每批 ≤20 人调用 POST /api/training/personnel-cert/verify-lookup
   ├─ 汇总全部明细到结果表（进度条按批更新）
   └─ SheetJS 将 found=true 的行写回证书等级/编号/发证日期列
5. 预览结果 →「下载回填文件」（*-查证回填.xlsx）
6. （可选）将回填文件再导入企业调研人员采集，或线下使用
```


## 四、后端设计

### 4.1 新接口

```
POST /api/training/personnel-cert/verify-lookup
Authorization: Bearer …
权限：建议 train:three_year_plan:view 或新建 train:personnel_cert:verify
       （与方案规划菜单同权即可，避免过细）
```

**Request**

```json
{
  "people": [
    { "rowIndex": 3, "name": "张三", "idCard": "110101199001011234" },
    { "rowIndex": 4, "name": "李四", "idCard": "110101199001011230" }
  ]
}
```

约束：

- `people` 非空，单次建议 ≤20（Controller `@Size(max=50)` 硬顶）
- `name` / `idCard` trim；空姓名或空证号 → 该条 `status=invalid`，不调外部
- `rowIndex` 原样回传，便于前端对齐 Excel 行

**Response**（对齐前端已有 `CertLookupRowResult` 形态）

```json
{
  "code": 0,
  "data": {
    "total": 2,
    "verified": 1,
    "notFound": 1,
    "invalid": 0,
    "failed": 0,
    "details": [
      {
        "rowIndex": 3,
        "name": "张三",
        "idCard": "110101199001011234",
        "status": "verified",
        "certLevel": "三级/高级工",
        "certNo": "ABC123",
        "issueDate": "2020-05-01",
        "message": null
      },
      {
        "rowIndex": 4,
        "name": "李四",
        "idCard": "110101199001011230",
        "status": "not_found",
        "certLevel": null,
        "certNo": null,
        "issueDate": null,
        "message": "未查到证书信息"
      }
    ]
  }
}
```

**status 枚举（与前端 `CertFillStatus` 对齐）**

| status | 含义 |
|--------|------|
| `verified` | 查到证书并返回主证信息 |
| `not_found` | 接口业务正常但无证 |
| `invalid` | 入参非法（姓名/身份证） |
| `failed` | 调用异常 / 配置缺失导致的本条失败 |
| `skipped` | 预留（本期可不用） |

> 说明：单请求内某人失败不应导致整批 500；配置完全未配置时可整批抛 `BusinessException`（「查证接口未配置」）。

### 4.2 服务职责

建议新建（放 `trainingdepartment`，避免污染 chazheng 页面契约）：

| 类 | 职责 |
|----|------|
| `PersonnelCertLookupController` | 路由 `/training/personnel-cert` |
| `PersonnelCertLookupApplicationService` | 校验分片、逐人调用、组装 VO |
| `PersonnelCertLookupReq` / `PersonnelCertLookupPerson` | 入参 |
| `PersonnelCertLookupResultVO` / `PersonnelCertLookupDetail` | 出参 |

核心伪码：

```java
public PersonnelCertLookupResultVO lookup(PersonnelCertLookupReq req) {
  Long tenantId = SecurityContext.currentUser().getTenantId();
  List<PersonnelCertLookupDetail> details = new ArrayList<>();
  int verified = 0, notFound = 0, invalid = 0, failed = 0;

  for (var p : req.people()) {
    if (!hasText(p.name()) || !hasText(p.idCard())) {
      details.add(invalidDetail(p, "姓名或身份证为空"));
      invalid++;
      continue;
    }
    if (!isValidIdCard(p.idCard())) {
      details.add(invalidDetail(p, "身份证格式无效"));
      invalid++;
      continue;
    }
    try {
      CertQueryOutcome outcome = chazhengCertQueryService
          .queryByNameIdCard(p.name().trim(), p.idCard().trim(), tenantId);
      PersonnelCertLookupDetail d = toDetail(p, outcome); // 复用等级解析思路
      details.add(d);
      switch (d.status()) {
        case "verified" -> verified++;
        case "not_found" -> notFound++;
        default -> failed++;
      }
    } catch (Exception e) {
      details.add(failedDetail(p, e.getMessage()));
      failed++;
    }
  }
  return new PersonnelCertLookupResultVO(
      details.size(), verified, notFound, invalid, failed, details);
}
```

字段映射（与 `ResearchCertBackfillService` 对齐，可抽公共工具类）：

| 返回字段 | 来源 |
|----------|------|
| `certNo` | 主证 `CollectedCert.certNo`（多证取等级最高） |
| `certLevel` | 从 `certName` 括号内等级文本；可带「三级」或「三级/高级工」 |
| `issueDate` | `CollectedCert.certDate` |

> 建议：将 `extractLevelText` / `pickPrimaryCert` 抽到 `chazheng.support.CertMappingSupport`，供抽屉回填与本页共用，避免两套规则漂移。

### 4.3 权限

| 方案 | 说明 |
|------|------|
| **推荐 A** | `@PreAuthorize("hasAuthority('train:three_year_plan:view')")` — 与方案规划同源 |
| 备选 B | 新增 `train:personnel_cert:verify`，角色授权跟随三年规划角色 |

本期不单独加菜单码（入口已在方案规划 Tab 内）。

### 4.4 限流与超时

- 继续依赖 `ChazhengCertQueryService` 内 `FixedRateLimiter`
- 前端单批 ≤20，总超时建议 axios `timeout: 120000`（与抽屉一致）
- 后端可不另开线程池（同步即可）

## 六、数据流与边界

### 6.1 不落库的理由

1. 本页是**机构线下材料预处理**工具，用户拿到回填 Excel 后用途多样  
2. 正式业务数据入口仍是：企业调研人员采集 / 查证管理 import  
3. 避免「临时 Excel」污染 `chazheng_user` 与规划库  

### 6.2 与采集抽屉的协同（建议产品文案）

> 「本页查证结果写回 Excel，不自动同步到企业调研。如需落库，请在企业调研 → 人员采集中导入或手工维护后使用『查证』。」

（二期可选：回填后提供「同步到指定调研企业」——需额外方案，本期不做。）

## 八、验收标准

1. 上传合法 Excel，人数解析正确，列映射说明正确  
2. 真实查证：有证人员 `status=verified`，证书三列可下载回填  
3. 末位无证 / 业务无证：`not_found`，不写空覆盖原单元格（仅 `verified` 写入，现有逻辑已满足）  
4. 非法身份证：`invalid`，不调外部  
5. 未配置 `chazheng_url`：明确报错，不静默成功  
6. 40 人分 2 批：进度可达 100%，结果表 40 行与 Excel 行号一致  
7. 企业调研抽屉查证与查证管理 import **行为不受影响**（回归）
