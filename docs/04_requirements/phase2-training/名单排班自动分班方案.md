# 分班需求澄清与实现方案  
（名单 + 排班表 → 自动建班 ≤50 人）

> 文档版本：v1.2  
> 编写日期：2026-07-17  
> v1.2：草稿可编辑 → 提交企业审核 → 通过后建班  
> v1.1：已落地 auto-pack（S1）与分班主路径改版  
> 目标：说清「你要的」与「现网已做的」差异，并给出可落地改造路径  

---

## 1. 你要的能力（产品定义）

用系统里已有的两类材料：

| 材料 | 来源 | 作用 |
|------|------|------|
| **人员名单** | 企业回传筛选名单 / 待分班池 | **谁要进培训班** |
| **排班表** | 企业回传月排班表 | **谁哪天能不能上课**（约束分班，不是另建一套「上午1班」课表） |

系统自动：

1. 解析名单得到学员池  
2. 结合排班表判断可上课约束（或按班组/倒班模式归类）  
3. **自动创建培训班级**，把学员分进去  
4. **每班人数 ≤ 50**（可配置，建议默认 50，下限可配如 20）  
5. 结果进入现网：`train_info_class` + `train_people_list` → 企业分班确认 → 班级人员  

**一句话：**  
要的是「稳定培训班名册（每班≤50）」，不是「按天按上午/下午拆出来的算法班课表」。

---

## 2. 与现网实现的差距（为什么觉得不对）

| 维度 | 你要的 | 现网主路径（排班驱动改造后） | 现网兼容 L1 |
|------|--------|------------------------------|-------------|
| 主产出 | 培训班 + 学员，班额≤50 | 先出「上午1班」等**时段算法班**，再物化成培训班 | 手工勾选名单建班 |
| 排班作用 | **约束/归类后打包进班** | 按日可上课 → 拆时段班（班可能很多） | 基本不用排班 |
| 班级形态 | 相对稳定的开班实体 | 物化后班级名≈算法班名，语义是「时段编组」 | 人工起名 |
| 班额 | 明确 ≤50 | 算法里 30～50，但是「同时段可上课人群」再拆 | 不自动控额 |

现网 L2 复用的是 Scheduling：**算谁哪天能上课 + 按日拆班**。  
你要的是开班运营：**把人装进不超过 50 人的培训班**。  
两者相关，但**主目标不同**——所以会感觉「不是我想要的」。

## 3. 推荐方案：名单入池 + 排班约束打包（Pack）

### 3.1 总体流程

```
status=4 + 名单 + 排班表
  → 确保 train_info_list
  → 解析名单 → train_plan_roster（待分池）
  → 解析排班 → 人×日可上课 / 倒班标签
  →【新】AutoPack：按策略分组成「候选班」且每班 ≤50
  → 写入 train_info_class + train_people_list
  → 企业分班确认
```

不再以「物化上午1班」为主闭环；Scheduling 引擎可降级为**可选约束计算**，或只复用班次规则部分。

### 3.2 自动分班策略（三选一，建议先做 S1）

#### S1 · 按生产班组 / 倒班类型打包（推荐首期）

1. 从名单取学员；从排班或名单「备注/班组」取 `shift_team`（如一班/二班/早班组）。  
2. 同一 `shift_team`（或同一倒班模式：早/中/夜为主）的人放同一候选池。  
3. 候选池按身份证去重后，按 **50 人** 切块：`1班、2班…`（或「电解一-1班」）。  
4. 排班用于：  
   - 校验/补全班组；  
   - 可选：剔除当月几乎全夜班、无可上课日的人进「未分入」警告。  

**优点：** 实现简单、班级稳定、符合「每班≤50」。  
**缺点：** 不精细到「每天上午能不能上课」。

#### S2 · 按「可上课重叠度」聚类后再切 ≤50（增强）

1. 用排班算每人可上课日集合（复用现有 ShiftTimeParser 规则：早全天、中仅下午、夜禁+次日禁）。  
2. 相似度高的人聚成一组，再按 50 切班。  
3. 适合「希望同班学员可一起上课的天数尽量多」。

**优点：** 更贴近倒班约束。  
**缺点：** 算法与调参成本高，首期不建议。

#### S3 · 仅按名单顺序切 50，排班只做过滤（最简）

1. 名单去重 → 过滤「排班显示全月不可上课」→ 按 50 切班。  

**优点：** 最快。  
**缺点：** 几乎没用上排班的分组价值。

**首期建议：S1；预留 S2 接口。**

### 3.3 班额与命名

| 项 | 建议默认 |
|----|----------|
| `classMax` | **50** |
| `classMin` | 不强制（尾班可少于 50）；或尾班 &lt;20 时提示合并 |
| 班级标题 | `{企业}-{工种可选}-{班组}-{序号}班`，如 `来铝-电解-一班-1班` |
| 人员主键 | 身份证；无证号进警告名单，默认仍可入班（可配置禁止） |

### 3.4 与企业确认的关系

- 自动创建的是 **`train_info_class`**，`company_confirm_status=0`。  
- 企业确认的仍是培训班，不是排班算法班字符串。  
- 未分入人员：任务结果里列出原因（无排班、全夜班、无身份证冲突等）。

## 4. 后端设计（相对现网怎么改）

### 4.1 新增能力（核心）

```
POST /training/division/auto-pack
```

请求示例：

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "strategy": "by_shift_team",
  "classMax": 50,
  "classNamePrefix": "来铝-2026-",
  "submitForCompanyConfirm": true,
  "excludeNoIdCard": false,
  "useShiftFilter": true
}
```

逻辑：

1. 校验 status=4、名单+排班（或按配置）。  
2. 若 roster 空：先解析企业名单（可自动调用现有 `roster/parse`）。  
3. 读排班：提取每人班组 / 主倒班类型 / 可上课天数（轻量，不必跑完整按日拆班）。  
4. 分组 → 每组按 `classMax` 切块 → 事务写 `train_info_class` + `train_people_list`，更新 roster `assign_status=1`。  
5. 返回 `{ classes:[{classId,title,nums}], unassigned:[], warnings:[] }`。

### 4.2 现网代码处置建议

| 现有模块 | 建议 |
|----------|------|
| `org-split`（手工勾选） | 保留为「手工调整」 |
| `shift-assign` 全量 generate/materialize | **降为高级/可选**（课表视角），或首期 UI 隐藏 |
| `ShiftTimeParser` / 班次规则 | **复用**于 S1 过滤与 S2 |
| `train_plan_roster` | **继续作为学员池**（主输入） |
| `train_shift_assign_*` | 非本需求必需；可不写 |

### 4.3 前端主路径（建议重做为）

```
选规划 → 培训信息 → 【自动分班】生成草稿 → 机构编辑班级/学员
  → 提交企业审核 → 企业通过后物化 train_info_class + train_people_list
         └ 手工调整（兼容 org-split，仍为立即建班）
```

页面文案明确：

> 系统根据人员名单与排班表生成分班草稿，机构编辑后提交企业；审核通过后才创建培训班（每班不超过 50 人）。

## 5. 数据与验收

### 5.1 落库（与开班域一致）

```
train_three_year_plan
  → train_info_list
      → train_division_pack_task（draft/pending → 企业审核）
          →（通过后）train_info_class（nums≤50，已确认）
              → train_people_list
```

### 5.2 验收用例

| ID | 场景 | 期望 |
|----|------|------|
| A01 | 80 人同班组 | 草稿 2 个班，如 50+30；通过后才落库班级 |
| A02 | 两班组各 40 人 | 草稿 2 个班，各 40，不混组（S1） |
| A03 | 含夜班为主人员 | 进未分入或单独班（按配置） |
| A04 | 无排班表 | 不可自动分班 |
| A05 | 企业确认方案 | pending → materialized，班级已创建且已确认 |
| A06 | 同身份证 | 同一培训信息下不进两个班 |
| A07 | 机构编辑后提交 | 改名/调人后 pending，企业可见最新方案 |

## 6. 工作量（按 S1 首期）

| 任务 | 估点 |
|------|------|
| 排班轻量解析：班组/主倒班/可上课天数 | 1.5d |
| `auto-pack` API + 切班事务 | 2d |
| 前端主路径改为「一键自动分班」 | 2d |
| 隐藏/降级现 L2 物化主路径 | 0.5d |
| 联调真实名单+排班 | 1d |
| **合计** | **约 7 人日** |

S2 聚类另加约 5～8 人日。

## 7. 决策项（实施前请确认）

1. **首期策略选 S1（按班组/倒班类型）还是 S3（纯名单切 50）？** → 建议 **S1**。  
2. **班额上限是否固定 50？** 下限是否不限制？  
3. **不同班组是否允许混班？** → S1 默认 **不允许**。  
4. **现网「按日算法班 + 物化」是否从主入口拿掉？** → 建议 **拿掉/收入高级**。  

确认后可按本方案改代码（替换当前「不是你想要的」主路径）。
