# 千铝工投云平台与智能体开发部技术选型与架构评审制度

制度编号：QLGT-YFGL-2026-103　　版本：V1.1　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为管控新技术引入与架构变更的评审决策，覆盖第三方组件与开源软件的合规审查，避免“技术孤岛”与架构腐化，特制定本制度。本制度遵循部门制度“简洁、可测试、可维护、持续迭代”的共同标准。

**第二条**　本制度适用于：新框架与新平台引入、核心架构调整、第三方组件与开源软件引入、第三方 API 接入。

## 第二章　技术选型流程与决策记录

**第三条**　选型提案须对比至少 2 个候选方案，从功能匹配度、成本、生态与社区活跃度、团队熟悉度、合规风险五个维度给出结论。

**第四条**　候选技术先进行不超过 2 周的试用验证（PoC），验证结论连同对比材料提交评审；通过后在架构决策记录（ADR）中归档，存入 docs/05_decisions 目录（ADR 归档目录以该目录为准）。

**第五条**　与部门既定技术路线（Java/Spring Boot 主干、React 管理端、MySQL 等）冲突的选型，升级至部门负责人评审；禁止为单一项目引入无人维护的孤岛技术。

## 第三章　架构评审与架构守护

**第六条**　重大架构变更必须评审，包括：新增服务边界、引入第二数据源、核心链路（登录鉴权、多租户、支付、考试）调整、存储架构变更。评审记录归档。

**第七条**　架构守护检查每半年开展一次，随季度复盘顺带进行，3 人团队不单设专项检查；检查内容：依赖版本健康度、模块耦合、技术债清单与治理计划，检查结果在部门内通报。

**第八条**　调用任何第三方 API（LLM、支付、短信等）前必须逐字段核对其官方文档，目标平台不支持的参数一律不传，禁止“假设兼容”。评审时对该项做明确确认。

## 第四章　第三方组件与开源软件合规

**第九条**　引入开源组件前审查许可证：商业交付项目禁止使用 GPL 系强传染性许可证组件；许可证结论登记在案。

**第十条**　引入前执行漏洞扫描，存在未修复高危漏洞（CVE）的版本禁止使用；组件版本统一登记，每半年核查一次漏洞与停更情况。

## 第五章　附则

**第十一条**　本制度由千铝工投云平台与智能体开发部负责解释。

**第十二条**　本制度自发布之日起施行。
