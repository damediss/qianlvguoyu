## 一级目录说明

| 目录 | 用途 |
| --- | --- |
| `docs/` | 需求、方案、正式交付、项目台账、技术决策 |
| `prototypes/` | HTML 原型、系统截图、流程演示页面 |
| `apps/` | 正式前端应用 |
| `services/` | 正式后端服务 |
| `packages/` | 共享类型、UI 组件、内部 SDK |
| `ai/` | Prompt、Skill、Agent、知识库目录规范 |
| `workflows/` | n8n、BPMN 和流程规则 |
| `infra/` | Docker、Nginx、数据库、环境变量模板 |
| `scripts/` | 文档生成、数据处理、检查和转换脚本 |
| `data/` | 导入模板、脱敏样例、业务字典 |
| `assets/` | 公共素材和大型素材索引 |
| `outputs/` | 生成产物和渲染检查结果 |
| `archive/` | 历史资料和暂未整理文件 |

## 维护规则

1. 根目录不直接放业务文档、截图、原型、脚本和生成产物。
2. 新需求资料放入 `docs/04_requirements/`。
3. 技术路线和架构决策放入 `docs/05_decisions/`。
4. 原型放入 `prototypes/`，正式前端代码放入 `apps/`。
5. 后端服务放入 `services/`。
6. 生成物放入 `outputs/`，正式交付物放入 `docs/01_delivery/`。
7. 不确定归属的历史文件先放入 `archive/`，确认后再迁移。
8. 第三方平台如 n8n、云厂商对象存储和 AI 模型服务仅按 `docs/05_decisions/` 中限定范围使用；对外产品化前必须重新做授权审查。
