# 跟班模拟考「新增试卷」复用组卷计划 — 可行性方案

> 日期：2026-08-12  
> 状态：方案稿（**先方案、不动代码**）  
> 对照：  
> - 跟班模拟考：[`跟班班级模拟试卷_实现方案.md`](./跟班班级模拟试卷_实现方案.md)（P0 已落地）  
> - 课程管理组卷计划：Admin `MakeExamPlanPage` → `POST /exam/make-exam-plans`  
> 问题：模拟考「新增试卷 / 配卷」能否复用组卷计划「添加组卷」？

---

## 一、结论（先看）

| 问题 | 答案 |
|------|------|
| 能否直接调用 `/exam/make-exam-plans` 当模拟考新增试卷？ | **不建议** |
| 能否整页嵌入 `MakeExamPlanPage`？ | **不建议** |
| 两边有没有可复用的东西？ | **有**：题库表 `exam_exam_detail` +「按规则抽客观题」的算法/交互范式 |
| 推荐路径 | **参考组卷计划增强跟班配卷**；可选 **抽取共享抽题引擎**；可选 **导入已有正式卷** |

**一句话：**  
组卷计划产出的是科目域正式卷（`exam_paper`）；模拟考需要的是班级域跟班任务快照（`train_follow_task_question`）。**共享题库与抽题思路，不共享落库与学生入口。**

---

## 二、两边分别是什么

### 2.1 课程管理 · 组卷计划

| 项 | 说明 |
|----|------|
| 入口 | 考试/题库菜单「组卷计划」`MakeExamPlanPage` |
| API | `GET/POST/PUT/DELETE /exam/make-exam-plans` |
| 「添加组卷」实际做了什么 | **一次完成**：写 `exam_make_exam_plan`（+ detail）**并生成** `exam_paper` / `exam_paper_detail`（或实操卷） |
| 维度 | **科目** `courseId`；可选比重 `rateId`、难度/分值区间、理论/实操、机考/打印 |
| 消费者 | 正式考试、竞赛适配器等读 `exam_paper`；**不是** App「我的班级 → 模拟考」 |

### 2.2 跟班 · 模拟考配卷（现状 P0）

| 项 | 说明 |
|----|------|
| 入口 | 跟班工作台 Tab「模拟考」`FollowMockExamTab` |
| API | `/training/follow-tasks` + `.../bank-draw` / `bank-type-counts` / `mock-used-question-ids` |
| 「新增模拟卷」实际做了什么 | 智能抽题预览 → `create` 草稿 `task_type=mock` → 题目 **快照**进 `train_follow_task_question` → 发布给花名册 |
| 维度 | **班级** + 本班 practice-scope 白名单；客观题；可 **排除本班其他模拟卷已选题** |
| 消费者 | App 跟班模拟考；答卷落 `train_follow_task_*` |

```text
组卷计划：  course → make_exam_plan → exam_paper（正式卷资产）
模拟考：    class  → follow_task(mock) → follow_task_question（教学快照）→ 学员作答
                ↑
           都从 exam_exam_detail 抽题，但下游分叉
```

## 三、对比表

| 维度 | 组卷计划 `/exam/make-exam-plans` | 跟班模拟考配卷 |
|------|----------------------------------|----------------|
| 归属 | 科目 / 考试域 | 班级 / 跟班域 |
| 落库 | `exam_make_*` + `exam_paper*` | `train_follow_task*` |
| 学员路径 | 非跟班模拟考入口 | App 模拟考（`channel=mock`） |
| 范围约束 | 科目下 L3 知识点 | **本班练习范围**白名单 |
| 跨卷去重 | 无「本班他卷」 | **`excludeOtherMock`** |
| 题型 | 单选/多选/判断 + 主观 + 实操 | P0 **仅客观题**（自动判分） |
| 抽题规则 | 比重、难度、分值区间、`isAll` | 按题型数量 + shuffle |
| 银行过滤 | 常见 `finalCheckStatus=1` | `status=1` + 范围内 |
| 生命周期 | 计划/卷 CRUD，可再生 | 草稿 → 发布 → 禁重考 / 关闭 / 重开 |
| 学情 | 考试域 | 跟班答卷；与刷题学情隔离（产品红线） |

**产品红线（已拍板，不可破）：**  
模拟考不改走 `/appsmart` / `exam_mock_paper`，也不应用正式 `exam_paper` 替代 follow 答卷域。

---

## 四、为什么不能「直接复用添加组卷」

1. **产物不对**：`POST /exam/make-exam-plans` 生成的是正式卷，App 模拟考读的是 follow 任务纸；对接错表则入口/进度/学情全断。  
2. **约束不对**：缺班级白名单、缺「排除本班其他模拟卷已选题」。  
3. **题型不对**：组卷支持主观/实操；跟班模拟考 P0 依赖客观自动判分。  
4. **语义不对**：「添加组卷」= 计划+生成卷一步到位；模拟考= 预览抽题 → 存草稿 → 再发布。  
5. **过滤口径可能不一致**：`finalCheckStatus` vs `status`，同一 UI 直接调会抽到不同题集。

## 五、可选集成方案（推荐顺序）

### 方案 A — 参考组卷计划，增强跟班配卷（推荐默认）

**做法：** 不调用 `/exam/make-exam-plans`；在 `FollowMockExamTab` 吸收组卷计划的交互优点（题型行配置、可选难度/分值、可选比重），仍走 `bank-draw` + `createFollowTask(mock)`。

| 优点 | 缺点 |
|------|------|
| 不碰红线；改动面可控 | 两套 UI 仍并存 |
| 保留 excludeOtherMock / 发布流 | 比重等规则若要做齐，需跟班侧补字段 |

**适合：** 教务主要痛点是「配卷表单太简」，而不是「要正式卷资产」。

---

### 方案 B — 抽取共享「理论客观题抽题引擎」（中期）

**做法：** 从 `ExamMakeExamPlanApplicationService.makeTheoryPaper` 与 `TrainFollowTaskApplicationService.drawBankQuestionsInternal` 抽出公共服务，例如 `TheoryObjectiveDrawService`：

- 入参：科目/知识点范围、题型数量、可选 rate/难度/分值、排除 ID 集、银行质量过滤策略  
- 出参：`List<exam_exam_detail.id>`  
- 组卷计划：结果写入 `exam_paper_detail`  
- 模拟考：结果经 `FollowTaskBankQuestionConverter` 写入 `train_follow_task_question`

| 优点 | 缺点 |
|------|------|
| 一套规则、两处消费 | 抽取成本中等；过滤策略要先统一拍板 |
| 后续竞赛/认定也可接 | 实操卷仍只留考试域 |

**适合：** 产品明确要求模拟考与正式组卷「同规则抽题」。

---

### 方案 C — 「选用已有组卷」导入模拟考（薄适配，可选增值）

**做法：** 模拟考新建时增加模式：

1. **智能抽题**（现网）  
2. **从组卷计划/正式卷导入**：选已有 `makeId` / `paperId` → 取 `exam_paper_detail.examId` 列表 → 过滤客观题 + `assertInClassScope` + 可选再跑 `excludeOtherMock` → 走现有 create 快照

| 优点 | 缺点 |
|------|------|
| 复用已生成的正式卷，开发量小 | 正式卷超出本班范围会失败/裁剪 |
| 不嵌入整页组卷 UI | 卷被组卷侧再生后，已导入的模拟考快照不自动变（应用快照语义，需文案说明） |

**适合：** 机构「先在题库组好标准卷，再发到班级模考」。

---

### 方案 D — 模拟考创建直接打 `/exam/make-exam-plans`（否决）

| 优点 | 缺点 |
|------|------|
| 表面省事 | 破坏通道边界；App/学情/去重全不兼容 |

**结论：不做。**

---

## 六、推荐决策

| 阶段 | 建议 |
|------|------|
| **P0 决策** | **方案 A**：跟班模拟考继续自有 API；配卷体验可对标组卷计划表单 |
| **有「标准卷入库再模考」需求时** | 加 **方案 C**（导入已有 `exam_paper`） |
| **两边抽题规则必须完全一致时** | 再上 **方案 B**（共享引擎） |

**不建议：** 把 `MakeExamPlanPage` 或 `POST /exam/make-exam-plans` 当作模拟考「新增试卷」的主路径。

---

## 七、若选方案 A / C，接口与落点示意（仍不动代码）

### A 增强配卷（示意）

```text
FollowMockExamTab
  ├─ 题型配置表（参考 MakeExamPlan detailList，仅 single/multi/judge）
  ├─ 可选：难度/分值区间、rateId
  ├─ POST .../bank-draw（扩展 FollowBankDrawReq）
  └─ POST .../follow-tasks  taskType=mock + sourceExamDetailIds
```

### C 导入正式卷（示意）

```text
GET  /exam/make-exam-plans/list?courseId=   （只读选卷）
GET  /exam/papers?makeId= 或现有取卷接口
     → 抽出 examDetailIds
POST /training/follow-tasks
     body: { taskType:'mock', sourceExamDetailIds, importFromPaperId?, ... }
服务端：客观题过滤 + 班级范围校验 + excludeOtherMock
```

学员侧、发布、答卷 **零改入口**。

## 九、总结

- `/exam/make-exam-plans` 的「添加组卷」= **科目正式组卷资产**，不是班级模拟考任务。  
- 跟班模拟考必须继续落在 **`train_follow_task(mock)` 快照**，才能保住 App、去重、学情红线。  
- **可复用的是抽题能力与表单经验，不是该 API 与页面本身。**  
- 推荐：**方案 A（默认）→ 按需加 C（导入）→ 规则强一致时再 B（引擎）**；否决整链复用 D。
