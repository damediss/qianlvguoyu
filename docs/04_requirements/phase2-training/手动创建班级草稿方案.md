# 手动创建班级草稿方案  
（勾选 / 上传名单 / 手填加人 → 草稿 → 企业审核通过后自动建班）

> 文档版本：v1.3  
> 编写日期：2026-07-21  
> 状态：已落地  
> 关联：`名单排班自动分班方案.md`、`按工种等级自动分班方案.md`、现网 `train_division_pack_task`  

---

## 1. 目标

机构侧**手动**组班时，也走与一键自动分班相同的审核闭环：

1. 手动创建 **1～N 个班级草稿**（不立即写 `train_info_class`）  
2. 班级人员来源三种（可混用）：  
   - **勾选**待分池 `train_plan_roster`（选报名/待分人员）  
   - **上传 Excel** 导入本班人员（解析后匹配/补入待分池）  
   - **姓名/身份证手填加人**（表单录入，匹配池或自动入库后再入班）  
3. 机构编辑完成后 **提交企业审核**  
4. 企业 **通过后自动物化**建班；驳回后机构可改再提  

**一句话：**  
先建班级草稿并加人，企业通过后再创建正式班级；去掉旧「勾选后立即建班」路径。

---

## 2. 与现网对照

| 能力 | 现网旧手工（Collapse 兼容） | 现网自动分班 | **本方案** |
|------|------------------------------|--------------|------------|
| 入口 | 勾选 roster → `org-split` | `auto-pack` | **新建手动草稿** |
| 落库时机 | **立刻**建 `train_info_class` | 企业通过后 | **企业通过后** |
| 审核对象 | 单个班级 `company_confirm` | `pack_task` | **复用 `pack_task`** |
| 人员来源 | 仅勾选待分池 | 策略自动切 | 勾选 + 上传 + **手填** |
| 策略标记 | — | `by_job_level` 等 | **`manual`** |

> 企业审核 UI（`EnterpriseClassConfirmPanel` 的 pack-task Tab）**无需新开一套**，手动草稿与自动草稿同一列表展示。

## 3. 总体流程

```
选中三年规划（名单 + 排班齐套，见 §5）
  → ensure train_info_list
  → POST 创建手动 pack_task（strategy=manual, status=draft, classes=[] 或预建空班）
  → 机构：新增班级 / 改名 / 设班额
       ├─ 从待分池勾选加入某班
       ├─ 上传本班 Excel → 解析匹配/补池 → 写入该班 members
       └─ 手填姓名/身份证（可选手机、工种、等级等）→ 匹配/补池 → 入班
  → 保存 patch → 提交 submit → pending
  → 企业 confirm → materializePackTask（现有逻辑）
       → train_info_class + train_people_list
       → roster.assign_status=1
```

驳回：`rejected` → 机构改草稿 → 再 `submit`。

## 4. 推荐实现路径（复用 pack_task）

**不新建审核表。** 在 `train_division_pack_task` 上增加策略值：

| 字段 | 手动草稿取值 |
|------|----------------|
| `strategy` | **`manual`** |
| `status` | 同现网：`draft` / `pending` / `rejected` / `materialized` / `superseded` |
| `classes_json` | 与自动分班相同结构：`[{tempId,title,group,nums,members[]}]` |
| `class_max` | 默认 50，提交时校验 |

物化、提交校验、企业确认/驳回：**直接复用**现有：

- `PATCH /pack-tasks/{id}/patch`  
- `POST /pack-tasks/{id}/submit`  
- `POST /pack-tasks/{id}/company-confirm` → `materializePackTask`  
- `POST /pack-tasks/{id}/company-reject`

## 5. 前置条件

| 项 | 建议 |
|----|------|
| 三年规划 | 企业已确认（现网分班入口条件） |
| 培训信息 | `ensureTrainInfo` 复用 |
| 筛选名单 / 待分池 | **推荐必有**：勾选依赖待分池；纯上传/手填也可补池（见 §6.3 / §6.4） |
| 排班表 | **必有**（与自动分班同入口材料齐套；手动路径不做可上课过滤，但上传排班为前置条件） |

与自动分班对齐：手动创建同样要求**筛选名单 + 排班表**齐套后方可进入；排班仅作材料门禁，不参与手动分组。

## 6. 接口设计

### 6.1 创建手动草稿

`POST /training/division/manual-pack`

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "classMax": 50,
  "classNamePrefix": "来铝-",
  "classes": [
    { "title": "来铝-电工-高级-1班", "rosterIds": [101, 102] }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `classes` | 可选；空则创建空草稿，前端再加班 |
| `rosterIds` | 可选；从待分池预填进对应班 |

行为：

1. `supersedeActivePackTasks`（与 auto-pack 一致，同培训信息仅保留一个活跃草稿）  
2. 写入 `strategy=manual`、`status=draft`  
3. 返回与 `auto-pack` 相同 VO，前端进入「编辑草稿」步骤  

### 6.2 草稿内：从待分池加人

**方案 A（推荐，少接口）：** 前端已有草稿编辑（移入/移出），扩展「从待分池勾选加入」：

- 拉 `GET /training/division/roster?assignStatus=0`  
- 本地写入 `classes[].members` 后 `PATCH pack-tasks/{id}/patch`  

**方案 B：** `POST /pack-tasks/{id}/classes/{tempId}/add-members`，body `{ rosterIds:[] }` —— 后端强校验去重与班额。

首期建议 **A**；若担心前端漏校验再补 B。

### 6.3 上传本班人员名单

`POST /training/division/pack-tasks/{taskId}/classes/{tempId}/import-members`  
`multipart/form-data`：`file`（xlsx）

解析复用 / 抽取 `TrainPlanRosterParseService` 列映射（姓名、身份证、手机、工种、等级、车间、班组）。

**匹配与入班规则：**

| 步骤 | 规则 |
|------|------|
| 1 | 按身份证优先，其次姓名，匹配当前规划待分池 `assign_status=0` |
| 2 | 匹配成功 → 加入该班 `members`（带 `rosterId`） |
| 3 | 池中无此人但有姓名（建议有身份证）→ **自动写入** `train_plan_roster`（`source=class_import`）再入班；缺姓名则进 unmatched |
| 4 | 已在本方案其他班 / 已在该培训信息学员中 → 跳过并记 warning |
| 5 | 导入后人数 > `classMax` → **拒绝整次导入并提示** |

响应：

```json
{
  "added": 28,
  "skipped": [{ "personName": "...", "reason": "已在其他班" }],
  "unmatched": [{ "personName": "...", "idCard": "..." }],
  "task": { "...完整 pack VO..." }
}
```

### 6.4 姓名/身份证手填加人

`POST /training/division/pack-tasks/{taskId}/classes/{tempId}/add-person`

```json
{
  "personName": "张三",
  "idCard": "110101199001011234",
  "phone": "13800000000",
  "jobName": "电工",
  "levelName": "高级",
  "workshop": "电解一车间",
  "shiftTeam": "一班"
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `personName` | **是** | 姓名 |
| `idCard` | 强烈建议 | 有证优先按证匹配；无证仅按姓名匹配（重名风险提示） |
| 其余 | 否 | 写入/补全 roster 用 |

**处理逻辑（与 Excel 单行等价）：**

1. 有身份证 → 在待分池按证匹配；无证 → 按姓名精确匹配（若重名多于 1 人则报错，要求补身份证）  
2. 匹配到 → 校验未在其他班 / 未在培训信息学员中 → 入班  
3. 未匹配到 → **自动插入** `train_plan_roster`（`source=manual_add`，`assign_status=0`）再入班  
4. 当前班已达 `classMax` → 拒绝  
5. 返回更新后的 pack VO + `rosterId`

> 与 Excel 导入共用同一套「匹配 / 补池 / 入班」服务方法，避免两套规则。

### 6.5 下载导入模板

`GET /training/division/member-import-template`  
表头与企业筛选名单兼容（姓名必填，身份证强烈建议），减少两套模板。

## 7. 前端（TrainingClassDivisionPage）

### 7.1 信息架构

步骤建议：

1. 选规划  
2. **选路径**：一键自动分班 | **手动创建班级**  
3. 编辑草稿（共用现有 step=2 编辑器）  
4. 提交企业审核  

手动路径主操作：

| 操作 | 说明 |
|------|------|
| 新建班级 | 输入班名，空成员 |
| 从待分池加人 | Drawer/Modal 勾选 → 写入当前班 |
| 上传名单 | 对当前班上传 Excel |
| **手填加人** | 弹窗：姓名（必填）、身份证、手机、工种、等级等 → 调 §6.4 |
| 移出 / 调班 | 复用现有草稿编辑 |
| 保存 / 提交 | 现有 patch + submit |

### 7.2 替换旧 Collapse

去掉或下线「兼容：勾选名单直接建班」：

- 文案改为引导使用「手动创建班级草稿」  
- `submitDivisionOrgSplit` 保留短期兼容，但 UI 不再主推；后续可标 `@Deprecated`

### 7.3 企业侧

`EnterpriseClassConfirmPanel`：

- 策略展示增加：`manual` →「手动组班」  
- 审核通过仍调 `companyConfirmDivisionPackTask`，**自动建班**（已有）

## 8. 校验与规则（与自动草稿对齐）

| 规则 | 说明 |
|------|------|
| 班额 | 每班 ≤ `classMax`（默认 50） |
| 同人单班 | `manual` 不允许同人出现在多个班（与 `by_job_level` 一致） |
| 身份证去重 | 方案内 / 培训信息内不可重复学员 |
| 无证手填 | 允许，但同名多人时必须补身份证 |
| 空班 | 不可提交 |
| 活跃草稿 | 同 `trainInfoId` 新开草稿时 supersede 旧 draft/rejected |

物化后：`company_confirm_status=1`（方案级已审，与现网 pack 一致）。

```

        ↑ 匹配 / 补池（class_import | manual_add）
   勾选 / 上传 Excel / 手填
        ↓
train_division_pack_task.classes_json   ← draft / pending
        ↓ 企业通过
train_info_class + train_people_list
train_plan_roster.assign_status=1
```

## 11. 决策项（已确认）

| # | 问题 | 确认结论 |
|---|------|----------|
| 1 | 手动路径是否必须排班表齐套？ | **是**（名单 + 排班材料齐套才可进；排班不参与手动分组） |
| 2 | 上传名单中「池外新人」是否自动写入待分池再入班？ | **是**（`source=class_import`，warnings 提示） |
| 3 | 一次手动草稿允许多班还是先只做单班？ | **多班** |
| 4 | 新建手动草稿是否 supersede 未提交的自动草稿？ | **是**（同 `trainInfoId`） |
| 5 | 旧「立即建班」入口是否直接下线？ | **是**（引导到手动草稿） |
| 6 | 是否支持姓名/身份证手填加人？ | **是**（池外自动入库 `source=manual_add`；无证同名冲突须补证） |

确认人：产品沟通 2026-07-21。已落地：`POST /manual-pack`、班内 import-members / add-person、前端手动路径、旧立即建班入口下线。
