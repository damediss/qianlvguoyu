## 1. 需求背景与目标

在"细目表管理"菜单下方新增菜单**"理论知识试题生成管理"**：

1. 导入某工种某等级的《理论知识考评要素细目表》（xlsx，指引第二章规定格式）；
2. 依据细目表，按指引的题量/题型/格式/参数要求，利用 LLM 批量生成理论知识试题；
3. 生成的试题**先落草稿暂存区**，经页面人工审核/编辑后，人工触发"入库"写入题库开发任务链路（`task_exam` / `task_examsub`，v1.1 核实真实表名），后续走既有专家初审/终审流程；
4. 入库时把细目表的考评点树同步进 `exam_knowledge_structure`，生成的试题可被既有组卷/按知识点筛选直接使用。

### 1.1 已确认决策（2026-09-04 与需求方确认）

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 支持等级 | **全部五个等级**（五/四/三级客观题：单选/多选/判断；二/一级另含主观题：简答/计算/绘图/论述/案例分析） |
| D2 | 入库路径 | **不写 exam_exam_detail**。新建"生成批次+试题草稿"暂存表 → 页面逐条/批量审核编辑 → 人工点"入库"写入 `task_exam(+_detail)`（客观题）/ `task_examsub(+_detail)`（主观题），后续走"题库开发任务"专家审核流程 |

| D4 | AI 辅助审题 | **二期再做**。一期只做确定性规则校验 + 人工审核 |

### 1.2 D2 合规性核实结论（应需求方要求核实）

对照 AGENTS.md《AI、Agent 与 MCP 规则》与《LLM 接入规范》：

- **"写操作默认生成草稿或待办，发布/审批/删除核心数据必须人工确认"** → 满足。LLM 输出只写草稿表（AI 侧）；入库动作是人工点击触发（人确认）；入库后试题仍处于 `task_exam.status=0 待审核`，还须经过既有专家初审→终审才被采信，相当于"人工确认"有两道。
- **"AI 生成内容必须标记来源、模型、生成时间和操作人"** → 靠表设计满足：批次表记录模型/参数/prompt 摘要/token 用量/耗时/操作人；草稿表记录 `ai_model`、生成时间、操作人，并经 `ai_batch_id` 随入库写入 task 明细表（需 ALTER 加列，见 §6.3），追溯链不断。
- **"AI/MCP 调用必须走受控 API 或 Application 层"** → 生成服务复用 `ai/` 包 LLM 客户端范式与 `exam_faq_model_config` 模型配置，不新建绕权通道。

结论：**D2 方案符合平台 AI 硬规则**，前提是 §6 的来源标记列全部落地。

## 2. 指引核心要求提炼（生成试题的指导原则）

> 以下来自指引第二章（理论知识题库编制方法）及附件 3 审核标准，是 prompt 设计、校验规则、导出表格的**唯一依据**。

### 2.1 题量题型硬指标（按等级）

| 等级 | 每考评点最低题量 | 等级总量下限 | 主观题要求 |
|------|------------------|--------------|------------|
| 五级/四级 | 单选 ≥4 + 判断 ≥2 | ≥1200 题 | — |
| 三级 | 单选 ≥3 + 多选 ≥2 + 判断 ≥2 | ≥1200 题 | — |
| 二级/一级 | 单选 ≥3（总≥360）+ 多选 ≥2（总≥240）+ 判断 ≥2（总≥240） | 总量 ≥920 题 | 简答/计算/绘图（5分制）≥40 题；综合/论述/案例分析（10或15分制）≥40 题；主观题**分值占比 40%～60%** |

考评点数量约束（导入校验用）：五~三级每等级考评点 ≥200 个；二~一级 ≥120 个；重要程度 **X ≥85%、Y ≤10%、Z ≤5%**。

### 2.2 题型代码（指引口径）

| 代码 | 题型 | 代码 | 题型 |
|------|------|------|------|
| A | 填空题 | E | 简答（计算、绘图）题 |
| B | 单项选择题 | F | 论述题 |
| C | 判断题 | I | 案例分析题 |

（D=多项选择题。组卷规则中"综合题"与论述/案例同档，10或15分制。）

### 2.3 试题格式规范（必须进入 prompt 与校验器）

- **单选题**：4 个备选项，仅 1 个正确答案，其余 3 个为有效干扰项（考生易混淆、与正确答案相近但非正确）；选项代码用英文大写字母并以"（ ）"圈起，即（A）（B）（C）（D）；题干一般采用空缺句，空缺部分用"（ ）"表示，句尾一律用句号；客观题避免疑问句、避免否定句式、避免复杂句式。
- **多选题**：5 个备选项（A~E），≥2 个正确答案；评分规则"多选或少选均不给分"。
- **判断题**：陈述句题干，答案用"√"/"×"。
- **简答/计算/绘图题**：疑问句或陈述句题干；须给出参考答案、评分要点、评分标准；每个评分要点 ≤2 分。
- **综合/论述/案例分析题**：须给出参考答案（全面客观）、评分要点、评分标准；每个评分要点 ≤3 分。
- **正确答案字母随机排列**，避免多数答案集中于某一选项（导出与入库前做分布校验）。
- 难度等级：易/较易/中/较难/难 = 1/2/3/4/5，以 3 为宜，1 或 5 的题 ≤20%；题目-目标一致性 1~5，原则上全部 =5（默认标 5）。
- 主观题建议分值取指引组卷档位：简答/计算/绘图 = 5 分制，综合/论述/案例分析 = 10 或 15 分制；各评分要点分值之和应等于建议分值（Validator 校验项，v1.1 补）。
- 内容红线：不超考评点范围、不缩小范围；考核心内容；避免单纯数字/文字记忆；答案唯一；题干完整不暗示答案；标点准确；法规表述与现行规定一致；社会主义核心价值观与意识形态合规（附件 3 第 23 条禁令清单）。
- 试题内容参数用考评点代码表示（如 `A-A-A-001`）。

### 2.4 组卷规则参考（指引第二章附表，导出/报告用）

| 级别 | 90 分钟 | 120 分钟 |
|------|---------|----------|
| 五级/四级 | 单选 80×1分 + 判断 40×0.5分 = 120 题 | 单选 160×0.5分 + 判断 40×0.5分 = 200 题 |
| 三级 | 单选 60×1 + 多选 20×1 + 判断 40×0.5 = 120 题 | 单选 120×0.5 + 多选 20×1 + 判断 40×0.5 = 180 题 |
| 二级/一级 | 单选 20×1 + 多选 10×2 + 判断 10×1 + 简答 4×5 + 综合 2×15 = 46 题 | 同左但综合 3×10 = 47 题 |

满分 100 分，60 分及格。**一期只做题库生成，不做组卷**；此表仅用于批次报告提示"题量是否满足组卷需要"。

### 2.5 样例细目表实测画像（导入解析器的验收基准）

- 文件 1 个 sheet，204 行 ×10 列，84 处合并单元格；表头 3 行（第 2~4 行），数据自第 5 行起。
- 列布局：A=一级（代码名称⏎（X:Y:Z） 多行单格）| B=一级权重 | C=二级 | D=二级权重 | E=三级 | F=三级考评权重 | G=相关知识要求 | H=考评点代码（001…）| I=考评点名称 | J=重要程度（X/Y/Z）。
- 权重为小数（0.45=45%）；单元格内多行文本按 `名称⏎代码⏎（X:Y:Z）` 排列，**与指引模板"代码/名称/比例"顺序不同，解析器须兼容**。
- 实测：考评点 200 个（X=181 / Y=12 / Z=7，满足 X≥85%）；一级 2 块（基本要求 A=0.45、工作要求 B=0.55）；二级 7 块；三级 19 块。
- 合并单元格解析必须"值向下填充"（含 A/B 列跨 90+ 行的大合并块）。

## 3. 技术评估

### 3.1 是否引入 Apache Fesod —— 结论：**不引入**

- Fesod 是原 Alibaba EasyExcel 的 Apache 孵化接续项目（`org.apache.fesod:fesod-sheet`，Apache 2.0，JDK8+，底层仍基于 POI），主打十万级以上行的低内存流式读写。
- 本功能数据量：细目表 ~200 行、单等级试题 1200~2000 行导出，**没有流式/内存痛点**。
- 平台现有 Excel 能力全部基于 **Apache POI 5.5.1**（`pom.xml:169-174`），已有成熟范式可复用：`ExamTaskXimuApplicationService`（细目表导入）、`ExamExamDetailApplicationService`（题库导入/命题模板）、`MubiaoExcelExporter`（细目表导出 XSSF+SXSSF）。合并单元格解析在 POI 下是既有能力。
- 引入 fesod 将造成"一个项目两套 Excel 库"，且其底层 POI 与项目 POI 5.5.1 需手工排包对齐；AGENTS.md 明确"不引入与既定技术路线冲突的新框架"。
- **触发再评估的条件**：未来出现单文件 >5 万行的题库导入/导出需求。

### 3.2 是否开启模型思考模式/思考强度 —— 结论：**生成链路默认开启，强度可配，机械环节不开**

第一性原理推演：

1. **任务本质**：给定考评点（名称+相关知识要求+重要程度+等级定位），产出同时满足约 15 条硬约束（§2.3）且专业知识正确的试题。失败模式有两类：(a) 约束违反（答案不唯一、题干暗示、超范围、干扰项无效、难度漂移）；(b) 专业事实错误（如氧化铝工艺参数错误）。
2. **思考模式买什么**：让模型在输出前进行"规划—自检—验证"，对 (a) 类多约束满足和 (b) 类事实自查有机制性帮助——这正是本任务的质量关键路径。
3. **成本侧**：思考 token 显著放大时延与费用。每等级 1200+ 题、按"1 考评点 1 次调用"分块（五级 200 次调用），思考模式下单次时延可能从秒级升到 30s~2min。**但架构本来就是"快速返回+异步分块+进度轮询"（AGENTS.md 踩坑 #11/#18），时延不堵 HTTP，成本换取的是人工审核环节的返工率下降**——人工审核 1200 题的人力成本远高于思考 token 成本。
4. **不依赖 LLM 自检**：格式/结构校验（JSON Schema、选项数、答案唯一性、字母分布、难度比例、重复检测）一律用确定性代码兜底（指引 §2.3 全部可编码），思考模式只是提高一次通过率，不是质量闸门。
5. **落地方式（零代码分支）**：`exam_faq_model_config` 已有 `thinking`（enabled/disabled）与 `reasoning_effort` 字段，`FaqLlmClient.putThinkingNode` 已实现按平台差异化传参。本功能默认模型 **GLM-5.3-Flash + thinking=enabled + reasoning_effort=low**（已确认，C3；客户端需按 v1.2 修订记录 C4 扩展 GLM 分支）；首轮试产（建议先跑 1 个三级范围 ≈10~30 个考评点）人工抽检合格率达标后，可在配置里把 thinking 调为 disabled 或 effort 保持 low 省时费；不达标则按试产数据上调档位。此决策不需要改代码。
6. **降档路径**：首轮试产（建议先跑 1 个三级范围 ≈10~30 个考评点）人工抽检合格率达标后，可在配置里把 thinking 调为 disabled 或 effort=low 省时费；不达标则保持。此决策不需要改代码。

### 6.4 exam_knowledge_structure 复用说明（v1.1 核实修订）

现有 4 级树：`level` 0~3（0=一级鉴定范围、1=二级、2=三级、3=鉴定点），**挂接维度是 `course_id`**（生产 17,844 个鉴定点 100% 有 course_id，course 经 `exam_course.work_type_id`+`level`（0~4，换算 course = 5 - level）关联工种等级）；`important` 为 **String（'X'/'Y'/'Z'）**；`series_no` 存编号；`type` 0=理论；**无权重列**。因此：

1. 细目表一/二/三级 → L0/L1/L2（level 0/1/2），考评点 → L3 鉴定点（level=3，important 存 X/Y/Z）。
2. 幂等匹配键 = `course_id + series_no(节点 full_code) + level + deleted=0`；命中即复用 id，未命中才插入（`type=0`、`status=1`、`amount=0`）。
3. course 兜底创建：蓝图未匹配到 `exam_course` 时，入库前按"`exam_work_type.id` + level 映射（course = 5 - level）+ 标题含工种名"创建 course 行（title=工种名+等级简称），再挂树。
4. 细目表各层权重存本方案 `exam_theory_blueprint_node.weight`，**不**写入知识点树；`amount` 不手工累加（沿用平台现有统计机制，避免双写不一致）。

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| LLM 专业事实错误（氧化铝工艺等） | 思考模式提高一次正确率；专家初审/终审是质量闸门（指引流程）；批次报告标注 AI 来源 |
