# 培训考试 · 多场成绩表合并（初考 / 补考 / 重考）方案

> **日期**：2026-08-20  
> **状态**：**P0+P1 已落地**（跨场合并 + 同场冲突收窄 + 冲突/空分拆 Tab）  
> **入口**：培训管理 → 运营流程 → 考试（`TrainingFollowExamPage`）  
> **上游**：[培训考试_企业成绩单导入匹配班级人员_实现方案.md](./培训考试_企业成绩单导入匹配班级人员_实现方案.md)  
> **背景**：已支持一次多选成绩表；同身份证跨表分值不同被判「表内冲突」，与业务不符  
> **实现**：`ExamScoreAttemptMergeSupport` + `ExamScoreImportApplicationService#preview`；前端 `TrainingFollowExamPage`

---

## 0. 结论（先看）

**产品一句话**：多份人社成绩花名册按**考试时间**归到同一学员后做**字段级合并**（空不覆盖），再匹配班级花名册并确认写入；仅「同一场内同分打架」才进冲突。

| 问题 | 定稿建议 |
|------|----------|
| 为何同人多表 | 初考不过 → **补考**只考理论；**重考**理论+实操都考 |
| 补考实操 | 表上常为空/`—` → **继承初考技能分** |
| 重考 | 本场理论、技能都有值 → **覆盖**上一场 |
| 综合列 | 仍只取表中「综合」；无则空；**不以理论代综合**（保持现状） |
| 冲突定义收窄 | 跨场重叠 **不算冲突**；冲突仅限同证同学员在**无法合并**时的硬冲突 |
| 写入 | 只写合并后的最终 `theory_score` / `real_score`(技能) / `exam_score`(综合) / `performance_score` |

## 1. 业务规则（来自业务确认）

| 场次 | 考什么 | 通过条件 | 成绩表常见形态 |
|------|--------|----------|----------------|
| **初考** | 理论 + 实操 | 理论≥60 且 实操≥60 | 四列成绩均可能有值 |
| **补考**（第二次） | **仅理论** | 理论≥60；实操用**初考** | 理论有分；技能多为 `—`/空 |
| **重考**（第三次） | 理论 + 实操 | 本场理论≥60 且 本场实操≥60 | 理论、技能均有新值 |

成绩单页头含 **考试时间**（及计划名称/编码），用于区分场次先后。

---

## 2. 现状问题

当前预览逻辑（简化）：

```
同身份证多行 → 若理论/技能/综合任一不等 → SHEET_DUP_CONFLICT（每行都进「冲突/空分」）
```

补考相对初考必然「理论变了、技能一边空一边有」→ 被当成冲突，出现近百人×多行 ≈ 大量「冲突/空分」，**无法确认写入**。

这与「多场合法重叠」矛盾，必须改为合并。

---

## 3. 目标行为

### 3.1 导入流程（相对现状）

```
勾选班级 → 多选成绩表上传
  → 各表解析（人+分+本表考试时间）
  → 【新增】按身份证跨表合并（见 §4）
  → 与选定班级花名册匹配
  → 预览「待写入 / 未在本班 / … / 冲突 / 空分」
  → 确认写入最终分
```

### 3.2 界面

| Tab / 展示 | 调整 |
|------------|------|
| 待写入 | 展示**合并后一行**；可副文案「初考+补考合并」等 |
| 冲突 | **仅**硬冲突（§4.4）；与空分拆开计数更清晰（建议） |
| 空分 | 合并后四项仍全空 |
| 班级人员侧栏 | 仍展示最终 理论/技能/综合/工作业绩 |

预览摘要建议增加：`合并人数`、`冲突人数`、`空分人数`（若拆 Tab）。

## 4. 合并算法（核心）

### 4.1 输入

每个解析行携带：

- 证件号码（规范化）
- 姓名、准考证号（审计）
- 理论 / 技能 / 综合 / 工作业绩（`—` → null）
- **考试时间**（取自页头「考试时间」；解析不到则用文件内计划编码字典序 / 上传顺序兜底，并在预览标黄）

一次上传的多个文件，全部行进入同一合并池。

### 4.2 排序键

同一身份证下，按以下优先级排序（升序 = 从早到晚）：

1. 解析到的考试时间起点（`2025-07-26 08:00 - …` 取起始）  
2. 若无时间：计划编码  
3. 再无：上传文件顺序 + 表内行号  

### 4.3 字段合并（空不覆盖）

对排序后的每一场，从左到右折叠：

```
theory       = 本场有值 ? 本场 : 保留上一有效
skill        = 本场有值 ? 本场 : 保留上一有效   // 补考空技能 → 继承初考
comprehensive= 本场有值 ? 本场 : 保留上一有效   // 仍不把理论写入综合
performance  = 本场有值 ? 本场 : 保留上一有效
```

合并结果记为 `MergedPersonScore`，再进入现有「匹配班级 / 待写入」逻辑。

**示例**

| 场次 | 理论 | 技能 | 合并后理论 | 合并后技能 |
|------|------|------|------------|------------|
| 初考 | 55 | 74.9 | 55 | 74.9 |
| 补考 | 62 | — | **62** | **74.9**（继承） |
| 重考 | 70 | 65 | **70** | **65**（覆盖） |

### 4.4 何时仍算「冲突」

合并前，对**同一身份证**的多行，仅当出现下列情况才标冲突（不自动合并写入）：

| 情形 | 处理 |
|------|------|
| A. 考试时间**相同**（同一场）且理论/技能/综合有不一致 | 冲突，需人工处理 |
| B. 无法判定时间且多行分值互斥、又不能按「空不覆盖」解释 | 冲突（兜底） |
| C. 跨场、后场某字段有值且与前场不同 | **合法覆盖**，非冲突 |

补考「技能为空」相对初考「技能有值」→ **合法**，走 §4.3。

冲突行：该身份证整组不进待写入（或进冲突 Tab 展示各场原始分，禁止一键写入该人，直到只留一场或改表重传）。

### 4.5 通过判定（P1，可选展示，不挡写入）

写入仍以业务导入分为准；达标提示仅预览用：

| 推断场次 | 规则（展示「是否达标」） |
|----------|--------------------------|
| 仅 1 场 | 理论≥60 且 技能≥60（技能空则未达标） |
| 末场技能空、理论有更新 | 按**补考**：理论≥60 且 继承技能≥60 |
| 末场理论+技能都有 | 按**重考/正考**：末场理论≥60 且 末场技能≥60 |

场次角色可用计划名称关键词辅助（`正考`/`补考`/`重考`），**排序仍以考试时间为准**。

## 5. 数据与实现锚点

### 5.1 已有落库（保持）

| 成绩列 | 字段 |
|--------|------|
| 理论 | `train_people_list.theory_score` |
| 技能 | `train_people_list.real_score` |
| 综合 | `train_people_list.exam_score` |
| 工作业绩 | `train_people_list.performance_score` |

确认写入对象 = **合并后的最终分**，不是某一场原始行。

### 5.2 代码落点

| 模块 | 改动 |
|------|------|
| `RensheScoreRosterParseService` | 确保页头「考试时间」解析到 `ParsedRoster` / 行级可带 `examTime`（或合并阶段用 roster 级时间） |
| `ExamScoreImportApplicationService.preview` | 多文件拼行后先 `mergeByIdCard(rows)`，再用合并结果做匹配；收窄 `scoresConflict` |
| `TrainingFollowExamPage` | 冲突/空分拆分或副标题说明；待写入展示合并来源 |
| 审计 `train_exam_score_import_*` | P0 可只存最终分；P1 在 item JSON 中带 `attempts[]` |

### 5.3 解析约定

- 单文件内考试时间：页头统一时间赋给该文件全部数据行。  
- 多文件：各文件各自页头时间。  
- 时间解析失败：预览标「时间缺失，按上传顺序合并」，并允许用户重传带时间的表。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| 考试时间解析失败导致场次顺序错 | 强制页头时间；失败则标黄 + 按上传顺序并提示 |
| 误把两场正考当成补考合并 | 同场（时间相同）分值不一致仍冲突；运营核对计划名 |
| 重考技能未录入被当成补考继承旧技能 | 重考表必须有技能列有值；预览显示「技能来源：初考/本场」 |
| 历史「冲突」预期变化 | 发布说明：跨场重叠改为合并 |

---

## 9. 验收用例

1. **仅初考**：一人一行，正常待写入。  
2. **初考理论 55 / 技能 74.9 + 补考理论 62 / 技能 —** → 合并 理论 62、技能 74.9，进待写入，**不进冲突**。  
3. **再加重考理论 70 / 技能 65** → 最终 70 / 65。  
4. **同一考试时间两行同分不一致** → 冲突。  
5. **两文件完全相同分** → 去重一行待写入。  
6. **综合仅一处有值** → 合并后综合取该值；他处空不冲掉。
