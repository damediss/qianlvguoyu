## 二、今日完成

### 1. 正式开考：预检、统一开始、候考确认

- 场次 `ready` 后可查询开考前检查；未通过则阻断开始。
- 开始接口：`POST /api/competition/formal-exam-sessions/{id}/start`，权限 `competition:exam-session:start`。
- 至少一名选手已进入候考（`ready`）才能开考；仍有未进入选手时，需管理端确认后才能开始。
- 开考将场次切到 `running`，并把全部候考选手切到 `running`，记录实际开考时间；时长从实际开考时间起算。
- 管理端正式考试面板展示预检项、场次状态、候考/在考人数，并提供开始比赛操作。

### 2. 选手端正式答题

- 独立入口：`/formal-exam?sessionId=`，不走管理端 `AuthGate`。
- 选手登录走竞赛选手身份，接口 `POST /api/competition/formal-exam/player/auth/login` 匿名放行；其余选手接口要求 `ROLE_COMPETITION_EXAM`。
- 登录桥接扩展到 `/api/competition/formal-exam/player/**`，与原模拟考 token 桥共用选手身份校验。
- 选手可查看场次上下文、确认进入候考、拉取试卷、单题保存、批量同步、交卷。
- 试卷投影只下发题干、选项和已保存答案，不下发标准答案。
- 交卷校验答案版本；本地未同步或仍有未答题时返回业务冲突码，前端需确认后再交。
- 前端用 IndexedDB 缓存答案，支持离线写入、按批同步、失败退避重试，以及服务端/本地版本合并。
- 界面覆盖：登录、确认进入、候考等待、答题、缺考、已交卷终态。

### 3. 运行中管控：强制交卷、到点收卷、缺考、结束

- 管理端可对 `running` 选手强制交卷，必须填写 1～500 字原因；截止后强制交卷改为自动交卷。权限 `competition:exam-session:force-submit`。
- 定时扫描到期场次（默认 5 秒）：在考选手自动交卷，仍待进入的选手记缺考，异常 `ready` 记日志不自动处理。
- 全部选手进入终态（已交/自动交/强制交/缺考）且人数与场次记录一致后，场次才能结束。
- 选手状态扩展：`waiting_enter` / `ready` / `running` / `submitted` / `auto_submitted` / `forced_submitted` / `absent`。
- 当前没有管理端「手动结束场次」接口，结束由到期收卷流程触发。

### 4. 客观题自动评分

- 评分状态与场次运行状态分离：`not_started` / `scoring` / `completed` / `failed`。
- 场次结束后自动评分；管理端可对未完成或卡住的评分重试。权限 `competition:exam-session:score`。
- 题型：单选、多选、判断、填空；未知题型按失败处理，不猜测。
- 落库选手成绩和逐题得分；缺考单独记结果。卡住超时默认 15 分钟后可重试。
- 管理端面板可看评分进度、选手成绩和逐题明细。

### 5. 同一赛事多赛项报名与场次冲突

- 报名唯一约束从「同一赛事一名选手一行」改为「同一赛事 + 同一赛项（工种）」；赛事成员关系仍保持一人一次。
- 同一选手可报同一赛事下的多个工种/赛项；同一赛项重复报名仍冲突。
- 跨赛事若时间重叠则禁止报名；时间字段不完整时直接拒绝，避免漏检。
- 理论排考、实操场次、正式考试场次之间增加时段重叠检查。
