## 1. 背景与目标

将国家职业技能标准 docx 中的**基本要求**（编号段落）与**工作要求**（4 列表格）解析为结构化知识树，经 LLM 概括叶节点（考评点）+ 人工审核后，产出两类交付物：

1. **知识树入库 SQL**：`exam_work_type` / `exam_course` / `exam_knowledge_structure` 的 INSERT 语句（父子层级、编码、重要程度），目标为 PHP 库（`gjjddb`，tenant_id=10159），由运维执行；
2. **理论知识考评要素细目表 Excel**：按等级×方向导出，版式对齐样例 `11_矿山救护工_初级工_细目表_主观_20260812171129.xlsx`（Sheet1）；
3. **操作技能考评要素细目表 Excel**（拍板⑤）：按等级×方向导出，版式对齐样例 `16_矿山救护工_初级工_细目表_操作技能考评要素.xlsx`；「试题量」列程序留空，人工审核后填写。

**为什么不直接写 PHP 库**：SaaS 对 PHP 库的既有架构约束是"只读 holder + exam_result 仅 INSERT 回写"（鉴权方案 §3.5/AI 同步学 §4.7），直写 PHP 业务表会破坏该边界。产物以 SQL 文件交付、运维执行，全程可审。SaaS 库内的 staging 草稿表仅作解析/编辑载体，不落 `exam_knowledge_structure`。

## 2. 输入/输出结构契约（已逐字段核实）

### 2.1 源 docx 结构（两本标准实测一致）

| 区块 | 形态 | 解析要点 |
|---|---|---|
| 封面/说明/职业概况（1.x） | 段落 | 仅取职业名称、职业编码（如 6-16-01-12）、版本年；其余跳过 |
| **2. 基本要求** | **编号段落**（不在表格内） | `2.1` 职业道德、`2.2` 基础知识 → L1；`2.1.1` → L2；`（1）（2）…` → 叶素材原文。**部分 L2 无列举项**（如矿山救护工 2.1.1）→ LLM 概括补叶 |
| **3. 工作要求**（3.1 五级/初级工 … 3.5 一级/高级技师） | **4 列表格**：职业功能/工作内容/技能要求/相关知识要求 | 表格归属于所在"3.x 等级"节；**含 vMerge 纵向合并单元格**（restart/continue 必须继承）；职业功能 → L1，工作内容 → L2；**相关知识要求**的 `（1）（2）…` → 理论叶素材；**技能要求**的编号项（`1.1.1 能…`）→ **技能叶素材**（拍板⑤） |
| 4. 权重表（末尾 2 张） | 表格：项目 × 等级（%），焊工为 **方向×等级矩阵** | 第 1 张=**理论知识权重表**（基本要求/相关知识要求 项目级）；第 2 张=**技能要求权重表**（各职业功能技能占比，如矿山救护工 装备操作 70%）；方向列识别（电焊工/气焊工/钎焊工/焊接设备操作工） |
| 干扰项 | `续表` 段落、页脚注（①②）、`6-16-01-12` 职业编码 | 按《DOCX转Markdown转换指南》坑 3/4/5 规则排除 |

### 2.2 目标知识树结构（对齐 `exam_knowledge_structure_矿山救护工初级.md` 样例）

```
L0  基本要求A                     level=0
L0  工作要求B                     level=0
L1    职业道德A-A                 level=1（2.1 → A 段第 1 字母）
L2      职业道德基本知识A-A-A      level=2
L3        工匠精神培养A-A-A-001    level=3 + important=X/Y/Z   ← LLM 概括 + 人工审核
```

- **编码规则**：基本要求=A 段 / 工作要求=B 段；L1 按序取字母 A/B/C…；L2 在 L1 编码后再取字母；L3 在 L2 编码后接 3 位序号（001 起）。编码**内嵌在 title 文本尾部**（如 `遵章守法，安全第一A-A-B-001`），与样例一致。
- **固定列默认值**（按样例）：`use_type=0, type=0, cover/intro 空, series_no NULL, sort_number=100, status=1, deleted=0, amount=10.00, user_id/org_id/org_name 可配置, tenant_id=10159（PHP 口径）, create_time=执行时 NOW()`。
- **字段类型差异（已核实）**：PHP 库 `important` 为 **varchar（X/Y/Z）**；SaaS 同名表为 int（语义不同、未使用）——staging 草稿表按 **varchar X/Y/Z** 存储，对齐 PHP 口径。

### 2.3 细目表 Excel 结构（对齐样例 Sheet1，10 列）

```
第1行：标题「{工种}({等级})理论知识考评要素细目表」（合并整行）
第2-4行：复合表头——考评范围(一级|二级|三级) + 相关知识 + 考评点(代码|名称|重要程度)
数据行（纵向合并单元格）：
  一级: 名称+代码+(X:Y:Z 计数) + 权重      如「基本要求 A（42:8:0）」0.25
  二级: 同上                                如「职业道德 A（10:0:0）」0.05
  三级: 名称+代码+(计数)+考评权重            如「职业道德基本知识 A（4:0:0）」0.02
  相关知识: docx 原文列举项（1.…2.… 换行拼接）
  考评点: 代码 001… | 名称（概括短语）| 重要程度 X/Y/Z
```

### 2.4 操作技能细目表结构（对齐样例 `16_矿山救护工_初级工_细目表_操作技能考评要素.xlsx`，13 列）

```
第1行：标题「{工种}（{等级}）操作技能考评要素细目表」（合并整行）
第2行：「职业： {工种}     级别： {五/四/三/二/一}」
第3-4行：复合表头——考评范围一级(代码重要程度比例|名称|考评比重|选考方式)
                     + 考评范围二级(代码重要程度比例|名称|技能要求|考评比重|选考方式)
                     + 考评点(代码|名称|重要程度|试题量)
数据行（纵向合并单元格）：
  一级: 代码+(X:Y:Z 计数) | 职业功能名称 | 考评比重 | 选考方式=必考
        如「A(3:1:0) | 事故预防 | 0.15 | 必考」
  二级: 代码+(计数) | 工作内容名称 | 技能要求原文(1.1.1能…↵1.1.2能…) | 考评比重 | 选考方式=任选一项
        如「A(2:0:0) | 安全检查 | … | 0.15 | 任选一项」
  考评点: 代码 001… | 名称（技能概括短语）| 重要程度 X/Y/Z | 试题量（程序留空，人工填写）
```

**与理论细目表的差异（拍板⑤ 要点）**：

| 维度 | 理论知识细目表 | 操作技能细目表 |
|---|---|---|
| 覆盖范围 | 基本要求A + 工作要求B 两支 | **仅工作要求部分**（职业道德/基础知识不入技能表） |
| 叶素材来源 | 表格「相关知识要求」列 | 表格「**技能要求**」列（`1.1.1 能查出…损坏` 编号项） |
| 权重来源 | 第 1 张**理论知识权重表** | 第 2 张**技能要求权重表**（事故预防 15% → 0.15） |
| 叶节点措辞 | 名词性知识短语（"安全生产方针内涵"） | 操作行为短语（"能查出风门…损坏" → "检查风门…的损坏状况"） |
| 特色列 | 相关知识原文列 | **技能要求原文列 + 选考方式 + 试题量**（试题量留空人工填） |
| 入库 | 入 `exam_knowledge_structure`（SQL 导出） | **不入库**，仅导出 Excel 交付 |

## 3. 总体流程

```
上传 docx（存 file 模块，返 fileId）
   │
   ▼
[1] 规则解析（同步，秒级）          ── DocxStandardParser
   骨架树：L0/L1/L2 + 理论叶素材 + 技能叶素材 + 双权重表 + 工种方向 + 等级
   │  写入 staging（status=parsed），页面立即可见骨架
   ▼
[2] LLM 概括（异步批处理）         ── 复用 FaqLlmClient + DeepSeek JSON mode
   按 L2 小节逐块双通道调用：
     理论通道：相关知识素材 → 知识短语考评点 + important
     技能通道：技能要求素材 → 操作行为短语考评点 + important
   │  全部落草稿（review_status=pending），ai_generation_draft 留痕
   ▼
[3] 人工审核编辑（页面）            ── 树形表格在线编辑/增删/调整
   │  可单小节「重新生成」；可微调 L1/L2 权重
   ▼
[4] 确认导出（页面按钮）
   ├─ 理论知识细目表 Excel（按 等级×方向）
   ├─ 操作技能细目表 Excel（按 等级×方向；试题量列留空）
   └─ 入库 SQL 文件（exam_work_type / exam_course / exam_knowledge_structure，PHP 口径，仅理论叶）
```

## 4. 系统架构与模块划分

平台内聚在 `platform-api`，**不引新框架、不引新 jar**（docx 读取用既有 `poi-ooxml` 的 XWPF；Excel 写出用 POI SXSSF；LLM 复用 `FaqLlmClient`）：

```
exam/standard/
  controller/StandardParseController.java          // 管理端 /api/exam/standard/**
  service/StandardParseApplicationService.java     // 用例编排（任务状态机）
  service/StandardLlmSummarizeService.java         // LLM 概括（按 L2 小节分块）
  parser/DocxStandardParser.java                   // 纯解析：docx → 骨架树（可单测）
  parser/model/…                                   // ParsedStandard/SectionNode/WeightTable 等 POJO
  export/KnowledgeSqlExporter.java                 // 知识树 → INSERT SQL 文件
  export/MubiaoExcelExporter.java                  // 树 → 理论细目表 Excel（POI 合并单元格）
  export/SkillMubiaoExcelExporter.java             // 树 → 操作技能细目表 Excel（拍板⑤）
  entity/ExamStandardTaskEntity.java               // staging：解析任务
  entity/ExamStandardNodeEntity.java               // staging：树节点草稿
  mapper/…                                         // 两个 BaseMapper
```

**线程边界**：LLM 概括走既有 `reviewSyncExecutor` 风格的独立线程池（AbortPolicy，坑 #12）；`tenantId` 在 HTTP 线程捕获后参数传递，异步链不调 SecurityContext（AGENTS.md 异步陷阱）；知识树/权重表一次性加载内存复用（坑 #18）。

**LLM 复用约束**：模型配置取 `exam_faq_model_config`（sys_dict 指定 code）；DeepSeek JSON mode + 空 content 重试沿用 `FaqLlmClient` 既有能力；调用留痕 `ai_generation_draft`（draftType=`standard_knowledge`）；**不支持的字段一律不传**（坑 #13）。

## 5. DOCX 解析器设计（DocxStandardParser，纯规则、黄金样例可单测）

### 5.1 解析步骤

1. `XWPFDocument` 顺序遍历 body 元素（`IBodyElement`：段落 `XWPFParagraph` / 表格 `XWPFTable`），保持文档顺序；
2. **标题识别**：沿用《转换指南》编号正则（`\d+(\.\d+)*\.? + 中文`），排除 `续表`/脚注/职业编码（编号后必须跟中文字符）；识别 `2.` `3.` `3.1` 等节边界，记录当前所在"等级节"（3.1=五级/初级 … 3.5=一级/高级技师）；
3. **基本要求段落解析**：`2.x` → L1 素材；`2.x.y` → L2 素材；`（n）xxx。` → 追加到当前 L2 的叶素材列表；
4. **工作要求表格解析**：
   - 4 列固定语义（职业功能/工作内容/技能要求/相关知识要求）；
   - **vMerge 处理**：`tcPr/vMerge[@val='restart']` 记录值，`vMerge` 无 val（continue）继承上一行同列值；gridSpan 横向合并按列序展开；
   - 每行产出（职业功能， 工作内容， 技能要求原文， 相关知识要求原文）；职业功能去重成 L1、工作内容成 L2；
   - **相关知识要求**内 `（1）（2）…` 拆**理论叶素材**；**技能要求**内编号项（`1.1.1 能…`，兼容 `1.` `（1）` `1)` 写法）拆**技能叶素材**（拍板⑤）；
   - 单元格内多段落按换行拼接；
5. **权重表解析**（末尾两张，vMerge 大类行需继承）：
   - **理论知识权重表**：首列大类含"基本要求/相关知识要求"行，取项目级理论权重；
   - **技能要求权重表**：首列大类为"技能要求"，取各职业功能的技能考评比重（如装备操作 70% → 0.70）；
   - 焊工类二级表头为方向列，产出 `Map<等级, Map<方向, Map<项目, 百分比>>>`；`—`（该等级无此项目）解析为 null；
6. **职业元信息**：职业名称（封面大字段落）、职业编码（`职业编码：x-xx-xx-xx` 正则）、版本年。

### 5.2 已登记解析陷阱（对应《转换指南》坑 + 实测）

| 陷阱 | 对策 |
|---|---|
| vMerge 纵向合并 | restart/continue 继承，悬空 continue 记解析警告 |
| 表格内编号段落 | 表格内容不进标题检测（坑 5） |
| 职业编码 `6-16-01-12` 误判标题 | 编号后必须中文字符（坑 3） |
| `续表` 行 | 跳过（坑 4/指南 Q4） |
| 中文间多余空格 | 仅清 `[ \t]`，不动换行（坑 2） |
| 换页导致一行表格拆断 | 以 vMerge 与列数校验，断行并入上一行 |
| 基本要求某 L2 无列举项 | 叶素材为空 → 标记 `needLlm=true`，交 LLM 概括 |

### 5.3 输出 POJO

```
ParsedStandard
 ├─ workTypeTitle / seriesNo(职业编码) / version
 ├─ directions: List<String>          // 无方向=单元素 ["默认"]
 ├─ levels: List<LevelDoc>            // 五级/初级…一级/高级技师
 │    ├─ levelCode(0~4) / levelName
 │    ├─ skeleton: Node树             // L0 基本要求A/工作要求B → L1 → L2
 │    │    └─ L2 节点携带双素材：theoryMaterials(相关知识列条目) + skillMaterials(技能要求列条目)
 │    ├─ theoryWeights: Map<项目编码, BigDecimal>   // 理论知识权重表（该等级×方向）
 │    └─ skillWeights:  Map<项目编码, BigDecimal>   // 技能要求权重表（该等级×方向）
 └─ parseWarnings: List<String>       // 解析异常提示，页面展示
```

## 6. LLM 概括设计（StandardLlmSummarizeService）

### 6.1 调用粒度与 prompt

**按"L2 小节 × 等级"一次调用**（矿山救护工初级约 12 个小节 = 12 次调用，焊工全等级约 60 次），输入输出契约：

```
system：你是职业技能鉴定命题专家，正在为「{工种} {等级}」编写理论知识考评点。
user：
  小节路径：基本要求/职业道德/职业道德基本知识
  原文素材：
   （1）……（2）……        ← 可能为空（无列举项）
  要求：
   1. 概括 4~8 个考评点，每个为 ≤20 字的名词性短语，不得照抄长句；
   2. 每个考评点给重要程度：X=核心必考，Y=重要（法律法规、安全规程类），Z=一般了解；
   3. 以 JSON 输出（必须含 "points" 数组）。
输出 JSON：{"points":[{"title":"工匠精神的基本内涵","important":"X"}, …]}
```

### 6.2 确定性护栏（不过度信任模型）

- **JSON mode + 解析失败重试 ≤2 次**（第二次把错误原因回喂）；仍失败 → 该小节叶素材原文逐条兜底为叶节点（`source=extract`，标记待人工）；
- **important 枚举校验**：仅接受 X/Y/Z，非法值 → 默认 X 并记警告；
- **数量护栏**：单小节叶节点 >15 截断并记警告（对照样例单节 4~35 条）；
- **编码生成在 Java 侧**（不让模型写编码）：按 §2.2 规则由序号器统一分配，杜绝模型编错码；
- 全部产出 `review_status=pending` 草稿，**人工确认前不参与导出**（AGENTS.md AI 规则 #3/#4：写操作草稿 + 来源/模型/时间留痕）。

### 6.3 技能考评点概括通道（拍板⑤）

技能叶素材是"能……"句式的能力描述，概括口径与理论不同（操作行为短语而非知识短语），**独立 prompt 通道**，同按 L2 小节一次调用：

```
system：你是职业技能鉴定命题专家，正在为「{工种} {等级}」编写操作技能考评点。
user：
  小节路径：工作要求/事故预防/安全检查
  技能要求原文：
   1.1.1 能查出风门、风筒、密闭墙等通风设施损坏
   1.1.2 能检查采矿工作面、掘进工作面、火区等风险点
  要求：
   1. 每条原文概括 1 个操作技能考评点，动宾/行为短语 ≤25 字，保留关键对象与动作，
      去掉"能"字能力句式（如「检查风门、风筒、密闭墙等通风设施的损坏状况」）；
   2. 每个考评点给重要程度：X=核心操作，Y=重要，Z=辅助/了解；
   3. 以 JSON 输出（必须含 "points" 数组）。
输出 JSON：{"points":[{"title":"检查风门、风筒、密闭墙等通风设施的损坏状况","important":"X"}, …]}
```

- 技能考评点与原文条目**原则上一一对应**（技能条目本身已较细）；模型只可合并拆分明显过粗/过细的条目，数量护栏放宽为原文条数 ×2；
- 技能叶节点 `dimension=skill`，**只用于技能细目表 Excel 导出，不进知识树入库 SQL**（§2.4 差异表）；
- 其余护栏（JSON 重试/枚举校验/编码 Java 侧分配/草稿人工确认）与理论通道一致。

### 6.4 批处理与任务状态机

```
任务状态：uploaded → parsed → llm_running → reviewing → confirmed → exported
LLM 执行：任务级异步（线程池）；按小节顺序执行；支持失败小节单独重试（页面「重新生成」按钮）
并发保护：同任务重复触发 LLM 直接 409（数据库状态前置校验）
```

## 8. 权重分配规则（LLM 不参与，纯规则 + 人工微调）

### 8.1 理论权重（理论细目表）

1. **项目级权重**（基本要求 A / 工作要求 B / 工作要求下各职业功能）：直接取 docx **理论知识权重表**（按 等级×方向 取值）；焊工方向专属职业功能只在对应方向树出现；
2. **L1 细分权重** = 项目权重 ×（该 L1 叶节点数 ÷ 项目总叶节点数），保留 4 位小数；
3. **L2 考评权重** = L1 权重 ×（该 L2 叶节点数 ÷ L1 总叶数）；
4. **重要程度比例**（细目表 `(42:8:0)`）= 该节点子树内 X:Y:Z 叶节点计数，导出时实时统计；
5. 页面对 L1/L2 权重可手动微调（校验：同项目下 L1 之和 = 项目权重，超限红字提示）；

> 对照样例：基本要求 0.25（docx 权重表）→ 职业道德 0.05 / 基础知识 0.20（按叶数 10:40 ≈ 1:4 分配，样例 0.05/0.20 吻合）。

### 8.2 技能考评比重与选考方式（技能细目表，拍板⑤）

1. **一级（职业功能）考评比重**：直接取 docx **技能要求权重表**（如矿山救护工 事故预防 15% / 事故救援 15% / 装备操作 70% → 0.15/0.15/0.70）；`—`（该等级无此项）则该职业功能不出现在该等级技能表；
2. **一级选考方式**：恒 `必考`（样例全量如此）；
3. **二级（工作内容）考评比重**：选考方式恒 `任选一项`——同一级下每个二级均承担该一级全部比重；**版式对齐样例：仅在每个一级的首个二级行标出数值，其余二级留空**；
4. **试题量列**：程序**留空**，由人工审核后填写（拍板⑤）；
5. **重要程度比例**（一级/二级代码后缀 `(3:1:0)`）= 该节点子树内技能叶的 X:Y:Z 计数，导出时实时统计；
6. 技能比重同样允许页面微调（校验：各一级之和 = 100%）。

## 9. 导出设计

### 9.1 入库 SQL 导出（KnowledgeSqlExporter）

- 目标口径：PHP 库（tenant_id=10159，`important` varchar X/Y/Z）；
- **仅含理论叶**（dimension=theory）；技能考评点不入库（拍板⑤）；
- **id/parent_id 处理**：PHP 表为 int auto_increment → 按层级分段生成，每个节点 `INSERT …; SET @k_A_A_A = LAST_INSERT_ID();`，子节点 `parent_id = @k_父编码`（编码任务内唯一，变量名用编码字母数字转义）；
- `exam_work_type` / `exam_course` 若已存在（按 title+series_no 匹配）则生成注释说明跳过，不重复插入；
- 生成顺序：work_type → course（每方向每等级一行）→ knowledge_structure（按层级序）；
- 文件头注释：来源 docx、生成时间、操作人、行数统计；文件落地 `outputs/` 并提供页面下载。

### 9.2 理论细目表 Excel 导出（MubiaoExcelExporter）

- POI SXSSF；按 §2.3 版式：标题合并行 + 4 行复合表头 + L0/L1/L2 纵向合并（`CellRangeAddress`）；
- 每个「等级×方向」一个文件（如 `焊工(五级)电焊工_理论知识考评要素细目表_yyyyMMddHHmmss.xlsx`）；
- 样式：表头加粗居中、权重列数字格式 `0.00`、边框细线；列宽自适应内容上限 60。

### 9.3 操作技能细目表 Excel 导出（SkillMubiaoExcelExporter，拍板⑤）

- POI SXSSF；按 §2.4 版式（13 列）：标题合并行 + 「职业/级别」行 + 复合表头 + 一级/二级纵向合并；
- 数据范围：仅工作要求部分的 L1（职业功能）/L2（工作内容）+ dimension=skill 的 L3 考评点；基本要求分支不出现；
- 一级：代码+(X:Y:Z 计数)、名称、考评比重（§8.2）、选考方式=必考；二级：代码+(计数)、名称、技能要求原文（`skill_requirement` 列）、考评比重（仅首个二级标出）、选考方式=任选一项；
- **试题量列留空**（人工审核后填写）；重要程度 X/Y/Z 照 staging；
- 每个「等级×方向」一个文件（如 `矿山救护工(五级)_操作技能考评要素细目表_yyyyMMddHHmmss.xlsx`）；样式同 §9.2。

## 12. 边界与异常

- docx 非国家标准格式（无编号标题/无权重表）→ 解析阶段报错并给出警告清单，不进 LLM；
- LLM 全局不可用 → 任务停在 `parsed`，骨架仍可人工补叶后导出（**主链路降级不挂**）；
- 权重表缺失某等级 → 该等级权重列为空，页面提示手工填写；
- **技能要求列为空或无编号项** → 该 L2 无技能叶素材，技能细目表对应行留空并记警告（不阻塞理论通道）；
- **技能要求权重表缺失**（个别标准可能只有理论权重表）→ 技能细目表比重列留空、页面提示手工填写，仍可导出；
- 同一 docx 重复上传 → 按 fileHash 提示已存在任务，选择覆盖重建或查看；
- 导出前置校验：存在 `review_status=pending` 叶节点 → 禁止导出并定位提示；
- 所有写操作（上传/编辑/重新生成/导出）记操作日志（@AuditLog）。

## 16. 修正计划（v1.4，需求方 2026-08-13 确认）

### 16.1 背景：两个已发现的问题

1. **焊工「气焊工」出现不应有的等级**。docx 1.4「职业技能等级」明确：气焊工只有五级/初级、四级/中级、三级/高级；钎焊工到二级/技师；电焊工、焊接设备操作工才到一级/高级技师。但当前 v1.3 上线版本中，预览树和导出的 SQL 出现了「焊工技师-气焊工」「焊工高级技师-气焊工」等只有 A 支（基本要求）的冗余课程。
2. **入库 SQL 总是新建 `exam_work_type`/`exam_course`**。PHP 库中已存在焊工 4 个工种（work_type_id 139~142）及 16 门课程，且这些 course 下尚无 `exam_knowledge_structure` 记录，完全可以复用。

### 16.2 根因说明

- **方向等级范围漏识别**：当前解析器只读了 1.4 中「本职业共设五个等级…」这一句，得到 5 个 levelCode；但没有继续解析接下来每个工种分别对应的等级范围，导致 `StandardTreeBuilder` 按「方向数 × 等级数」全量循环（5×4=20）。
- **A 支判断位置错误**：`StandardTreeBuilder` 在循环里先把 A 支（基本要求）节点加进去，随后才判断 `aWeight == null && B 支为空` 则 `return`；这只能阻止 B 支，已经创建的 A 支节点仍然入库。

### 16.3 修正方案 A3：权威约束 + 权重兜底

#### 16.3.1 解析 1.4「职业技能等级」段落

在 `DocxStandardParser` 中增加对 1.4 子节的处理：

- 当 `mainSection == 1 && sectionOneSub == 4` 时，连续读取后续普通段落（直到遇到新的标题 1.5/2.1 或空段落）。
- 匹配段落模式：`<方向>工种分别为[：:]\s*(.+)`，例如：
  - `气焊工工种分别为：五级/初级工、四级/中级工、三级/高级工。`
  - `钎焊工工种分别为：五级/初级工、四级/中级工、三级/高级工、二级/技师。`
- 把「五/四/三/二/一」映射为 `levelCode` 0~4，存入 `ParsedStandard.directionLevels`（`Map<方向, List<Integer>>`）。
- 段落内可能包含多个方向（用分号/句号分隔）或换行，需做分句、容错、兜底。

#### 16.3.2 树构建器按权威约束过滤

`StandardTreeBuilder.buildTree` 调整：

1. 先检查 `directionLevels`：若当前 `(levelCode, direction)` 不在允许列表，直接跳过整棵树（不建 A 支也不建 B 支），并记录 `WARN: 方向<方向>不包含等级<等级>，已按 1.4 跳过`。
2. 若 `directionLevels` 为空（未解析到 1.4 或解析失败），降级为权重表兜底：把现有 `if (aWeight == null && B 支为空) return;` 判断**提前到 A 支创建之前**，避免无效 A 支入库。
3. 若 `directionLevels` 存在但与权重表冲突（权重表在该组合有非空值但 1.4 不允许），以 1.4 为准并记录 `WARN: 1.4 与权重表冲突，以 1.4 为准`。

#### 16.3.3 预期结果

- 焊工重新上传后，有效组合为：
  - 电焊工 5 个等级、气焊工 3 个等级、钎焊工 4 个等级、焊接设备操作工 5 个等级，**共 17 棵 preview 树**。
- SQL 导出（新建模式）生成 17 门 `exam_course`，不再是 20 门。
- 技能/理论 Excel 也只导出这 17 个组合。

### 16.4 修正方案：复用已有课程模式

#### 16.4.1 模式定义

在 `KnowledgeSqlExporter` 中增加 `SqlExportMode`：

- `CREATE`（默认）：现有行为，生成 `exam_work_type` + `exam_course` + `exam_knowledge_structure` 全量 INSERT。
- `REUSE`：复用目标库中已存在的 `exam_work_type` 和 `exam_course`，仅生成 `exam_knowledge_structure` 的 DELETE + INSERT。

#### 16.4.2 匹配规则

- 方向 → `exam_work_type`：`title = <方向>`（如「电焊工」「气焊工」），`tenant_id = 目标 tenant`，`deleted = 0`。
- 等级 → `exam_course`：`work_type_id = @wt_方向` 且 `level = levelCode`，同 tenant、deleted=0。
- 匹配失败：直接返回 400 错误，提示「缺少方向 X 等级 Y 的 course，请先在课程管理维护」。

#### 16.4.3 删除旧树再写入

复用模式下，对每个要写入的 `course_id`，在生成 `exam_knowledge_structure` INSERT 之前先执行：

```sql
DELETE FROM exam_knowledge_structure
WHERE course_id = @c_level_direction AND tenant_id = 10159;
```

并在 SQL 文件头部加注释：

```sql
-- 复用已有课程模式：将删除以下 course_id 下全部旧 knowledge_structure，执行前请备份！
-- 本文件由 <操作人> 于 <时间> 生成，来源 task_id=<id>
```

#### 16.4.4 前端与接口

- `StandardParseController.exportSql` 增加可选 query 参数 `mode=create|reuse`，默认 `create`。
- 前端导出按钮增加下拉/弹窗选择：「新建课程（默认）」「复用已有课程」。`api.ts` 的 `downloadExport` 透传 `mode`。
