# 国家职业技能标准 → 培训教材 生成功能实现方案

> 版本：v1.0　日期：2026-10-13
> 需求方拍板记录（2026-10-13，三项均取推荐项）：
> - **A1**：教材数据**独立于 `exam_knowledge_structure`**，新建 `textbook_*` 系列表，与知识树靠「工种 + 方向 + 等级 + 节点号」关联，不扩展知识树字段
> - **B1**：内容生成粒度 = **按「节」**（一次输入该节全部知识点 + 技能点 + 目标字数，输出一节正文），可单节重新生成
> - **C1**：一期**只交付大纲 + 目录 + 每节字数配比**，专家评审通过后再开放正文生成
> 参考材料：`docs/osta-standards/铝电解工.docx`（及已转换的 `铝电解工_docx.md`，761 行）、`docs/osta-standards/标准理论知识权重映射配置指南.md`
> 关联功能：《职业技能标准细目表生成功能实现方案》（v1.6）、《AI课件生成-标准docx转PPTX-方案》、《理论知识试题生成管理方案》

## 1. 背景与目标

围绕国家职业技能标准，自动生成培训教材的**大纲、目录、骨架与篇幅配比**，再由领域专家（或 LLM 辅助、专家审定）填充具体内容。

目标交付物（按 C1 分期）：

1. **一期**：选定「工种 × 方向 × 等级」后，产出结构化大纲（章 / 节 / 知识点 / 技能点）+ 每章每节的目标字数 + 可导出的目录（Markdown / Excel）；
2. **二期**：按节生成正文（讲解 + 案例 + 习题），专家逐节审定后合成教材文档。

### 1.1 与既有功能的关系（不重复造轮子）

| 已有能力 | 本方案怎么用 |
|---|---|
| `exam/standard/parser/DocxStandardParser` | 直接复用。已能产出 `ParsedStandard`：职业元信息 + 基本要求树 + 各等级工作要求 + 双权重表 + `directionLevels` 方向等级映射 |
| `StandardL2WeightInitializer`（最大余数法） | 复用其算法思路，把「权重分摊」从分值改为字数 |
| `StandardLlmSummarizeService` | 二期正文生成的状态机、批处理、护栏样板 |
| `courseware/KnowledgePointEnumerator` + `DocxSectionParser` | 确定性知识点枚举口径保持一致 |
| `ai/infrastructure/FaqLlmClient` + `exam_faq_model_config` | 正文生成的调用通道与模型配置 |
| `ai_generation_draft` | 生成留痕（模型 / 时间 / 操作人） |

**本方案与细目表的边界**：细目表面向**考评**（产出考评点、重要程度 X/Y/Z、试题量）；教材面向**教学**（产出章节、讲解正文、案例习题）。二者共用同一份标准解析结果，但下游产物、粒度、数据表各自独立（A1）。

## 2. 关键约束：必须先选「方向 × 等级」

这是本方案最重要的一条，来自铝电解工标准的实测。

### 2.1 实测证据

`铝电解工_docx.md` 第 3.1 节（五级/初级工）正文首段原文：

> 本级别 2~ 11 项职业功能为可选项。铝电解槽操作工考核职业功能 1、2、12 项；铝吸出工考核职业功能 1、3、12 项；多功能机组操作工考核职业功能 1、4、12 项；物料输送及烟气净化工考核职业功能 1、5、12 项；电解槽计算机监控工考核职业功能 1、6、12 项；铝及铝合金熔铸工考核职业功能 1、7、12 项；炭极生产工考核职业功能 1、8、12 项；物料分析检测工考核职业功能 1、9、12 项；铝电解筑炉工考核职业功能 1、10、12 项；铝电解综合工考核职业功能 1、11、12 项。

即：**10 个方向，每个方向只考 3 项职业功能（1 + 各自专项 + 12）**。

4.1 理论知识权重表中，2~11 项职业功能均标注 ∗：

> 注：标有"∗"的职业功能为可选项，申报人根据实际情况任选其一。

且这些可选项的权重值恒相同（如铝电解槽操作∗：50 / 50 / 55 / 45 / 40），因为它们互斥。

### 2.2 结论

**不存在"一本《铝电解工》教材"，只存在"《铝电解工—铝电解槽操作工（五级/初级工）》"这样的分册。**

因此：

- 产品的第一道门是**「工种 × 方向 × 等级」三元组选择器**，未选定不得进入大纲生成；
- 方向 → 职业功能的对应关系**必须以标准 3.x 正文的这句说明为准**（写在正文里，不在权重表里），需要专门解析或人工登记；
- 若直接把整本标准丢给模型生成目录，模型会把 10 个方向内容全部塞进一本，产出不可用。这是本方案要消除的首要风险。

## 4. 总体流程

```
选择「工种 × 方向 × 等级」（三元组，必填）
   │
   ▼
[1] 规则解析（同步，秒级）          ── 复用 DocxStandardParser
   取该等级的：基本要求树 + 工作要求表 + 权重表 + 培训学时
   │
   ▼
[2] 方向过滤（规则）                ── 按 2.1 的方向→职业功能映射
   只保留该方向考核的职业功能（铝电解槽操作工 = 1、2、12）
   │
   ▼
[3] 骨架生成 + 篇幅配比（规则，零 LLM）
   总字数 = 培训学时 × 系数
   章字数 = 权重% × 总字数（最大余数法凑整）
   节字数 = 章字数 × 该节条目数占比
   │  落库 textbook_outline，页面可见，可人工微调
   ▼
[4] 专家评审大纲（页面审阅 / 导出目录）
   │
   ▼
[5] 二期：按节生成正文（异步批处理）   ── FaqLlmClient + 确定性护栏
   │  落 ai_generation_draft 留痕；逐节人工审定
   ▼
[6] 二期：合成导出 docx
```

## 6. 骨架抽取（纯规则，零 LLM）

### 6.1 复用解析器

`DocxStandardParser` 产出 `ParsedStandard`，本方案直接消费：

- `basicSections`：基本要求 L1 树（`StandardNodeDoc`，含 `theoryMaterials`）
- `levels[].*`：各等级工作要求（L1 职业功能 → L2 工作内容 → `skillMaterials` / `theoryMaterials`）
- `theoryWeights` / `skillWeights`：`StandardWeightTable`，按 `levelCode|direction` 取值
- `directionLevels`：1.4 节的方向 → 等级权威约束

### 6.2 方向 → 职业功能映射（难点）

标准把这条规则写在 3.x 正文首段（见 §2.1 原文），不在表格里，格式在各标准间不统一。方案：

1. **优先解析**：正则抽取"XX 工考核职业功能 N、M、K 项"句式，产出 `{方向: [职业功能序号]}`；
2. **解析失败 → 人工登记**：页面提供「方向 → 职业功能」勾选项，由管理员确认并持久化到 `textbook_project.direction_function_json`；
3. **兜底**：若标准无方向（如单方向工种），方向列表为单元素 `["默认"]`，全部职业功能生效。

铝电解工的 10 个方向映射以 §2.1 原文为验收对拍基准。

### 6.3 章的确定

章的来源分两部分：

1. **基础篇**（等级无关）：2.1 职业道德、2.2 基础知识 及其下 2.x.y。权重取理论权重表中 `基本要求-职业道德` / `基本要求-基础知识` 两项；
2. **专业篇**：该等级工作要求表中、经 §6.2 过滤后的职业功能。权重取理论权重表中同名项目（用 `StandardWeightTable.findRow` 的 `normalizeItemName` / `normalizeMatchKey` 宽松匹配）。

**权重为 `—`（null）的项目 → 该等级无此章**，直接不生成。实测三级及以上无"工作准备"章，二级及以上无"设备管理"章（被"设备和技术管理"取代）。

## 7. 篇幅配比算法（确定性，LLM 不参与）

### 7.1 总字数

```
总字数 = 培训参考学时 × 每学时字数系数
```

- 培训学时取 1.8 节（铝电解工：40 / 60 / 80 / 100 / 120）；解析不到时由人工填写
- **每学时字数系数默认 2500**，可配置。理由：40 学时 ≈ 10 万字（初级工分册）、120 学时 ≈ 30 万字（高级技师分册），与职业培训教材常见体量相符。**该系数建议由专家确认后固化**（方案标注为待确认项，不写死）

### 7.2 章字数

```
某章字数 = 总字数 × 该章权重% ÷ 100
```

用**最大余数法**凑整到整数，保证各章之和严格等于总字数（复用 `StandardL2WeightInitializer` 的思路）。

### 7.3 节字数

```
某节字数 = 该章字数 × (该节知识点条数 + 技能点条数) ÷ 该章总条目数
```

同样最大余数法凑整，章内各节之和严格等于章字数。

### 7.4 人工微调

页面允许改章/节字数；改动后**重新校验合计**（不等于上级字数时给出提示但不阻塞，由专家判断）。所有配比与人工改动均需记录，导出目录时附「配比依据」列（权重来源 + 是否被人工调整），保证可追溯。

## 8. LLM 内容生成设计（二期）

### 8.1 粒度（B1：按节）

一次调用输入**一节**的全部信息：

- 节标题、所属章标题
- 该节全部**知识点**条目（标准原文，逐条列出）
- 该节全部**技能点**条目（标准原文）
- 该节目标字数（±20% 允许区间）
- 术语约束：**必须使用标准原文表述，不得改写或自造术语**

输出 JSON：`{ sections: [{ heading, paragraphs[], case?, exercises[] }] }`

### 8.2 确定性护栏（对齐细目表方案 §6.2）

1. **字数校验**：输出字数超出 ±20% 判为不合格，记录并可重生成，不自动采纳；
2. **知识点覆盖校验**：该节每条知识点条目的核心词必须在正文中出现，缺失则标黄提示专家；
3. **术语一致性**：正文出现的术语需能回溯到标准条目，新增术语单独列出供专家确认；
4. **禁区**：工艺参数、安全规程、法律法规条文**不允许模型编造**——prompt 明确要求引用标准原文，无法确认时输出"[待专家补充]"占位而非猜测。这是硬约束，涉安全；
5. **留痕**：每次生成写 `ai_generation_draft`（模型名、时间、操作人），对齐 AGENTS.md 的 AI 硬规则。

### 8.3 异步与多租户红线

- 独立线程池 `textbookContentExecutor`：**AbortPolicy**（AGENTS.md 异步红线第 2 条，禁 CallerRunsPolicy）
- Worker 线程**禁止调用 `SecurityContext`**；tenantId / userId 在 HTTP 线程捕获后经参数传递，Worker 自行 `TenantContextHolder.set` + `finally clear()`
- 长任务拆「快速返回 + 异步执行 + 进度轮询」三步，禁止单接口同步完成

- 模型配置沿用 `exam_faq_model_config`，新增 `model_code`（如 `textbook-content`），不新建配置机制
- 前端无新依赖

## 12. 风险与注意点

| 风险 | 应对 |
|---|---|
| 方向 → 职业功能句式各标准不统一，解析会失败 | §6.2 三级兜底；解析失败时页面强提示人工确认，不允许静默取全部 |

## 13. 测试与验收

**单元测试（纯规则，必须覆盖）**

- 方向 → 职业功能解析：以铝电解工 §2.1 原文为对拍，10 个方向映射逐条断言
- 章过滤：三级/高级工不得出现"工作准备"章；二级/技师不得出现"设备管理"章
- 最大余数法：各章字数之和严格等于总字数；各节之和严格等于章字数
- 权重为 `—` 的项目不生成章

**集成测试**

- 上传 `铝电解工.docx` → 选「铝电解槽操作工 × 五级/初级工」→ 断言章集合 = {基本要求-职业道德, 基本要求-基础知识, 工作准备, 铝电解槽操作, (12 项)}
- 总字数 = 40 × 2500 = 100000，各章字数之和 = 100000

**手工验收**

- 导出目录，交领域专家评审章节完整性（是否有漏项、是否有不该出现的方向内容）
- 二期：随机抽 5 节，专家盲评正文可用率

## 14. 分期（tracer bullet：纵向切片优先）

| 阶段 | 内容 | 交付 |
|---|---|---|
| **M1** | 表结构 + 迁移；复用 `DocxStandardParser` 打通「选三元组 → 解析 → 落库」 | 后端接口 + 单测 |
| **M2** | 方向过滤 + 骨架生成 + 篇幅配比 | 大纲接口 + 最大余数法单测 |
| **M3** | 大纲编辑页 + 目录导出（**一期验收点**） | 页面 + e2e |
| **M4** | 二期：按节生成正文 + 护栏 + 审定流 | 正文生成 + 留痕 |
| **M5** | 二期：合成导出 docx | 导出器 |

**一期只做 M1–M3**，且**首个验证组合固定为「铝电解工 × 铝电解槽操作工 × 五级/初级工」**（40 学时、职业功能 1/2/12、理论权重 50）。该组合跑通并经专家认可后，再横向扩展到其他方向与其他等级，最后再考虑其他工种（仓库已有 16 份标准 docx）。
