# 本地开发环境

> 从根目录 `AGENTS.md` 拆出（2026-09-20 拆分）。搭环境、起服务、本机调试时阅读。

## 环境路径

工具安装路径因成员电脑而异，**不要假定固定绝对路径，也不要照抄任何历史文档/对话中的示例路径**。需要定位工具时按以下顺序解析：

1. 本机覆盖文件 `AGENTS.local.md`（已 gitignore，若存在优先采用其中记录的路径）
2. 环境变量：`JAVA_HOME`、`MAVEN_HOME`
3. PATH 探测：`where javac`、`where mvn.cmd`、`where node`、`where mysql`
4. 常见安装位置兜底（匹配最新版本）：`C:\Program Files\Java\*`、`D:\Program Files\Java\*`、`C:\Program Files\MySQL\MySQL Server *\bin\mysql.exe`
5. IDE 内置 Maven 兜底：JetBrains 系自带 `<IDE 安装目录>\plugins\maven\lib\maven3\bin\mvn.cmd`（2026-09-23 实测 IntelliJ **2019.3.3 自带的 3.6.3** 可正常 compile/test-compile，虽低于文档要求的 3.9+）
6. 仍未找到 → 停下询问用户，不要自行下载安装

版本要求：JDK 21、Maven 3.9+、**Node 20 LTS+**（18 已 EOL）、MySQL 8.4（`java -version` / `mvn -v` / `node -v` 验证）

## 环境变量

完整变量（40+ 个，含 RabbitMQ、短信限流、文件存储、Token TTL、WeKnora 等）见模板：`infra/env/platform-api.env.example`。

**敏感值不落文档**：真实数据库地址/账号/密码写在已 gitignore 的 `AGENTS.local.md`，不要写进任何入库文件；也不要照抄历史文档里的连接串（历史上文档与模板口径不一致，照抄会连错库）。

## Redis

Redis 用于 Sa-Token 会话与缓存（pom 含 `spring-boot-starter-data-redis` + `sa-token-redis-jackson`，`application.yml` 有完整 Lettuce 池配置）。本地可用 Docker 起（`infra/docker/docker-compose.platform-api-dev.yml`）；不配置时部分缓存能力降级，**不要假定完全无依赖**。

## 常用命令

```bash
# 后端构建（JAVA_HOME / mvn 按"环境路径"规则解析）
$env:JAVA_HOME = "<JAVA_HOME>"
mvn.cmd compile -f services/platform-api/pom.xml -s scripts/custom-maven-settings.xml

# 后端直接启动（使用预构建 JAR）
java -jar services/platform-api/target/platform-api-0.1.0-SNAPSHOT.jar

# 前端开发服务器
cd apps/admin-web && npm run dev

# 前端构建 + 类型检查（合并前必跑；无 tsc/test 通用 script）
cd apps/admin-web && npm run build

# 后端跑单个测试类（合并前验证）
mvn.cmd test -f services/platform-api/pom.xml -s scripts/custom-maven-settings.xml \
  -Dtest='SomeTest,OtherTest' -DfailIfNoTests=false

# 访问
# 前端: http://localhost:5173
# 后端: http://localhost:8080/api
```

**注意（2026-09-23 实测）**：
- **surefire 首次运行需要联网**。加 `-o`（离线）会因本地仓库缺 `org.codehaus.plexus:plexus-utils:1.1` 报 `PluginResolutionException`，不是代码问题。
- 前端构建**不要与 `mvn compile` 同时跑**：本机两者并行时 vite 打包阶段会长时间无响应（实测 15/12 分钟不结束）。
- **构建很慢时先怀疑新引入的大依赖，而不是先怪机器**。案例：exceljs 用静态 `import` 会让 vite 卡在 `transformed` 之后不结束，改动态 `import()` 后 1m13s 完成——详见踩坑库 #28。
- 沙箱/受限环境里 `rm -rf dist` 可能被 safe-delete 机制拦截（trash 失败后 fail-closed）且**不报错到构建日志**；核验产出请直接看 `dist/index.html` 的时间戳，别假定"清理过就是干净构建"。
- **删除前端依赖后必须确认 lockfile 同步**：`grep '"node_modules/<包名>"' apps/admin-web/package-lock.json` 应为 0；若仍有残留（普通 `npm install` 不一定会重写 lock），跑 `npm install --package-lock-only --no-audit --no-fund` 补上。否则他人 `npm ci` 会因 lock 与 `package.json` 不一致而失败（2026-09-23 删除 xlsx 时踩到）。
