# 分班主路径改为「排班表驱动」改造方案

> 文档版本：v1.1  
> 编写日期：2026-07-16  
> v1.1：按方案落地代码（materialize / 主路径向导 / 兼容模式）  
> 目标系统：`qianlvguoyu_saas`  
> 目标流程：上传厂区月排班表 → 算谁哪天能上课 → 拆成算法班 →（物化）培训班+学员 → 企业确认  
> 依据：Scheduling `scheduling-backend` 流程；现网一期 L1 + 二期 L2（T0）已落地

---

## 1. 背景与问题

### 1.1 现状（双路径）

| 路径 | 入口 | 输入 | 产出 | 问题 |
|------|------|------|------|------|
| **L1 组织分班**（主 UI） | 勾选确认名单 → `org-split` | 筛选名单 | `train_info_class` + `train_people_list` | **不按倒班可上课时间拆班** |
| **L2 排课分班**（折叠） | `shift-assign/generate` | 排班表 | `train_shift_assign_*` | 算法班需**手工 bind**；**不写学员** |

运营期望接近 Scheduling：**以月排班表为主输入，系统自动算出可上课时段并拆算法班**，结果还要进入 SaaS 开班域（企业分班确认、班级人员）。

### 1.2 目标流程（改造后主路径）

```
三年规划 status=4 + 排班表齐套（名单建议保留作人员补全）
  → 选规划 / 确保 train_info_list
  → 选定年月（厂区 = targetOrg）
  → Adapter 预览（T0，后续 T1…）
  → 预检（可上课 / 未知班次 / 未排入）
  → 生成算法班（train_shift_assign_*）
  → 【新增】物化 materialize：算法班 → train_info_class + train_people_list
  → 提交企业分班确认
  → 班级人员 / 开班申报
```

一句话：**L2 升为主路径；L1 变为「算法班物化为培训班」的落库步骤，而不是手工勾选名单拆班。**

---

## 2. 产品决策（必须先拍板）

### 2.1 推荐方案：**L2 主路径 + 一键物化（A）**

| 决策点 | 推荐 | 说明 |
|--------|------|------|
| 主输入 | **企业回传排班表**（可支持分班页补传/覆盖） | 对齐 Scheduling「上传月排班表」 |
| 名单文件 | **仍要求齐套**（或降级为「建议」） | 用于身份证/工种补全、与规划人员对齐；解析失败不阻断 L2 |
| 算法班 → 培训班 | **生成后自动/一键物化** | 每个算法班（或按策略合并）→ 一条 `train_info_class` + 去重学员 |
| 企业确认 | 仍确认 **物化后的培训班** | 不确认「上午1班」字符串 |
| 旧 org-split | **降为高级/兼容**（默认隐藏） | 无排班表或 T0 失败时人工兜底 |
| Adapter | 先 T0；异构走三期 | 非标准表必须选模板，否则只给预检失败提示 |

### 2.2 备选（不推荐作主案）

| 方案 | 做法 | 缺点 |
|------|------|------|
| B. 仅改 UI 把 L2 提前 | 仍手工 bind，不写 people | 企业确认/班级人员仍空 |
| C. 删除 L1 | 只留 shift_assign | 与开班申报/确认链路断裂 |

## 3. 目标业务规则

1. 仅 `status=4` 可进分班。  
2. **分班门禁以排班表为主**：`enterpriseShiftFileId` 必有；名单建议必有（配置开关 `requireRoster=true` 默认开）。  
3. 必须先有 `train_info_list`（`three_year_plan_id`）。  
4. 引擎规则沿用现网 L2：早/白全天、中仅下午、夜当天+次日禁；班额默认 30～50。  
5. **人员主键**：优先身份证；无证号用「工号」，再无用「姓名」（与 Scheduling personKey 对齐，并在物化时尽量回填证号）。  
6. **物化去重**：同一 `trainInfoId` 下同一身份证只进一个培训班（冲突进警告，不静默覆盖）。  
7. 物化后 `company_confirm_status=0`，走现有企业分班确认。  
8. 调课（patch）若发生在物化之后：要么禁止，要么「再物化」覆盖策略（见 §5.3）。

## 4. 目标前端流程（替换三步向导）

| 步骤 | 名称 | 操作 | 对应 API |
|------|------|------|----------|
| 0 | 选规划 | 列表 status=4；显示排班/名单齐套状态 | `GET /division/plans` · `/ready` |
| 1 | 培训信息 + 年月 | ensure train_info；选 year/month；班额；下载/补传排班 | `ensure-train-info`；可选补传接口 |
| 2 | 预检 | Adapter 预览 + 预检结果（未知班次、未排入、算法班列表） | `POST /shift-assign/adapters/preview` · `/precheck` |
| 3 | 生成并物化 | 一键：generate → materialize →（可选）提交确认 | `generate` + **新** `materialize` |
| 4 | 结果 | 算法班明细、培训班映射、跳转企业确认/班级人员 | `GET /tasks/{id}` · summary |

UI 调整要点：

- **去掉**步骤 3 主操作「勾选名单 + org-split」（收入「兼容模式」折叠）。  
- **提升**现有 `ShiftAssignPanel` 为向导主体，而不是折叠附属。  
- 预检页展示 Scheduling 同款信息：warnings、algoClassNames、unassigned、dailyStats 摘要。

## 5. 后端改造设计

### 5.1 已有可复用（尽量不重做）

| 能力 | 现状 |
|------|------|
| 解析 + 可上课 + 拆班 | `service/shiftassign/engine/*` |
| 任务落库 | `train_shift_assign_task/record` |
| preview / precheck / generate / patch / bind-class | `TrainShiftAssignController` |
| 培训班 / 学员 / 企业确认 | `train_info_class` · `train_people_list` · company-confirm |

### 5.2 新增核心 API

#### `POST /training/shift-assign/tasks/{id}/materialize`

将算法班物化为 SaaS 培训班+学员。

请求示例：

```json
{
  "trainInfoId": 9,
  "mode": "algo_class_as_train_class",
  "submitForCompanyConfirm": true,
  "classNamePrefix": "来铝-2026-07-",
  "onlyUnbound": true,
  "matchRoster": true
}
```

| mode | 含义 |
|------|------|
| `algo_class_as_train_class`（默认） | 每个算法班名 → 1 个 `train_info_class` |
| `bind_existing` | 仅按已有 bind 映射补学员，不新建班 |
| `merge_by_person_set`（可选二期） | 人员集合相同的上午/下午班合并为一个培训班 |

事务步骤：

1. 校验 task 归属、`trainInfoId` 与 plan 一致。  
2. 按 `algo_class_name` 聚合 record 中的去重人员（姓名/工号/身份证）。  
3. `matchRoster=true` 时用 `train_plan_roster`（或名单再解析）按证号/姓名补全 phone、工种。  
4. 创建或更新 `train_info_class`（title = prefix + 算法班名；`company_confirm_status=0`）。  
5. 写入 `train_people_list`（`type=student`）；跳过已存在同证号。  
6. 回写 `train_shift_assign_record.train_class_id`；task 标记 `status=materialized`。  
7. 返回 `{ trainInfoId, classes:[{algoClassName, classId, nums}], warnings[] }`。

#### （可选）`POST /training/shift-assign/generate-and-materialize`

编排：`generate` + `materialize` 单事务或串行，供前端「一键」。

#### （可选）分班页补传排班

复用三年规划 `upload-enterprise-return`，或新增：

`POST /training/division/plans/{planId}/shift-file`  
仅更新 `enterprise_shift_file_*`，不改变 status。

### 5.3 物化后调课策略（二选一，需产品点选）

| 策略 | 行为 | 建议 |
|------|------|------|
| **冻结** | materialize 后禁止 patch；需「作废任务重跑」 | **默认推荐**（实现简单） |
| **增量再物化** | patch 后调用 materialize(onlyDiff=true) | 后期再做 |

### 5.4 门禁微调

| 原规则 | 改造后 |
|--------|--------|
| ready = 名单 AND 排班 | **主路径**：排班必填；名单由配置决定 |
| 前端必须先 org-split | 改为必须先 generate(+materialize) |
| L2 bind 手工选班 | materialize 自动建班并绑定；bind-class 保留给高级调整 |

### 5.5 权限

继续复用 `DIVISION_VIEW` / `DIVISION_MANAGE`；materialize 归 `DIVISION_MANAGE`。

## 6. 数据流对照

```
【Scheduling】
  Excel → parse → ClassAssignResult → scheduling_class_assign
       →（可选）bind training_class

【改造后 SaaS】
  企业排班 Excel（plan.enterprise_shift_file_id）
       → ExcelScheduleParseService / ScheduleAlgorithmService
       → train_shift_assign_task + record
       → materialize
       → train_info_class + train_people_list
       → 企业 company-confirm
```

禁止继续「只 bind 不写 people」作为主闭环。

## 8. 验收标准

1. 齐套（至少排班表）的 status=4 规划，可不做名单勾选，完成：**预检 → 生成 → 物化 → 企业确认 → 班级人员可见学员**。  
2. 算法班数量与 `train_info_class` 数量在默认 mode 下一致（或按文档声明的合并规则）。  
3. 中班日仅下午有 record；夜班当天+次日无课（沿用现单测）。  
4. 物化后同 trainInfo 身份证不重复。  
5. 兼容模式仍可用 org-split（不破坏旧操作习惯）。  
6. 非 T0 排班表：预检失败信息可读，不产生半成品班级。

## 9. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 企业排班非标准人日表 | 预检强提示；并行推进三期 Adapter；兼容模式兜底 |
| 算法班过多（按日拆班）导致培训班爆炸 | 物化 mode 可选「按人员稳定班」或「仅绑定不按日建班」——**首期默认按算法班名建班，需产品确认是否接受「上午1班」作为班级标题** |
| 排班表无身份证 | matchRoster + 姓名匹配；无证号写入 people 但标警告 |
| 与旧 L1 数据并存 | materialize `onlyUnbound`；同 plan 多次生成用新 task，旧班不自动删 |

### 9.1 关键产品澄清（实施前书面确认）

**Scheduling 的「上午1班」是「某日某时段的上课编组」，不是稳定行政班。**  
若业务要的是「张三整个月固定在 1 班」，需要额外聚合策略（按人员高频算法班 / 按生产班组），本方案首期**不做**，避免 silently 做错。

首期交付语义建议写进 UI：

> 本系统按「可上课时段」拆班（与倒班表一致）。生成的培训班名称对应算法班（如上午1班），企业确认的是这些培训班级。

---

## 10. 建议实施顺序

1. **先做 materialize API**（不改 UI 也能 Postman 打通闭环）。  
2. **再改向导主路径**（L2 升主、L1 兼容）。  
3. **最后**补传排班、门禁开关、文档验收。  
4. 异构表多了再开三期 Adapter。
