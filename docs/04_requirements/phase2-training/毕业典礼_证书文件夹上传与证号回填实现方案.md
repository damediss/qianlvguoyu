## 一、结论（先看）

| 问题 | 答案 |
|------|------|
| 要解决什么 | 把人社下发的证书 PDF（文件夹）挂到**已选班级**花名册人员上，写入**真实证书编号** + **证书文件** |
| 匹配键 | **身份证号**（唯一锚人）；姓名仅展示/告警，不作自动落库键 |
| 班级范围 | 列表**多选班级**后上传；证书**只回填到本次勾选的班级**花名册（不写未选班） |
| 身份证范围约定 | **业务保证：同一身份证不会同时出现在本次已选的多个班级**；若出现视为脏数据拒绝写入 |
| 上传形态 | 支持一次选择**多个文件夹**（或等价多批 PDF / 多 ZIP）；前端「上传证书文件夹」入口已占位 |
| 交互范式 | **预览匹配 → 确认写入**（对标考试成绩导入，禁止静默全量落库） |
| 现网缺口 | 无导入 API/UI；`batchIssue` 只生成 `GC-{classId}-{peopleId}` 假号且不存文件 |
| 数据落点 | `train_certificate`：`people_id` / `class_id` / `certificate_no` / `file_path`（+ 可选 level/workType） |

**一句话：** 勾选班级（可多班）→ 上传多文件夹证书 → 抽身份证与证号 → 只在已选班内按身份证唯一匹配 → 预览确认后回填到对应班的人员（证号+文件）。

## 二、样本与可行性依据（已验证）

### 2.1 文件形态

| 项 | 事实 |
|----|------|
| 格式 | 人社证书多为 **PDF**（约 1.9MB/份）；产品文案可称「证书文件」，兼容后续图片 |
| 文件名 | `{证书编号}_{姓名}_{外部流水号}.pdf`；第三人数字段**不是**身份证/准考证 |
| 正文 | 文本层可抽出：姓名、居民身份证号、证书编号、工种、等级等（抽查 27/27 成功） |
| 同名风险 | 业务上同班可同名同姓 → **禁止仅用姓名匹配** |

### 2.2 库侧与业务约定

| 项 | 含义 |
|----|------|
| 回填目标 | **仅** `classId ∈ 本次勾选` 的 `train_people_list` 行；未选班一律不写 |
| 匹配键 | 在已选班花名册并集内，用规范化 `id_card` 找唯一 `people_id` |
| 业务不变量（冻结） | **同一身份证不可能出现在本次选中的多个班级**（教务勾选的班集合互斥于人） |
| 库内历史旁证 | 全局库中同一 `id_card` 仍可能跨班存在（如复训）；**本导入不以全局为准**，只看已选班；若已选班内撞车 → 数据异常，不提供「手选落班」 |
| 已有 `train_certificate` 字段 | 足以承载证号 + `file_path`；无需为 P0 新建业务表（可选加导入批次表便于审计） |

### 2.3 与「选一个班」样本的差异

`2025百色皓海新型学徒9.18` 五人按身份证均在库，但分属高级 2/3/4 班。因此产品要求**多选班级**一次导入是合理的；预览需标出「未在已选班」。

## 三、产品规则（评审冻结项）

### 3.1 入口与前置

1. 用户在毕业典礼列表勾选 **≥1 个班**（沿用现网 `selectedClassKeys`）。  
2. 点击 **上传证书文件夹**；未选班时按钮可点但提示「请先选择班级」，或 disabled + tooltip。  
3. 支持：  
   - 浏览器 `webkitdirectory` / `directory` **多文件夹**（多次添加合并，或一次多选若浏览器支持）；  
   - 兜底：多选 PDF、或多个 ZIP（ZIP 内按文件名扁平展开，忽略目录层级差异）。  

### 3.2 解析规则

| 字段 | 优先级 |
|------|--------|
| 身份证号 | ① PDF 文本正则 18 位；②（二期）OCR；③ 不从文件名第三人段猜 |
| 证书编号 | ① PDF 文本 `S…`；② 文件名第一段；两者都有则不一致 → **冲突行** |
| 姓名 | PDF / 文件名仅用于展示；与花名册不一致 → **警告仍可写**（以身份证为准） |
| 等级/工种 | 能解析则写入 `level` / `work_type`；解析失败不挡主流程 |

P0 **不做 OCR**；无文本层 PDF 记为 `PARSE_FAILED`，人工排除或二期 OCR。

### 3.3 匹配规则（仅在已选班内；身份证→至多一人）

对每份可解析文件，在**已选班花名册并集**中按身份证匹配：

| 结果码 | 条件 | 默认可否确认写入 |
|--------|------|------------------|
| `MATCHED` | 已选班中 **恰好 1 条** `id_card` 命中 | 是 → 回填到该班该学员 |
| `DUP_IN_SELECTION` | 已选班中同一 `id_card` **≥2 条**（违反业务约定） | **否**（脏数据；提示班 ID，不提供手选） |
| `NOT_IN_SCOPE` | 身份证有效但不在已选班 | 否（证书不属于本次勾选范围） |
| `NO_IDCARD_ON_ROSTER` | 班内人员 `id_card` 为空导致无法匹配 | 否 |
| `PARSE_FAILED` | 抽不出身份证或证号 | 否 |
| `CERT_NO_CONFLICT` | 文件内证号与文件名不一致 | 否（或警告后以正文为准，建议拍板：**以正文为准并警告**） |
| `DUP_CERT_NO` | 证号已绑定其他 `people_id` | 否（或覆盖策略，见 3.4） |

说明：多选班的意义是「一批证书对应多个班的人」（如 9.18 分属高级 2/3/4 班），不是「同一人落多个班」。正常情况下每条证书只会 `MATCHED` 到其中一个已选班。

**班内无人证书文件**：预览汇总「已选班花名册有身份证但本次未出现的人数」（信息项，不强制）。

### 3.4 写入与覆盖策略（建议默认）

| 场景 | 建议默认 |
|------|----------|
| 该 `people_id` 尚无证书行 | INSERT，`certificate_type=renshe` 或 `skill_level`（与 graduation 假号区分） |
| 已有行且证号为 `GC-…` 假号 | **允许覆盖**证号 + 文件（真实证替换占位） |
| 已有行且证号为真实号且相同 | 更新 `file_path`（补文件），幂等 |
| 已有行且证号不同 | **拒绝**，预览标冲突；人工先清或选「强制覆盖」（权限可二期） |
| 未结业学员 | **允许**挂证（认定证与结业打标解耦）；名单仍可查 |
| 不合格结业 | **允许**挂证（与「批量建证仅 passed」区分：本流程是外部真证导入） |

### 3.5 权限

建议：`train:graduation:update` 或 `train:graduation-ceremony:view` + update；与结业办理同权。文件 `private` 策略存储。

## 四、交互方案（前端）

### 4.1 列表工具栏

```
[刷新] [导出已选台账] [清空选择] 已选 N 个班          [上传证书文件夹]
```

（「上传证书文件夹」已占位，本期接真功能。）

### 4.2 上传弹窗（建议三步）

1. **范围确认**：展示已选班 ID/名称列表；可「重新去勾选」。  
2. **选择文件**：按钮「添加证书文件夹」可多次追加；列表显示文件夹名、文件数；支持移除某批。  
3. **预览表**（调用 preview API 后）：

| 列 | 说明 |
|----|------|
| 文件名 | 源文件 |
| 解析证号 / 身份证 / 姓名 | 解析结果 |
| 匹配班级 / 学员 | 命中则展示（唯一班+人） |
| 状态 | Tag：可写入 / 需处理 / 失败 |

底部：**可写入 x / 需处理 y / 失败 z**；主按钮「确认回填」仅提交 `MATCHED` 行。

### 4.3 结果反馈

- Toast：成功 a，跳过 b，失败 c。  
- 刷新结业学员弹窗内证号列；可选打开文件链接。  
- 不自动改结业状态。

### 4.4 对标实现参考

考试成绩导入：`TrainingFollowExamPage` 多班勾选 + 预览 + 确认写入。证书导入 UX/状态机与其对齐，降低教务学习成本。

## 五、后端方案

### 5.1 API（建议挂在 `/training` 结业域）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/graduation/certificates/import/preview` | `classIds` + 多文件（multipart）；返回预览行，**不落库**（或短时缓存 token） |
| POST | `/graduation/certificates/import/commit` | 提交 previewToken 或显式 `items[]`（peopleId/classId/certificateNo/fileId） |

**推荐两段式（与成绩导入一致）：**

1. **preview**：解析 + 匹配，文件可先入临时存储或仅内存/临时目录；返回 `previewId`。  
2. **commit**：按 `previewId` + 用户确认的行，正式挂到 `train_certificate` 并转正文件。

若担心大文件内存：preview 即 `FileApplicationService.upload(private)`，commit 只写业务关联；取消则定时清理未引用临时文件（P1）。

### 5.2 解析实现要点

- PDF：`PDFBox`（Java 侧已有 POI 生态，可增 pdfbox）抽取文本 + 正则：  
  - 身份证：`\d{17}[\dXx]`  
  - 证号：`S\d{18,}`（按样本调整）  
- 图片：P0 可拒绝或标 `PARSE_FAILED`；P1 OCR。  
- 单文件失败不影响同批其他文件。

### 5.3 匹配实现要点

```
selectedClassIds → load people (id, classId, realname, idCard)  // 仅已选班
index: normalize(idCard) → List<PeopleRef>  // 业务上期望 size≤1
for each file:
  parse → idCard, certNo, name
  candidates = index.get(idCard)
  if empty → NOT_IN_SCOPE
  if size==1 → MATCHED（回填到该 classId/peopleId）
  if size>=2 → DUP_IN_SELECTION（拒绝，不手选）
```

身份证规范化：大写 X、去空格；花名册空证不参与索引。

### 5.4 写入

- Upsert 键建议：`(tenant_id, people_id, deleted=0)` 唯一业务约束（若无 DB 唯一索引，应用层先查再写；建议 Flyway 补 **uk_cert_people** 或「每人一证」产品假设写进注释）。  
- `file_path`：`/api/files/{fileId}/download`（与归档包一致）。  
- 可选新增 `file_id` 列（P1，便于权限下载）；P0 仅 `file_path` 可验收。  
- `certificate_type`：建议 `skill_level_cert` / `renshe`，与 `graduation` 假号类型区分。  
- 审计：`@AuditLog`；可选 `train_certificate_import_batch` 记操作者、班列表、成功失败数（P1）。

### 5.5 结业名单展示增强（小改）

`graduation-students` 已有 `certificateNo`；补返回 `certificateFilePath`（或 `filePath`），弹窗「证书」列可点击打开 PDF。属同波次薄改前端。

## 八、风险与对策

| 风险 | 对策 |
|------|------|
| 花名册缺身份证 | 预览明确失败原因；引导资料收集补全 |
| 纯图片 PDF | P0 失败列表；P1 OCR |
| 同证号多人 | 拒绝双绑 |

| 浏览器文件夹 API 差异 | ZIP/多文件兜底 |
| 与假号建证并存 | 类型字段区分 + 覆盖规则写死 |

## 十、验收用例（P0）

1. **未选班上传** → 拦截提示。  
2. **勾选高级 2/3/4 班 + 上传 9.18 文件夹** → 预览 5×`MATCHED` → 确认后名单可见真实 `S…` 证号且可打开 PDF。  
3. **只勾选高级 3 班 + 同上** → 3 可写、2×`NOT_IN_SCOPE`。  
4. **故意改坏一份 PDF 文本** → `PARSE_FAILED`，其余可写。  
5. **同名不同身份证**（造数）→ 各自按身份证命中，互不串。  
6. **重复确认同一批** → 幂等（同证号更新文件或跳过）。
