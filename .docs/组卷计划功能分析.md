## 四、核心业务逻辑（自动组卷）

添加组卷计划时根据 `examType` 分两条路径：

### 路径 A：理论组卷（examType=0）

#### 模式1：全选模式（isAll=1）
1. 查出该科目下所有 L3 知识点
2. 查询所有终审通过（final_check_status=1）的试题，按题型分组统计
3. 自动生成明细 → 创建试卷 → 从题库随机抽题填充

#### 模式2：自定义模式（isAll=0）
1. 用户手动配置明细（题型+数量+难度+分值范围）
2. 如果有 `rateId`（比重），按比重百分比分配各知识点的题目数
3. 如果没有比重，按用户填写的数量直接抽题
4. **抽题条件**：
   - 题型匹配
   - 终审通过（final_check_status=1）
   - 难度范围（difficultyStart ~ difficultyEnd）
   - 分值范围（startPoint ~ endPoint）
   - `ORDER BY RAND()` 随机排序
5. 创建试卷 → 填充随机抽到的试题

### 路径 B：实操组卷（examType=1）
- 走 `OperatePaperService` / `OperatePaperDetailService`
- 需要传入 `num`（总题数）
- 根据科目 level 映射等级名（初级工/五级, 中级工/四级, 高级工/三级, 技师/二级, 高级技师/一级）
- 创建实操试卷

## 六、表关联关系

```
exam_make_exam_plan (组卷计划主表)
  ├── courseId → exam_course (科目)
  │                └── workTypeId → exam_work_type (工种)
  │                └── level → 等级 (0初级/1中级/2高级/3技师/4高级技师)
  ├── rateId → exam_knowledge_rate (比重方案)
  │              └── exam_knowledge_rate_detail (比重详情)
  │                    └── knowledgeId → exam_knowledge_structure (知识点)
  └── exam_make_exam_plan_detail (明细配置)
        ├── type → 题型 (single/multi/judge/essay/...)
        ├── difficultyStart~End → 难度范围 (0~4)
        ├── startPoint~End → 分值范围
        └── 抽题来源: exam_exam_detail
              └── knowledgeId → exam_knowledge_structure (L3节点)
              └── final_check_status = 1 (终审通过)
              └── ORDER BY RAND() (随机抽题)

组卷结果:
  exam_paper ← makeId ← exam_make_exam_plan
    └── exam_paper_detail ← examId ← exam_exam_detail (抽到的具体题目)
          └── 按题型分组统计数量
```
