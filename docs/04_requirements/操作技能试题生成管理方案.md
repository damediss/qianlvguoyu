## 1. 需求背景与目标

在"理论知识试题生成管理"菜单下方新增菜单**"操作技能试题生成管理"**：

1. 导入某工种某等级的《操作技能考评要素细目表》（xlsx，指引第三章规定格式）；
2. 依据细目表，按指引的题量/格式/评分标准要求，利用 LLM 批量生成**现场操作类**试题（每题 = 准备要求 + 考核试题 + 评分标准三件套）；
3. 生成的试题**先落草稿暂存区**，经页面人工审核/编辑后，**仅审核通过的草稿**可由人工触发"入库"写入题库开发任务链路（`task_examshicao(+_detail)`，实操命题任务），后续走既有实操专家初审/终审流程；
4. **一期不写知识点树**（C2）：细目表层级与考评点关系完整保留在蓝图树中，供页面检索与导出使用；`exam_knowledge_structure`（type=1 实操）打通推迟二期。

## 2. 指引核心要求提炼（生成试题的指导原则）

> 以下来自指引第三章及附件 3 审核标准（第 8~14、18~26 条），是 prompt 设计、校验规则、导出表格的**唯一依据**。

### 2.1 题量硬指标（C3 口径）

- 每个考评点出 **5 题**（指引为 3~5 题，一期固定取上限 5）；
- **试题总量：五至三级每个等级 ≥50 道；二至一级每个等级 ≥30 道**（第三章第四节原文："现场操作类题库一般每个考评点下出 3-5 题，原则上五至三级每个等级不少于 50 道题，二至一级每个等级不少于 30 道题"；审核标准第 13/20 条同口径）；
- 总量为**等级口径、可跨批次累积**：发起预检与入库前按"该（工种,等级）全部来源有效明细（手工/导入/AI 均计）+ 本次"合计校验（S10/S9），不足即拦截并提示缺口；
- 样例（二级，23 考评点）：23×5 = 115 题 ≥ 30 ✓；发起预检同步通过。

### 2.2 考评点与试题的结构要求

**考评点**（细目表已承载，导入时校验/展示）：
- 定位于**典型工作任务**，名称采用动宾结构或主谓结构；
- 考评点统一考核要求 = 该点下所有试题的共性要求；各试题的具体要求在题内细化；
- 评分标准一般以**考评点统一评分标准**体现（评分记录表方式）；各试题有特殊要求时可分别编制——本方案按"每题自包含完整评分表"生成（入库粒度=题，`pingfen` 按题存），prompt 要求同点内各题评分框架保持一致。

**单道试题三组成**（第三章第四节（一））：

1. **准备要求**：
   - 考场准备：试题名称、本题分值、考核时间、考核形式、考核有关说明、场地/材料/工量具/**设备设施准备表**（序号/名称/规格/单位/数量/备注 6 列）、故障或工况设置说明（如样例"六选三"式设置项）；
   - 考生准备：试题名称、分值/时间/形式同上、（工、量具及）其他准备。
2. **考核试题**：本题分值、考核时间、考核形式、**具体考核要求**（考评点统一要求的细化）、**否定项说明**；
   - 否定项标准表述："若考生发生下列情况之一，则应及时终止其考试，考生该试题成绩记为零分"；
   - 本题分值 = 100 分，权重 = 所属**二级考评范围权重**（指引示例："100分，权重 14%"即二级块权重）。
3. **评分标准（评分记录表）**：考核内容 / 评分要素 / 配分 / 评分标准 / 最大扣分 / 步长（一次扣分的最小分值）；
   - "考核内容"列不单独入库（`pingfen` JSON 为 5 键，与 PHP 导入链路一致，S4）：导出 Sheet2 的"实操题目"列承载考核内容，入库 `content` 已含试题名称；
   - 配分合计 = 本题分值（100）；最大扣分 ≤ 配分；步长 ≤ 最大扣分；
   - 评分要素应尽可能细致、量化、可操作（审核标准第 25 条；其"每个要点分值以不超过 3 分为宜"针对主观题分步评分，实操评分记录表按指引第三章示例为 50/20/30 大粒度配分 + 扣分制，**不适用 3 分上限**，Validator 不做该校验）。

### 2.3 审核标准红线（附件 3，prompt 与 Validator 依据）

- 第 18 条：题型题量、考核方式、考核时长、分值权重、所考技能要素与考评蓝图一致；
- 第 20 条：试题应为典型工作任务，内容含准备要求/考核试题/评分标准三件套，总量达标；
- 第 21 条：社会主义核心价值观，内容正确无争议；考核项目为典型工作任务且有代表性；考核试题完整；**评分标准细化可操作；否定项设置合理**；无偏题怪题；
- 第 22 条：试题与考评蓝图一致，体现国家职业标准；试题间相互独立、无重复或提示；无歧视特定群体内容；**体现重要考评点的试题占比 ≥85%**（一期在批次报告展示 X 点题量占比供核对，不做硬拦截——样例细目表 X 占 78%，S6）；
- 第 23 条：原则性禁令清单（同理论链路，prompt 全文内联）；
- 第 24 条：表述清晰规范无歧义，术语符合行业现行规定；
- 第 26 条：参数标注（内容参数用考评点代码表示，如 `A-A-001`）。

### 2.4 组卷参考（由竞赛平台自动组卷承接）

本方案继续限定在操作技能题库生成、审核、导出和入库，不在题目生成批次中实现竞赛试卷编排。竞赛场景的细目表选考方式、结构权重、末级绑定、整卷分值缩放、单套/多套去重和参考时长计算，统一由《竞赛组卷与多套试卷编排修订说明》及竞赛平台的 `CompetitionPracticalMakeExamAllocator` 承接。题库生成阶段只维护 `questionQuota` 对应的库存和覆盖率，不把它当作竞赛试卷题数。

竞赛组卷时，必须结合上下级选考关系确定最终题位，不能固定以一级或二级作为抽题单元。下级范围均为必考时，每个下级范围分别形成一道题；一级范围必考、其二级范围为任选一项时，每个一级只形成一道题，系统从该一级的二级候选范围中任选一个范围并抽取一道完整实操题。前者可形成 14 个下级题位，后者如一级 A/B/C/D 均必考则形成 4 个题位。分值取最终必考题位对应的整卷权重，任选候选权重不得相加。

### 2.5 样例细目表实测画像（导入解析器的验收基准）

文件：矿山生产集控员（二级/技师），1 个 sheet，**28 行 × 13 列，73 处合并单元格**。

- R1 标题（A1:M1 合并）；R2 职业/级别行；R3 三块表头（A3:D3=考评范围一级 | E3:I3=考评范围二级 | J3:M3=考评点）；R4 子列表头；**数据 R5~R27；R28 为"填表人/审表人"页脚**（解析截断）。
- 列布局：A=一级代码⏎（X:Y:Z）（多行单格）| B=一级名称 | C=一级考评比重（小数，0.1=10%）| D=一级选考方式 | E=二级代码⏎（X:Y:Z）| F=二级名称 | G=技能要求（多行，`1.1.1 能…` 编号条目）| H=二级考评比重 | I=二级选考方式 | J=考评点代码（001…，**每个二级块内从 001 重排**）| K=考评点名称 | L=重要程度（X/Y/Z）| M=试题量（**样例全空**）。
- 实测结构：一级 4 块（A 作业环境确认 10% / B 生产监控管理 40% / C 生产运行总结 40% / D 技术管理和培训指导 10%，合计 100%）；二级 10 块（2+3+2+3）；考评点 23 个；X:Y:Z = 18:5:0；一级全"必考"，二级全"任选一项"。
- 合并单元格解析必须"值向下填充"（一级块跨 4~6 行、二级块跨 2~3 行）。
- 数据quirk：G 列技能要求含多余空格（"能对 生产 系统 开启"）——解析层做空白规范化；M 列试题量空 → 一期固定按 5 生成，列值仅作提示（见 T2）。

## 3. 技术评估

### 3.1 Excel 组件：沿用 POI 5.5.1（不引入新库）

与理论方案 §3.1 同一结论：数据量 30 行级，无流式痛点；平台 Excel 能力全部 POI；合并单元格解析为既有能力。

### 3.2 模型与思考模式

默认 **GLM-5.3-Flash（官方编码 `glm-5.3-flash`）+ thinking=enabled + reasoning_effort=high**（C6，需求方指定高档位），理由同理论方案 §3.2（多约束满足 + 专业事实自查是质量关键路径；异步架构下时延不堵 HTTP）。差异仅在输出体量与档位：

- 实操单题三件套输出 ≈ 800~1600 tokens，**1 点 5 题 ≈ 4K~8K tokens + 思维链** → **max_tokens 按 16384 配置**（GLM-5.3-Flash 最大输出 128K，空间宽裕；复盘 §7.1#9 教训：预算必须给思维链留空间）；
- **响应超时沿用 180s**（`chatCompletionDetailed` 参数化既有能力）；**effort=high 会拉长思维链与单块耗时**，试产须观察单块耗时分布，逼近超时线时按配置调高超时或下调 effort（S7）；
- **jsonMode（response_format=json_object）沿用开启**（复盘 §8.1#3：GLM 官方支持结构化输出，语法类失败靠它兜底；内容形态类失败走 Validator + 整块重试）；
- 截断预案（S7）：试产观察 `finish_reason=length` 频率；频发则通过配置项切换为"1 点 1 题"粒度（块数 ×5，单块输出降为 1 题）。

### 3.3 异步编排：整体复用理论链路范式，零新设计

以下机制理论链路已上线并经生产验证，本链路原样复制（仅换表/换业务体）：

- submit 秒回 + 线程池异步 + 进度轮询；
- **run_id 编排独占权**（防 pause→resume 双编排器）；
- 块级并发信号量（默认 5，可配）+ 编排/执行分离双线程池；
- **多轮自动补跑**（默认 4 轮，轮间退避，可配）+ 熔断锁存（`breakerTripped` 事件锁存，不读实时计数）；
- 块级事务原子化（TransactionTemplate）、断点续跑（有草稿即跳过）；
- 写库先提交后投递（复盘 §8.1#1 生产事故教训）；
- usage 每块 SQL 原子累加（prompt/completion/cached 三列）+ 失败原因落库 + 错误响应体透出入异常消息；
- Worker 线程 `TenantContextHolder.set` + `finally clear`，全链路禁调 `SecurityContext`。

块粒度：**1 考评点 = 1 次 LLM 调用，产出该点全部 5 题**（同点内评分框架一致性的保证手段；块数 = 考评点数，二级样例仅 23 块，并发压力远小于理论）。降级预案见 §3.2 截断预案。

**多批次语义**（S5）：同一蓝图允许多个生成批次并存（不同参数/重跑产出更多样的题是期望行为）；跨批次相似题去重本期不做，与理论一期决策一致。

## 7. Prompt 与校验设计要点

### 7.1 prompt 结构（实施时落到 `SkillGenPromptBuilder`）

- system（批次内恒定，保缓存命中）：实操命题专家角色；"以下规则为《指引》的硬性要求，必须严格遵守；规则未覆盖之处按通用命题规范处理，不得臆造指引条款"；三件套结构说明；评分记录表 6 列规则（配分合计=本题分值、最大扣分≤配分、步长≤最大扣分、要素细化可操作）；否定项要求与标准表述；内容红线（附件 3 第 21~24 条全文内联）；X/Y/Z 含义；**同点 5 题差异化要求**（覆盖不同工况/侧面/参数组合，不得同义改述，S5）；"只输出 JSON"；JSON Schema 逐字段说明；few-shot 示例 1 题（声明内容不得照抄）。
- user（仅点数据）：`{full_code, name, importance, level1_name/weight/select_mode, level2_name/weight/select_mode, skill_requirements[], level, question_count: 5}`。
- 等级差异写进 user：考核要求深度须符合该等级职业活动水平（二级=技师，含技术管理与培训指导类任务）。
- 考核时间：由模型按任务复杂度建议（min），Validator 校验 ∈ 5~240；页面可改。

      "note": "考核有关说明（可空）",

### 7.3 SkillQuestionValidator 规则（确定性兜底，全部可编码）

| # | 规则 | 失败处理 |
|---|------|----------|
| V1 | 题数 = 5（精确，不多不少） | 整块失败 |
| V2 | 每题五要素非空：name / site_prepare.equipment≥1 行 / examinee_prepare / requirements / negatives | 整块失败 |
| V3 | negatives 含"终止其考试"与"零分"语义表述 | 整块失败 |
| V4 | scoring 行数 ∈ 3~10；每行 item/scoreDesc 非空 | 整块失败 |
| V5 | scoring 配分合计 = 100（数值解析后比对） | 整块失败 |
| V6 | 每行 score>0、maxDeduct>0 且 ≤ score、step>0 且 ≤ maxDeduct | 整块失败 |

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| LLM 专业事实错误（矿山集控工艺等） | 思考模式（effort=high）提高一次正确率；专家初审/终审是质量闸门（指引流程）；批次报告标注 AI 来源 |
