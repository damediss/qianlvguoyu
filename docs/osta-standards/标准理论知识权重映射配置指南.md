> 版本：v1.0　日期：2026-08-04

## 1. 数据模型结论：不建新表、不加字段，复用 `exam_knowledge_rate` + `exam_knowledge_rate_detail`

| 决策 | 说明 |
|---|---|
| 复用现有两表 | `exam_knowledge_rate`（主表：course_id + title + type）+ `exam_knowledge_rate_detail`（knowledge_id + rate%），与 SaaS 组卷、PHP 组卷计划完全同构 |
| **用 `type` 字段区分权重来源** | 枚举约定：**type=0 = 人工组卷规则**（现有 26 行全部为此值，现状不动）；**type=1 = 实操（技能）权重**（既有约定，本功能不使用）；**type=3 = 国标理论知识权重**（本指南生成，需求方 2026-08-04 拍板）；type=2 预留未用 |
| `is_standard` 字段不可用作标记 | 现有数据该字段几乎全为 1（含"火法初级组卷规则""难度-较难"等人工规则），已失去语义，引擎**不读**它 |
| 权重挂 L1 节点 | detail 的 `knowledge_id` 直接挂知识树 **L1 节点**（职业道德/基础知识/生产操作…），引擎从 L1 向下解析 L3 子孙知识点取题（SaaS 组卷 `ExamMakeExamPlanApplicationService:464-495` 已是此机制） |
| 每课程仅一条 type=3 | 一个 course_id 只允许存在一条 `type=3 AND deleted=0` 的主表行；引擎若查到多条取 id 最大者并记 warn 日志 |
| 不改 PHP 任何代码 | PHP 组卷计划按 `rate_id` 显式引用比重行，新增行不影响存量组卷；PHP 管理端"知识比重"页面会显示这些行（标题可辨识，请勿随手编辑） |

### 引擎选择回退链（实现方案 §5.7 详述）

```
① course_id 下 type=3（国标权重，本指南配置）
→ ② course_id 下 type=0 最新一条（人工组卷规则，现有数据）
→ ③ 知识点题量占比（兜底）
```

## 2. 知识树的"三棵树"结构（实测结论）

每门 course 的知识树固定有 **3 棵 L0 根**：

| L0 根 | 内容 | 是否挂题 | 权重配置是否使用 |
|---|---|---|---|
| 基本要求 | 职业道德、基础知识 | **是** | **使用** |
| 相关知识（要求） | 工种专属考核项目（生产操作/设备管理/…） | **是** | **使用** |
| 技能要求 | 与"相关知识"内容平行的技能考核树 | **否**（实测 183 课程该树题量=0） | **忽略** |

> 配置与校验时一律过滤 `技能要求` 树（`l0.title='技能要求'`）。题目只挂在理论两树上，与标准"理论知识权重表"的作用域天然一致。

### 4.3 今后新增工种/职业时的梳理 SOP（照此流程）

1. **备标准**：拿到该职业《国家职业技能标准》4.1 理论知识权重表（可按工种列区分）；
2. **拉知识树**：
   ```sql
   SELECT l1.id, l1.title, l0.title AS l0_root
   FROM exam_knowledge_structure l1
   JOIN exam_knowledge_structure l0 ON l1.parent_id = l0.id
   WHERE l1.course_id = <课程id> AND l1.level = 1 AND l1.deleted = 0
     AND l0.title <> '技能要求'
   ORDER BY l0.id, l1.id;
   ```
3. **填映射工作表**（按下表格式，每门课一张）：

   | L1 节点 id | 树节点标题 | 对应标准考核项目 | 标准权重% | 处理说明 |
   |---|---|---|---|---|
   | （SQL 拉出） | （SQL 拉出） | （人工填） | （查标准填） | 同名/近似/拆分/跳过 |

4. **四种情形的处理规则**：

   | 情形 | 处理 | 示例 |
   |---|---|---|
   | 树节点与考核项目同名/近义 | 直接 1:1，rate=标准权重 | "设备检修与维护"→"设备检修与维护" |
   | 标题不同但内容一致 | 1:1，rate=标准权重，detail 的 comments 注明标准项目名 | "物料浸出"→"湿法冶炼" |
   | 一个考核项目拆在多个树节点里 | 每个节点一行 detail，**拆分 rate 使合计=标准权重**（按各节点题量比例拆，或凭教学判断） | 标准的"安全环保"内容散在"安全防护"+"环境保护"两个节点 |
   | 考核项目在树中无对应节点 | **跳过不配**（引擎按已配节点归一化），并在工作表注明；同时评估题库是否缺该类题（缺题是题库建设问题，非映射问题） | 某等级树中没有"故障判断与处理"节点 |
   | 树节点在标准中无对应项目 | 检查是否挂错树（如误用了"技能要求"树的节点）；确认后**不配** | — |

## 6. 执行后验证 SQL

```sql
-- ① 每门课恰有一条 type=3 且 detail 合计=100
SELECT r.course_id, r.id, r.title, COUNT(d.id) AS items, SUM(d.rate) AS sum_rate
FROM exam_knowledge_rate r
JOIN exam_knowledge_rate_detail d ON d.knowledge_rate_id = r.id AND d.deleted = 0
WHERE r.type = 3 AND r.deleted = 0
GROUP BY r.course_id, r.id, r.title
ORDER BY r.course_id;
-- 预期：10 行，sum_rate 全部 = 100

-- ② 抽查 detail 挂载节点确为理论树 L1
SELECT d.knowledge_id, k.title, k.level, k.course_id
FROM exam_knowledge_rate_detail d
JOIN exam_knowledge_rate r ON r.id = d.knowledge_rate_id AND r.type = 3
JOIN exam_knowledge_structure k ON k.id = d.knowledge_id
WHERE d.deleted = 0 AND (k.level <> 1 OR k.deleted = 1);
-- 预期：0 行
```

## 7. 注意事项

1. **不要修改/删除现有 type=0 的人工规则**——PHP 组卷计划按 rate_id 引用它们；
2. 若同一 course 误配两条 type=3，引擎取 id 最大者并记 warn 日志——发现后把多余行 `deleted=1` 即可；
3. 权重变更（标准修订）时：**新增一行 type=3 配置并把旧行 deleted=1**，不要原地 update——进行中的 AI 复习计划已按旧权重快照排题（实现方案 §5.1 计划生成时固化快照）；
4. SaaS 库 `exam_knowledge_rate` 是 PHP 库快照，**本配置不需要同步到 SaaS 库**（AI 同步学引擎直读 PHP 库）；若日后 SaaS 管理端组卷也要用国标权重，再单独同步。
