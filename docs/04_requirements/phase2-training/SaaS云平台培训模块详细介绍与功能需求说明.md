## 一、模块定位与价值

### 1.1 是什么

培训模块是 SaaS 云平台上服务**企业技能提升、新型学徒制、岗位技能培训**等业务的数字化中枢。它以「企业—班级—学员」为主线，把培训部日常工作从分散的 Excel、微信群、纸质台账，收敛到统一平台：需求摸清、方案谈妥、人分进班、材料备齐、过程跟得住、考后能取证、补贴有证据。

### 1.2 解决什么问题

| 痛点 | 模块价值 |
|------|----------|
| 企业人才底数不清、规划难落地 | 调研采集 + 三年规划 + 企业确认 |
| 分班靠人工、易错漏、企业难确认 | 排班/规则驱动分班，企业在线确认后物化班级 |
| 开班材料重复制作、人社格式多变 | 模板挂载 + 一键生成开班材料包 |
| 开班后考勤、影像、作业靠群文件 | 跟班工作台：按班进班、考勤与学情集中看 |
| 考前刷题与课堂作业语义混淆 | 通道分离：刷题/同步学/跟班作业各走其道 |
| 多部门协同无统一视图 | 按流程阶段推进，菜单与角色权限隔离 |

### 1.3 服务谁

| 角色 | 在系统中的典型工作 |
|------|--------------------|
| 培训部教务 / 跟班教务 | 调研落地、规划、分班、开班准备与申报、跟班抽查、材料与补贴跟进 |
| 企业侧（人事 / 班主任） | 确认方案与名单、督促材料与考勤、日常班级动态 |
| 授课老师 / 助教 | 排课落实、布置随堂练/作业、看完成情况 |
| 班长 | 课堂拍照录像、缺勤提醒（代签需确认） |
| 学员 | App 提交资料、签到、刷题、做练习、考前复习 |

> 班级层五角色（跟班教务 / 企业班主任 / 主讲·助教 / 班长 / 学员）的数据模型、权限矩阵、迁移与分期见：[培训班级五角色落地实现方案.md](./培训班级五角色落地实现方案.md)。
| 认定 / 综合办 / 总经理 | 认定条件、协议与立项审批、归档与结算（按权限进入） |
| 培训机构 | 师资安排、人社侧协同（平台侧预留对接与材料能力） |

### 1.4 建设原则（产品红线）

1. **班级为中心**：开班后一切过程数据（考勤、留痕、作业、日志）挂在班级 / 课次 / 业务日上。  
2. **开班前可闭环、开班后可扩展**：主链路先跑通，跟班与补贴按里程碑加深。  
3. **App 与管理端同一真相源**：学员与老师在 App 操作，管理员在后台看进度与证据。  
4. **学习通道不混用**：考前复习（promote）≠ 班级刷题 ≠ 跟班课堂作业。  
5. **证据可审计**：签到、影像、作业、材料版本可追溯，服务补贴与稽核。

## 二、总体业务流程

培训业务在平台上可概括为四段，对应从「谈项目」到「拿补贴」：

```text
① 项目启动与规划
   企业调研 → 方案规划（含三年规划/企业确认）→（协议/立项，规格能力）→ 分班

② 开班与执行准备
   开班准备（花名册、师资、课表、角色）→ 开班申报（材料生成）→ 信息收集（报名/资料审核）

③ 培训实施与考核
   跟班（考勤、留痕、作业、日志、刷题学情）→ 考试/考前辅导 → 结课 → 认定获证

④ 项目收尾
   补贴材料与拨款跟踪 → 资料归档 → 项目结算与总结
```

管理端流程导航当前呈现为：

**企业调研 → 方案规划 → 分班 → 开班准备 → 开班申报 → 跟班 → 考试 → 申报补贴**

其中「信息收集」已有独立业务页，宜纳入流程条（申报之后、跟班之前），使运营路径与真实作业顺序一致。

## 三、开班前主链路 · 功能需求叙述

### 3.1 企业调研

**业务目的**  
摸清企业培训需求与人员底数，形成可进入规划的人才与需求数据。

**功能要求（文字）**

1. 支持按企业建立调研组织/任务，维护企业基本信息与联系人。  
2. 支持导入或采集企业在岗人员信息（姓名、身份证、手机、岗位、工种意向、等级等），并支持字段校验与查重。  
3. 支持与人才识别/查证能力衔接，对关键人员资格进行核对提示。  
4. 支持将调研结果作为后续「三年规划 / 方案规划」的输入，减少人工二次录入。  
5. 支持采集进度可视（应交、已交、缺项），便于市场与培训部协同催办。

**验收口径（业务语言）**  
调研结束后，培训部能明确：这家企业要训什么工种、大致多少人、名单是否基本可用。

---

### 3.2 方案规划

**业务目的**  
在调研基础上输出可被企业确认的人才培养/培训规划方案，并锁定可进入分班的人员范围。

**功能要求（文字）**

1. 支持创建与维护三年（或项目期）人才规划：目标工种、等级、规模、年度安排等。  
2. 支持对企业推送方案确认；企业可确认、驳回或要求补交名单/排班资料。  
3. 支持企业回传确认名单、排班表等附件，系统记录版本与状态（已确认 / 待补交）。  
4. 支持规划与下游分班的衔接：未齐套时应有明确提示，避免盲目分班。  
5. 宜区分培训模式（如自费认定、新型学徒、岗位技能提升），为后续材料与补贴策略预留口径（可分期落地）。

**验收口径**  
企业点头确认后，系统内存在「可分班」的人员池与状态，而不是一堆散文件。

---

### 3.3 分班

**业务目的**  
把确认名单按规则或排班约束拆成可开班的班级，并物化为平台班级与花名册。

**功能要求（文字）**

1. 支持基于确认名单自动/半自动生成分班草稿（班额、工种、等级、车间班组等约束可配置）。  
2. 支持手动调整分班草稿：调人、拆班、合班、标注异常。  
3. 支持企业审核分班方案；审核通过后方可物化。  
4. 物化后自动生成班级（班名、人数、关联项目/企业/工种等级）及学员花名册。  
5. 物化时同步或补开学员 App 账号，并对「未开账号」学员给出清单与一键补开能力。  
6. 支持从排班表驱动的分班路径（与规则分班并存时，主路径需产品标明，避免运营混淆）。

**验收口径**  
审核通过后，管理端能看到真实班级卡片，花名册人数与企业确认一致，学员可登录 App。

---

### 3.4 开班准备

**业务目的**  
班级落地后，配齐人、师、课表与资料收集入口，达到「能申报、能开班」的条件。

**功能要求（文字）**

1. **花名册管理**：学员增删改查；设置班长；查看手机、证件等关键信息。  
2. **教务与负责人**：维护班级教务、企业侧负责人等人员映射。  
3. **正式班级角色（完善重点）**：支持指派企业班主任、培训部跟班教务、主讲、助教等角色，权限与跟班能力挂钩（双轨：企业管日常、教务管合规）。实现方案见 [培训班级五角色落地实现方案.md](./培训班级五角色落地实现方案.md)。  
4. **课表**：上传或解析课表文件，形成上课日期、时段、课程、教师等信息，供跟班与申报引用。  
5. **班级资料收集**：可为班级发起资料收集计划（与全局信息收集协同），督促学员补齐材料。  
6. **师资库**：维护可用讲师档案，支持按工种等级筛选导入班级。

**验收口径**  
任意班级可回答：班长是谁、班主任/教务是谁、主讲是谁、课表是否就绪、名单是否齐。

---

### 3.5 开班申报

**业务目的**  
按人社/机构要求，快速生成开班申报所需电子与纸质材料包。

**功能要求（文字）**

1. 支持维护开班材料模板（按地市或培训类型区分），并挂载到具体班级/项目。  
2. 支持一键生成材料包（花名册、申请表、课表、承诺书等，以实际模板配置为准）。  
3. 生成内容应尽量自动带入班级实名数据：班名、人数、负责人、联系电话、教师、课时、培训地点等；缺项应在生成前明确提示。  
4. 支持生成结果下载、重新生成与版本管理。  
5. 支持与企业盖章、机构提交人社等线下环节的状态备注（系统内留痕）。

**验收口径**  
教务无需从零拼 Word/Excel，生成包可经少量核对后对外提交。

---

### 3.6 信息收集

**业务目的**  
组织学员（或企业代填）提交报名与开班所需个人信息与证照，完成审核后进入培训执行。

**功能要求（文字）**

1. 支持创建报名/信息收集计划，生成二维码或链接供 App/H5 填写。  
2. 支持学员填写：身份证、联系方式、学历、工作单位、照片与证件影像等（字段可配置）。  
3. 支持后台审核：通过、驳回补正、批量导出。  
4. 支持 OCR/影像辅助（在已开通能力范围内），降低人工录入。  
5. **应纳入培训主流程导航**，置于开班申报之后、跟班之前，避免运营漏做。  
6. 与开班准备中的「班级资料收集」职责应产品说明清楚：全局计划 vs 班级补采，避免双入口混乱。  
7. 宜提供齐套率摘要（应交/已交/待审），作为进入跟班的软性或硬性门禁依据。

**验收口径**  
跟班开训前，班级关键材料审核状态清晰，缺人缺件可催办。

---

## 四、开班后实施 · 功能需求叙述

### 4.1 跟班总览

**业务目的**  
以班级工作台为入口，让班主任、跟班教务、老师在同一班内完成日常教学过程管理。

**功能要求（文字）**

1. 提供班级列表（班名、企业、工种、起止日期等），点击进入跟班工作台。  
2. 工作台按业务日 / 课次切换，支持「有排课挂课次、无排课按日」两种粒度。  
3. 工作台至少包含：概览、考勤、排课、刷题学情、角色、指标；并规划留痕、作业、日志、督导等能力。  
4. 概览应展示：学员数、当日出勤与构成、累计出勤率、近日出勤、缺勤/低出勤预警、今日待办。

---

### 4.2 考勤管理

**业务目的**  
如实记录学员到课情况，支撑过程合规与补贴证据。

**功能要求（文字）**

1. 支持按日查看全班考勤状态：出勤、迟到、早退、缺勤、未登记。  
2. 支持管理端标记出勤/缺勤，记录签到签退时间。  
3. 支持导入人社/培训平台导出的「考勤信息列表」（Excel），按身份证匹配本班学员；同日多课次可按规则合并。  
4. 支持查看单个学员历史考勤明细。  
5. 规划能力：班长代签须本人或班主任确认后方计入有效出勤；有效出勤口径进入出勤率指标。

---

### 4.3 过程留痕（照片 / 视频）

**业务目的**  
保留课堂真实发生证据，满足督导与补贴稽核。

**功能要求（文字）**

1. 支持班长、班主任、教务按课次或按日上传课堂照片、视频。  
2. 支持证据列表、审核状态、缺失提醒（当日是否缺影像）。  
3. 上传通道复用平台统一文件服务，控制大小与格式。

---

### 4.4 作业与随堂练

**业务目的**  
老师布置课堂练习/作业，学员在 App 作答，管理端查看完成与正确情况；与考前刷题体系分离。

**功能要求（文字）**

1. 支持任务类型：正式作业、随堂练习；可挂课次或业务日。  
2. 老师（App）可组题发布；发布时固化应交学员名单。  
3. 学员（App）拉取待做任务、答题提交；客观题自动判分。  
4. 管理端跟班「作业」页展示任务列表、完成率、未交名单、答卷明细。  
5. 题目发布后使用快照，避免题库改题影响已发任务。  
6. 插班学员对未关闭任务可自动补发（按既定产品决策）。  
7. **不**将跟班作业接到 App 考前 promote 通道。

---

### 4.5 班级刷题与同步学

**业务目的**  
在培训周期内提升学员掌握度：班级可限定刷题范围；同步学服务复习巩固。

**功能要求（文字）**

1. **班级刷题**：管理端为班级配置科目/知识点白名单；学员 App 带班级身份刷题，学情回流班级看板。  
2. **同步学**：学员按既有同步练习能力学习；登录与令牌策略按平台统一方案。  
3. 刷题答卷、作业答卷、考前任务答卷分通道统计，指标不混算。

---

### 4.6 跟班日志、督导与预警

**业务目的**  
班主任记录每日班级情况，教务抽查合规，对异常学员形成闭环。

**功能要求（文字）**

1. 班主任工作日志：日期、出勤概况、异常学员、沟通与处理（对齐线下「班主任工作日志表」）。  
2. 日志须落库，支持按班级与日期查询（不仅本地暂存）。  
3. 督导检查：设备、纪律、到课等清单勾选与复核。  
4. 学员预警：如出勤率低于阈值、连续缺勤、作业未交等，列表可下钻明细。

---

### 4.7 考试与考前辅导

**业务目的**  
组织考试计划，并引导学员考前复习，提升通过率。

**功能要求（文字）**

1. 管理端维护考试计划（时间、工种、班级范围等）。  
2. 考前辅导主要通过 App 题库/复习能力完成；督促由企业班主任与培训部协同。  
3. 通过率数据优先来自考试/认定结果，跟班侧做聚合展示。

---

### 4.8 结课与认定衔接

**业务目的**  
培训结束后完成结课通知，接收获证名单，为补贴准备人员口径。

**功能要求（文字）**

1. 支持班级结课/毕业相关状态与通知。  
2. 支持接收或导入获证学员花名册，与培训花名册核对。  
3. 认定申报、证书下载等能力可与认定子系统协同，培训侧保留名单回写与归档入口。

---

## 五、项目收尾 · 功能需求叙述

### 5.1 申报补贴

**业务目的**  
按政策要求整理补贴申报材料，跟踪审批与拨款。

**功能要求（文字）**

1. 支持按班级/项目生成或挂载补贴材料清单。  
2. 支持材料核验（缺项提醒），降低退件率。  
3. 支持记录申报节点与拨款进度。  
4. 过程证据（考勤、影像、作业等）可按目录导出索引，服务稽核抽查。

> 实现分期与人社 L1–L3、以及与班级五角色 R2–R3 的对齐见：[补贴与人社扩展实现方案.md](./补贴与人社扩展实现方案.md)。

### 5.2 结算与归档

**业务目的**  
完成项目财务闭环与资料长期保存。

**功能要求（文字）**

1. 支持项目结算申请与审批（企业、机构分成口径可配置）。  
2. 支持项目总结录入与审批。  
3. 支持按项目—班级—阶段—版本归档资料并检索。

## 六、跨切能力 · 功能需求叙述

### 6.1 角色与权限

1. 平台按租户隔离数据；用户按角色授权菜单与操作。  
2. 培训相关角色至少覆盖：培训部、企业用户、学员、老师、班长，以及综合办/总经理等审批角色（按开通范围）。  
3. 班级内角色（班主任、跟班教务、主讲、助教、班长）决定跟班端可见操作，须与开班准备指派一致。

### 6.2 协议与立项（规格能力）

1. 培训协议：模板、生成、多级审批、签订留痕。  
2. 项目立项：立项表申请、审批；立项后可生成十大管理表台账（总体计划、人员台账、课件、师资排课、材料审核、考勤过程、考核认定、获证花名册、补贴跟踪、结算总结等）。  
3. 扩展表：风险、整改、变更、预算、发票、讲师资质、请假补课、考务、证书签收、补贴核验清单等，按项目需要启用。

### 6.3 材料与模板中心

1. 开班材料、补贴材料、协议等统一模板管理。  
2. 生成、上传、审核、版本与下载。  
3. 按「项目—班级—阶段」归档。

### 6.4 移动端（App）

1. 学员：资料提交、学习/刷题、作业、签到（按开通能力）。  
2. 老师：布置练习、查看进度、批改（分期）。  
3. 班主任/班长：考勤督促、影像上传、日志（分期）。  
4. 跟班相关接口走 SaaS 鉴权通道；考前复习保持既有通道，互不替代。

### 6.5 报表与指标

| 指标 | 业务含义 |
|------|----------|
| 出勤率 | 有效出勤 ÷ 应到（按日或课次） |
| 作业/随堂练完成率 | 达标提交 ÷ 应交 |
| 通过率 | 合格 ÷ 参考（认定/考试结果） |
| 满意度 | 问卷均分或 NPS（规划能力） |
| 材料齐套率 | 已审通过 ÷ 应收集 |

支持班级维度与学员维度下钻，并驱动预警。

## 七、非功能需求（摘要）

1. **性能**：常用列表与进班操作在常规网络下秒级响应；大批量导入（名单、考勤）有进度与失败明细。  
2. **安全**：租户隔离、权限校验、操作审计；证件号等敏感信息脱敏展示与传输保护。  
3. **可靠**：关键业务软删除可追溯；文件存储可恢复。  
4. **体验**：流程导航清晰；空态与缺权限有明确说明；移动端适配主流机型。  
5. **扩展**：培训模式、地市模板、角色码可配置扩展，避免写死单一企业场景。

## 九、对外一句话与三段话介绍（可直接用于材料）

### 9.1 一句话

**千铝国昱 SaaS 培训模块，以班级为中心，贯通企业调研、规划分班、开班申报、信息收集、跟班实施到考试补贴，让培训过程可管、可证、可追溯。**

### 9.2 三段话

第一段（定位）：  
本模块面向铝业及职业技能培训场景，服务培训部、企业、培训机构与学员多方协同。管理端负责流程推进与证据监管，App 端承担采集、学习与课堂练习，数据同出一源。

第二段（主链路）：  
开班前，系统支持企业调研与人员采集、三年/项目规划及企业确认、智能或排班驱动分班并物化班级，完成花名册与师资课表准备、开班材料一键生成，以及学员信息收集与审核，为正式开训备齐条件。

第三段（实施与收尾）：  
开班后，跟班工作台集中管理考勤、排课、刷题学情，并规划留痕、作业、日志与预警；考试与认定衔接获证名单；项目收尾支撑补贴材料、拨款跟踪与结算归档，满足合规审计与经营复盘需要。
