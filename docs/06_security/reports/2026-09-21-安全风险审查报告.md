# 千铝国昱 SaaS 平台 — 安全风险审查报告

> 审查日期：2026-09-21
> 审查范围：`services/platform-api`（Java 后端主工程）、`apps/admin-web`（管理端前端）、`deploy/`（nginx + systemd 部署）、配置与凭据管理
> 审查方式：静态代码审计 + 配置审计 + 依赖核查（未做运行时渗透测试、未做动态扫描）
> **说明**：本报告不复制任何真实密钥原文，仅给出位置与处置建议

---

## 0. 结论速览

| 等级 | 数量 | 一句话 |
|---|---|---|
| **P0 致命** | 6 | 凭据已泄露进版本库、租户可被伪造、全站明文传输、匿名文件接口 —— 其中任意一条被利用即可造成数据泄露或资源滥用 |
| **P1 高危** | 13 | 认证与传输层防线存在多个可被绕过的缺口 |
| **P2 中/低** | 7 | 加固项与合规缺口 |

**总体判断**：项目在**业务功能与工程规范**上成熟度较高（多租户插件、异步链路、审计日志、全局异常处理都做了），但**安全基线存在系统性缺口** —— 集中体现在三个根因：

1. **凭据管理失控**：生产密钥既写进了配置默认值，也进了 git 历史
2. **信任边界错位**：租户身份取自客户端可控的 `X-Tenant-Id`，而认证主体取自 token，两者从未做一致性校验
3. **默认即危险**：CORS、上传大小、JWT 密钥、测试开关的"兜底默认值"在生产上就是攻击面

## 1. P0 致命风险（建议 24 小时内处置）

### P0-1 多租户越权：`X-Tenant-Id` 请求头可被任意伪造

- **位置**
  - `common/filter/TenantContextFilter.java:84,104,122` —— `TenantContextHolder.setTenantId(Long.valueOf(tenantIdHeader))`，直接采信请求头
  - `security/filter/SaTokenBridgeFilter.java:96` —— 认证主体 `tenantId` 取自数据库 `user.getTenantId()`
  - `config/MybatisPlusConfig.java` —— `TenantLineHandler.getTenantId()` 读 `TenantContextHolder` 拼 SQL
- **问题**：两个来源**从未比对**。已登录租户 A 的用户，只要把请求头改成 `X-Tenant-Id: B`：
  - 认证通过（token 有效，主体是 A）
  - 但多租户拦截器按 B 拼 `WHERE tenant_id = B` → 读写租户 B 的数据
  - 权限码仍按 A 加载，形成"用 A 的角色操作 B 的数据"的错配
- **代码自身已承认该风险**：`ai/service/LlmProxyService.java:21,44` 注释写着「禁止使用 TenantContextHolder（**来自 X-Tenant-Id header，可伪造**）」。也就是说团队知道这个头不可信，但只在 AI 模块做了规避，**全局链路没有修**。
- **影响**：跨租户读取/篡改任意业务数据（学员、证书、认定、竞赛、财务补贴）
- **修复**
  1. 在 `SaTokenBridgeFilter`（及 `AppTokenAuthFilter`）认证成功后，用**主体租户覆盖** `TenantContextHolder`，并校验与 header 一致，不一致直接 403
  2. `TenantContextFilter` 降级为"仅当无认证主体时的兜底"，且需校验该用户是否属于该租户
  3. 补一个集成测试：A 租户用户带 B 租户 header 调用列表接口，断言 403

### P0-2 生产密钥硬编码在配置默认值中，且已提交进 git 历史

- **位置**：`services/platform-api/src/main/resources/application.yml`

| 行 | 配置项 | 性质 |
|---|---|---|
| L274-275 | `platform.file.cos.secret-id` / `secret-key` | 腾讯云 COS **永久密钥**，默认值即真实值 |
| L301 | `platform.wechat.mini.app-secret` | 微信小程序 secret |
| L303-304 | `platform.baidu.api-key` / `secret-key` | 百度 OCR 密钥 |
| L330 | `platform.weknora.api-key` | WeKnora `sk-` 密钥 |
| L31-34 | `spring.datasource.url/username/password` | 默认值直连**公网 MySQL**（`43.138.163.7:3308`），账号密码均为真实值 |
| L36-37 | 注释中的另一套内网库密码 | 虽已注释，仍属明文凭据残留 |

- **加重情节**
  - 该文件的提交历史已进版本库（`git log` 可见），**轮换密钥前这些值永久可回溯**
  - `outputs/config/backend.env` **已被 git 跟踪**，其中 `MYSQL_PASSWORD`、`JWT_SECRET` 均为非空真实值
- **影响**：COS 桶被接管（文件被删/被覆盖/外链盗刷）、短信与 OCR 资源被盗刷、数据库被直连
- **修复**
  1. **立即轮换**上述全部密钥（COS、微信、百度、WeKnora、DB 账号）
  2. `application.yml` 所有敏感默认值改为空或占位符，缺失即启动失败（fail-fast），不要让应用"带默认值悄悄跑起来"
  3. 清理 git 历史（`git filter-repo` 或 BFG），并确认远端已强制推送
  4. 删除 `outputs/config/backend.env` 或加入 `.gitignore`；引入 `gitleaks` / `trufflehog` 进 CI 卡口

### P0-3 JWT 密钥存在弱默认值

- **位置**：`application.yml:262` `platform.security.jwt-secret: ${JWT_SECRET:dev-only-change-me-dev-only-change-me}`
- **问题**：默认值为可预测的公开字符串。任何环境只要漏配 `JWT_SECRET`，攻击者即可**自行签发合法 JWT**（用于 OIDC / IdToken 场景）
- **修复**：改为无默认值；启动时校验长度 ≥32 且非已知占位串，否则拒绝启动

### P0-4 全站明文 HTTP，无 TLS

- **位置**：`deploy/nginx.conf:30-33` —— 仅 `listen 80`，无 443、无 `ssl_certificate`；文件头注释自述「公网测试环境（IP 直连，无域名，无 HTTPS）」
- **影响**：登录密码、`Authorization` Bearer token、`X-Tenant-Id`、身份证号、手机号全程明文公网传输，可被中间人直接嗅探与重放
- **附带缺失**：无 HSTS、CSP、`X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy` 等安全响应头
- **修复**：申请证书并启用 443 + 80 强制跳转 HTTPS；补齐安全响应头

### P0-5 文件接口匿名放行，可匿名上传/下载/删除

- **位置**
  - `config/SecurityConfig.java:129` —— `auth.requestMatchers("/files/**").permitAll()`（**不限方法**）
  - `config/SecurityConfig.java:128` —— `GET /exam/files/**` 放行
  - `file/service/FileApplicationService.java:558-564` —— `getTenantIdSafe()` 在未认证时**兜底返回 `0L`**
  - `file/controller/FileController.java` —— 全部端点**无 `@PreAuthorize`**
- **问题链**
  1. 任何人无需登录即可 `POST /files` 上传，落库 `tenant_id = 0`，存储到 COS
  2. 上传者随后可凭 id 匿名 `GET /files/{id}/download` 与 **`DELETE /files/{id}`**
  3. 结合 P0-1，认证用户改 `X-Tenant-Id` 即可跨租户下载/删除**他人**文件（证件照、身份证扫描件、证书 PDF 等）
  4. 上传体积上限 1GB（`application.yml:22-23`），无全局限流
- **影响**：官方域名被用作恶意文件托管/钓鱼分发；存储成本盗刷；敏感证件图片越权读取
- **修复**
  1. `/files/**` 收紧为需认证，上传/删除加权限码（如 `file:upload` / `file:delete`）
  2. `getTenantIdSafe()` 删除 0 兜底，未认证直接 401
  3. 下载校验 `accessPolicy`（当前 `buildDownloadResponse` 未校验策略字段，仅写入时默认为 private）
  4. 上传做类型白名单 + 大小分级限制 + 病毒扫描

### P0-6 内部服务鉴权密钥默认为空

- **位置**
  - `application.yml:179` `platform.bot.actor-context-secret: ${BOT_ACTOR_CONTEXT_SECRET:}` —— MCP/Bot 链路共享密钥，默认空
  - `application.yml:354` `platform.rencaishibie.internal-token: ${RENCAI_INTERNAL_TOKEN:}` —— 内部引擎调用凭证，默认空
- **问题**：注释写明「MCP 与 platform-api 必须配置相同的随机值，禁止提交真实密钥」，但**默认值为空**，等于"不配也能跑"
- **影响**：若生产未配，内部接口可被未授权直连调用（Bot 代为操作、人才识别引擎被外部调用）
- **修复**：改为必填，启动时校验非空

## 2. P1 高危风险

### P1-1 CORS 兜底为「凭证 + 通配源」
- **位置**：`config/CorsConfig.java:33-53`
- **问题**：`platform.cors.allowed-origins` 未配置时走 dev 分支 → `addAllowedOriginPattern("*")` **且** `setAllowCredentials(true)`。Spring 在该组合下会回显请求源，实际效果是**任意站点可发起带凭据的跨域请求**
- **叠加**：`deploy/nginx.conf:64` 在 OPTIONS 预检直接返回 `Access-Control-Allow-Origin: '*'`，**绕过后端 CORS 校验**
- **修复**：无配置时 fail-fast 或仅允许 localhost；nginx 层删掉 ACAO `*`，交由后端统一控制；显式枚举生产域名

### P1-2 App token 链路可被指定任意租户
- **位置**：`security/filter/AppTokenAuthFilter.java:109-117`
- **问题**：`tenantId` 默认 `DEFAULT_TENANT_ID`，随后**完全采信** `X-Tenant-Id` 头覆盖，无白名单校验
- **附带**：token 为对齐 PHP 的 SHA-1 明文串，代码中**未见过期时间校验**，泄露即长期有效；且库中允许重复 token（注释称现网 85 组重复）
- **修复**：tenantId 以 token 关联用户记录为准；补充过期校验；评估迁移到随机 token + 定期轮换

### P1-3 登录接口缺少暴力破解防护
- **位置**：`auth/service/AuthApplicationService.java:70-71`
- **问题**：验证码校验被注释关闭（注释写明「临时关闭，LoginReq 已移除 captchaToken 字段」）；全代码库**未见登录失败计数/锁定**；仅 `chazheng` 模块有 `FixedRateLimiter`，**无全局限流**
- **影响**：`/auth/login` 可被无限制爆破
- **修复**：恢复验证码或引入失败锁定（5 次锁 15 分钟）；接入全局限流（Bucket4j / Sentinel）；登录失败打审计日志

### P1-4 身份证号明文写入日志
- **位置**
  - `trainingdepartment/service/SignUpRegisterTestService.java:294` —— `log.info("扫码报名成功 ... idCard={}", req.getIdCardNumber())`
  - `trainingdepartment/service/SignUpRegisterTestService.java:461` —— 同上（修改路径）
  - `chazheng/service/ChazhengApplicationService.java:223` —— `log.warn("跳过非法定身份证长度行[{}]: {}", i, idCard)`
- **加重**：同文件 `ChazhengApplicationService.java:470` 已使用 `maskIdCard()`，说明**有脱敏工具但这三处漏用**
- **影响**：日志（含 `logs/` 目录与可能的日志采集系统）沉淀大量明文身份证号，属个人信息合规红线
- **修复**：统一走 `maskIdCard()`；建立"敏感字段禁止直接入日志"的静态检查规则

### P1-5 WebSocket 跨站劫持（CSWSH）
- **位置**
  - `competition/exam/realtime/FormalExamRealtimeWebSocketConfig.java:32,34`
  - `competition/realtime/CompetitionPracticalRealtimeWebSocketConfig.java:20`
  - `config/PracticalScoringWebSocketConfig.java:22`
  - 均为 `setAllowedOriginPatterns("*")`
- **叠加**：`SecurityConfig.java:132-135` 将四个 ws 握手路径 `GET` 全部 `permitAll()`
- **影响**：恶意站点可在受害者浏览器中建立 WebSocket 连接，读取实时评分/考试推送数据
- **修复**：`setAllowedOriginPatterns` 收窄为白名单域名；握手阶段校验 token（ticket），而非放到子协议/查询串

### P1-6 含敏感字段的表被排除在多租户过滤之外
- **位置**：`config/MybatisPlusConfig.java` `ignoreTable()`
- **问题**：`platform_user`、`platform_user_detail`、`platform_user_token`、`platform_sms` 等**21 张表**不做 `tenant_id` 过滤。其中 `platform_user` / `platform_user_detail` 承载**姓名、手机号、身份证**等个人信息
- **影响**：一旦业务层漏写租户条件（或遭遇 P0-1 的 header 伪造），直接跨租户全表可见
- **修复**：逐一复核这 21 张表的豁免必要性；对含个人信息的表改用显式租户条件；为豁免清单补充评审记录与到期复核

### P1-7 依赖存在已知漏洞：`xlsx` 0.18.5
- **位置**：`apps/admin-web/package.json:48`（lock 已锁定 0.18.5）
- **问题**：SheetJS 0.18.5 受 **CVE-2023-30533**（原型污染，<0.19.3）与 **CVE-2024-22363**（ReDoS，<0.20.2）影响。项目大量使用该库做 Excel 导入（报名、花名册、题库）
- **修复**：升级至 ≥0.20.2（注意 API 兼容）；或迁移到 `exceljs`（项目已引入 4.4.0）

### P1-8 前端存储型 XSS 面 + token 存 localStorage
- **位置**
  - `pages/exam/reviewSyncStats/StudentDetailPage.tsx:66` —— `dangerouslySetInnerHTML={{ __html: html }}`，**未消毒**（另三处 `RichTextEditor` / `SnapshotPaperPreview` / `FormalExamStem` 均调用了 sanitize 函数，唯独此处裸渲染）
  - `stores/authStore.ts:22` —— token 取自 `localStorage`
- **影响**：题库题干等富文本被注入脚本时，可直接窃取 localStorage 中的 token
- **修复**：该处接入与其余三处相同的 sanitize；评估 token 改内存 + `HttpOnly` 刷新令牌方案

### P1-9 生产测试开关可匿名放行管理端接口
- **位置**：`config/SecurityConfig.java:150-156`；`application.yml:265`
- **问题**：`PERMIT_TEST_APIS=true` 时 `/training/sign-ups/**` **全路径匿名放行**，包含管理端 CRUD/二维码/导出。默认 false，但属于"一个环境变量即失守"的设计
- **修复**：改为仅在 `dev` profile 下可启用，生产 profile 强制忽略

### P1-10 上传体积与 DoS 面
- **位置**：`application.yml:9,22-23` —— `max-http-post-size: 1GB`、`max-file-size: 1GB`
- **叠加**：无限流；`/files` 匿名上传（P0-5）；nginx 层 `client_max_body_size 50M` 与后端 1GB 不一致
- **修复**：按业务分级设限（普通 20M，导入 100M）；统一前后端；接入限流

### P1-11 公网数据库连接未加密
- **位置**：`application.yml:31` —— JDBC URL 含 `useSSL=false`，且默认就是公网 IP 直连
- **影响**：数据库流量明文传输
- **修复**：启用 TLS（`useSSL=true&requireSSL=true`）或改为内网/VPC 专线

### P1-12 OnlyOffice 集成端点匿名放行且回调无签名校验
- **位置**：`SecurityConfig.java:131` `/training/office/**` permitAll；`TenantContextFilter` 亦将其列入白名单前缀
- **问题**：文档保存回调若未校验来源签名，攻击者可伪造回调写入/覆盖文档内容
- **修复**：回调走 OnlyOffice 约定的签名/密钥校验；来源 IP 白名单

### P1-13 Redis 与内部凭证默认无保护
- **位置**：`application.yml:74` `REDIS_PASSWORD` 默认空；L146 `WEKNORA_PUBLISH_TOKEN` 默认空
- **问题**：Redis 承载 Sa-Token 会话，无密码即任意人可读写会话（配合内网可达即可横向）
- **修复**：强制密码与网络隔离；空值即拒绝启动

## 4. 已核查且**未发现**问题的项

避免"看起来对"，以下是实际验证过的**阴性结果**：

| 项 | 核查方式 | 结论 |
|---|---|---|
| MyBatis SQL 注入 | 扫描全部 `*.xml` 与 `@Select/@Update` 注解中的 `${}` | 仅发现 `ExamExamDetailFixMapper` 的 `${backupTable}`/`${listTable}`，经查由服务端常量生成（`KnowledgeFixDedupService.java:65`、`KnowledgeFixWriteBackService.java:65`），回滚侧还有正则/前缀校验 → **不构成注入** |
| 命令执行 | grep `Runtime.getRuntime` / `ProcessBuilder` | 0 命中 |
| 通用异常堆栈泄露 | `GlobalExceptionHandler.handleException` | 返回固定 `"Internal server error"`，不回显堆栈 → 安全 |
| `eval` / `new Function` | 前端全量扫描 | 0 命中 |
| Spring Boot 版本 | `pom.xml:10` | 3.5.16，较新，无已知重大 CVE |
| `sanitize-html` / `axios` | `package.json` | 2.17.6 / 1.7.9，版本安全 |
| 密码存储 | `SecurityConfig.passwordEncoder` | BCrypt + 无前缀兼容；`{noop}` 仅用于 OIDC client_secret，未用于用户密码 → 可接受 |
| 逻辑删除 | 全局禁用 `setDeleted(1)+updateById` | 抽查 `FileApplicationService` 使用 `deleteById` 语义 → 符合规范 |

## 5. 处置优先级建议

**第一批（24 小时内，止损）**

4. 补齐 `JWT_SECRET`、Bot secret、Rencai token 的必填校验（P0-3、P0-6）

**第二批（本周内，堵防线）**
