# 千铝工投云平台与智能体开发部云平台产品规划与版本迭代管理办法

制度编号：QLGT-CPGL-2026-001　　版本：V1.0　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为规范云平台整体功能规划、需求梳理、PRD 编制、版本迭代、商业化场景设计全流程，明确多租户管理、权限体系、计费模块、数据驾驶舱看板等核心通用模块的设计标准与迭代节奏，保障平台功能贴合业务与客户需求，特制定本制度。

**第二条**　本制度管"规划—PRD—版本迭代"；项目立项、里程碑与结项复盘按 YF-01《产品与项目全生命周期管理制度》（修订版）执行，两项制度在需求入池处衔接。

## 第二章　产品规划与路线图

**第三条**　产品版本路线图按季度滚动制定，明确各版本目标、核心功能与发布时间，由产品与方案角色编制、部门负责人审定后公示。

**第四条**　路线图的需求输入统一来自需求池：任何渠道（会议、群消息、口头、客户反馈）提出的需求都须补录需求单后方予受理，未入池的需求不进版本；路线图调整须经部门负责人批准并记录原因。

**第五条**　需求单必填项：业务背景、目标用户、要解决的问题、预期效果、验收标准、期望时间。必填项不全的退回补充，不进入评审。优先级按"业务价值 × 紧急程度"分 P0–P3。

## 第三章　PRD 编制标准

**第六条**　PRD 统一使用部门模板（附录 B 附件 1），至少包含：场景与用户故事、功能清单、交互流程、数据口径、验收标准、依赖与风险。

**第七条**　PRD 质量三条硬标准：① 验收标准可核对（写"能做到什么"，不写"体验良好"）；② 数据口径写明取数字段与来源表；③ 涉及多租户、权限、计费的必须单列一章说明隔离与授权规则。

**第八条**　PRD 评审结论只有三种：通过、补充后复审、拒绝（写明理由）。通过后 PRD 冻结，变更走需求变更控制。

## 第四章　版本迭代管理

**第九条**　版本节奏：月度小版本（缺陷修复 + 小功能）、季度大版本（核心功能 + 架构调整）。版本范围在开发启动后冻结，冻结后新增需求一律进下一版本或走变更评审。

**第十条**　版本发布前必须完成：测试准出（P0/P1 缺陷为 0）、文档更新（接口文档、部署手册随版本）、参数核对（本次新增 sys_dict 项已登记并设默认值）。

**第十一条**　参数治理：所有业务参数（开关、阈值、条数、时长）统一收口 sys_dict，读写经钳制函数并记录告警日志；**参数变更视同配置变更**，走变更流程并在发布说明中列明，禁止以改参数方式绕过版本管理。

## 第五章　核心通用模块设计标准

**第十二条**　四大通用模块的设计标准：

| 模块 | 设计标准 |
|---|---|
| 多租户管理 | 租户数据隔离由数据访问层自动过滤，业务代码禁止手写租户条件；对外不下发可猜解的租户标识 |
| 权限体系 | 菜单 → 权限码 → 角色授权三步链，后端是最终裁决点；雪花 ID 一律字符串下发 |
| 计费模块 | 计费判定以确定性代码为准，禁止 AI 参与金额计算；计费记录留痕可审计 |
| 数据驾驶舱 | 指标口径单一来源（附录 A），看板取数走接口不直连库，支持按租户隔离 |

**第十三条**　商业化场景设计（订阅套餐、私有化报价项、增值服务）由产品与方案角色出方案，部门负责人审定；商务谈判与合同按制度 21 执行，部门只对技术方案与交付边界负责。

## 第六章　附则

**第十四条**　本制度由部门负责人负责解释，自发布之日起施行。
