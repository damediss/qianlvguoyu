## 1. 本轮结论

源文档派生 POC 已具备可重复的代码、Schema、数据库迁移和结构回归验证。当前可以确认：

- platform-api 能将 WeKnora 知识文档固化为私有不可变 source snapshot，并生成带版本的 manifest。
- 生成链路不再从空白 Word 构造合同，而是读取快照并在原 DOCX 上执行受控替换。
- 甲方、乙方、金额、项目名和服务范围支持正文、跨 run、表格、页眉与页脚替换。
- 派生前后正文段落数、表格数、页眉/页脚部件及其段落拓扑保持一致。
- 被替换 run 的加粗、斜体、字体和字号能够保留；旧字段残留会阻止生成。
- 同一源文件在解析器升级时复用快照并递增 manifest 版本，不重复保存源文件。

本轮不能确认复杂真实合同的分页、多级编号、文本框、内容控件和签章区视觉效果。该项仍是进入测试环境部署前的业务验收门槛。

## 3. DOCX 样本盘点与拟真源文档

原仓库内没有三份可用于本 POC 的软件技术服务历史合同：两个扩展名为 `.docx` 的归档文件并非 OOXML ZIP，其余可读 DOCX 为职业标准、申报表或证明模板。

2026-08-17 已新增三份完整拟真合同源文档：

1. 软件技术服务框架协议：正文跨 run 字段、付款/交付表、页眉页脚、十个章节和签署区。
2. 软件系统开发实施合同：五类字段位于表格相邻单元格，并包含里程碑、付款和验收结构。
3. 信息平台运行维护服务合同：多页条款、SLA、三个 section、横向附件、独立页眉页脚和签署区。

三份文档均已由生产派生服务真实读取，状态为 `derivable`，五类字段全部识别；替换后旧值清零，源/派生拓扑一致。它们可作为测试环境的拟真源文档，但由于内容由系统生成，不能替代最终上线前对真实脱敏历史合同的复核。
