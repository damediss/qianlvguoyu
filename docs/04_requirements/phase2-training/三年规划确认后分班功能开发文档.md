## 1. 文档说明

### 1.1 目的

指导研发按方案落地分班能力，打通：

```
三年规划企业确认（status=4）
  + 企业回传筛选名单 / 排班表（齐套）
  → SaaS 分班页
  → L1 组织分班（培训班 + 学员）→ 企业分班确认
  →（二期）L2 按排班表排课分班 → 绑定培训班
```

### 1.2 范围与非范围

| 做 | 不做 |
|----|------|
| 一期：组织分班（按**确认名单**） | 一期解析排班表自动分班 |
| 二期：Scheduling 引擎 + 标准人日排班 | 整站搬 Vue2 Scheduling |
| 三期：异构排班 Adapter | 复活 `train_people_list` 大宽表 |
| 分班页三步向导 | 用 `train_schedule` 存排课任务 |

### 1.3 两层分班（开发勿混淆）

| 层级 | 依据 | 期次 | 产出 |
|------|------|------|------|
| **L1 组织分班** | 企业筛选**人员名单** | **一期必做** | `train_info_class` + `train_people_list` |
| **L2 排课分班** | **人员排班表**（标准化后人×日） | 二/三期 | `train_shift_assign_*`，绑定 L1 |

> 企业「分班确认」只确认 L1 培训班级。  
> 「按排班表分班」= L2，不是一期范围。

## 3. 业务规则（实现必须遵守）

1. 仅 `status=4` 的规划可进分班。  
2. **分班门禁**：`enterpriseRosterFileId` 与 `enterpriseShiftFileId` 均非空。  
3. 必须先有 `train_info_list`，再写班级（`train_info_id` 必填）。  
4. 人员匹配主键：**身份证**；无证号仅展示，分配时需人工确认。  
5. 同 `trainInfoId` 下同一身份证不可分入多个班。  
6. `target_org_id` → `company_id`（经 `sys_org`，默认视为同 ID，不一致时在 `ensure-train-info` 集中转换）。  
7. 企业驳回班级：只改 `company_confirm_status`，不回滚计划状态。  
8. 一期隐藏排课分班入口；名单解析失败允许 fallback 到 `plan_item`。

### 5.2 一期 API

Controller：`@RequestMapping("/training/division")`（与现网 `/training` 一致，网关加 `/api`）。

#### GET `/plans`

| 参数 | 说明 |
|------|------|
| page, pageSize | 分页 |
| keyword | 标题/编号 |
| readyOnly | 默认 false；true 时仅齐套 |

过滤：`status=4` + 租户 + 企业范围。  
响应 `PageResponse` items：`planId, planNo, title, targetOrgId, orgName, status, statusLabel, enterpriseReturnReady, roster/shift 文件名与 ID, linkedTrainInfoCount, pendingRosterCount`。

#### GET `/plans/{planId}/ready`

```json
{
  "planId": 1,
  "status": 4,
  "enterpriseReturnReady": true,
  "rosterFileId": 11,
  "shiftFileId": 12,
  "rosterFileName": "...",
  "shiftFileName": "...",
  "missing": []
}
```

#### POST `/plans/{planId}/ensure-train-info`

请求：

```json
{
  "planYear": 2026,
  "workTypeId": null,
  "workTypeLevel": null,
  "title": "来铝-2026-培训班",
  "reuseExisting": true
}
```

逻辑：校验 status=4 + 齐套；`reuseExisting` 时按 planId(+工种) 查已有；否则新建 `train_info_list`（`three_year_plan_id`、`company_id=target_org_id`）。  
响应：`{ trainInfoId, created, title }`。

#### POST `/roster/parse`

请求：

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "mode": "enterprise_roster",
  "fallbackToPlanItem": true,
  "planYear": 2026,
  "jobName": null
}
```

逻辑：

1. 齐套校验。  
2. 软删该计划下 `assign_status=0` 的旧 roster（可按 trainInfoId 限定）。  
3. `mode=enterprise_roster`：读回传名单字节 → POI 解析（表头含「姓名」；身份证/手机/工种/车间/备注→班组）。  
4. 失败且 fallback：从 `train_three_year_plan_item` 去重灌池，`source=plan_item`。  
5. 响应：`{ total, withIdCard, withoutIdCard, source }`。

#### GET `/roster`

参数：`planId`（必填）、`trainInfoId`、`assignStatus`、`page`、`pageSize`。

#### POST `/org-split`

请求：

```json
{
  "planId": 1,
  "trainInfoId": 9,
  "submitForCompanyConfirm": true,
  "classes": [
    {
      "title": "高二班-1班",
      "workTypeId": null,
      "workTypeLevel": null,
      "dateStart": "2026-08-01",
      "dateEnd": "2026-12-31",
      "rosterIds": [1, 2, 3]
    }
  ]
}
```

事务：

1. 校验计划/培训信息归属。  
2. 校验 rosterIds；身份证在请求内与已有 people 不重复。  
3. 创建/更新 `train_info_class`（`company_confirm_status=0`）。  
4. 写 `train_people_list`（`train_id`, `train_class_id`, `type=student`, realname, id_card, phone）。  
5. 更新 roster：`assign_status=1`, `train_class_id`。  
6. 返回 `{ trainInfoId, classCount, classes:[{classId,title,nums}] }`。

#### GET `/train-info/{id}/summary`

返回：`trainInfoId, title, planId, companyId, companyName, classCount, peopleCount, pendingRosterCount`。

### 5.3 二期 API（`/training/shift-assign`）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/adapters/preview` | 异构→标准人日预览（三期可先做 T0 直通） |
| POST | `/precheck` | 警告列表，不落正式结果 |
| POST | `/generate` | 跑引擎，写 task+records |
| GET | `/tasks/{id}` | 结果 |

引擎迁入：`ScheduleAlgorithmService`、`ExcelScheduleParseService`、`ShiftTimeParser`、domain DTO + 单测；去 JPA，班次 Map / 配置注入。

| 中 16–24 | ✗ | ✓ | 无 |
| 夜 00–08 | ✗ | ✗ | 全禁 |

上课时段默认：上午 08:00–12:00，下午 14:00–18:00。

### 6.2 三步向导（一期）

**步骤 1 — 选择规划**

- 表格：已确认计划；Tag「已齐套 / 待补交」。  
- 未齐套：禁用「分班」按钮。  
- 可选：仅显示材料已齐 Checkbox。

**步骤 2 — 培训信息**

- 展示规划/企业；下载名单、排班附件（现有 download API）。  
- 输入培训信息标题 →「生成/复用培训信息」。  
- 有 `trainInfoId` 后可「下一步」。

**步骤 3 — 组织分班**

- 「解析确认名单」→ 待分池表格（勾选）。  
- 班级名称 +「保存并提交企业确认」→ `org-split`。  
- 成功提示可跳转「班级人员」或留在本页；invalidate 企业分班确认 query。

**二期**：同页折叠「排课分班」（一期不展示）。

## 8. 验收标准

### 8.1 一期

1. 齐套计划可完成：生成培训信息 → 解析名单 → 建班分人。  
2. 未齐套无法进入步骤 3（前后端均校验）。  
3. 库：`three_year_plan_id`、roster、class、people 可追溯。  
4. 企业账号可在「分班确认」确认/驳回。  
5. 同培训信息下身份证不重复分班。  
6. `fen_ban` 进入本页而非班级人员页。  
7. **一期不要求**按排班表自动拆班。

### 8.2 二期

1. 标准人日排班可生成 `train_shift_assign_*`。  
2. 早/中/夜可排规则符合配置。  
3. 算法班可绑定已有 `train_info_class`。  
4. 不破坏一期班级人员。
