## 架构决策

### 1. 可控服务化（不做全量微服务）

一期采用可控服务化策略，核心业务集中在 `services/platform-api/`，不拆出 `course-service`、`exam-service` 等细业务服务。AI、MCP、文件、工作流保持独立工程边界，但一期可先在 platform-api 内用包隔离。

### 2. 包结构隔离

`services/platform-api/src/main/java/com/guoyu/platform/` 下的包：

```
common/  config/  security/  tenant/  system/
file/  workflow/  course/  question/  exam/  training/
ai/  chazheng/  integration/
```

### 3. 数据库主键策略

- MySQL 8.4，主键使用雪花 ID，类型统一 `BIGINT`
- 多租户字段统一 `tenant_id`
- 逻辑删除通过 `deleted` 字段（MyBatis-Plus 自动处理）

### 4. 认证架构

- Sa-Token 管理 Token 生命周期（tik 模式，3天过期，并发登录允许）
- Spring Security `@PreAuthorize` 做接口级鉴权
- SaTokenBridgeFilter 桥接 Sa-Token 与 Spring Security

### 5. 多租户架构

- TenantContextHolder（ThreadLocal）存储当前租户
- TenantContextFilter 从 HTTP Header 解析 tenant_id
- MyBatis-Plus TenantLineInnerInterceptor 自动拼接 SQL 条件
- 前端请求拦截器附加 X-Tenant-Id Header

### 6. 工作流分工

- Flowable 管核心业务流程状态、审批、驳回、留痕
- n8n 只做内部自动化、通知、定时、接口同步和 AI 草稿触发
- 不向客户开放 n8n 编辑器

### 7. AI 与 MCP 边界

- AI Gateway 和 MCP Server 不直连业务数据库，只调用 platform-api 的受控 API
- AI 生成内容默认为草稿，课程发布/审批必须人工确认
- MCP Tool 必须定义名称、用途、参数 schema、权限要求和审计日志

### 8. 数据库连接池

- 从 HikariCP 切换到 Alibaba Druid 1.2.24
- 关闭所有监控统计（stat-view-servlet、web-stat-filter、filter.stat）
- 保留 SQL 防火墙（wall filter）防注入
