# 运营数据面板新增"同步练习"统计面板方案（草稿·待审）

> 状态：待审核（v0.1 · 2026-09-27）
> 位置：课程管理 → 运营流程 → 运营数据面板（页面实际名"数据面板"，menu id=4929 `/training/dashboard`，权限码 `train:dashboard:view`）
> 读者：**领导**（培训机构/平台运营决策层），不是运营执行人员

---

## 1. 背景与目标

"同步练习"是 App 学员端的 AI 同步学功能：系统按三阶段法给学员自动排每日复习（新题 + 错题复盘 + 仿真模考），答题数据落在 SaaS `ai_review_*` 六张表。目前它的统计能力只有一个**面向运营执行层**的明细页（考试管理 → 同步学统计，`exam:review-sync:stats:view`），指标细、要筛选、要下钻——不适合领导。

本方案在运营数据面板中新增一个"同步练习"统计分区，让领导 **10 秒钟看懂三件事**：

1. **用没用**——多少学员开通了同步练习，现在还活着多少
2. **勤不勤**——学员投入了多少题量、任务完成得怎么样
3. **好不好**——正确率、错题消灭、模考及格率有没有撑住（最终关联考证通过率）

设计原则（领导视角，贯穿全文）：

- **结论前置**：每行 KPI 就是一个判断句，红绿灯 + 环比，不让领导自己做除法
- **一屏看完**：KPI 三行 + 图两张 + 薄弱点一个，不滚动第二屏
- **明细不搬**：学员明细表、L3 粒度、Excel 导出**不进本面板**（已有的明细页承担，面板只放"查看明细 →"入口）
- **不堆大数**：作答总数这类"看着大但没感觉"的数，必须配人均/比率才有意义

## 2. 现状盘点（探索结论，可直接复用的资产）

| 资产 | 位置 | 复用方式 |
|---|---|---|
| 9 条现成聚合 SQL | `exam/reviewsync/mapper/ReviewSyncStatsMapper.java`（按天活跃/作答/正确率、任务完成率、范围汇总、错题牌级快照、错题每日新增/消灭、知识点 L3 正确率、按计划聚合） | 跨包注入，加时间范围过滤即可；tenant 由多租户插件自动追加 |

| 明细统计页 | `apps/admin-web/src/pages/exam/reviewSyncStats/StatsOverviewPage.tsx`（支持 embedded 嵌入） | 面板"查看明细"跳转目标，不重做 |
| 页面惯例 | `TrainingDashboardPage.tsx`：antd Card/Statistic/Row/Col + ReactECharts + TanStack Query（10s 轮询 liveQueryOptions）+ 局部 Alert 降级 | 新区块照此惯例 |
| 数据量判断 | 当前作答仅数百~数千行级，实时 GROUP BY 毫秒级；统计设计文档已预留二期 `review_sync_stats_daily` 预聚合表（百万级后再上） | 本期**直查**，不建表、不上定时任务 |

**缺口**（现成 SQL 没有、需新增的聚合，仅 3 条）：① 计划状态分布（active/completed/abandoned 计数 + 中断人次）；② 模考汇总（完成套数、平均分、及格率）；③ 近 7 日活跃学员数（distinct platform_user_id，可从现有 dailyAnswerTrend 派生或单写）。

## 3. 指标体系（领导三问 → 指标口径）

### 3.1 第一问：用没用（规模与留存）

| 指标 | 口径 | 来源 |
|---|---|---|
| 计划学员数 | `ai_review_plan` 总行数（累计开通） | 新增 SQL① |
| 进行中 / 已完成 / 已放弃 | plan.status 分布计数 | 新增 SQL① |
| 放弃率 | abandoned / 总数（🔴 >20% 标红） | 计算 |
| 近 7 日活跃学员 | `ai_review_answer` 近 7 天 distinct platform_user_id | 新增 SQL③ |
| 7 日活跃率 | 近 7 日活跃 / 进行中计划数 | 计算 |
| 累计中断人次 | sum(plan.interruptCount > 0 的计划数) | 新增 SQL① |

### 3.2 第二问：勤不勤（投入与坚持）

| 指标 | 口径 | 来源 |
|---|---|---|
| 累计作答数 | `ai_review_answer` 总行数 | 复用 answerTotals |
| 人均作答 | 累计作答 / 计划学员数 | 计算 |
| 任务完成率 | 近 30 天 day.status=done / (done+skipped+abandoned+过期 pending) | 复用 dailyDayCompletion 汇总 |
| 今日作答 / 今日活跃 | 当天 answer 计数 / distinct 学员 | 复用 dailyAnswerTrend 末点 |

### 3.3 第三问：好不好（效果，领导最关心）

| 指标 | 口径 | 来源 |
|---|---|---|
| 整体正确率 | 近 30 天 sum(isCorrect)/count | 复用 answerTotals |
| 累计消灭错题 | `ai_review_wrong_item` removed=1 计数（三级淘汰毕业数） | 复用 wrongSnapshot/wrongDailyRemoved |
| 在册错题（红/黄） | cardLevel 分布 removed=0 | 复用 wrongSnapshot |
| 模考完成套数 | `ai_review_mock_paper` status=done 计数 | 新增 SQL② |
| 模考平均分 / 及格率 | avg(score)；score ≥ passScore 占比（🟢 ≥60% / 🔴 <40%） | 新增 SQL② |
| 薄弱考核项目 Top5 | L1 节点正确率最低 5 项（近 30 天，作答 ≥50 次才参评防噪声） | 复用 knowledgeAgg 变形 |

**趋势图 2 张**（领导看方向，不看每日抖动）：

- 图 A「近 30 天活跃与正确率」：柱=每日作答数，线 1=活跃学员，线 2=正确率（复用 dailyAnswerTrend）
- 图 B「错题新增 vs 消灭」：每日堆叠柱（绿=消灭，红=新增），消灭持续大于新增 = 题库在收敛（复用 wrongDailyNew/wrongDailyRemoved）

**明确不做进面板的指标**（避免给领导制造噪声）：学员明细表、L3 级知识点掌握度、每日计划物化量、LLM 鼓励语用量、环比过于敏感的"今日"单点值（今日数据只作附属小字）。按机构/班级拆分本期不做（统计设计文档拍板"全部学员，不做机构隔离"，二期再议）。

### 4.3 一目了然的落地手段

- **三行分组用「规模 / 投入 / 效果」小标题隔开**——对应领导三问，扫标题即知结构
- **红绿灯 Tag**：放弃率 >20%、及格率 <40%、活跃率 <40% 标红；达标线绿；其余中性灰。阈值集中在前端常量，便于调
- **大数字格式化**：万单位缩写（86.5万）、百分比 1 位小数，沿用页面 `formatRate` 惯例
- **「查看明细 →」**：跳转已有同步学统计总览页（考试管理菜单下）；注意该页权限码是 `exam:review-sync:stats:view`，领导角色若无此码则链接置灰并 tooltip"需考试管理权限"（不因此阻断面板本体）
- **轮询与降级**：挂同一 `liveQueryOptions`（10s）略重，本面板改为 **60s 轮询**（统计数据无秒级实时诉求，也护住 DB）；局部失败用 Alert 降级，不拖垮整页（页面现有 partialErrors 惯例）
- 雪花 id 不下发本面板（无明细行），无精度问题

## 5. 后端设计

**一个聚合端点**，一次拿全（避免前端 6 个请求）：

```
GET /training/dashboard/review-sync?days=30
@PreAuthorize("hasAuthority('train:dashboard:view')")
→ ApiResponse<ReviewSyncPanelVO>
```

`ReviewSyncPanelVO` 结构：scale{totalPlans, active, completed, abandoned, abandonRate, active7d, activeRate7d, interruptPlans}、effort{totalAnswers, avgAnswersPerPlan, dayCompletionRate, todayActive, todayAnswers}、effect{correctRate, removedWrongs, redWrongs, yellowWrongs, mockDone, mockAvgScore, mockPassRate}、trend30d[{date, answers, activeUsers, correctRate}]、wrongTrend30d[{date, newCnt, removedCnt}]、weakTop5[{l1Title, correctRate, answerCnt}]。

实现位置二选一（建议 B）：

- A. `TrainDashboardApplicationService` 加方法——但该 service 是"全表拉内存聚合"风格，不适合 answer 大表
- **B. 新增 `trainingdepartment/service/ReviewSyncPanelApplicationService`**，注入 `ReviewSyncStatsMapper`（exam 包，无权限注解，跨包注入无碍）+ 新增 3 条 SQL（放 `ReviewSyncStatsMapper` 还是新建 `ReviewSyncPanelMapper`，实现时按"不污染考试域"原则放新 Mapper 更干净）；Controller 端点挂 `TrainDashboardController`

新增 3 条 SQL 口径：

1. 计划状态分布：`SELECT status, COUNT(*), SUM(interrupt_count>0) FROM ai_review_plan GROUP BY status`（进行中数从 status=active 行取）
2. 模考汇总：`SELECT COUNT(*) done, AVG(score), SUM(score>=pass_score)/COUNT(*) FROM ai_review_mock_paper WHERE status='done'`
3. 近 7 日活跃：`SELECT COUNT(DISTINCT platform_user_id) FROM ai_review_answer WHERE created_at >= CURDATE()-6`

防御性编程按 AGENTS.md：Mapper 返回 null 检查、比率除零兜底（计划数=0 时返回 null 前端显示"--"）。

## 11. 风险与限制

1. **"应开通学员"分母缺失**：渗透率（开通学员/应开通学员）没有可靠分母（哪些学员"应该"用同步练习无口径），本期用"计划状态分布 + 活跃率"替代，不向领导展示渗透率以免误读
2. **模考样本少时及格率抖动**：done < 10 套时前端显示"--"并 tooltip"样本不足"
3. **与考证通过率的关联分析不做**：那是长线 BI 命题（需关联认定结果表），不在本面板承诺；领导若问起，口径是"模考及格率为先行指标"
4. **明细页权限割裂**：领导角色当前大概率没有 `exam:review-sync:stats:view`，"查看明细"可能长期置灰——若终审决定领导需要下钻，追加一条权限 seed 迁移（role 授权），本方案默认不做
