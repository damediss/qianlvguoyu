# 数据关系速查（断言字段/数据归属前必读）

> AGENTS.md 只做索引，本文件承载“字段在哪、表怎么连”的取证标准与核心关系。
> 触发：任何“某字段/某数据在哪、是否存在、是否只存在某处”的判断之前。

## 30 秒红线

断言“不存在 / 只有 / 没有结构化数据”前，五项至少做完四项并写进结论；缺项只能写“未在 X 中发现”：

1. **全库列搜索**（不是单表 `SHOW COLUMNS`）：`SELECT TABLE_NAME, COLUMN_NAME FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND COLUMN_NAME LIKE '%work_type%';`
2. **迁移目录 grep 概念词**：`grep -rn "work_type_id" services/platform-api/src/main/resources/db/migration*/`
3. **实体/Mapper 搜索**：`grep -rn "@TableName\|workTypeId" services/platform-api/src/main/java`
4. **反向引用搜索**：谁引用了 `T.id`（`grep -rn "examId\|exam_id" ...`），一对多关联表通常在这里出现
5. **读一处写入路径**：`create/update` service，确认字段是直接存、关联表存，还是由别的表反查

补充两条：

- **页面字段名 ≠ 存储字段**：如页面“工种选择”提交的是 `course_id`，工种/等级由 `exam_course` 反查后写入关联表。
- **“该信息只在标题文本里”是最后手段解释**：出现此判断必须先查关联表与写入路径。

## 核心关系（只收一对多与名不副实的）

| 概念 | 落点 | 关系/口径 |
|---|---|---|
| 考试计划 | `train_exam_list` | 主表；`level` 是计划类型占位串，不是工种等级 |
| 计划 ↔ 工种/等级/课程 | `train_exam_work_type_list(exam_id)` | 一对多；`work_type_id`、`level`、`course_id` 都在这里 |
| 页面“工种选择” | 提交 `course_id` | 保存时由 `exam_course` 反查 `work_type_id/level`（`TrainExamListApplicationService.saveWorkTypeList`） |
| 等级码 | `train_exam_work_type_list.level` | 数字 0~4 = 五级~一级；与常见 1~5 方案码反向（转换 `5 - level`） |
| 工种树 | `exam_work_type` | 树形；共享粒度取叶子，父级是职业 |
| 真题 | `exam_zhenti` | 当前只挂 `exam_id`；共享改造需先从关联表取 scope |
| 取题链路 | `train_exam_list → train_exam_work_type_list → exam_course → exam_knowledge_structure → exam_exam_detail` | 同步学、题库都走这条 |

新增一对多关系时追加一行，不要只写在方案文档里。

## 事故锚点（2026-10-20）

历年真题共享方案 §2 只对 `train_exam_list` 做 `SHOW COLUMNS`，就断言“工种/等级只存在于标题文本”，漏掉 `train_exam_work_type_list`（1067 行、租户 10159 全量）。实体、Mapper、`saveWorkTypeList()`、同步学取题链都在用它；`SHOW TABLES LIKE '%exam%'` 或反向搜 `examId` 任意一步都能命中。
