## 一、问题与目标

### 1.1 现状断层

| 层 | 现状 | 问题 |
|----|------|------|
| 产品叙事 | 小培 = 学习编排脑；内部 = 合同/运营助手 | 对外常混称「智能体」，边界不清 |
| 学员小培 | FAB + bootstrap/chat 已落地；摘要卡 / 深链已补 | O3 真机验收未勾；讲题链与文档不完全一致 |
| LLM | 方案 D8「仅润色」 | **FaqLlm 润色未真正接线**；关模型仍可用规则（符合红线） |
| WeKnora | `ask_kb` / 拍照等走知识库 | KB 内容运营未齐 → 空命中 / 超时体验差 |
| 工程 | `ClassAssistantApplicationService` ~3k 行 | 意图纠正堆叠 + 学员/班务同服务，难测难演进 |
| 内部智能体 | 企微合同 MVP + 管理端 WeKnora 嵌入 | 无「培训运营助手」产品化；O4-KR3 试评未做 |
| 观测 | 少量 `[小培] chat intent=` 日志 | 无意图命中 / KB 命中 / 深链同源 / 耗时看板 |

### 1.2 优化目标（可验收）

| # | 目标 | 度量 |
|---|------|------|
| G1 | 学员主路径稳 | O3 验收单全勾；「该刷哪」`examId` 与班绑定一致（接 O4-KR2） |
| G2 | 讲题可信 | 有官方解析必先出；无则降级明确；禁止装懂编造 |
| G3 | 数字可信 | 进度/错题/覆盖率**只来自 Tool**；润色不得改数 |
| G4 | KB 可用 | 政策/工种问答有命中；失败短答本地兜底，不整窗挂死 |
| G5 | 双轨隔离 | 内部 Agent 不得写学员答卷 / 不得混用学员 KB 当办公 Wiki |
| G6 | 可演进 | 意图路由可单测；关键路径有埋点 |

### 1.3 非目标（本期明确不做）

| 不做 | 原因 |
|------|------|
| 聊天内直接答题 / 新建答卷域 | P0 已锁；通道隔离 |
| 合并 A/B/C 错题与指标 | 已锁 |
| 老师催交 / 抽题布置进小培主路径 | D1；另立需求 |
| 把合同 Agent / 运营 Agent 并入 App `assistant/chat` | 权限与场景不同 |
| 数字人 SDK / 全站 FAB | 另立或后置 |
| 人社终态、自费三模式等运营大盘 | 属培训运营主线，非本方案 |

## 二、双轨架构（先看）

```text
┌─────────────────────────────────────────────────────────────┐
│ 轨 A · 客户产品使用智能体（AI 小培）                           │
│  App FAB → assistant/bootstrap|chat                          │
│  规则意图 → Tool(同步学/精准学只读/作业入口) → 可选润色         │
│  自由问 / 讲题兜底 → WeKnora Agent「AI助教_智能问答」           │
│  动作：深链 syncHome / precise / 作业页（不写答卷）             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 轨 B · 公司内部工作智能体                                      │
│  企微 / 管理端 WeKnora Widget / MCP                            │
│  合同材料生成、制度 FAQ、培训运营只读问答与跳转                  │
│  真相源：platform-api 管理端 API + 文件/COS + 审计              │
│  禁止：直接改 ai_review_* / appsmart 答卷；禁止共用学员 KB 混库 │
└─────────────────────────────────────────────────────────────┘
```

| 维度 | 轨 A 小培 | 轨 B 内部 |
|------|-----------|-----------|
| 用户 | 学员（班长可共用 FAB） | 员工 / 教务 / 商务 |
| 入口 | App 班级 FAB | 企微 / 管理端嵌入 |
| 鉴权 | PHP itoken → App 跟班 | 员工 SSO / 管理端 Token / 企微 |
| 知识库 | `AI助教_智能问答`（考证/学习） | 合同 Wiki / 制度 / 运营手册（独立 KB） |
| 写权限 | **无答卷写**；仅跳转 | 受控业务 API（合同任务等）+ 审计 |

## 三、轨 A · 小培优化设计

### 3.1 维持冻结决策（继承 P0）

继续生效：D1–D10（仅学员价值、主通道 C、讲题降级链、规则+Tool、LLM 只润色、无计划隐藏假进度等）。  
若代码与文档冲突：**以可验收行为为准修订文档**，再决定是否补代码（见 §3.3）。

### 3.2 能力分层（优化后目标态）

| 层 | 职责 | 实现要点 |
|----|------|----------|
| 入口 / 壳 | FAB、摘要卡、chips、场景（sync/precise） | 保持 `XiaopeiSheet`；旧 `assistant` 路由仅引导 |
| 意图路由 | 文本/chip → intent | **以服务端为准**；收敛端侧 soft 改写；硬纠正可测 |
| Tool | overview / resolveClassExam / wrong / homework… | 数字只出这里；失败给原因文案 |
| 讲题链 | 解析 → 同步学讲解 → WeKnora / 明确无法讲 | 对齐 D4；超时 fail-closed |
| 润色 | FaqLlm 可选 | 输入=结构化槽位+草稿；输出禁改数字；关配置=纯规则；**开关见 §3.5** |
| KB | ask_kb / 政策补充 | 独立超时与短答兜底；记 `kbHit` |
| 动作 | navigate 深链 | `exam_id` + `classId` 同源（O4-KR2） |

### 3.3 文档 vs 代码对齐（评审拍板项）

| 项 | 方案原文 | 现网倾向 | 本方案默认 |
|----|----------|----------|------------|
| 讲题第三档 WeKnora | D4 有 | 常跳过以控延迟 | **P1 补齐**：无解析且无同步学讲解时再调；有超时则「暂无法讲解」 |
| LLM 润色 | D8 有 | 未接线 | **P1 可选开关**：默认关或灰度开；关=验收必过 |
| 班务意图 | 早期仅学员 | 同服务残留 staff chips | **P1 隔离**：staff 走 `persona=class_assistant` 且不进学员 FAB |

### 3.4 工程结构（行为不变前提下拆分）

建议从 `ClassAssistantApplicationService` 抽出（不改变对外 API）：

| 组件 | 职责 |
|------|------|
| `AssistantIntentRouter` | detect / hard-correct / soft-route |
| `AssistantSyncTools` | loadSyncSnapshot / summary / go_sync |
| `AssistantExplainChain` | resolve → review explain → WeKnora |
| `AssistantKbService` | ask_kb + 超时兜底 |
| `AssistantReplyPolish` | 可选 FaqLlm |

对外仍：`GET|POST …/classes/{classId}/assistant/*`。

### 3.5 润色开关放哪（默认关、灰度开）

> 现状：**尚未接线**，无独立开关 UI。下列为优化落地时的约定位置（对齐现网「模型配置行 + 字典灰度」习惯）。

采用 **两级开关**，都在**管理端 / 配置表**，**不**放进 App 小培弹窗（学员不可自开）：

| 级 | 作用 | 放哪 | 默认 |
|----|------|------|------|
| **L1 总开关** | 是否允许调用 FaqLlm 做话术润色 | 表 `exam_faq_model_config` 新增场景行：`model_code = xiaopei-reply-polish`（名称如「小培回复润色」）；`status = disabled` 全站关，`enabled` 才允许调模型 | **disabled** |
| **L2 灰度** | 总开关打开后，哪些人真正走润色 | `sys_dict.code = xiaopei_polish_gray_enabled`（false=仅白名单；true=租户内全开）+ **独立白名单表** `xiaopei_polish_whitelist`（`scope_type=user\|class`，**禁止**复用 `ai_review_gray_whitelist` 以免与同步学灰度语义混用） | **gray_enabled=false**，白名单空 |

**判定伪代码（服务端）：**

```text
if model_config(xiaopei-reply-polish).status != enabled → 不润色（规则原文）
else if !gray_enabled && user/class 不在白名单 → 不润色
else → FaqLlm 润色（失败回退规则原文）
```

**管理端入口建议：**

1. **主操作**：题库/AI「模型配置」页（现网维护 `exam_faq_model_config` 的同一处）→ 找到「小培回复润色」行 → 启停 = L1。  
2. **灰度操作**：系统字典 +（可选）跟班/运营旁路「小培润色白名单」；首期可只做 **用户级白名单**，班级级后补。  
3. **bootstrap 只读回传**：`polishEnabled: boolean`（当前学员是否会润色），供埋点/联调，**不渲染学员开关**。

**明确不放：**

| 位置 | 原因 |
|------|------|
| App 小培设置 / 弹窗 Toggle | 费用与话术需运营控，避免学员误开 |
| 仅环境变量 | 无法按人灰度，运维改发版成本高（可作为紧急熔断第三级，可选） |
| 跟班「同步学」灰度开关 | 语义不同，勿混用 `ai_review_gray_enabled` |

**紧急熔断（可选 L0）：** 配置中心 / 环境变量 `XIAOPEI_POLISH_FORCE_OFF=true` 时无视 L1/L2，一律不润色。

**数字防篡改（实现约定）：** 润色 Prompt 禁止改数之外，展示层以 Tool 槽位（如 `accuracy`、`wrongBookCount`、今日题量）为准渲染；模型输出仅作叙述句，服务端可用「槽位回填」覆盖回复中的百分比/个数，抽检失败则回退规则原文。

### 3.6 可观测性（P0 即做最小集）

每次 chat 结构化日志（或轻量表）字段建议：

`classId, platformUserId, intent, source(rules|kb|explain_resolve|explain_review|explain_kb|error), examId, entryVisible, kbHit, latencyMs, polish(on|off|skip)`  

看板至少：意图分布、KB 命中率、深链失败率、P95 耗时、错误码。

### 3.7 知识库运营（与开发并行）

| 内容包 | 用途 | Owner |
|--------|------|-------|
| 工种考证政策 FAQ | ask_kb / 报考结论补充 | 教务 + 内容运营 |
| 高频错因 / 考点短文 | 讲题兜底语料 | 教研 |
| 拒答边界说明 | 不编造进度、不代查他人学情 | 产品 |

上线门禁：抽样 **20 问**，命中率 ≥ **70%**（可评审调整）；超时必须短答。内容包 v1 Owner：教务指定 1 人，与 P1 开发**并行**，未达标则讲题第三档 / ask_kb 保持「暂无法讲解」话术，不阻塞 P0。

### 3.8 防答非所问（域门禁）

> 踩坑：「我的学习情况怎么样」误进 WeKnora → 长篇「知识库检索情况 / FAQ 容器」说明，学员要的是本班进度。

| 规则 | 说明 |
|------|------|
| **个人数据域** | 学情 / 错题 / 作业模考 / 能不能考过 → **只走 Tool**；`looksLikeKnowledgeBaseWorthy=false` |
| **末位硬锁定** | soft / chip 误传 `ask_kb` 后，仍用 `resolvePersonalDataIntent` 纠回 |
| **KB 准入** | 仅考点/工艺/概念/考证/粘贴题；裸「学习」不再当作值得检索 |
| **元话术拦截** | 回复含「知识库检索情况」「数据获取说明」等 → 替换为本班快照短答（`source=weknora_meta_replaced`） |
| **回归单测** | `XiaopeiIntentRoutingTest`：每条踩坑口语进表，禁止再漏 |

观测：`chat_metrics` 中 `intent=ask_kb` 且问句含「学习情况/进度/错题」应趋近 0；出现则补词表而非扩 KB。

## 八、建议评审结论（请拍板）

1. **确认双轨**：小培 ≠ 内部智能体，禁止合并入口与 KB。  
2. **P0 只验稳 + 埋点 + 文档对齐**；O3 按 **P0 档**勾选，不堆讲题三档/润色。  
3. **P1 主投入**：讲题链、润色 L1+L2（独立白名单表）、KB 运营、意图收敛。  
4. **内部智能体**：P2 **另立排期**，不占小培 P1；合同收口 + 运营只读试点。
