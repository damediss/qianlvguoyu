# 培训部数字化功能需求规格说明书

## 1. 项目概述

本项目旨在为培训部及其相关部门提供一个数字化管理系统，支持从项目启动及规划、培训执行、认定到项目收尾的全流程管理。系统将实现10个部门的协调合作，包括培训部、认定部、课程部、市场部、技术部、综合办、总经理、企业、培训机构和第三方认定机构。

## 2. 业务流程分析

### 2.2 项目阶段

#### 2.2.1 项目激动及规划阶段

1. 市场部：对企业需求进行调研工作
2. 企业：提出培训需求
3. 企业：提供企业人才数据
4. 市场部：召开项目研讨会（所有相关部门参加）
5. 培训部：人才数据识别
6. 培训部：根据人才数据及企业需求，输出3-5年的人才规划方案
7. 企业：企业对方案确认
8. 培训部：拟企业签订培训协议
9. 综合办：二审培训协议，并审批
10. 总经理：三审培训协议，并盖章
11. 培训部：完成培训协议初稿
12. 企业：企业法务确认
13. 培训部：培训协议总稿确认
14. 培训部：签订培训协议
15. 综合办：审批培训协议
16. 总经理：审批培训协议
17. 企业：企业签订培训协议
18. 培训部：参加动员大会（培训流程）
19. 市场部：参加动员大会（培训的好处）
20. 企业：组织企业在职员工开展动员大会
21. 培训部：确认培训人员名单
22. 认定部：确认是否符合认定申报条件
23. 企业：培训人员确认
24. 培训部：发起立项，填写《项目立项表》
25. 综合办：审核《项目立项表》并审批项目
26. 总经理：审批《项目立项表》并完成立项
27. 培训部：项目成立，立项后创建“十大管理表”
28. 培训部：确认培训工种、等级
28. 课程部：制作培训课件
29. 综合办：审批课件
30. 总经理：审批课件
31. 培训部：建立培训群，将收集材料二维码发到班级群
32. 技术部：调试app是否正常运行
33. 企业：将培训员工邀请到班级群
34. 培训部：拟定开班时间/工种，与培训机构确定时间与教师
35. 培训机构：依据开班情况，能否安排授课老师
36. 培训部：将开班情况反馈给企业
37. 企业：接收培训时间和教师食宿安排
38. 培训部：和学校签订培训协议及授课承诺书
39. 培训机构：签订培训协议及授课承诺书

#### 2.2.2 培训执行阶段

1. 培训部：审核学员提交的材料，督促学员提交材料
2. 技术部：保证平台正常使用
3. 企业：共同督促学员提交材料
4. 培训部：制作开班材料上传人社系统
5. 技术部：班级材料模板一键生成
6. 培训机构：提交线上人社系统审批
7. 培训部：制作开班纸质材料
8. 技术部：班级材料模板一键生成
9. 企业：纸质材料部分需要企业盖章
10. 培训机构：纸质材料盖章
11. 培训部：确认上课时间，场地，建立班级群，工作人员
12. 企业：确认上课时间，场地，学员进班级群，班主任
13. 培训机构：授课老师形成安排确认
14. 培训部：培训第一天，组织每个班5-10分钟的开班仪式
15. 技术部：签到表，图片，视频上传
16. 企业：确保班级全员参加开班仪式
17. 培训机构：授课老师登录人社考前系统
18. 培训部：开始学员培训，按跟班要求进行跟班
19. 技术部：课件学习，课后作业
20. 企业：班主任每天上传考勤，上课照片，上课视频
21. 培训机构：授课老师登录人社系统进行考勤，课件讲解，课后作业讲评
22. 培训部：考前辅导（将学员导入app进行复习）
23. 技术部：题库使用
24. 企业：督促学员共同使用
25. 培训机构：错题解析
26. 培训部：结课通知
27. 认定部：制作认定申报材料
28. 企业：结课

#### 2.2.3 认定阶段

1. 培训部：接收获证学员名单
2. 认定部：推送获证学员花名册
3. 技术部：上传获证学员花名册
4. 企业：推送获证学员花名册

#### 2.2.4 项目收尾阶段

1. 培训部：制作补贴材料
2. 技术部：补贴材料模板生成
3. 认定部：下载证书
4. 培训机构：人社系统提交申报和补贴材料盖章
5. 培训部：资料归档
6. 总经理：资料归档
7. 培训部：补贴材料跟进拨款进度
8. 培训部：项目结算
9. 总经理：审批
10. 企业：审批
11. 培训机构：企业是否参与分成
12. 第三方培训机构：院校分成
13. 培训部：输入项目总结
14. 总经理：审批
15. 企业：审批

### 3.2.5 任务管理与人机料法环（5M）

培训业务在系统中用 **「培训任务」** 作为执行单元：先有任务台账（创建/维护任务），再通过 **任务配置 → 资源配置**，按 **人机料法环** 把人员、资源、内容、规则与环境要素挂载到具体任务上。该结构与原型侧栏 **任务管理 / 任务配置 / 资源配置** 完全一致，便于与业务导图对照。

| 5M | 分项（词条） | 培训语境下的含义（摘要） | 典型数据或能力 |
| --- | --- | --- | --- |
| **人** | 师资与教务 | 主讲/助教指派到班级、班主任与跟班、授课资质与承诺书绑定任务 | 派师锁定、教务到岗、资质到期预警 |
| **人** | 参训学员 | 学员名单、企业确认、资格审核与认定条件衔接 | 名单导入、确认流、资格审核、同步排课池 |
| **机** | 机 | 执行侧「硬」资源：合作机构、讲师<strong>池</strong>、场地及设备等到账与冲突（派师到班在「人 · 师资与教务」） | 机构台账、讲师池与资质、场地占用、资源冲突检测 |

**与「实施流程」的关系：** **业务流程** 描述分班→排课→开班→培训→认定→申报→结业→回款等阶段顺序。**组织流程** 使用与任务侧相同的 **人机料法环词条**，但在原型中与 **任务管理 → 任务配置 → 资源配置** 分轨：**组织视角单独页面**（治理、RACI、例会、制度发布、预算池与分成决议等），**任务视角**仍为各资源配置操作台（名单、资源台账、课包、费用执行、分班排课参数等）。两轨通过页面内「打开任务侧…」互链对照。

**侧栏与导图：** 菜单层级严格对齐业务导图「培训」四层结构，**不在导图节点之外增加侧栏词条**（例如参训学员台账仅通过「创建任务」页 5M 表进入）。导图在「任务配置 · 资源配置」下将「法」拆为日程计划、模式选择、规则三项；**实施流程 · 组织流程** 导图「法」无下级节点，原型侧栏对应 **唯一菜单「法」**（`p-10-05`），模式/规则的组织分项演示页（`p-10-06`、`p-10-07`）仅通过该页内按钮进入，不单独占侧栏。

## 5. 系统架构和数据模型

### 5.1 系统架构

系统采用B/S架构，分为前端和后端两部分：

- **前端**：使用HTML、CSS、JavaScript等技术，构建用户界面，实现与用户的交互。
- **后端**：使用Java、Python等技术，构建服务器端应用，处理业务逻辑和数据存储。
- **数据库**：使用MySQL、Oracle等关系型数据库，存储系统数据。
- **中间件**：使用Tomcat、Nginx等中间件，提供Web服务和负载均衡。

### 5.2 数据模型

#### 5.2.1 核心实体

| 实体   | 描述             | 主要字段                                   |
| ---- | -------------- | -------------------------------------- |
| 用户   | 系统用户，包括各部门的人员  | 用户ID、用户名、密码、角色ID、部门ID、姓名、联系方式等         |
| 角色   | 用户角色，包括各部门的角色  | 角色ID、角色名称、权限列表等                        |
| 部门   | 系统部门，包括10个参与部门 | 部门ID、部门名称、部门描述等                        |
| 项目   | 培训项目           | 项目ID、项目名称、企业ID、项目状态、创建时间、结束时间等         |
| 项目立项表 | 立项审批信息         | 立项表ID、项目ID、申请部门、申请时间、审批状态、审批人、审批意见等 |
| 十大管理表 | 立项后过程管理台账      | 管理表ID、项目ID、表类型、负责人、状态、更新时间、附件等 |
| 企业   | 参与培训的企业        | 企业ID、企业名称、联系人、联系方式、地址等                 |
| 培训   | 具体的培训活动        | 培训ID、项目ID、培训工种、培训等级、培训时间、培训地点、培训机构ID等  |
| 培训人员 | 参与培训的人员        | 培训人员ID、姓名、性别、身份证号、联系方式、企业ID、培训ID、是否获证等 |
| 协议   | 培训协议           | 协议ID、项目ID、协议内容、签订时间、状态等                |
| 材料   | 培训相关材料         | 材料ID、材料名称、材料类型、材料内容、上传时间、上传用户ID等       |
| 认定   | 培训认定信息         | 认定ID、培训人员ID、认定结果、认定时间等                 |
| 财务   | 项目财务信息         | 财务ID、项目ID、补贴金额、拨款进度、结算状态等              |

#### 5.2.2 关系模型

- 用户与角色：多对一关系，一个用户对应一个角色，一个角色可以对应多个用户。
- 用户与部门：多对一关系，一个用户对应一个部门，一个部门可以对应多个用户。
- 项目与企业：多对一关系，一个项目对应一个企业，一个企业可以对应多个项目。
- 项目与项目立项表：一对一关系，一个项目对应一份立项表，立项表对应一个项目。
- 项目与十大管理表：一对多关系，一个项目对应10类管理表，每类可按版本迭代。
- 项目与培训：一对多关系，一个项目可以包含多个培训，一个培训对应一个项目。
- 培训与培训人员：一对多关系，一个培训可以包含多个培训人员，一个培训人员对应一个培训。
- 项目与协议：一对多关系，一个项目可以包含多个协议，一个协议对应一个项目。
- 项目与材料：一对多关系，一个项目可以包含多个材料，一个材料对应一个项目。
- 培训人员与认定：一对一关系，一个培训人员对应一个认定，一个认定对应一个培训人员。
- 项目与财务：一对一关系，一个项目对应一个财务，一个财务对应一个项目。

## 6. 其他需求

### 6.1 集成需求

- 与人社系统的集成：支持与人社系统的数据交互，如上传开班材料、申报补贴等。
- 与企业内部系统的集成：支持与企业内部系统的数据交互，如获取企业人才数据、推送培训信息等。
- 与培训机构系统的集成：支持与培训机构系统的数据交互，如确认授课老师、提交材料等。

### 6.2 移动端需求

- 支持移动端访问：系统应支持通过手机、平板等移动设备访问，方便用户随时随地进行操作。
- 移动应用功能：开发移动应用，支持培训人员签到、提交材料、查看培训信息等功能。

### 6.3 报表需求

- 项目报表：支持生成项目进度、培训效果等报表。
- 财务报表：支持生成补贴拨款、项目结算等财务报表。
- 统计分析：支持对培训数据进行统计分析，为决策提供依据。

### 6.4 培训需求

- 系统使用培训：为各部门用户提供系统使用培训，确保用户能够熟练使用系统。
- 操作手册：提供详细的系统操作手册，指导用户使用系统。

## 7. 总结

本需求规格说明书详细描述了培训部数字化功能的需求，包括业务流程分析、系统功能需求、非功能需求、系统架构和数据模型等方面。系统将实现10个部门的协调合作，支持从项目启动及规划、培训执行、认定到项目收尾的全流程管理，提高培训管理的效率和质量。
