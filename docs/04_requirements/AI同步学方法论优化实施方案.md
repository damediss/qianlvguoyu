## 2. 优化目标与原则

**目标**：把"宣称层"与"机制层"对齐——对学员说的每句话都有代码兑现；把参数纳入可论证区间；为效果验证建好数据管道（可证伪性）。

**原则**：

1. **名实合一优先于机制先进**：先消除"说了没做"，再谈"做得更好"。
2. **规则引擎主干不动**：三阶段调度、权重锚定、判分闭环经实证是坚实的，本方案全部为增量与修正，不重写主干。
3. **一切新行为可单测、可复现**：补实现的 ABCD 与原决策表逐行对应，测试先行。
4. **文案改动走冻结流程**：文案方案 §9"改文档 → 冻结 → 同步 App"，本方案 §4 给出逐字新旧对照，需求方审核后落文案方案 v1.1。
5. **灰度可控**：机制级改动（W3/W4/W6）全部带 sys_dict 开关，默认不扰动存量学员。

## 7. W4 错题扩展间隔 + 答对题抽回（三期，机制级，默认灰度关）

> 目标：把"每日全量集中重现"改为"有间隔的提取练习"，回应 G6/M10/M11；同时缓解中断正反馈（M7）——复盘队列变小后，新题被挤压的程度下降。

### 7.1 黄牌到期调度（`next_due_date`）

- `ai_review_wrong_item` 加列 `next_due_date DATE NULL`。
- 规则：
  - 红牌：`next_due_date=NULL`（每日到期，保持高频纠错）；
  - 红升黄：`next_due_date = 今天+1`；
  - 黄牌答对（未达毕业）：连对 1 次后 `+3 天`；第 2 次答对且满足既有"间隔>3 天"→升绿（状态机条件不变，间隔由调度天然保证）；
  - 黄牌答错：回红+加星，`next_due_date=NULL`；
  - 加星题：不受 due 限制，每日到期（顽固盲区保持高压）。
- 复盘队列改为：红牌全量 + `next_due_date ≤ 今天` 的到期黄牌 + 加星置顶（排序不变）。
- 迁移：存量黄牌 `next_due_date=今天`（全到期，行为与现状一致，随答对渐进出清）。
- 开关：`ai_review_spaced_review_enabled`（默认 0=现状每日全量）。

### 7.2 答对题间隔抽回（低成本复测通道）

- 阶段 2 每日复盘队列混入"已答对且 ≥7 天未在任何轮次出现"的必做池题：数量 = `复盘量 × ai_review_recall_percent`（默认 10，即 10%，0=关），上限 10 题/天；
- 抽回题答错 → 正常入册红牌（验证了"答对≠掌握"的缺口）；答对 → 仅记 answer，不进错题本；
- 该通道同时是 W5.2"绿牌/答对题再错率"指标的数据源之一。

### 7.3 交互约束

- 超前学习不受影响（队列计划级）；daily_total_cap 挤压逻辑不变（复盘优先）；
- W3-B 案"3 天只出红牌"期间：due 调度暂停（红牌每日出本来就是强口径）。

## 10. W8 知识漏洞提示与 AI 讲解补实现（二期）

> **定位**：W8 不是"新增 AI 功能"，三分之一是**名实欠账**（W8.1，接口承诺了却没有），三分之二是**把系统已有的诊断翻译成学员听得懂的话**（W8.2），其余是埋点（W8.3）。同类题加练（W8.4）不进二期，理由见 §10.9。
> **提出来源**：需求方 2026-10-15 提问"模型除了鼓励，能否分析学员知识漏洞、告诉学员怎么补、并提供必要帮助"；2026-10-16 拍板"按建议写详细方案，排入二期"。
>
> **引用约定（防止实施时误读）**：本节中形如 `§5.2` / `§7.9` / `§15.4` / `§1.1` 的编号指 **《AI同步学（学员复习）实现方案》v1.7**；形如 `§1.2` / `§13.8` / `§16` 的指**本方案**章节。代码行号以当前主干为准，实施前复核。

### 10.1 现状实证（代码级）

| # | 现象 | 代码证据 |
|---|---|---|
| ① | **承诺可讲解，接口不存在** | `ReviewPlanApplicationService:1978` 在作答响应中返回 `explainAvailable = transition.star() && !correct`；而 App 端 controller 仅有 overview/today/question/answer/mock/start、mock/submit/finish/progress/advance-day/availability，**全库无 `/explain` 端点**。学员侧拿到"可以讲解"的标记，点进去没有落点 |

**结论**：诊断能力富余，翻译层与帮助层空缺。W8 补的就是这两层。

### 10.2 设计原则（先立规矩，再谈实现）

1. **规则算，模型说。** 漏洞判定与排序 100% 由规则引擎实现（确定性、可单测、零成本、可复现）；LLM 只做"翻译成人话"和"讲为什么错"。**禁止让 LLM 做统计与排序**——§1.2 已论证 LLM 做调度慢、贵、输出不确定、无法单测，本项目 D2 与 §2 原则 2 已确立"规则引擎主干不动"。
2. **不新增触发点。** 提示挂在每日任务物化处（现 `generateAsync` 调用点，1626–1628 行附近），与每日鼓励语同一时机异步生成。**不新增定时任务**（每日物化 job 已移除，入口是 overview/today/advance-day 懒触发）。
3. **可证伪优先。** 提示的曝光与点击同批落库，绑进 W5。否则又造一个"宣称了却无法验证"的功能——G1 的教训不能再犯一次。
4. **grounded 讲解。** 讲解只允许基于题干/选项/正确答案/官方解析/学员错答，**禁止引入题外知识**；安全规程类知识点走"仅展示官方解析"白名单。职业技能认定有标准答案，讲错要担责。

### 10.3 W8.1 补 `/appreviewsync/explain`（名实欠账）

#### 10.3.1 接口契约

| 项 | 内容 |
|---|---|
| 路径 | `POST /appreviewsync/explain`（App 端，走 `AppTokenAuthFilter` + `gateGrayRelease`） |
| 入参 | `{examId, questionId}` |
| 出参 | `{explainText, fromCache: 0/1, source: official_resolve\|llm\|none}` |
| 门禁 | `ai_review_explain_gate=star`（默认，现口径）：仅加星红牌可讲；`=wrong`：首次答错即可讲 |
| 越权 | 非本学员的 plan/question → 业务异常（不绕过权限，AGENTS.md 全栈硬规则 5） |

#### 10.3.2 讲解生成（三段式，≤200 字）

提示词输入**只有**六项：题干、选项、正确答案、官方解析（若有）、学员错答、知识点名称。

输出结构（提示词内约束，后处理校验长度）：

```
① 为什么错（≤60 字）——指向学员具体错在哪，不复述题干
② 记住什么（≤80 字）——该知识点最该记的一句，不得超出题面与官方解析范围
③ 下次怎么辨（≤60 字）——给一个可执行的读题动作（如"先圈否定词""逐项判断再选"）
```

**护栏（硬约束，写进提示词与后处理）**：

- 禁止引入题外知识、禁止给出与官方解析冲突的说法；官方解析与题面冲突时以题面为准并记 warn
- 禁止"保过/必过/稳过"类保证性表述（沿用文案方案 §3 第 4 条）
- 不出现参数名/表名/模型名/内部文档名（沿用文案方案 §3 第 3 条）
- 安全规程、法律法规、工艺参数类知识点命中关键词白名单 → **跳过 LLM**，直接返回官方解析（与教材生成方案的护栏同口径）
- 输出标注：App 端讲解卡片底部固定一行"AI 生成，以官方教材为准"

#### 10.3.3 缓存、降级、限流

| 环节 | 策略 |
|---|---|
| 缓存 | 三级：Caffeine 进程内（questionId，TTL 24h）→ `ai_generation_draft` 查重（`source_type='ai_review_question'`，`source_id=questionId`）→ 调 LLM。**同题跨学员复用，调用量≈去重错题数而非人×次** |
| 降级 | LLM 异常/超时/配置缺失 → 返回官方解析（`source=official_resolve`）；无官方解析 → `source=none` + "该题暂无解析，建议先记住正确答案"（**不编造**） |
| 限流 | 每日每学员上限 `ai_review_explain_daily_limit`（默认 10）；超限返回降级文案，不调 LLM |
| 留痕 | `ai_generation_draft`：`draftType='ai_review_explain'`、`sourceType='ai_review_question'`、prompt/result/modelName 齐全（AGENTS.md AI 规则）；留痕失败不影响主链路 |
| 主链路隔离 | 讲解是独立接口，**作答链路不依赖它**；LLM 超时时 `answer` 仍 200（沿用 §13.8 测试断言） |

### 10.4 W8.2 漏洞提示（每日一条）

#### 10.4.1 输入（全部现有数据，零新表）

| 数据 | 来源 |
|---|---|
| 各 L3 首答正确率、覆盖率 | `ai_review_answer`（`attempt_seq=1` 口径）× `ai_review_plan.must_do_ids` |
| 各 L3 在册错题数 | `ai_review_wrong_item`（`removed=0`，按 `knowledge_id` 分组） |
| 各 L1 归一化权重 | `ai_review_plan.weight_snapshot`（§5.7） |
| 题型正确率、错因分布 | `ai_review_answer.question_type` / `user_answer` / `use_time_sec` |

#### 10.4.2 漏洞分算法（规则层，纯逻辑可单测）

对每个 L3 知识点计算：

```
accuracyFirst = 首答正确率（attempt_seq=1 的 is_correct 均值）   // 样本 <3 视为不足，置 null
wrongRatio    = 在册错题数 / 已作答题数                          // 无作答时为 0
weightNorm    = 所属 L1 的归一化权重（weightSnapshot）           // 无权重配置时取 1/L1 数
coverageGap   = 1 - 已做题数 / 必做池该题数

样本充足：score = 0.40×(1-accuracyFirst) + 0.30×wrongRatio + 0.20×weightNorm + 0.10×coverageGap
样本不足：score = 0.30×wrongRatio + 0.20×weightNorm + 0.50×coverageGap   // 没做过 = 潜在漏洞，权重让给覆盖缺口
```

取 `score` 降序 Top `ai_review_gap_hint_top_n`（默认 3），同分按 `knowledgeId` 升序（保证可复现）。

**口径说明**：权重取值 0.4/0.3/0.2/0.1 为**工程拍板**（无文献出处），按方案 §2 原则与 M5 的处置精神，一律经 `dictIntInRange` clamp 并可配置，**不对外宣称这些系数有实证依据**。这条必须写进附录 A。

#### 10.4.3 错因分类（规则层，四类）

| 类型 | 判定规则 | 给学员的说法（文案素材） |
|---|---|---|
| `miss_select` 漏选 | 多选 && 0 < 得分 < 满分 | "这题你选对了一部分，是记得不全——这类题要一项一项单独判断" |
| `wrong_select` 错选 | 多选 && 得分 = 0 | "选进了不该选的，这类说法最容易混，重点记差异" |
| `hesitant_correct` 假掌握 | 答对 && `use_time_sec` > 该计划该题型的 P75 | "这几题做对了但犹豫很久，不算真会，后面还会回来" |
| `instant_wrong` 完全不会 | 答错 && `use_time_sec` < 5s | "这几题基本没印象，先看一眼解析再往下" |

> `hesitant_correct` 是 W4（答对题间隔抽回）的天然候选池——二期只做提示，不自动加题；W4 上线后可直接复用这批题做抽回（见 §10.9）。

#### 10.4.4 输出形态

- 位置：今日任务卡片下方（与鼓励语同区域，不打断答题）；学情页同步展示当日/最近一次
- 长度：≤`ai_review_gap_hint_max_len`（默认 100 字）
- 结构：**一句结论 + 最多 3 个漏洞点（知识点名 + 一句为什么） + 一个动作按钮**（"先去补第 1 个"→ 跳该知识点的错题清单）
- 全对/无数据：输出"目前没看出明显漏洞，保持节奏"，**不空白、不报错**

#### 10.4.5 生成时机与兜底

- 时机：每日物化时异步生成（挂点同 §10.2 原则 2），结果进 Caffeine（planId+dayIndex，TTL 24h）
- **规则兜底（必须）**：LLM 不可用/超时/配置缺失时，用模板拼装（知识点名 + 在册错题数 + 一句话），保证学员永远看得到内容。模板是默认路径，LLM 只是润色
- 开关：`ai_review_gap_hint_enabled=0`（默认关），二期验收通过后打开

### 10.6 文案族与冻结流程

**流程**：按 O-8 默认口径，**并入 W1 的文案冻结批次**（文案方案 v1.1），不单开一轮评审。遵循文案方案 §9"改文档 → 冻结 → 同步 App"。

**语体规范**（沿用文案方案 §3）：第二人称"你"、短句口语、不暴露内部实现、无保证性承诺、每条可溯源到已实现机制。

**文案示例（≤100 字，供冻结评审）**：

1. 「今天重点补这 3 处：**电解槽效应**（错 5 次）、**氧化铝浓度**（对 4 错 3）、**安全规程**（还没练过）。先清第 1 个，它在考试里分量最重。」
2. 「昨天错的题里，有两道是**漏选**——你选对了一部分，是记得不全。多选题要一项一项单独判断，别凭印象。」
3. 「有 6 道题你做对了但想了很久，不算真会。这两天它们还会回来，到时候别靠蒙。」

**溯源要求**（写入文案方案 §7 溯源表）：

| 文案声称 | 机制出处 |
|---|---|
| "今天重点补这 N 处" | §10.4.2 漏洞分 Top N（规则层） |
| "错 X 次 / 对 A 错 B" | `ai_review_wrong_item.wrong_count` / `ai_review_answer` 首答口径 |
| "是漏选，记得不全" | §10.4.3 错因分类 `miss_select` |

### 10.7 成本估算（不给具体金额，只给量级口径）

- **提示**：活跃学员数 × 1 次/日（物化时生成，学员当天多次打开不重复调用）
- **讲解**：因题级缓存跨学员复用，实际调用量 ≈ **去重错题数**，而非"人数 × 题数"；再叠加每日每学员上限封顶
- 计费模型沿用 `exam_faq_model_config` 现配（`deepseek-v4-flash`，maxTokens 6000）
- **护栏**：`ai_review_explain_daily_limit` 与 `ai_review_explain_gate` 双重封顶；成本异常时先把 gate 切回 `star`

### 10.8 风险与护栏

| 风险 | 等级 | 处置 |
|---|---|---|
| **讲解幻觉**（讲错知识点） | 高 | grounded 六项输入 + 题外知识禁入 + 安全类白名单不调 LLM + 底部固定"AI 生成，以官方教材为准" + `ai_generation_draft` 可追溯 |

### 10.9 不进二期的部分：W8.4 同类题加练

**内容**：对 Top1 漏洞点，从必做池同 L3 的未做题/在册错题里取 5–10 题生成"专项补漏包"，插进后续每日任务。

**不进二期的理由**：它改的是"每日任务生成"这块逻辑，而二期 W3（ABCD 重排）已在动、三期 W4（间隔调度）还要动同一块。**三改一区，冲突风险与回归面都太大**。

**排期**：W4 落地之后（四期，或与 W6 同批灰度）。复用的基建：`QuestionSelectDomainService`（已有取题与权重轮转能力）+ W4 的抽回通道（`hesitant_correct` 池正好是现成的候选集）。

## 16. 分期建议与排期入口

| 期 | 工作包 | 出口标准 |
|---|---|---|
| 一期（本周可启） | W1 + W2 | §14.1/§14.2 全勾；对外宣称风险清零 |
| 二期 | W3 → W8.1 → W8.2 + W5（**顺序锁定**） | §14.3/§14.7/§14.5 全勾；可证伪数据开始积累 |
| 三期（灰度） | W4 + W6（依赖 W3-B） | §14.4/§14.6 全勾 + 灰度观察 2 周 |
| 四期（或并入 W6 灰度批） | W8.4 同类题加练（依赖 W4 落地后） | §14.7 增补条目 |
| 待证触发 | W7（O-1 核实后）、成绩回流（O-5 数据源到位后） | 对应验收节 |

**二期顺序为何锁定为 W3 → W8.1 → W8.2 + W5**：二期主体是"补课"（补死代码、建数据管道），业务侧零感知，排期评审时最易被砍；W8.2 是二期唯一学员看得见的东西，天然更容易活下来。若不锁顺序，会出现"新功能挤掉 P0 欠账"的倒挂——而真正消除风险的是 W3。故约定：**W3 未过验收，W8.2 不得上线**（W8.1 为名实欠账，可与 W3 并行或紧随）。W8.2 另带独立开关 `ai_review_gap_hint_enabled`，工期紧张时可单独滑出二期而不拖累欠账。

**审核方式建议**：按工作包逐项回复"通过/调整/不做"，我按回复修订本方案后冻结为 v1.1，再按分期实施。
