# 千铝工投云平台与智能体开发部容量与性能管理制度

制度编号：QLGT-YWGL-2026-107　　版本：V1.1　　发布日期：2026-10-16

## 第一章　总则

**第一条**　为常态化评估系统容量与性能水位，提前规划扩容，治理慢 SQL 等性能隐患，避免“撑到出事才扩容”，特制定本制度。本制度遵循部门制度“简洁、可测试、可维护、持续迭代”的共同标准。

**第二条**　本制度适用于全部生产系统的容量规划与性能管理。

## 第二章　容量评估与规划

**第三条**　每季度由 3 组接口人评估业务量（注册量、活跃用户、考试场次、数据增长量）与资源水位，输出容量评估表。

**第四条**　水位线规则：CPU、内存、磁盘、数据库连接数任一项月均峰值达到 70% 时启动扩容规划，达到 85% 时启动紧急扩容。扩容执行走 YW-02 资源申请流程。

## 第三章　性能基线与压测要求

**第五条**　性能基线：核心查询接口 P95 不超过 500 毫秒，核心提交接口 P95 不超过 1 秒；页面首屏加载不超过 3 秒。

**第六条**　大版本（涉及核心链路、数据结构或高并发场景变更）上线前必须压测，压测并发按预估峰值 2 倍执行，压测报告随发布单归档。3 人团队压测由开发岗自行执行，报告归档即可，不设专职性能岗。

## 第四章　慢 SQL 与性能问题治理流程

**第七条**　慢查询（执行时间超过 1 秒）由数据库日志每日汇总；新增慢 SQL 由责任开发在 3 个工作日内认领并给出优化方案。

**第八条**　生产环境禁止无索引全表扫描；大表结构变更按 YF-05 评审后执行，并评估锁表影响与变更窗口。

**第九条**　性能问题治理结果在月度运维例会通报，未按期治理的升级为部门负责人督办。

## 第五章　扩容申请与执行流程

**第十条**　扩容申请说明：当前水位、业务依据、目标规格、费用变化，经运维负责人审批后执行；执行后验证业务指标并更新台账。

**第十一条**　扩容后 1 个月内回评效果，未达预期的分析原因并调整方案。

## 第六章　附则

**第十二条**　本制度由部门负责人负责解释。

**第十三条**　本制度自发布之日起施行。
