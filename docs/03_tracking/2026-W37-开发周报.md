## 七、风险、阻塞与需要协调

### P0

1. **答案并发写入死锁**：100 Pad 出现 `CompetitionFormalCandidateAnswerMapper.insert` 死锁并被映射为 500，导致答案未同步完成、10 人交卷 409。需要稳定锁顺序或 upsert，并在新事务边界内做有限重试；当前工作区已有相关实现和测试，但尚未形成提交和复测结论。
2. **实时消息序号与追赶语义**：smoke/L1 出现 Outbox seq 重复/缺口；当前正在补游标表、唯一约束、catch-up 查询和跨节点发布逻辑，需验证断线重连、重复消息、节点切换和 at-least-once 语义。
3. **场次终态未闭环**：压测中选手已提交但 `submitted_total` 仍为 0，场次仍为 `running`，评分状态未自动进入 `scoring`。需明确“全部终态 → 场次结束 → 评分启动”的唯一状态机。

### P1

1. Flyway 迁移版本与两套目标库历史尚未核对；新迁移必须在 `mvn compile` 后验证，不能修改已应用历史脚本或仅以隔离库 repair 结果代替正式验收。
2. 控制台 candidates 查询在 100 Pad 出现约 60 秒级 p95，Druid `max-active=20`；需要按 SQL 峰值、锁等待和连接持有时间重新估算，不得直接把连接池拍脑袋调大。
3. nginx 单 IP `ip_hash` 使压测流量偏向单节点，当前双节点结果不能完全代表均衡生产拓扑；需增加明确的节点亲和/分流对照。
4. 竞赛产品仍缺实操评分、选手入口链接/二维码、设备级清退，以及离线 20 题恢复、统一截止自动交卷等完整场景。
