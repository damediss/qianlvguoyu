# 竞赛成绩、排名与晋级规则合同（COMP-SCORE-00 V1.0 开发基线）

> 状态：当前开发范围已冻结，可进入开发；本版本功能完成后，下一优先级立即进入“并发考试与赛前刷题容量专项”；P0-05、P0-07、P0-08 为明确后置项，不纳入本版本开发与验收。
> 业务输入：2026-07-29 业务补充说明及企业微信确认截图；适用对象为竞赛赛制 A/B。
> 关联文档：[竞赛成绩、排名与晋级专项：可行性评估及业务补充清单](competition-scoring-ranking-feasibility-and-business-rfi.md)。

## 1. 合同目标与适用边界

本合同冻结竞赛的成绩来源、实操评分、排名、晋级/奖项、人工确认、解锁重评与撤销重排规则。竞赛在业务上可复用认定的题库、实操评分流程和平板端能力，但赛事、赛段、选手、裁判回避、成绩版本、排名和奖项快照仍归 `competition` 领域管理。

本轮不启动竞赛选手端、在线考试会话、仿真平台接口、并发容量实施、公开大屏、电子签章/证书。当前合同范围开发完成后，必须优先启动[竞赛考试并发与赛前刷题容量设计](../05_decisions/competition-exam-concurrency-capacity-design.md)及其实施、压测和模拟赛，不得将该专项继续排在奖项、公示仲裁或仿真接入之后。

结合当前代码链路核对，开发阶段顺序冻结如下：

1. 当前阶段 A：先补齐赛前编排桥接，包括赛事工种、选手工种归属、赛段/资格审核 API、赛制 B 规则版本与成绩域就绪检查。
2. 当前阶段 B：完成本合同 V1.0 范围内的理论判分、实操评分、裁判流程、成绩与排名基础能力及基础端到端验收。
3. 下一阶段：当前阶段 A/B 全部完成后，立即实施并发考试与赛前刷题容量专项，包括答题会话、批量保存、交卷幂等、缓存限流、监控、压测和全规模模拟赛。
4. 后续阶段：待业务规则或外部接口确认后，再排入 P0-05 奖项、P0-07 公示仲裁与撤销重排、P0-08 仿真接入。

当前实现与上述阶段之间的证据和缺口见[竞赛模块全链路现状与成绩专项衔接缺口](competition-end-to-end-chain-gap-assessment.md)。

## 2. 已确认业务规则

| 编号 | 规则 | 合同口径 |
| --- | --- | --- |
| C-01 | 排名范围 | 每个**工种**独立形成成绩、排名、晋级和奖项名单；不设分组。不同工种的选手不互相比较。 |
| C-02 | 赛制 A | 总分由理论与仿真成绩按赛事规则版本的权重合成。 |
| C-03 | 赛制 B | 理论、仿真、实操均按 100 分制换算。`总分 = 理论得分 × 理论权重 + ((仿真得分 + 实操得分) ÷ 2) × 仿真实操组合权重`；两项权重之和为 100%，总分满分为 100 分。创建赛事时必须填写两项权重，取值为 0%–100%，相加必须为 100%；赛事发布后锁定。 |
| C-04 | 理论题来源与试卷 | 从现有题库抽题；专家与各企业裁判分别提供部分试题，结合形成 A、B 两套试卷。每个工种可按设备数量分时段考试，每个时段固定使用指定卷；题目、答案、分值和判分规则须在开考前形成不可变快照。多选题仅在选手所选答案集合与标准答案集合完全一致时得满分，漏选、错选或多选均得 0 分，不设部分分和倒扣分。 |
| C-05 | 实操与仿真依据 | 实操、仿真评分以经确认的技术文件及其版本为准；系统只引用已锁定的文件/评分细则版本。 |
| C-06 | 分项满分 | 理论、仿真、实操均按 100 分制换算；实操按评分标准扣分。 |
| C-07 | 裁判数量与汇总 | 每名选手固定 3 名有效裁判评分，实操得分取三人算术平均并保留 2 位小数。裁判缺评、回避、退出或无法完成重评时，由现场已绑定的备用裁判补位；系统保留被替换裁判、替换原因及全部历史评分。 |
| C-08 | 裁判绑定主体 | 仅竞赛组委会管理员或主裁判长可在后台绑定裁判账号。身份证用于匹配本地人员档案和避免身份/账号冲突，短信验证码用于确认当前用户能够接收该手机号的验证码；两者都是本地登录校验，不做外部实名认证。腾讯云仅负责发送短信验证码。 |
| C-09 | 裁判提交锁定 | 裁判提交评分后立即锁定，裁判本人、主裁判长和组委会管理员均不得直接修改已提交评分。 |
| C-10 | 解锁重评 | 仅主裁判长可发起评分解锁申请，必须填写修改原因；系统管理员审批通过后，指定评分单才可解锁重评。原评分、申请、审批和新评分必须完整保留。 |
| C-11 | 主裁判长复核 | 主裁判长可查看本赛项全部裁判评分明细，但不能直接修改他人评分；发现问题只能发起驳回/解锁重评流程。 |
| C-12 | 回避 | 裁判与选手存在师徒、亲属、同单位等关系时，须赛前申报回避。后台可为裁判绑定禁评选手名单；匹配后系统必须阻止其打开、保存或提交该选手评分。 |
| C-13 | 及格线与缺考 | 不设置 60 分或其他达标线。正常完赛选手按实际得分参与本工种排名；缺考记 0 分并标注“缺考”，在输出名单中展示，但不参与排名、不占用名次。 |
| C-14 | 并列排名 | 使用竞赛标准“1334”占位法：同一名次有两人时，两人均保留该名次，下一名次跳过已占用名次。 |
| C-15 | 晋级截取 | 前 N 名包含并列；若第 N 名所在并列组跨越截取线，该并列组所有选手均晋级/获奖。 |
| C-16 | 奖项配置 | 后台按最终排名顺次截取，可配置一等奖、二等奖、三等奖等数量或比例；比例取整与奖项区间见 P0-05。 |
| C-17 | 人工确认触发 | 仅限极端并列（完整排序字段均相同）、仲裁申诉、设备重大故障导致重赛等情形。 |
| C-18 | 公示期撤销/重排 | 最终公示期默认 3 个工作日。期间如出现作弊实锤、裁判舞弊等新证据，经仲裁委员会三分之二以上委员签字同意，管理员可撤销已确认成绩/名次并重新排名；系统必须发布官方更正公告并通知所有受影响选手。 |

## 3. 成绩来源与规则版本

### 3.1 统一原则

每项可用于计算的成绩均必须包含：赛事、赛段、工种、选手、来源类型、规则版本、原始分、确认状态、取得时间和操作者/外部流水号。成绩来源未经确认，不得进入总分、排名或获奖计算。

| 来源 | 获取方式 | 进入计算的前提 |
| --- | --- | --- |
| 理论 | 考试会话服务端按题型判分 | 已交卷、试卷快照存在、自动/人工判分已完成。 |
| 仿真 | 仿真系统签名回调或经授权的人工确认 | 技术文件版本、外部成绩流水和耗时均已对账。 |
| 实操 | 裁判评分单按评分细则提交 | 所有有效裁判评分已锁定，且不存在待处理的解锁申请。 |

### 3.2 理论试卷 A/B

1. 每个工种的理论试卷由现有题库中已审核可用的题目组成；专家、企业裁判的出题来源只作为题目来源与审计标签，不能绕过题库审核、答案维护和权限控制。
2. A、B 卷均须独立生成版本号、题目清单、题序、题型、题目分值、标准答案、判分规则、审核/发布人和发布时间；开考后禁止覆盖原版本。
3. 单选、判断题按标准答案完全匹配判分。多选题由服务端按答案集合比较，仅当选手答案集合与标准答案集合完全一致时取得该题全部分值；漏选、错选或多选均得 0 分，不设部分分和倒扣分，选项提交顺序不影响结果。判分规则随试卷形成不可变快照，不能由前端自行计算。
4. 每名选手在开考前由服务端确定试卷版本；选手端仅接收本人的题目投影，不接收标准答案、其他试卷或出题人信息。
5. 同一工种可按设备容量分时段考试。例如 200 名选手、100 台设备时，第一时段 100 名选手使用 A 卷，第二时段 100 名选手使用 B 卷；系统必须将选手、时段和试卷版本在开考前固定，不能随机换卷。
6. 同一工种的 A/B 卷参与同一榜单前，必须具有相同考试时长、相同理论满分和已确认的等值性审核记录；否则系统不得合并排名。
7. 已收到两种理论试卷模板，见 P0-03。每个工种在赛事发布前选择其适用模板，A/B 卷必须采用同一已确认模板。

### 3.3 实操评分单与重评状态机

评分最小业务单元为“赛事 + 赛段 + 工种 + 选手 + 裁判 + 实操评分细则版本”。推荐状态如下：

```text
assigned → draft → submitted_locked
                     ↓（主裁判长填写原因）
              unlock_requested
                     ↓（系统管理员批准）
              unlocked_for_rescore → submitted_locked
                     ↓（系统管理员拒绝）
              unlock_rejected
```

- `submitted_locked` 评分单不可由任何裁判直接修改。
- 解锁申请必须指向具体评分单，记录申请原因、证据 fileId（如有）、申请人、审批人、审批时间和审批意见。
- 获批后创建新的评分修订版本，保留旧版的逐项扣分、总分、提交时间和提交人；成绩计算只采用当前已锁定的有效版本。
- 裁判回避命中后，评分单状态应为 `recused` 或不生成评分单，且不得通过管理员代操作绕过回避校验。

### 3.4 实操分汇总

实操评分已冻结为：

```text
实操得分 = round((裁判1有效分 + 裁判2有效分 + 裁判3有效分) ÷ 3, 精度)
```

有效分仅指已锁定、未回避、未作废的裁判评分。任何一名必需裁判未提交、退出、被标记回避或无法重评时，主裁判长/组委会管理员须从现场备用裁判中完成补位；补位评分锁定前，该选手实操成绩为“待确认”，不得进入总分计算。

认定模块当前的三人评分流程可复用评分细则、任务生成、平板评分、草稿/提交、锁定和审计能力；但认定的最终整数取整规则不能直接假定为竞赛规则。竞赛的分值精度、重评修订和排名汇总由本合同确定。

## 4. 总分、排名与 1334 名次

### 4.1 总分计算

总分计算必须引用已发布且锁定的赛制规则版本。计算时保存理论、仿真、实操原始分、权重、运算步骤、取整方式、结果和计算时间，支持重算生成新版本，不覆盖历史结果。

赛制 B 已冻结为以下公式：

```text
仿真实操组合分 = (仿真得分 + 实操得分) ÷ 2

总分 = 理论得分 × 理论权重
     + 仿真实操组合分 × 仿真实操组合权重

理论权重 + 仿真实操组合权重 = 100%
```

理论、仿真和实操均以 100 分制输入，因此组合分也为 0–100 分，总分满分固定为 100 分。例如理论权重 40%、仿真实操组合权重 60%，理论 85 分、仿真 90 分、实操 80 分时，总分为 `85 × 40% + ((90 + 80) ÷ 2) × 60% = 85` 分。

### 4.2 排名范围与排序键

1. 排名计算范围固定为同一赛事、同一赛段（如适用）、同一工种、同一成绩规则版本下的正常完赛选手；不按企业、裁判来源或其他分组拆榜。
2. 缺考选手记 0 分并标注“缺考”，保留在输出名单中，但从正常排名池排除且不占用名次；弃赛、违纪、取消资格、成绩待确认的展示与是否进入排名池仍按相应状态规则处理。
3. 沿用原始业务描述的排序建议，须由业务最终确认：

| 赛制 | 排序顺序 |
| --- | --- |
| A | 总分降序 → 仿真分降序 → 理论分降序 → 仿真操作总耗时升序 → 人工确认。 |
| B | 总分降序 → 实操得分降序 → 仿真分降序 → 理论分降序 → 人工确认。 |

4. “1334”只适用于以上全部自动排序字段仍相同的选手。若分项或耗时可打破总分相同，不构成并列名次。
5. 排名快照生成后不可原地覆盖；重评、仲裁或撤销应生成新版本，并保留旧版本、差异原因和更正公告关联记录。

### 4.3 1334 算法与截取线

设排序完成后的并列组人数依次为 `g1, g2, ...`，第一个并列组的显示名次为 1；下一组显示名次为此前所有组人数之和再加 1。例如两个选手完整并列第一，名次显示为 `1、1、3`。

晋级或奖项使用“显示名次 + 并列组”截取：当截取线为 N 时，选中所有显示名次小于 N 的选手，以及显示名次等于或跨越 N 的完整并列组。系统不得按数据库行数截断并列组。

## 5. 晋级、奖项、确认和撤销

### 5.1 晋级与奖项快照

每次生成晋级/奖项候选时，保存排名快照版本、工种、截取规则、候选选手、并列扩容原因、创建人和时间。发布后选手端和公开端只读取已发布快照，不实时聚合内部成绩。

奖项可采用“固定人数”或“比例”两种配置。比例配置必须明确是累计上限（例如前 10%、前 30%、前 60%）还是区间比例（10%、30%、60% 三段），以及人数向上/向下/四舍五入规则；详见 P0-05。

> 当前阶段不开发奖项比例和奖项名单生成。排名快照可先实现，奖项能力待 P0-05 重新启动后补充。

### 5.2 人工确认

人工确认只可处理以下事件：

- 完整排序字段均相同的极端并列；
- 已受理的仲裁申诉；
- 经认定的设备重大故障导致补赛或重赛。

人工确认记录必须包含：触发事件、关联成绩/排名版本、证据、处理结论、处理人、时间和是否影响已发布名单。人工确认本身不能绕过裁判锁分规则；需要变更实操评分时仍须走解锁重评。

### 5.3 公示期撤销与重排

> 本节作为后续规则保留，当前阶段不开发仲裁委员会签字、公示期撤销、重排和更正公告流程；待 P0-07 重新启动后实施。

1. 默认公示期为 3 个工作日；工作日、节假日和起止时间的系统口径见 P0-07。
2. 公示期内发现作弊实锤、裁判舞弊等新证据时，仲裁委员会的有效同意票数必须达到**全体有效委员人数的三分之二以上**；人数除不尽时向上取整。委员名单和有效人数以发起撤销时锁定的委员会版本为准。
3. 系统管理员在审批链完成后执行撤销：作废受影响成绩/名次快照，重新计算排名、晋级和奖项候选，生成新发布版本。
4. 每次撤销/重排必须关联官方更正公告，并向所有受影响选手发送站内信；短信通知是否启用遵从赛事通知配置和供应商状态。
5. 公示期结束后的撤销条件、归档后更正权限和证书/成绩单撤销规则见 P0-07。

## 6. 权限与审计合同

| 动作 | 允许角色 | 不允许事项 | 必留审计 |
| --- | --- | --- | --- |
| 绑定裁判账号 | 竞赛组委会管理员、主裁判长 | 普通裁判、企业用户、选手绑定自己或他人 | 绑定人、裁判、本地身份证匹配结果、短信验证码校验状态、赛项、时间。 |
| 配置禁评名单/回避 | 竞赛组委会管理员、主裁判长（最终角色以权限矩阵冻结） | 回避命中后继续生成/保存/提交评分 | 关系类型、来源、配置人、变更历史。 |
| 提交评分 | 被授权且未回避的裁判 | 提交后直接编辑 | 逐项扣分、总分、版本、设备/请求 ID、时间。 |
| 发起解锁 | 主裁判长 | 裁判自行解锁、主裁判长直接改分 | 原因、目标评分单、证据、申请时间。 |
| 审批解锁 | 系统管理员 | 审批人直接修改评分 | 审批结果、意见、时间。 |
| 确认/发布排名 | 竞赛组委会授权角色 | 覆盖已发布快照 | 规则版本、快照版本、发布人、时间。 |
| 撤销/重排 | 系统管理员，在仲裁委员会阈值达成后 | 无仲裁依据直接撤销 | 委员签字记录、新证据、更正公告、受影响名单。 |

所有写操作记录操作日志；后端按租户、赛事、工种、赛段、角色和回避关系裁决，前端按钮隐藏不构成权限控制。

## 8. 冻结后的验收样例

1. 同一赛事内两个工种分别计算排名，任何跨工种成绩均不进入对方榜单。
2. A/B 卷均从已审核题库创建快照；同一工种按已配置时段固定分配 A/B 卷，选手只能取得本人卷的题目投影，不能读取答案或另一卷。
3. 多选题仅在选手答案集合与标准答案集合完全一致时得满分；调整选项提交顺序仍得满分，任一漏选、错选或多选均得 0 分。
4. 三名有效裁判均锁分后，实操得分按 2 位小数计算；裁判回避、退出或无法重评时，备用裁判补位前相关选手成绩转为待确认，不参与新排名。
5. 回避名单命中的裁判无法查看、保存或提交对应选手评分，后端返回权限/回避拒绝并写审计。
6. 裁判提交后自行修改被拒绝；主裁判长申请、系统管理员批准后产生新的评分版本，旧版本仍可查看。
7. 总分相同但分项不同的选手依排序键决定先后；所有排序键相同者按 1334 显示相同名次。
8. 第 N 名处并列时，完整并列组均被纳入晋级/奖项快照，系统不会按行数截断。
8. 公示期内仲裁委员会达到阈值后，撤销生成新排名和官方更正公告；受影响选手均收到通知，旧快照可审计。
