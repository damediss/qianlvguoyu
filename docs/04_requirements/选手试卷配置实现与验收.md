# 选手试卷配置

入口：赛事赛段编排画布 → 理论配置 → 选手配置；也可从试卷工作台的“配置选手试卷”进入。

复用赛事、工种等级、参赛资格、选手档案、赛段已发布理论试卷快照。新增 `competition_stage_paper_assignment`，保存赛段与选手档案、试卷快照的关系；现有排考关系必须关联场次、考场，因此分卷配置单独保存。

选手范围为赛事有效参赛资格、有效选手角色、已匹配工种且技能等级符合当前赛段的档案。等级优先使用档案等级 ID，历史空 ID 使用名单等级文本匹配赛事等级编码、名称和来源文本。沿用既有排考的当前赛段限制。全名单工作区要求赛事管理数据范围，参赛企业不能读取平台赛事其他单位名单。

试卷数量动态读取。随机打散选手后循环分配，各卷人数最多相差一人。自动分配立即保存草稿；人工修改在本地草稿中即时更新统计与筛选，点击保存或确认后落库。确认要求全部符合条件的选手均分配有效试卷；后续修改保存后恢复待确认。移出等同取消分配。

接口前缀：`/api/competition/stages/{stageId}/paper-assignments`。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/summary` | 赛段、工种等级、动态试卷与统计 |
| GET | `/players` | 按姓名编号、单位、试卷、状态筛选分页 |
| GET | `/visualization` | 当前候选列表及分配结果 |
| POST | `/auto-allocate` | 平均随机分配 |
| PUT | `/assignments/{contestantProfileId}` | 单人分配或取消 |
| PUT | `/assignments/batch` | 批量修改 |
| PUT | 空路径 | 保存草稿变化 |
| POST | `/confirm` | 保存并确认完整配置 |

写操作使用事务及赛事行锁，复用平台审计日志。查看、管理、确认权限分别为 `competition:stage-paper-assignment:view/manage/confirm`；确认接口同时要求管理权限，因为请求可携带分配变化。ID 以字符串返回。

部署需编译并通过现有 Flyway 流程应用 `V20260907_004__create_competition_stage_paper_assignments.sql`。部署前核对目标库迁移历史不存在版本冲突；无需新增环境变量或独立服务，沿用平台现有启动与健康检查。权限迁移后重新登录以刷新权限。

验证命令：前端 `npx tsc -b`、`npm run test:competition-stage-planning`；后端指定 `CompetitionStagePaperAssignmentSchemaContractTest` 和 `CompetitionStagePaperAssignmentApplicationServiceTest`。Docker 可用时追加 `-Dcompetition.mysql.integration=true -Dtest=CompetitionStagePaperAssignmentMySqlTest`，使用独立 MySQL 8.4 测试库验证迁移、空值持久化及回滚。

人工验收：配置任意 5 套试卷和 123 位符合条件选手，自动分配后各卷 24 或 25 人；修改、移出、筛选后统计随草稿变化，保存刷新可恢复；未分配时不能确认；其他赛段或失效试卷不可提交。

当前两个视图共享全量候选草稿以保持未保存调整的筛选一致性；后端另提供分页接口。保存单次最多 5000 个变化项。分卷关系尚不替代既有场次、考场排考流程。
